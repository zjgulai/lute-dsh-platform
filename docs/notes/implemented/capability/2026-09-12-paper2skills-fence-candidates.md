# paper2skills：代码围栏按宽松候选枚举 + 语法定终点抽取

- 生命周期：implemented
- 类别：capability
- 日期：2026-09-12
- 对应 ADR：[ADR-0050](../../../adr/ADR-0050.md)
- 订正：[ADR-0049](../../../adr/ADR-0049.md) 的「那 21 张是真实的代际差异」

## Problem

ADR-0049 留的下一入口是「那 21 张『源站卡 ≠ vault 卡』的代际差异」，判据是
「源站 ⑦ 段节选不是 vault 任何围栏的行前缀」。这一轮先复核判据本身，发现归因错了。

### 一、判据漏读，不是两代产物

旧围栏正则 ` ```[ \t]*(?:python|py)?[ \t]*\r?\n(.*?)``` ` 有两个缺陷：

- **不锚行首** → 前一个围栏的**收尾** ```` ``` ```` 被当成开栏，配对整体错位，
  被错位吞掉的开栏再也不会进入候选。`Skill-Context-Kubernetes-KB-Orchestration`
  的 338 行实现就此消失。
- **只认 python/py** → 源站发布的是卡里**第一个**块，不问语言。
  `Skill-MAS-Orchestrator` 首块是 ```` ```bash ```` 的 `cd … && python orchestrator.py`。

用与路径无关的判据（扫全部历史 7,385 个相关 blob）复核：21 张里 **19 张的代码就在
HEAD 里**，只有 **2 张**是真正的源站独有。

### 二、同类但更贵：6 张已「确证」的卡是被截断的

卡里的 Python 会把整张 markdown 卡塞进三引号字符串，那串里就有 ```` ``` ````。
旧判据在那里提前收尾，而「节选是围栏开头」这条 oracle **照样成立**——它只校验起点，
管不了终点。`Skill-Skill-Card-API-Serving` 取 66 行，真身 **443 行**。

### 三、第一次的复核结论本身是错的

本轮第一次跑出来的读数是「20/21 在 vault 历史里命中」。**那是我的提取器与管线口径
不一致造成的**——退化成「匹配一个空行」，几乎命中任何围栏。补了两组对照才抓出来：

- 阳性：oracle 抽样 20 张，节选**应当**在 HEAD 命中 → 修正后 20/20；
- 阴性：节选尾部接一行垃圾，**应当**全不命中 → 0/20 误命中（第一次那版是 20/20 误命中）。

## Decision

见 ADR-0050，七条：宽松枚举候选、oracle 候选不问语言但结果必须 Python、
终点按 `ast.parse` 定且失败退回自然块、行中切断用明示的弱判据、
`offset` 改实测、降级路径保持改前语义、加 `--check` 与 `--selftest`。

## Alternatives considered

- **严格按 Markdown 配对**：`Skill-BERT-SRL-Event-Frame-Extraction` 第 188 行有个孤立的
  裸 ```` ``` ````，严格配对会把后面的 ```` ```python ```` 开栏吞成收尾，374 行实现整块消失。
- **降级路径也走宽松候选 + `ast.parse` 门槛**：兜不住 —— `## ④ 技能关联`、`### 前置技能`
  都是合法 Python **注释**，实测 15 张卡把整段正文当成了实现。
- **对不闭合的围栏猜一个收尾位置**：那是编造，不是恢复。15 张如实记 `NO_PAIRED_PYTHON_FENCE`。
- **给 `unverified` 也加 parse 门槛**：会凭空丢 5 张已交付的卡，属于另一件事。

## Consequences

前后对账（`.scratch/p2s-card-generation/diff-before-after.py`，逐卡比对）：

| 读数 | 改前 | 改后 |
| --- | ---: | ---: |
| `oracle` | 1,262 | **1,277** |
| `unverified` | 40 | 40（不变） |
| `unrecovered` | 36 | **21** |
| 落盘 `implementation.py` | 1,302 张 / 253,648 行 | **1,317 张 / 259,365 行** |
| 已恢复且可 `ast.parse` | 1,277 / 1,302 | **1,297 / 1,317** |
| 单测（`node --test test/*.spec.mjs`） | 68 | **77** |

变化分类，**逐类都要求能解释**：

- **0 张**原本确证的卡掉出确证集（这是最要紧的一条）。
- **540 张**只因候选枚举变密而 `fence_index` 位移，**正文 sha256 一字未动**。
- **6 张**确证卡取回真身：160→389、43→266、169→334、55→242、66→443 行；
  1 张 72→71（同一次修正的副产物）。
- **15 张**从未恢复转为确证（最大一张 784 行）。
- **4 张**改记为 `EXCERPT_MATCHES_NON_PYTHON_FENCE`（发布的是运行方式，不是实现）。
- **15 张**原因码由 `NO_FENCE_IN_VAULT` 改为更准确的 `NO_PAIRED_PYTHON_FENCE`（同一批卡）。

边界：

- 21 张仍未恢复（15 不闭合 / 4 首块是 bash / 2 源站独有）。
- 20 张已恢复但源码本身写坏（全角 `（`、`：`），**是源的问题**，索引如实记 `parses=False`
  （已从 25 张降到 20 张）。
- `fence_index` 语义变为「第几个候选块」，只作定位线索，不参与任何断言。

红测（真注入，逐条都报出来了）：

| 注入 | 期望 | 实测 |
| --- | --- | --- |
| 篡改索引里一张卡的行数 | `--check` 失败 | ✗ `lines: 盘上 999 ≠ 重算 214`，exit 1 |
| 把围栏判据退回旧正则 | `--selftest` 失败 | ✗ 8 条断言失败（干净报错，非崩溃），exit 1 |
| 改脚本里的说明文字不重跑 | `--check` 失败 | ✗ `note: 盘上与脚本里的说明不一致`，exit 1 |

端到端：`assemble-skills` → `import-paper2skills` → `verify-install` 全通过；
上盘 1,317 个 `references/implementation.py` 里 **1,297 个正文可 `ast.parse`**，
与索引 `parses=false` 的 20 张**逐一对上**。

## 教训

凡写「全 X 都 Y」先跑计数。本轮入口那句「源站卡 ≠ vault 卡」在 ADR-0049 里被写成了结论，
实际是判据的产物；这是本仓第三次栽在同一处。另加一条同源的：**先证明判据能报「否」，
再相信它报的「是」**——本轮的第一次复核结论就是缺阴性对照才错的。
