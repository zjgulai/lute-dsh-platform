# 从语料 vault 的 git 明文恢复完整实现

对应 [ADR-0049](../../../adr/ADR-0049.md)。本文只记**怎么发现的、怎么验的**，
判据与取舍在 ADR，不在此复述。

## Problem

上一轮的收尾入口是：**「带编号的旧富代码代（41 个目录、中位 373 行）没有任何卡在引用
——它可能与这 1,338 张卡无关，而且是唯一还活着的真实现。」**

入口里两句话，量下来**都不成立**；而顺着它摸到的第三条，比入口假设的大一圈：
**完整实现根本没有丢。**

## 怎么查出来的

### 一、先证伪入口的第一句：「没有任何卡在引用」

写了一条命令给全部证据的取证脚本 `.scratch/p2s-two-trees/dossier.py`（九项检查，
只读、每项自带基数与分母），第一项就是穷举 `code_path` 的落点：

| 落点 | 张数 |
| --- | ---: |
| 指向**编号树** | **18** |
| 指向无编号树 | 820 |
| 无 `code_path` | 500 |

上一轮写过「卡的 `code_path` **838/838 全指向**无编号树」——**18 条反例**。
同一类错第三次了：把「绝大多数」写成「全部」，没跑计数就下全称判断。
这条已写进 ADR 的「后果」当纪律。

### 二、编号树不是「旧的一代」，是 vault 的下游

按技能目录名求交集，两棵树只重叠 1 个（`category_compliance_prescan`）。41 个编号目录
（17 个顶层）与 1,012 个无编号目录基本互斥。而且 41 个干净地裂成两半，零例外：

| 分组 | 张数 | 带年份后缀 | 行数中位 |
| --- | ---: | ---: | ---: |
| **有**同名卡 | 19 | **0** | 181 |
| **无**同名卡 | 22 | **22** | 597 |

决定性的是抬头：每个 `model.py` 第一段都写 `Auto-extracted from: paper2skills-vault/<域>/<卡 id>.md`
——**它是从 vault 抽出来的，不是 vault 的来源**。方向与入口假设相反。

再把卡面节选拿去比：18 张卡里 **17 张的节选落成 `model.py` 的连续行块，起始行号全是第 6 行**
——正是 5 行溯源抬头之后的正文首行。也就是说 `model.py` 与卡面节选出**同一个抽取器、同一个上限**。

### 三、证伪入口的第二句，也是上一轮的第二条全称断言

上一轮写「预览是这份代码唯一存世的地方」。这次先做一个最朴素的检查：
**vault 工作区里那份 `.md` 到底是什么？**

```
$ file paper2skills-vault/04-供应链/Skill-Safety-Stock-Replenishment.md
data
$ xxd | head -2
00000000: 887d 1c6e cd0a a302 6ffb 6091 0ca0 e917  .}.n....o.`.....
00000010: 39 2b 76 86 fa ea 75 0a fe ff 00 00 00 00 00 00
```

**1,545 个 `.md` 里 1,353 个是二进制容器**（32 字节头 + 到第 1024 字节的零填充 +
高熵正文，正文熵 6.9 bits/byte），只有 192 个还是真文本。排除过两个平凡解释：
`xattr` 空、无 `com.apple.decmpfs`（不是 APFS 压缩）；`brctl` 报
`Client zone not found`（不是未下载占位符）。改写时间在 2026-07-17 那次提交之后，
但 **`mtime` 被保留成原值**——只看时间戳会误判成「6 月就是这样」。

**但同一个目录是一个 2.3 GB、238 次提交的 git 仓库。**

```
$ git -C <repo> ls-tree -r HEAD paper2skills-vault/ | (统计 .md blob)
1545 条路径 / 1426 个唯一 basename
$ git show HEAD:paper2skills-vault/04-供应链/Skill-Safety-Stock-Replenishment.md | head -12
---
title: Safety Stock and Replenishment Strategy
...
## ③ 代码模板
```

**明文在里面。** HEAD 是 `4a4fa0d4`（2026-07-17，提交信息写着「→ 1338 Skills / 14901边」），
按域名解析 `vault/<src_domain>/<card id>.md`：**1,338/1,338 全部定位到，1,272 张有代码段。**

### 四、连通性：卡面那 60 行就是完整代码的开头

光有文件不够，得证明「这份就是卡里那份」。以卡面节选为 oracle 去选围栏：

**1,262 张命中，且偏移恒为第 1 行，零例外。**

### 五、恢复出来的东西可用

| | 卡面节选 | vault 完整代码 |
| --- | ---: | ---: |
| 可 `ast.parse` | 808 / 1,258 | **1,248 / 1,258（99.2%）** |

**443 张是「节选被截断而失败、完整代码却能解析」。** 上一轮报的「457 张不能直接运行」
正是这一批——它们可修。

落盘的是 **1,302 张 / 253,648 行**（中位 182 行）；上面那张表里的 1,258 张是「卡面有节选、
vault 也有 ③ 段」的比较集，两者不是同一个总体。

## 怎么验的

| 项 | 证据 |
| --- | --- |
| 取证复现 | `python3 .scratch/p2s-two-trees/dossier.py` 一条命令出九项读数 |
| 容器守卫 | 管线读到二进制容器即 `exit 1`（`looks_like_container()`），不静默产乱码 |
| 覆盖率守卫 | 确证集 < 1,200 或偏移出现非 1 → 响亮失败 |
| 卡面节选位置 | 逐张断「节选 = `implementation.py` 第 6 行起」：**1,259 命中 + 3 脱敏命中 + 40 无 oracle = 1,302，零不符** |
| 单测 | 48 → **68 全绿**（新增 12 条脱敏 + 8 条 ⑦ 段新口径） |
| 红测 | 六条注入全部报出：注入密钥 / 改坏抬头 / 加一行 / 删文件 / ⑦ 段退回旧说法 / 篡改正文首行；还原后归零 |
| 负结果是真的 | 那个 key 在 `generated/source-code.json` 里 **3 处**、在 `staging/`（出口）里 **0 处** |
| 装库 | `implementation.py` **1,302** 个落进 `~/.dsh/skills`；`verify:install` 问题 0 |
| 门禁 | `pnpm run gate` 15/15；`pnpm run gate:full` 19/19 |

## 三处自己算错又改回来的

1. **按 basename 解析 vault 卡。** vault 里 119 张卡在不同域下有同名副本，其中 18 张在
   `<域>/00-知识库-Skill卡片/` 下是**旧副本**；按 basename 取会静默拿到旧副本——
   实测把 **16 张本有代码的卡判成「无代码段」**，命中数从 1,262 漂到 1,246。
   改为优先取**域根**后，1,338/1,338 全部落到域根、歧义清零。
2. **放宽 ③ 段判据反而更差。** 试过把 `## ③ 代码模板` 放宽成「标题含『代码模板』」，
   结果段边界用 `^#{1,N}` 判定时 **Python 注释 `# 说明` 被当成标题**，段体被截断，
   命中数掉到 1,246。oracle 判据没有这个问题，遂弃用放宽方案。
3. **同样的 basename 错，在验证脚本里又犯一次。** 校验「节选在第 6 行」时，
   我用 `os.path.basename(r)` 作 key —— 而 1,302 个文件**全在名为 `references` 的目录里**，
   于是全部塌成一个 key，报「NO_FILE 1302」。这是同一个错误的第二次现身；
   根因相同：**basename 不承载身份时不能当 key**。

另外还有一处 off-by-one：抬头里写着「卡面节选 = 本文件第 6 行起」，
而 `[...head, '', code]` 实际把正文放在第 7 行。已改成 5 行抬头**紧接**正文，
与那句断言、与语料编号树 `model.py` 的形状三者一致。

## Consequences

- 卡面不再说「完整实现不在本包内」——那句话已被证伪。改为指向
  `references/implementation.py`，并把「截断的是节选、不是那份实现」分开说。
- 40 张「卡页压根没发布代码」的卡现在有了实现，但**没有 oracle 可校验**，
  卡面与安装校验两处都强制标注「未经交叉核对」，不许混进确证集。
- 36 张仍未恢复（15 张 vault 无围栏 / 21 张源站卡与 vault 卡是真实代际差异，非本包可修）。
  > **订正（[ADR-0050](../../../adr/ADR-0050.md)，同日）**：后半句**反了**。21 张里 **19 张的
  > 实现一直在 vault 的 HEAD 里**，是选围栏的正则漏读（不锚行首导致配对错位、只认 `python`
  > 标注看不到 `bash` 首块）；**只有 2 张是真正的源站独有**。修好后未恢复 36 → **21**，
  > 落盘 `implementation.py` 1,302 → **1,317** 张。本条按原样保留，读时以订正块为准。
- **纪律**：`paper2skills-vault/**.md` 在工作区已不可读，任何新写的脚本都必须走 git 历史。
- **纪律**：凡写「全 X 都 Y」，先跑一次计数。本轮四条全称断言，两条假。
- **纪律**：`.scratch/**` 是 gitignore 白名单，取证脚本会进仓库——**里面不许写死凭证**。
  本轮真踩到：自证脚本写死了那个 API Key，另有更早两个 scratch 快照各含 3 处；
  三处已就地脱敏，`git log -S` 确认从未进过历史。
