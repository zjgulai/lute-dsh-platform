# 技能库的效果实测：接线是通的，效果是负的（ADR-0035）

> 决策记录（ADR-0015 的 Note 侧）。决定本身见 [ADR-0035](../../../adr/ADR-0035.md)；
> 判据、数字与已知边界见 [`packages/capabilities/dsh-paper2skills/docs/eval-report.md`](../../../../packages/capabilities/dsh-paper2skills/docs/eval-report.md)。

## Problem

[ADR-0031](../../../adr/ADR-0031.md) 那一轮把 1338 张论文技能卡装进技能库、接进 50 个岗位 preset，
验证到的是**结构性与保真性**：装了多少、字段对不对、字节有没有少、缺口关了几个。
这些全是「有没有接上」，没有一个字是「接上之后好没好」。

用户授权补上这一段：L6 路由与执行实测（真实 subagent，正面触发 / 负面不触发 / 边界）与
L7 SkillOpt 轨迹优化（rollout + held-out 验证门，只对高价值卡做）。

跑之前有两件事必须先想清楚，否则跑出来的数字没法用：

**其一，技能卡根本不在模型的目录里。** 1338 张全部 `disable-model-invocation: true`——这是 O1 的
硬要求（既有 272 技能的全局目录已占约 7.2 万字符，不能再涨）。所以「模型会不会想起来用这个技能」
是个假问题。真正决定可达性的路由面只有两个：preset 的 `skill-subset` 白名单与斜杠命令。
L6 必须测这两个面的正确性，而不是测触发。

**其二，用合成字段出题就是自己考自己。** 每张卡的 `description` / `whenToUse` / `workflow`
都是 S2 子任务写的。若拿它们出题、再拿它们判分，测的是「自己跟自己一致不一致」。
所以出题 agent 只读卡页**逐字正文的 ①②③ 段**（物化成单独文件，物理上不含合成字段），
判分用**与卡无关的固定量表**。

## Decision

见 [ADR-0035](../../../adr/ADR-0035.md) 的三条：效果断言必须有实测背书；实测判据事前定死
（双臂对照 + 盲判与位置偏差检验 + held-out 门）；未过门的改动一律回滚并留可复核证据。
此外报告必须自带噪声尺度。

这里记录的是**怎么跑出来的**，以及这次踩到的四个坑——坑比结论更可复用。

### 实测怎么跑的

| 环节 | 做法 |
| --- | --- |
| L6-A 静态面 | 全量 1338 张，零模型调用。读真实产物：装好的 SKILL.md、50 个 preset 的 skill-subset、`data/classification.json`、`generated/coverage.json` |
| L6-B 抽样 | 抽样框 259 张（模型可见 ∧ L3 归本岗 ∧ 正文可用），按「近重复/独苗 × 8 责任域」分桶轮转抽 40 张（种子 20260912） |
| L6-B 四臂 | 正样本 × {keyword, situational} + 负向 × {keyword, situational}；负向候选换到**同 L2 责任域、零 L3 交集**的另一岗——跨域负向太容易 |
| L7 选卡 | 高价值 = `fills_gap_strong` 非空 ∧ 被 preset 露出，全库 36 张，按 8 个缺口分层抽 20 |
| L7 双臂 | control（不给卡）vs treat（读卡全文）；加 `treat_silent` 诊断臂；再加 `patch` 臂 |
| L7 判分 | 盲配对，与卡无关的三维度 0–5 × 3，X/Y 顺序由 case_id 奇偶决定 |

### 结论

**L6：路由面基本干净。** M1 供给可达 134/151（差的 17 个就是已登记的结构性空白）、
M2 越岗暴露 0/374、M6 分类字段 1338/1338 一致。真实抽样 158 次有效调用：
正样本 top-1 **97.4%**（keyword）/ **89.7%**（situational），负向真实误召 **5.0%**。

**错选的解剖比准确率有用**：5 次正样本错选里 **4 次选中了同 L3 的孪生卡**
（退货根因 ← → 客诉根因、平台政策变更监控 ← → 法规变更监控、跨平台 SKU 实体对齐 ← → 商品知识图谱查询），
1 次答 none。分层数据一致：岗内有孪生卡的 33 例 situational 掉到 87.5%，7 例独苗是 100%。
而负向的 4 次真实误召**全部是跨 L3 的语义近邻**——它们不共享任何 L3，静态的同 L3 近重复检测抓不到。
**两类缺陷互补，且只有前一类能被静态检查覆盖。**

**L7：给卡反而更差。** 六个对比方向全部一致：

| 对比 | Δ（treat − control） | 胜/负/平 | 符号检验 p |
| --- | ---: | --- | ---: |
| run1 holdout | −0.85 | 3 / 15 / 2 | 0.0038 |
| v2 holdout · C-vs-T | −0.95 | 6 / 13 / 1 | 0.084 |
| v2 holdout · C-vs-S | −1.95 | 1 / 17 / 2 | 0.0001 |

`treat_silent`（照给卡但禁止提及资料）比 `treat` **更差**，说明伤害不在元话语——
逐份核过：三臂写进文件的正文里元话语命中均为 0/40，中位长度 514/638/534，中位量化判据数 9/8/8，
长度与判据密度都没有系统性差异。

机制在读成对样本时露出来了：卡里装的是**论文的方法与参数**，任务问的是**这家公司该怎么干**。
control 写「近 30 天、播放≥5万、≥3 个博主独立用、连续≥2 周」（推出来的作业规则），
treat 写「72 小时为一个语义演变周期、信息熵 ≥ 0.65、新颖度 ≥ 5.0」（论文实验条件的参数）；
control 写「Recall@FPR=0.5%」（定义口径），treat 写「欺诈召回由**基线 42%** 提升至 ≥60%」（用户从未给过的数）。
判官给 control 的高分理由反复是「可直接落地」，给 treat 的低分理由反复是「阈值待标定、缺算式、偏框架」。

**「显然的修复」被实测证伪。** 按这个机制，我在纯合成字段 `## 边界与不做` 加了一条全局条款
（「参数移植纪律」：卡里的数值是论文实验条件的取值，不是你业务的实测值，引用必须写明来路与标定口径），
重装配重安装 1338 张后重跑。**差距变大不是变小**：train −0.55 → −1.15，holdout −0.95 → −1.10。
硬证据：该条款让 **26/40** 份产出挂上「待标定 / 需重新标定 / 临时默认值」这类对冲措辞（其他三臂 **0/40**），
长度与量化判据数都没变——它把「敢下判断的方案」变成了「处处留白的说明」，正是要修的那个毛病。
按门禁回滚，复核：`grep -rl 参数移植纪律 ~/.dsh/skills | wc -l` → `0`；20 张卡 `cmp` 逐字节一致；
`verify-install.mjs` → 应装 1338 / 已装 1338 / 问题 0。

### 四个坑（可复用的部分）

**坑一：手写用例冒充抽样。** L6-B 第一次全量跑批时，我把 40 条用例的 `card`/`preset` 手打进了 workflow 的
`args`，而真实抽样清单在 `eval/out/l6-cases.json` 里。结果第 9–40 例的卡根本没被抽中，出题 agent
找不到 `author-input/<card>.md`，**正确地拒绝编造并报 BLOCKED** —— 32/40 例作废。
教训：**用例必须从磁盘读，不经过人手转抄**。后来的 L7 跑批改成「任务文本落盘 + agent 自己读文件」，
args 里只留 `case_id` 与 `card`。

**坑二：workflow 子任务有约三成瞬时失败率，且 `null` 会被误读成模型答错。**
pilot 32 次路由里 10 次返回 `null`，指标直接算成「7/8」。诊断方式：拿同一条 prompt 走普通 `subagent`
一次成功 → 确认是并发抖动而非模型/schema 问题。修法是**强重试并记录尝试次数**：
最终 158/160 有效，attempts 中位数 1、尾部到 6。**关键纪律：`null` 不能计入分母。
把基础设施失败当成模型失败，会把准确率凭空压掉 30 个百分点。**

**坑三：workflow 的返回体会被截断，长文本不能靠返回体搬运。**
L7 第一轮把 20 张卡的完整产出塞进返回值，结果连落盘的 spill 文件都被截到 50KB，原始数据永久丢失，
只能重跑。修法：**让子 agent 把成品用 write 工具落盘，返回体只回 `{"written": true}`**，
判官也改成自己读文件。这一改同时带来两个好处：产物可复核、返回体小到不会再被截。

**坑四：判分者噪声必须实测，否则会把噪声当结论。**
同一批 control 文件在两轮里被判出 **12.75 与 13.45**（差 0.60～0.70）；同一实验两次跑出
p=0.0038 与 p=0.084。所以报告里凡低于 0.7 的 Δ 一律写成「不可分辨」。
另外**位置偏差检验必须做且必须成对**：control 作 X 时领先 1.17 分、作 Y 时也领先 1.17 分，
位置效应只有 ±0.25 且成对抵消——这才敢说差值不是顺序造成的。

## Alternatives considered

| 备选 | 为什么不选 |
| --- | --- |
| 让 L6 测「模型会不会自动触发技能」 | 1338 张全部 model-off，这个面根本不存在；测出来的数字解释不了任何真实场景 |
| 用卡自己的 `description` 出题与判分 | 自己考自己。判据必须与合成字段非同源——出题读逐字正文，判分用与卡无关的固定量表 |
| 负向臂直接换到另一个责任域的 preset | 太容易，「拒答率 100%」什么也证明不了。取同 L2 责任域、零 L3 交集的另一岗才有区分度 |
| 用绝对分（treat 得了 12.7 分）当结论 | 12.7 是高是低说不清；只有配对差值可判读 |
| 补丁只跑训练侧就上线 | 本次 train 与 holdout 同时变差；只看 train 会把「更差」误读成「没效果」 |
| 把结论是负的这件事记成「未运行」 | 违反 AGENTS.md「不接受口头验收」。负结论是这次最有用的产出 |
| 顺手把 678 对孪生卡合并掉 | 合并即丢卡（每 L3 只留一张），是材料侧决策不是技能库侧；列为待决项交人拍板 |

## Consequences

- 技能库现在有两个分开的家：结构/保真面在 [`docs/test-report.md`](../../../../packages/capabilities/dsh-paper2skills/docs/test-report.md)，
  效果面在 [`docs/eval-report.md`](../../../../packages/capabilities/dsh-paper2skills/docs/eval-report.md)。
  两边的数字不再混在一起说。
- **接线价值成立 ≠ 效果价值成立**：缺口关闭 8/9、本岗可达 134/151 是接线面的成绩；
  而效果面按当前合成规范是负的。这个区分必须保持，否则「装了 1338 个技能」会被顺口说成「提升了能力」。
- 落进仓库的新增物：`eval/` 下 5 个脚本（静态面、用例构造 ×2、汇总、报告）、`docs/eval-report.md`、
  本 Note 与 [ADR-0035](../../../adr/ADR-0035.md)。跑批产物落 `eval/out/`（派生产物，不入库）。
- 四个待决项交人拍板（`何时不用` 跨岗指引、孪生卡合并、跨 L3 语义近邻检测、**把「用卡姿势」写进 preset persona**）。
  最后一条是机制指向的方向：要改的可能不是卡，是**用卡的姿势**——先拿方法、再翻成经营方案。
  这条在 preset 侧就能验，成本远低于重跑 S2。
