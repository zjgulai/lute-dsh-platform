# 分类已经存在，缺的是把它显示出来：算法技能页（ADR-0041）

> 决策记录（ADR-0015 的 Note 侧）。决定本身见 [ADR-0041](../../../adr/ADR-0041.md)；
> 页面契约、数字口径与已知边界见
> [`packages/surfaces/dsh-algo-skills-local/README.md`](../../../../packages/surfaces/dsh-algo-skills-local/README.md)。

## Problem

[ADR-0031](../../../adr/ADR-0031.md) 与 [ADR-0035](../../../adr/ADR-0035.md) 两轮把 1338 张论文技能卡
装进了本机，并把每张卡按组织自己的分类法（4 面 / 8 责任域 / 151 责任 / 50 岗位）归了位——
分类结果**写进了每张卡自己的 frontmatter**。然后就没有然后了：**没有任何界面渲染这份分类**。

后果不是「少了个页面」，而是三件事同时不可见：

1. **1338 张卡在技能选择器里是一串平铺的名字。** 「按组织归位」这件事只存在于 frontmatter 里，
   用户看到的是 1338 行，看不到「4 面承载 1338 张卡」这个形状。
2. **两类缺口被结构性隐藏。** 语料没能归类的 11 张卡、以及语料没有任何供给的 2 个岗位
   （AGT-011 硬件结构与材料工程 / AGT-025 零售渠道与B2B拓展）在任何列表里都不出现——
   它们不是少了，是**没有位置可站**，于是等于不存在。
3. **归位与接线被默认当成一回事。** 卡归哪个岗位由**分类**决定，preset 是否挂载它由**另一次
   独立决策**决定（`scripts/role-presets` 的人工映射表）。实测两者并不重合：326 张归本岗且
   本岗已接线，23 张归本岗但接线到别岗，978 张完全未接线。只显示归位，就是在暗示 978 张卡
   有一条通向模型的路径——而它们没有。

本轮的触发是用户的两条要求：在设置页侧边导航做一个「类似出海技能」的「算法技能」页承载这
1338 张卡，下钻关系为 **L1 4 面 → L2 责任域 → 岗位**；做完之后再把出海技能按同一分类标准重构。

## Decision

见 [ADR-0041](../../../adr/ADR-0041.md) 的三条：

1. **分类的运行时家是「已安装的技能本体」，不是任何包的数据目录。**
2. **归位与接线是两个字段，页面必须分开显示。**
3. **页面只读；唯一的写（模型调用开关）被收窄到 `p2s-` 卡。**

第 1 条是这轮最省事也最意外的一条发现。原本的假设是「新页需要一个从
`dsh-paper2skills/data/` 生成的 catalogue」（出海技能页就是这么做的：`build_preset_catalog.py`
从受管清单生成 `lib/catalog.js`）。实测否定了这个假设：把 50 个岗位 preset 的
`material_skill_names` 抽出来，**恰好覆盖 taxonomy 的 151 条责任名，151/151，且每个责任名唯一
属于一个岗位**。于是连接键 `卡的 l3_business → 岗位` 完全由已安装的运行时状态闭合：

| 来源 | 取的字段 |
| --- | --- |
| `~/.dsh/.agent-presets/agt-*/manifest.json` | 面 / 责任域 / order、本岗责任名、标准产物、考核口径、岗位头像 |
| `~/.dsh/skills/p2s-*/SKILL.md` | `l1_plane` / `l2_domain` / `l3_business` / `l3_all` / `user_summary` / 调用开关 |

这意味着新包**不读任何其他包的数据目录**，因此 `taxonomy.json` 保持一份事实一个家
（[ADR-0009](../../../adr/ADR-0009.md)），而页面也不会因为 `dsh-paper2skills` 那份 20MB 的
`data/` + `generated/` 而背上跨包耦合。

第 3 条里的「收窄」是相对既有实现的一处**主动收紧**：`dsh-overseas-skills` 的 toggle 只校验
「安全的 kebab 名字」，本页额外要求 `^p2s-`。理由是安全的 kebab 名字不等于本页拥有的卡——
`~/.dsh/skills` 里同时住着手工撰写的技能，而这条路由没有资格碰它们。

4. **改写只动值，不动拼法。**（验收前补的一条，见下「写路径按下去之后」。）

### 写路径按下去之后：一个开关点两次不该改动文件

前五轮验的全是读。这条插件只有一个写，也正是用户一键可触发的那一个——卡片上的开关。
它此前只被两种东西碰过：`routes.spec.ts` 的假 TreeSource，和 `corpus-write.spec.ts` 的**只读**
真语料。「真进程 + 真信任栅栏 + 真 1338 张卡 + 真缓存失效 + 真落盘」从没跑过。
`live-toggle-probe.py` 把它按下去（开→关，逐字节比对，`finally` 无条件还原），
15 条断言里红了一条：

```diff
-disable-model-invocation: "true"     +disable-model-invocation: true
-user-invocable: "true"               +user-invocable: true
```

值换了是本分，顺手把**拼法**也换了就是事故。流水线把所有标量写成 JSON 带引号，写盘器写成裸值，
于是「点开又点回去」这件不改变开关的事会永久改变这张卡的字节——1338 张里 1337 张会中，
而此后「用户点错了」与「有人手改过这张卡」再也分不出来。

**决定：按文件原本的拼法回写**（该键不存在时写裸值），并保留 frontmatter 块的行尾。
可对外承诺的性质随之变成一句可检验的话：**点开再点回去，磁盘上的字节一模一样**；
它对全部 1338 张真卡逐张断言（先红：失败清单恰好 1337 个卡名；后绿：包内 133 + typecheck）。
备选是「照流水线的规范写带引号的值」——那会让 1 张裸值卡与任何手写卡反向偏离，故不取。

两种拼法都是**合法**的，所以这不改变任何行为，只脏字节：宿主自己的
`dsh-skill-filesystem` 的 `frontmatterBoolean` 同时接受布尔、`1/0`、`"1"/"0"`、
`true/yes/on`、`false/no/off`。这条此前没被任何测试或文档建立过——
`corpus-write.spec.ts` 只验了「页面自己的读取器读得回来」，而真正消费这张卡的是宿主。

## Alternatives considered

**A. 扩展现有 `dsh-paper2skills`（数据零拷贝）。** 被否的两条理由：一是该包是纯管线
（无 host / client，`.dsh` 里未安装），把它改成「管线 + 运行时插件」要动 `exports` 主入口、
加 `cordis.patch.yml`、进 profile 依赖，且 `file:` 链接会把 20MB 的 `data/`+`generated/`
暴露成硬链接副本；二是页面属 `surfaces` 组（[ADR-0011](../../../adr/ADR-0011.md)），
而该包在 `capabilities` 组。

**B. 挂进已有的 `dsh-role-matrix-local`。** 那个包已经在渲染 4 面 × 8 责任域 × 50 岗位，
看起来是最小改动。否决理由：它从 preset 的 LUTE manifest 建树，把 1338 张卡的分类事实搬进去，
会让「卡属于哪个责任」在 role-matrix 与 paper2skills 两处各有一个家。

**C. 从 `data/classification.json` 生成 catalogue（沿用出海技能页的形态）。** 这是最初的
默认方案。被第 1 条的实测否定：生成物会成为 taxonomy 的第二份副本，而运行时状态本来就能
闭合这条 join。**代价要说清楚**：本页因此看不到 `confidence`（849 high / 473 medium / 16 low）
与 `fills_gap` 审计——那些事实只在 `classification.json` 里，页面不读它。

**D. 跨包共享一个渲染器。** 客户端模块加载器**确实**支持 `require` 另一个本地包的 client
（`dsh-client-modules` 的注释与 `normalizeSpecifier` 明确把 `<id>/client` 与裸包名归一化到同一
exports）。所以「一个通用技能目录页 + 两个数据提供者」在机制上可行。**没有选它**，因为
[ADR-0035](../../../adr/ADR-0035.md) 那一轮的实测结论是「正面接线、反面效果」，
在效果尚未翻盘之前把两个页面耦合成一个渲染器，等于把出海技能页也绑到一个未经验证的结构上。
本包与出海技能页因此是**同构但各自独立**的两个页面。

**E. 一次请求拉全树 vs 逐级懒加载。** 选了一次拉全树：实测负载 848 KB / 7.9 ms（环回），
客户端不需要 1338 次往返，也不会在展开时闪。代价是首屏负载偏大，用 15 s 的宿主 TTL 缓存
与「切换开关后立即失效」抵掉。

**F. 12 枚层头像：生成 vs 复用 vs 先留空。** 选生成（lute-brand-icons，与既有 272 枚同族）。
复用被否是因为语义错位——`sc-a-market` 是「市场与选品」不是「经营管理」；留空被否是因为
用户明确要求「类似出海技能的头像 icon」。

## Consequences

**正面**

- 1338 张卡第一次有了组织形状；两类结构性缺口（11 张未归类、2 个空白岗位）在页面上有一等位置。
- 归位与接线分开显示，1001 张卡（978 张完全未接线 + 23 张接线到别岗）的「归了位但没有一条通向
  自己岗位的模型路径」这个事实第一次可见。
- 新包零跨包依赖，`taxonomy.json` 仍是唯一事实源；`pnpm run gate` 15/15 绿。

**负面 / 已知边界**

- 页面看不到 `confidence` 与 `fills_gap` 审计（见备选 C）。
- **面下的责任域是「切片」**：一个责任域可以服务多个面，因此 4 面下共出现 12 个责任域切片
  （`domainSlices: 12`），而分类法只有 8 个不同的责任域（`distinctDomains: 8`）。页面两个数都报，
  以免把 12 说成「12 个责任域」。这是实测出来的结构，不是笔误。
- 树只扫 `p2s-` 卡；同目录下的手工技能不进树，也不受 toggle 管辖。
- 装载**不需要宿主重启**：`dsh-market` toggle 走热挂载（`restart:false / refresh:true`，
  `activation.state=live`），落盘只有用户 patch 层 2 行。但**客户端刷新是必需的**——
  且首版即使刷新也不会出现新 section，成因见
  [2026-09-12-settings-slot-must-inject.md](../contract/2026-09-12-settings-slot-must-inject.md)。
- 写路径的拼法修正**要等应用重启才在运行中的进程里生效**：热挂载那一刻模块已进 Node 的
  模块缓存，改盘上的 `lib/index.js`（已重新 `ln -f` 接上装机副本）不会回滚它。页面行为不受影响
  （两种拼法对两个读者都合法），但 `live-toggle-probe.py` 会一直红到重启为止——
  要看修复本身用 `deployed-toggle-probe.mjs`（import 出货产物，14/14）或包内测试。
- 开关**不需要重启**就能生效：`dsh-skill-filesystem` 默认开着 `watchFile`（100ms 轮询 /
  200ms 稳定阈值）。这一条读自宿主源码，不是在界面上实测的。

**后续动作**

1. 用户目视验收本页（下钻关系、12 枚层头像观感、卡片信息密度）。
2. 验收通过后再启动任务 2：出海技能按 **场景 → 4 面 → 岗位** 重构，并为 251 项出海技能
   补上「面 + 岗位」归属（方法已定：LLM 出初稿 → 逐条复核 → 落映射表）。
3. 任务 3（1338 张卡的优化方案）待 1、2 之后讨论。
