# 新应用抽屉新增「业务系统」分区：31 个外部系统按岗位分组，外链经宿主打开

- 日期：2026-09-13
- 状态：implemented
- 对应 ADR：[ADR-0062](../../adr/ADR-0062.md)
- 相关：ADR-0045（本条的**部分修订对象**：产品分区目标函数原样保留，抽屉增加第二分区）、ADR-0009（catalog 是这份事实唯一的家）、ADR-0043（失败必须给出为它负责的读数）、ADR-0054（判据是装载点字节，不是「文件写对了」）、ADR-0033（产品卡的 preset 必填规则不受影响）

## Problem

用户要求把 `https://lute-tlz-dddd.top/systems.html` 下的全部卡片链接「以类似卡片的形式存放到新应用中，并按照当前的岗位角色来分类」。

动工前的取证发现四件互相独立、混在一起看就会做错决定的事：

1. **源页面要登录，且页面里没有岗位数据。** `/systems.html` 302 到 `/login.html?next=/systems.html`；登录面是 `POST /portal/session`（JSON `{email,password}`，成功种 `lute_portal_session`）。取到页面后逐卡解析得 **31 张卡 / 31 个唯一域名**，每卡带中文名、英文名、中英简介、类型 chip、技术标签与动作文案。但分类只有它自己的 `data-category` 五类（creation 5 / insight 7 / growth 8 / ai 8 / operations 3），**页面里没有任何岗位字段**——按岗位分类只能靠人工判断，抓取抓不到。

2. **31 个目标全是外部域名。** 没有本地工作目录、没有 preset、没有 `entry.service`，因此在 `planOpen()` 现有三级判据下**全部落在第 3 级「不可用」**。任何「直接塞进现有管线」的做法都会产出 31 张看着能按、按了什么也没发生的卡——正是这个抽屉明令禁止的失败态。

3. **本机壳拒绝外链拉起浏览器。** 实测应用产物的 `setWindowOpenHandler`（P0-6v2）：http/https 一律 `{action:'deny'}`，只对 `mailto:` 调 `shell.openExternal`。也就是说仓库里既有的 `<a target="_blank">` 写法在这个壳里**点了不会有任何反应**，没有浏览器侧兜底可用。

4. **「新应用」刚被剪枝。** ADR-0045 把该面的目标函数冻结为「一张只摆已产品化产品的启动台」，并删掉了 24 张点不开的占位卡。往里加 31 张卡是对该 ADR 的显式修订，必须登记而不是静默做。

## Decision

1. **落点：扩展 `dsh-newapp-local`，加第二分区「业务系统」。** 产品分区（目标函数 ADR-0045 M1/M2/M4/M5）**一行不改**；新分区只列外部系统。四个候选落点里选它的理由是用户的原话就是「存放到新应用中」，且剪枝针对的是**占位**噪音而新分区全是可点开的卡，两者不冲突。ADR-0045 的修订写法：抽屉 = 两个分区，上分区目标函数不变，下分区不产生禁用卡，M1/M2 只对上分区生效。

2. **两份契约，不共用一个开卡联合类型。** `planOpen()` 逐字不变（产品的三级：面板 / 开会话 / 禁用）；系统走 `planOpenSystem()`，只有一档 `{level:0, kind:'url'}`，外加两个禁用原因（无地址 / 无 opener）。理由：产品的禁用来自「本机没装」，系统根本不存在这个状态；把两者并成一个 `kind` 联合，迟早会出现「给没有工作目录的东西返回 `session`」。

3. **外链由宿主打开，且只接受 slug。** 新路由 `POST /api/dsh-newapp/open-system` 的 body 是 `{"slug": "<catalog key>"}`，**客户端永远不传地址**；宿主用 slug 在自己的 catalog 里解出地址，再用 `open`（darwin）/ `rundll32 url.dll,FileProtocolHandler`（win32）/ `xdg-open`（linux）启动，argv 传参、不经 shell。这条设计直接对应 P0-6v2 的意图：路由不是「打开任意 URL」的原语，未知 slug 是 404。

4. **三份文件三个家，都不进仓库外。** `src/catalog/systems.json`（机器写：身份）/ `role-map.json`（人写：岗位归属 + 一句理由）/ `reachability.json`（带日期的巡检读数）。`sync-systems.mjs` 只写第一份，`probe-systems.mjs` 只写第三份，第二份永不自动覆盖。凭据只从 DSH 凭据服务或环境读，脚本不写任何凭据（AGENTS.md 红线）。

5. **catalog 随构建打包，不做运行期文件读取。** 实测装载点包只带 `lib/` + `cordis.patch.yml` + `README.md`（`files` 字段），且构建产物的运行期 import 只有 `node:child_process` / `node:fs` / `node:path`；运行期 `readFileSync('../catalog/…')` 会指向一个不存在的路径，且只在 profile 同步后表现为一个空分区。因此 JSON 用 `with { type: 'json' }` 静态导入，由 tsdown 内联（宿主半边 8 KB → 71 KB），并加断言锁住这个形状。

6. **岗位归属：多对多 + 主岗位分组。** 每系统 1 主岗位（决定分组，一系统只出现一次）+ N 兼属（卡上 chip，且参与搜索命中）。分组顺序沿用 role-matrix 的两层分类（平面 → 责任域 → 岗位编号）。**确实不认识**的岗位分组照常渲染并标记，不隐藏——隐藏会让一次 preset 改名看起来像系统被删了。

7. **面板打开时零网络。** 可达性只在离线脚本里探测，结果带日期写进 catalog；卡片把它读作「某日的读数」而不是「此刻可用」。在渲染路径上发网络请求会让抽屉在断网时变空、在站点抖动时变慢。

8. **卡片视觉走既有品牌契约。** 严格执行 `tests/stylesheet.spec.ts` 的三条 token 法则：颜色字面量只住在品牌块（`.root, .entry`），`var()` 兜底 = 该 token 的浅色实测读数，字号只走官方简写阶梯，`font-family`/`font-variant` 覆盖必须写在简写之后。图标不是复制源站 SVG 标记，而是**同步脚本把它拆成封闭词汇**（`path`/`circle`/`rect`/`line` + 白名单属性），浏览器半边渲染成真实 React 元素——避免把「脚本从远端页面生成的 JSON」变成注入面。

## Alternatives considered

- **A · 31 份 `product.json` + 给 `planOpen` 加外链档**：改动最小、复用最多，但会让抽屉里出现 31 个「不是 Agent 的产品」，`product.json` 的语义与「点开直接跑」的承诺同时被稀释。省下的代码不值得付这个语义代价。
- **C · 新建独立插件**：零 ADR 冲突，但侧边栏再多一个入口（已有 7 个 `*-local` 面），且牺牲用户明确表达过的「一个入口装下全部」。
- **D · 挂进 `dsh-role-matrix-local` 岗位矩阵**：分类轴天然就是岗位，但该插件 README 明确声明「只读预设目录」，为这件事破它的边界不划算。
- **`<a target="_blank">` 或 `window.open`**：实测被主进程拒绝，点了没反应——不可用。
- **`@deepseek-ai/dsh-native-command` 的 `openNativePath` / `session.openWorkspacePath`**：前者接**文件路径**，其 Windows 分支是 PowerShell `Invoke-Item`、WSL 分支要 `wslpath` 转译，对 URL 都是错的；后者会先把参数按会话工作目录解析，URL 会被改写。两个都是「路径打开器被拿去做 URL 的活」，所以自写 30 行、只声明它真正需要的三条平台命令。
- **每次打开抽屉实时抓取**：永远最新，但断网变空、站点抖动变慢，且把面板的可用性绑到站点的登录态上。
- **让岗位映射也由脚本推导**（按关键词匹配岗位描述）：源页面没有岗位字段，任何自动推导都是把猜测写进一份会被当事实读的文件。人工写 + 每条附理由 + 单测约束覆盖面，才是可复核的形态。
- **`dangerouslySetInnerHTML` 渲染源站图标**：最省事，但把远端页面的标记直接送进 DOM。

### 实况探针：`accept:newapp-systems`（32 条，真 curl 打真 HTTP）

单测与门禁之外补的一条探针，补的正是它们**结构上答不了**的几件事：产物里到底有没有这两条路由、catalog 有没有**真的**被内联进 `lib/index.js`、栅栏在真实 HTTP 事务里成不成立（尤其**包没包住会开浏览器的动作路由**）、以及 `open-system` 的输入词汇是不是真的只有那 31 个 slug。

**它不打成功路径。** `open-system` 的成功路径会真的在你机器上弹出浏览器，所以三条断言全部打在**拒绝**上：未知 slug 必须 404、只送 `url` 不送 `slug` 必须 400、body 非对象必须 400。它们合起来证明的是同一件事——**客户端送不进任意地址**（P0-6v2 的正面实现）。真实的开浏览器由人点一次来验收；**"探针全绿"不等于"点开能开"**，这句写进探针文件头就是为了不让那片绿被读成后者。

**它自己的三个错，值得记下来当反面教材：**

1. **一条恒真的断言。** `grouping-exact` 第一版断言「Σ组内条数 = 系统数」。而这份分组是 `for (s of systems) grouped[primary].push(slug)` 建出来的——每个系统**按构造**只落一个桶，等式恒成立，无论 role-map 写成什么样。**一个恒真的断言给出的绿不是证据，是装饰。** 判据已换成两条能被证伪的：分组后的 slug **集合**必须与仓库源文件相等（集合比，不是比条数——比条数会被「少一个 A、多一个 B」骗过去），且**组数等于写死的 14**。
2. **把 preset 目录名当成了岗位 id。** 断言写成 `/^agt-\d{3}$/` 直接转红——`agt-NNN` 是 preset 目录名，`AGT-NNN` 才是岗位 id。那条红是探针写错了，不是目录写错了；记在这里是因为下一个读的人会先怀疑目录。顺带把兼属岗位 `also` 也纳入同一判据（原来只查 `primary`）。
3. **对自己的协议误判。** 响应体是 JSON，`"slug"` 在线格式上是 `\"slug\"`；第一版按未转义写法断言，把 400 的正确响应判成失败。

**变异测试（证明这几条不是空转）。** 逐条把期望值改错，确认它们**会红且退出码转 1**：`EXPECTED_SYSTEMS 31→30` → `catalog-size` 红；`EXPECTED_GROUPS 14→13` → `grouping-exact` 红；`ALLOWED_DOMAIN` 换成别的域 → `href-allowlist` 红。

最强的一条是**改产物本身**：把 `role-map.json` 里 `ana.primary` 掏空 → 重建 → 探针**照旧全绿**。这不是探针漏判，而是它**读的是装载点的字节**——而那次重建**根本没到装载点**（`lib/index.js` 的硬链接此前已被打断，两边的 inode 不再相同）。跑一次 `sync-profile.mjs --apply --loadpoint` 后立刻转红（`all-classified → 未分类：ana`、`grouping-exact → 组数 15（期望 14）`、3 项真失败、exit 1），还原并重新同步后回到绿。**结论有两层**：探针确实在测被装载的那份字节；以及**「重建」不等于「生效」，中间必须有一次 `--loadpoint` 同步**（ADR-0054）。

**退出码三态，不许压平。** 0 全绿 / 1 有真失败 / **3 = 阶段 A–C 全绿但阶段 D 因宿主未重启无法判决**。3 不是绿，它明说「这件事没被验证过」；也不是红，没有任何读数为这个失败负责。重启前实得 **32/32、exit 3**；**重启后 34/34、exit 0**——两条原先显示 ⏳ 的实况探针（`live-systems`、`live-catalog-matches-build`）转成了真实绿，第三项 `live-fence` 在重启前就已单独答 403。三态设计因此被真实走了一遍：**没有一次是拿绿去假装一件事已经发生**。

顺带修掉探针里一处「拿缺席覆盖已有读数」的写法：`live-fence` 原本被并进 `restartRequired` 分支一起显示成「待重启复核」，而实况明明答了 **403**（一条真实的绿）。栅栏与 `systems` 路由是两件事——宿主旧到没有 systems 路由，并不妨碍它的栅栏正常工作。



### 两半之间那条缝：`catalog-roundtrip.spec.ts`（6 条，跑在**真 catalog** 上）

补探针时发现另一处结构性的空白：`systems-routes.spec.ts` 断言宿主半边**发了 31 条**，`systems.spec.ts` 断言客户端半边**解析与分组正确**——但后者每一条喂的都是**手写夹具**（`wire()` / `view()`）。**没有任何一个测试，把宿主真正产出的那份 payload 喂给客户端真正在用的那个解析器。**

这条缝不是学术问题，因为两边都**按设计会丢东西**：`parseSystems` 会丢掉 slug 为空 / 重复 / name 非字符串 / href 不是 `https://*.lute-tlz-dddd.top` 的条目（并记进 `dropped` 而不是抛错）；`groupSystems` 按 `primary` 折叠，名册不认识的岗位会保留但标 `known:false`。**一个触发丢弃规则的条目，在抽屉里就是一张少掉的卡**——而既有测试全部保持绿色：宿主测试数的是 payload 里的条数，客户端测试数的是夹具。

所以这份测试的核心断言是 **`dropped` 必须为空**，且宿主发布的每个 slug 必须原样出来且只出来一次。变异测试证明它抓得住：把某条 `href` 改成 `evil.example` 后**3 条转红**，并且指名道姓——`dropped` 里是那条，slug 集合差一个是 `ana`，开卡计划 30 ≠ 31。顺带一提，同一次变异里「分组」与「页脚覆盖」两条**保持绿**（它们算的是已经解析过的那 30 条，自洽）——这恰好说明**丢弃断言才是承重的那一条**，别的断言在它失效时不会替你报警。

它顺手钉住了第二处**只在两半之间才存在**的东西：**岗位 id 的大小写**。实况名册（`dsh-role-matrix-local`）发布的是 preset 目录名 `agt-003`（小写，实测 50 个全小写），而 catalog 按材料写的岗位 id 是 `AGT-003`（大写）。`SystemsSection` 用 `label.id.toUpperCase()` 把两边接上，注释写着这一步是"keeps that difference from silently emptying every group"。这份测试**两向都断言**：接上之后 14 个组**全部 `known: true`** 且标题带着名册的名字；**拆掉这座桥**（按路由原样的小写键喂进去）则 14 个组**全部 `known: false`**、标题退化回裸 id。第二种状态**不报错、不丢卡**——仍然是 31 张卡 14 个组，只是分组标题从「AGT-003 经营参谋 · …」变成「AGT-003」。这正是那种只有"把失败形态也写成断言"才看得见的退化。



### 视觉验收：一台相机，不是一名裁判

「卡片必须精美」不是测试能判定的事，所以本轮的仪器是一台**相机**：`tests/design-preview.spec.tsx` 用**真组件**（不是手抄的标记）配夹具渲染，把 CSS-module 的哈希类名反转回源类名，加装**外壳自己的主题样式表**（从应用产物里逐字取出，不重打），写出浅深两页；`scripts/design-probe.mjs` 用真实 Chrome 打开它们，截图并量少数几个塌了就会变的读数。

这台相机在本轮抓到**两个真缺陷**，两个都不是肉眼在单一主题下能看见的：

1. **同一行的卡底不齐，高差 102px。** 网格拉伸的是**网格项**（`<li class="sysItem">`），不是它里面的按钮；卡片按自身内容定高，于是摘要长短不同的同一行，卡底差出 102px。修法是 `.sysCard { flex: 1 }`。jsdom 不做布局，本目录其他用例对这一类缺陷全盲。
2. **品牌绿文字读不了。** `--lute-brand-deep` 在卡面上实测 3.27:1（浅）/ 3.42:1（深），都低于 12px 正文的 4.5:1 门槛——**两种主题都不达标**。修法是在品牌块里新增一对**文字用品牌绿**（`--lute-brand-ink` 浅色加深、`--lute-brand-ink-dark` 深色提亮），由一个 `body[data-ds-dark-theme]` 选择器切换（逐字沿外壳自己的切主题方式）。改后：动作标签 5.47:1 / 6.88:1。

同一轮还修了两处「照抄外壳反而更差」的地方：外壳的 caption 灰在卡面上是 2.13:1（英文名 1.97:1），而英文名与技术标签是**内容不是装饰**，改用 secondary（5.36 / 5.8）；外壳的 warn 对（`state-warn-tertiary` 底 + `state-warn-primary` 字）是**面**的组合，11px 文字实测 1.99:1，改为浅色用深琥珀字、深色用琥珀字（14.3 / 7.2）。

对比度从「三条抽查」升级为**十条全覆盖**：第一版只断言卡名、动作、分组标题，会放过一块「登录提示 1.99:1、英文名 1.97:1」的版面——**只覆盖部分文字的底线，等于给没看的那部分发合格证**。

**仪器自检（也补上了）。** 首次运行探针时预览用例编译失败，而探针照旧从**上一轮的 HTML** 产出了一整屏绿色数字。现已加时间戳守卫：预览文件比它引用的源文件旧就 exit 2，不产出任何绿色。这与仓库既有教训同型——「一个只会说『无响应』的仪器，等于没有仪器」。


**这次修订改掉了它自己的门禁。** `tests/contract.spec.ts` 里有一条断言把路由表钉死为 `['health','products']`，原文写着「本包不拥有任何数据源」。本次改动让这句话不再成立（catalog 成了本包拥有的第一份数据），断言因此被**按新事实重写**而不是放宽：路由表仍钉死，但注释改为「本包恰好拥有一份数据集，加第二份必须是一次有意的决定」。

**健康的不变量：`open-system` 的输入词汇就是 catalog 的键。** 客户端传 slug、宿主解地址，未知 slug 404。「未知 slug 不是地址」这条由 `systems-routes.spec.ts` 的用例守着，因为它一旦松动，这个路由就变成 P0-6v2 特意移除的那个原语。

**已知代价，如实记账：**
- 宿主半边因内联 catalog 从约 8 KB 涨到 71 KB（gzip 20.5 KB）。这是「装载点不带数据文件」的代价，选它是因为另一条路的失败模式是静默的空分区。
- `dsh-newapp-local` 的身份变了：它的 README 自述「只读，不拥有任何事实」，现在它拥有 catalog。§Decision 4 把三个家分开就是为了让这个变化尽量小，但变化本身无法消除。
- 岗位映射是人的判断。31 个系统覆盖 23/50 个岗位，另外 27 个岗位在这批系统里没有入口——这是事实，页脚报数，不为了让每个岗位都有一组而硬塞归属。
- 源页面自带的 5 类分类**不进 UI**（两个分类轴同屏会让用户分不清分组依据），但字段照抓进 catalog，需要时随时可上。
