# 岗位白名单是授予，不能被文件开关否决：`respectFileFlags` 的两难与产物选择（ADR-0072）

> 决策记录（ADR-0015 的 Note 侧）。决定本身见 [ADR-0072](../../../adr/ADR-0072.md)；
> 同一场诊断的另外两个缺陷（真值归属与词表）见
> [2026-09-13-skill-invocation-truth-and-vocabulary.md](../surface/2026-09-13-skill-invocation-truth-and-vocabulary.md)（ADR-0070）。

## Problem

「有些卡片打不开」在效果层的真身：**岗位预设声明装配的技能，模型根本调不到**。读数（改前）：

| 指标 | 值 |
| --- | --- |
| 有白名单的预设 | 50 个 `agt-*`（另 1 个手写 `bobo-cto`） |
| 白名单位 | 439 个（跨 50 个岗位） |
| **实际不可被模型调用** | **275 个（62.6%）** |
| 全部生效的预设 | **0 个** |
| agt-001（衡远）8 个白名单 | 6 个失效，只有 `pb-002` / `pb-008` 真的能用 |

机制是两条各自正确的决定的乘积：

1. [ADR-0031](../../../adr/ADR-0031.md)：语料 1338 张卡**一律**写 `disable-model-invocation: "true"`
   （全局模型目录已占约 7.2 万字符），可见性**只经** preset 的 `skill-subset` 逐岗白名单开放。
2. `dsh-skill-subset` 的正向注册：`modelInvocable = respectFileFlags ? !parsed.disableModel : true`；
   50 个 `agt-*` 预设生成时写的是 `respectFileFlags: true`（I3 立项，目的是「设置页开关在
   preset 会话内同样生效」）。

`true` × 全库 model-off = **白名单被它自己挂载的技能否决**。注册成功了（没有 404、没有报错、
没有日志），只是 `modelInvocable: false`。两边界面都正常，没有任何读数异常——这是
[P-02](../../../pitfalls-playbook.md) 那一类：仪器全绿，能力已死。

### 为什么两条不能同时成立

- ADR-0031 要的是「岗位装配 = 唯一授予通道」；
- I3 要的是「用户级的开关在岗位会话里也有最终决定权」。

在语料全库 model-off 的前提下，这两句话对同一张卡给出相反结论：岗位说「我装配了它」，
文件说「不许自动调用」，而 I3 让文件的话优先。**必须选一个**。

### 选哪个：证据

- `dsh-skill-subset` 自己的文档说这一行的用途是「把这些技能重注册为**模型可见**
  （遮蔽全局 model-off 副本）」，并把「子集内全部可调用」列为 **O1 默认策略**；
  `respectFileFlags: true` 被它自己标注为「严格语义（I3 立项）」。**默认是授予，I3 是那个偏差。**
- ADR-0031 的原话是「可见性**只经** preset 的 skill-subset 逐岗白名单开放」——
  白名单是授予通道，不是建议。
- 反例证明这不是「一律关掉就好」：手写的 `bobo-cto` 预设名单几乎全是**文件已开**的手写技能，
  在那里 I3 是有意义的（用户把某张卡关掉，bobo-cto 会话里也该关着），而且它**没有坏**。
  所以判据要管的是**不变量**（每个预设必须交付它声明的卡），不是旗标的值。

## Decision

见 [ADR-0072](../../../adr/ADR-0072.md)：

1. **生成的 `agt-*` 预设改用 `respectFileFlags: false`**：岗位装配由岗位自己负责，
   设置页开关管的是岗位之外。产物语义由生成器里一个常量
   （`SUBSET_RESPECTS_FILE_FLAGS`）唯一决定，它同时决定渲染值与判据算法——翻它不会静默失效。
2. **生成收尾加一条「白名单生效性」判据**：逐张核对白名单里的技能在产物的语义下是否真的可被
   模型自动调用，有死位就 `exit 1` 并给出两条出路。它与既有的「悬空引用」判据并列——
   悬空 = 名字指向不存在的技能（注册报错被 catch 吞掉），死位 = 技能存在、注册成功、
   却永远不会被挑中。**两种静默失败，两种读数。**
3. **`bobo-cto` 不动**：它没坏，改它没有证据支撑。

## Alternatives considered

- **把 275 个死位对应的卡在文件层打开（`disable-model-invocation: false`）。** 被否为主路径：
  · 它要改用户语料里约 258 个文件（本轮全程没碰过语料，这次也不该由显示层的问题引出语料改动）；
  · 它让这些卡进入**每一个**会话的模型目录，正是 ADR-0031 要避免的；
  · 它是**数据**修复，翻不回来（改回即重新失效），而生成器一行是可逆的。
  留作判据允许的第二条出路：谁要保留 `true`，就必须用它。
- **一刀切把 `bobo-cto` 也改成 `false`。** 被否：证据不支持。它的名单是文件已开的手写技能，
  I3 在那里既生效又无害；为了「一致性」去削弱一个用户级开关的实际效力，是拿证据换整齐。
- **只加判据不改语义（让判据先红着）。** 不可能：门禁是硬门槛（ADR-0014），
  红着的判据会阻塞整条流水线，等于把「已知且已决策」的事故挂成常驻故障。
- **改 `dsh-skill-subset` 的默认值，让 `respectFileFlags` 缺省为 false 生效更强。**
  被否：插件是跨产品的共享契约（`bobo-cto` 与别的产物也用它），本轮的产品取舍不该写进插件的
  默认语义里；生成器是这次决策的正确归属地。
- **不加判据，只改这一行。** 被否：这正是它当初坏掉的方式——两条各自正确的决定，
  谁都不知道乘起来是错的。没有判据，下一次「顺便把 I3 打开」会再犯一遍，且同样无声。

## Consequences

- **正面**：
  - 50 个岗位的白名单位从「439 里 275 个死」变成「439 里 0 个因文件开关而死」；
    实测重跑核对：`respectFileFlags: false` 下正向注册恒为可调用。
  - 判据**可证伪**：把常量翻回 `true` 后重跑，判据打印死位清单并 `exit 1`
    （实测），所以「下次又被打开」这条复发路径被拦住了。
  - 页面口径随之改准：卡上的提示从「模型不会自动调用」改为「本岗之外不自动调用」，
    并说明本岗会话照常自动调用——语义变了，界面的话也要跟着变，否则刚修的谎换了个人说。
- **负面 / 边界**：
  - **设置页的开关在岗位会话里不再有最终决定权**：用户把某张卡关掉，某个挂载它的岗位会话
    仍会自动调用它。这是本条明确买下的代价（岗位装配由岗位负责）；页面上必须说清这一点。
  - 手写预设 `bobo-cto` 有 7 条白名单指向**不在 `~/.dsh/skills` 的技能**（3 个来自插件、
    4 个 `pb-cto-0X` 文件不存在），子集插件重注册时会 ENOENT 告警。它们因为在白名单里而
    **不被 `hideOthers` 遮蔽**，所以照常可见——今天无害，但属于「名单与磁盘不一致」的潜在账，
    本轮不动。
  - 生成物与仓库的同步是手动的：`~/.dsh/.agent-presets/agt-*` 不在仓库里，
    本轮用逐文件 `sed` + `tmp+mv` 落地（不能整目录重生：`agt-033` 带一条本机独有的
    KOL Hunter 产品装配，整目录重写会抹掉它，该文件自己写着这句警告）。
- **后续动作**：
  - 若将来要让设置页开关在岗位会话内也生效（重开 I3），**必须同时**决定那 439 个白名单位的
    数据怎么改——判据会强制这两件事一起做。
  - `bobo-cto` 的 7 条悬空引用值得一次单独清账（要么补技能、要么从名单里去掉）。
