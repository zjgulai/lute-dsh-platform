# 2026-09-18 · 设置页探针的「设置入口」锚：可访问名在 title 还是 description

关联：[ADR-0087](../../../adr/ADR-0087.md)（设置页呈现层：锚点取 ARIA 语义而非类名解析）、
[ADR-0104](../../../adr/ADR-0104.md)（render / live 两级验收的口径）。

## Problem

**现象。** `pnpm run accept:settings-shell` 在设置页**没开着**时退出 2，报
`window-off-screen`「窗口拉不到前台，AX 树停在 N 个节点（hasWindow=true）」。
2026-09-18 实测：窗口 `on_screen=true`、1580 pt 宽、树里 882 个节点可读 —— 窗口就在台面上。

**根因（实况读数，不是推断）。** 设置入口节点是 `AXPopUpButton`，
**`AXTitle=""`、`AXDescription="设置"`** —— 可访问名挂在 `description` 上
（`mac.ax.dump` 的节点自带该字段）。探针的两处匹配（`SIGHT_PROGRAM` 的 `hasTrigger`
与 `AX_PROGRAM` 的触发器查找）都只认 `AXTitle`，于是 `ensureOnScreen()` 判
`hasTrigger=false`；设置页也没开着 → 两个条件都不成立 → 连试 6 次后抛错，
并把原因说成「窗口拉不到前台」。

**代价。** 这是 P-04 那一类：错误报告路径把真实原因盖住，**并且会再把人骗去重启一次** ——
同一份文件里已经记过一次同型的浪费（2026-09-15 那次也是据此让用户重启，重启没用）。

**同期暴露的第二件事。** AX 子树是**增量**建的：模态关掉之后连续三次 dump 读到
**32 → 262 → 599** 个节点。32 个节点时探针报「找不到设置入口」，等于把「树还没建全」
说成「入口不存在」—— 与上一条同型的错报。

## Decision

1. 「设置入口」规则收成**一个家**：`SETTINGS_TRIGGER_NAME / ROLES / NAME_FIELDS`。
   JS 求值器 `isSettingsTrigger()`（供自检）、`pyTriggerPredicate()`（生成实况 python 片段）。
   **改规则只能改常量**，两侧同时变；自检里有一条断言钉住生成物覆盖了每个字段与每个角色。
2. 名字字段从 `title` 扩到 **`title 或 description`**：两者都是 ARIA 语义面
   （name-from-contents 与 aria-label），不是类名解析。只认一个，等于把「上游此刻把名字
   放哪个字段」当成了契约。
3. 前置失败按**真实状态**分类，不再两条并一条：
   - `window-off-screen`：没有窗口（实测 off-screen 整棵树只有 1 个节点）；
   - `ax-tree-incomplete`：有窗口但节点数 < `AX_TREE_FLOOR`（120，增量建树中）；
   - `settings-entry-unreadable`：树够大，但既没有入口、也没有已开的设置页。
4. 自愈轮询 6 → **10** 次（每次 `set frontmost` + 2s，≈20s，够实测的建树过程走完）。
5. 自检加 **8 个夹具 + 4 条同源断言**；门禁加 **2 条突变控制**（名字字段缩回只认 title、
   角色集合缩成一个），两条都必须判红并点名。

## Alternatives considered

- **只改 `AX_PROGRAM` 的匹配，不加自检**：等于把「名字字段有两个」留在纪律里。P-08 的判据是
  「纪律守不住的东西要用机制守」—— 这条规则刚红过一次，正是加机制的时机。
- **让两处各自解析节点（JS 与 python 各写一份规则）**：两处各写一份必然改一处漏一处；
  现在的做法是同一组常量生成两个语言的求值器，并用例钉住同源。
- **把「树太小」并进 `settings-entry-unreadable`**：类型名会撒谎（真实状态是树没建全，
  不是入口不存在）。分开命名，报告才能告诉读的人下一步该做什么。
- **把 `named_panels` 的对话框锚也一起放宽到 `description`**：本轮没有那条读数
  （实测对话框节点 `title="设置"`），属于没有证据的放宽，不做。
- **新建 ADR**：本改动是 ADR-0087 已经定下的原则（锚点取 ARIA 语义）的一个**实例**；
  另立编号会让同一条原则有两个家。故只链接，不新增编号。

## Consequences

- **正面（实况判决，非预期）**：设置页**没开着**时探针能自己按下入口并给出判决。
  2026-09-18 干净复测（设置页由探针自己打开，`探针开启=true`）：`exit 0`、校准 `scale=1`、
  三个锚残差 `0 / 0 / 0`、分组标题 **5/5**、**L1 导轨独立滚动**（滚到底末项 40 CSS px
  = 目标全高的 1.00）、**L2 面板 960 CSS px**（官方对照 800）。同一状态在旧写法下是 exit 2。
- **正面**：报告能区分三种前置失败，不再把「名字换了家」与「树没建全」都说成「窗口不在前台」。
- **证据**：`--self-test` **14 个状态 / 39 条断言**（原 27 条，新增 12 条）；
  `node --test scripts/gates/settings-shell-criteria.test.mjs` **11/11 通过**
  （新增 2 条突变控制，均按预期判红并点名）。
- **代价**：`AX_TREE_FLOOR = 120` 是**经验下界**（实测合法树规模：模态盖住主界面 152~288、
  主界面 599~1344），它只用来分「该重试」与「该报缺入口」，**不是判据**；
  上游若把主界面缩到 120 节点以下，这条会误报 incomplete。
- **代价**：失败路径的等待从 ≈12s 升到 ≈20s。
- **未验证**：`ax-tree-incomplete` 分支本身没有再被触发过（32 节点那条读数是加该分支之前取的，
  无法按需制造「建树中」的状态）；`settings-entry-unreadable` 有一次实况读数。
- **残余风险（有读数、无法定性）**：复用「别人已经开着的设置页」时（`探针开启=false`），
  L1 曾读到 `false`（导轨与内容区一起动、末项 22 CSS px）；同一台机器上探针**自己开页**的
  两次读数都是 `true`（scale 1.214 与 scale 1 各一次）。当次另有会话在同一个 app 实例上做
  CDP 直读，无法区分「真实缺陷」与「状态污染」。**拿到可复现读数之前不动判据。**
- **后续**：`docs/pitfalls-playbook.md` 值得加一条（「前置谓词太窄 → 把 A 状态报成 B 状态」），
  但该文件当时持有另一个会话的未提交改动，本轮不碰，免得把别人的在飞工作一起提交。
