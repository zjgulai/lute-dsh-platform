# ADR↔Note 互链校验改为逐篇解析（2026-09-11）

> 本文件是本次修复的决策记录（ADR-0015 的 Note 侧；决定本身是 ADR-0015 已确立契约的
> **实现修正**——「ADR 头部的决策记录行与 Note 正文中的 ADR 引用双向互链，由门禁校验可达」，
> 因而不新增 ADR 编号）。

## Problem

`adr-note-links` 这个门禁校验项把 Note 路径**写死成单值**：

```js
// scripts/gate.mjs
const NOTE_PATH = 'docs/notes/implemented/architecture/2026-09-11-lute-refactor-three-phase.md'
```

而校验逻辑是「收集所有带「决策记录」链接的 ADR 编号，断言**这一篇** Note 提到每一个」。
于是产生一个隐含要求：**任何新增的 ADR，无论主题多远，都必须在那篇中心 Note 里被提一句**。

后果已经出现过两次：

1. **ADR-0019**（品牌皮肤对官方 UI 的改写锚治理）与中心 Note 的三期重构毫无关系，
   却被迫在中心 Note 里加了一段「后续的 ADR-0019 属独立主题……记录在 <另一篇 Note>」的例外说明；
2. **ADR-0020**（岗位小队编队契约）同样无关，于是同一段说明被再扩写一次，列出第二篇 Note。

这类例外说明有三个问题：它**不承载任何决策**（只是一个指路句）、**没人会主动维护**
（下次新增 ADR 时最自然的动作是再补一句而不是去修门禁）、并且它让门禁的通过条件与
「文档里写了一行合规文本」相关，而不是与「链接真的双向可达」相关——**假阳性会训练人
忽略输出**，这一点在本仓库已有先例（`patch-anchors` 的 v1 脚本正因维护了错误的判据而假通过）。

一个次要但真实的症状：那条例外说明是跨主题写入的，它让「一份事实只有一个家」（ADR-0009）
在形式上被稀释——中心 Note 开始携带与自己无关的 ADR 目录。

## Decision

**把校验改为逐篇解析、逐篇回引：**

1. `checkAdrNoteLinks` 的入参从 `{ notePath, noteText }` 改为 `{ readNote }`
   ——`readNote(仓库根相对路径) => string`，读不到返回空串（自然判为未回引）。
2. 对每篇 ADR：解析它自己「决策记录」行的链接 → 若目标不存在则报错（原行为不变）；
   若存在，则**在那一篇 Note 的正文里**查 `ADR-NNNN`。缺失时报
   `<Note 路径>：正文未引用 ADR-NNNN（由 <ADR 路径> 指向）`——同时点名两侧，便于定位。
3. 移除 `scripts/gate.mjs` 的 `NOTE_PATH` 常量（改后无引用）。
4. **移除中心 Note 里那两行为闸门打的例外说明**（ADR-0019 / ADR-0020 的指路句），
   恢复为一句范围声明「本 Note 的「决策记录」声明覆盖 ADR-0007 ~ ADR-0018」。

改动方向是**收紧而非放宽**：ADR-0019 / ADR-0020 现在必须由**它们自己指向的** Note 回引，
而「别的 Note 提到了这个编号」不再能顶替。

## Alternatives considered

**保持现状，继续往中心 Note 里补例外说明。** 被否决——这是把门禁的实现缺陷转嫁成文档债务：
每加一篇 ADR 就多一行没人维护的指路句，而门禁仍然没有在测它声称在测的东西。

**放宽为「任意一篇 Note 提到该编号即可」。** 被否决——那等于取消双向互链中的「回引」一半，
ADR 可以指向任何 Note 而无需那篇 Note 知晓，正是本次要消除的松散。

**新增 ADR-0021 记录这次改动。** 被否决——本次没有引入新的决策类别，只是把 ADR-0015 已写明的
契约（「两轨以 ADR 头部的决策记录行与 Note 正文中的 ADR 引用双向互链」）落实到实现。
按 ADR-0015「ADR 只用于难逆转、没有背景就难理解且经过真实取舍的决定」，此处归 Note 即可
（先例：`2026-09-11-preset-lint-and-profile-files-sync.md` 同样延伸 ADR-0014 而不新增 ADR）。

**顺手把 Note 路径也从 ADR 头部改为可配置映射。** 被否决——链接已经在 ADR 头部逐篇写明了，
再引入一份映射表就是第二份事实源（ADR-0009）。

## Consequences

- **正面**：门禁重新在测它声称在测的东西（「该 ADR 的那篇 Note 回引了它」）；
  新增独立主题的 ADR 不再需要污染中心 Note；那两行例外说明已删除；
  违规信息同时点名 ADR 与 Note，定位更快。
- **代价**：校验从「读一次文件」变成「按需读 N 次文件」（实测 ADR 15 篇、其中 14 篇带链接，
  开销可忽略）；`checkAdrNoteLinks` 是签名变更，调用方与测试同步改（已改）。
- **验证**：
  - 门禁自带测试 `npm run test:gate` **38/38 通过**，其中 5 条覆盖 ADR↔Note 互链
    （含 2 条新增回归测试：两篇 ADR 各指向自己的 Note 时互不牵连 / 别的 Note 提到该编号不能顶替）。
  - **变异测试通过**：把实现临时还原为旧的单 Note 逻辑后，恰好 3 条测试转红
    （`Note 未引用其 ADR 编号必须被拒绝`、`两篇 ADR 各指向自己的 Note 时互不牵连`、
    `别的 Note 提到了该编号不能顶替自己那篇`）；还原后 38/38。证明这几条断言非空转。
  - `pnpm run gate` quick 与 `gate:full` 均 15/15 通过。
- **未做**：`docs/adr/README.md` 中「共享同一篇决策记录 Note」的分组说明仍描述
  ADR-0007~0018 的现状，本次不改——它是事实陈述而非门禁耦合。
