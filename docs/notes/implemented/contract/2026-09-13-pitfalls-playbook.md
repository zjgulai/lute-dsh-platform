# 复发故障总账：把「下次会再犯」做成一份会自己报错的清单

> 决策：[ADR-0071](../../../adr/ADR-0071.md) · 分类：contract · 生命周期：implemented

## Problem

### 记下来了，但记在了按时间排的地方

2026-09-13 一天落库 31 个提交、16 篇 Note、7 篇 ADR。把当天修掉的缺陷按**根因**归并，
只剩不到十类——而其中三类在**同一天各复发了两次以上**：

| 根因类 | 当天的复发证据 |
| --- | --- |
| 未验证的事实被钉进出货面 | TCC 待授项先错写成「自动化」，再错写成「输入监控」 |
| 「知道」没有变成「拦住」 | `$VAR` 吞多字节这条陷阱早已写在注释里，之后仍新犯 4 处 |
| 一条事实多个家，只改了一处 | README 改对后，其余五处仍写着「自动化」 |

这些教训**一条都没丢**：它们全在 ADR 与 Note 里，写得比这份总账详细得多。
丢的是**检索面**——复发按根因发生，而文档按时间排列。下一次开工的人不会先读 16 篇 Note；
于是他换一个外壳（这次是「输入监控」，上次是「自动化」），把同一个根因再犯一遍。

### 总账的固有死法

按根因组织的清单有一个明确的死法：它靠自觉维护。条目里点名的机制会被重命名、被删除，
或者一开始就写成了一个**从来没有存在过**的名字——「有门禁守着」这种自我安慰读起来完全正常，
甚至比真实情况更让人放心。而没有任何东西会因此停下来。

这正是当天记下的 P-03 本身。所以这件事的难点不在「写一份清单」，在**让清单无法说谎**。

### 取证时顺带发现的两件事

1. 常驻规则 `AGENTS.md` 写着「链接可达性由门禁校验（ADR-0009）」——而在此之前，
   真正被校验的只有 ADR ↔ Note 一条链路。**常驻规则自己就是一处未验证的声明。**
2. 实测 `docs/` 与仓库根两份 Markdown 共 **419 条相对链接，6 条是死的**，且全部是层级写错。
   最刺眼的是同一天、同一模板写出的 5 篇 Note 里**错了 4 篇**：
   Note 住在 `docs/notes/<lifecycle>/<class>/` 下，指向 `docs/adr/` 的 ADR 需要**三层**上溯，
   而这 4 篇写了两层（唯一写对的那篇在同一个目录里）。另一处是 SOP 的三条「决策来源」，
   从 `docs/sop/` 出发却按仓库根写。

   死指针的危害不是「点不开」：读者看到「对应 ADR：[ADR-0067]」会以为背后有决策事实，
   实际上那条路通向空地址——它把「这里没有依据」伪装成「这里有依据，只是我没点」。

## Decision

1. **新建 `docs/pitfalls-playbook.md`**，作为「复发故障」唯一 home，按**根因类**组织
   （不按日期、不按事件）。每条四段固定：症状 / 根因类 / 已落地机制 / 下一版默认动作。
   事实留在 ADR / Note / SOP，本页只写「模式 + 机制名 + 链接」（ADR-0009）。
   当天归并出 **9 条**：P-01 未验证的事实被钉进出货面、P-02 仪器假绿、P-03 「知道」没有变成
   「拦住」、P-04 写了但从没跑到、P-05 隔着一层解释器写字面量、P-06 把平台行为当常量、
   P-07 一条事实多个家、P-08 用纪律守只有机制能守住的东西、P-09 死指针。
2. **机制必须点名**：`gate:<门禁名>` 或 `script:<路径>`，至少其一。没有名字的机制说明等于没写。
3. **新增门禁 `pitfalls-playbook`**：四段结构齐全非空；`gate:<名字>` 必须在**实时**注册表里
   （`gate.mjs` 传入 `CHECKS.map(c => c.name)`）；`script:<路径>` 必须真实存在；编号自 P-01 连续；
   全文相对链接可达；且 `AGENTS.md` 与 `docs/README.md` 都必须回引本账。
4. **新增门禁 `docs-link-integrity`**：`docs/` 全部 Markdown + 仓库根两份的相对链接必须可达。
   刻意跳过代码块与行内代码（模板占位符不是链接目标），刻意让空输入判红（收集器失效是
   本项唯一的真空绿路径）。
5. **两条校验各配反向自测并挂进门禁**，自测含恒真桩突变。两个 selftest 起子进程一律走
   `nodeCommand()`：在 pnpm 下 `process.execPath` 是宿主 Electron，子进程会「退出码 0 且没有输出」，
   于是**测试一条没跑也判绿**（ADR-0040；这也正是总账 P-02 的形状）。
6. **修掉 6 条死链**，并修正 `AGENTS.md` 里两处不成立的指引：指向 `architecture.md`「第 4 节」
   （该章节不存在）改为第 0 节；「链接可达性由门禁校验」由局部事实变成全局事实。
7. **新增条目的门槛**：同一根因复发过两次，或第一次的代价大到不允许发生第二次。

## Alternatives considered

- **用 `.learnings/`（`self-improvement` 技能的默认形态）。** 被否：会造出第二个事实家
  （ADR-0009），且**没有门禁守它**。当天教训里正有一条是「知道写在注释里、没变成拦住」，
  再建一个没人守的目录等于当场再犯。技能本身仍然有用——它的价值在「发现问题时先归因」，
  而不在「再开一个文件夹」。
- **只写一篇 Note，不加新文档。** 被否：会被同日 16 篇 Note 淹没，检索面问题原样保留。
- **只回填各自的家，不建总账。** 部分采纳（本次确实回填了 SOP 与常驻规则），但不够：
  回填纠正的是分散的事实，没有回答「下次从哪一眼看全」。
- **把总账并进 `docs/architecture.md`。** 被否：地图页的定位是组合/归属/门禁契约，
  按根因组织的故障清单塞进去会同时破坏两页的定位。
- **给「不复述 ADR 数字」也加机器校验。** 不可行：判断一句话是不是给同一条事实再造了一个家
  需要语义理解。故写成显式约定并标明「**无强制**」——诚实读法就是分清楚哪些是拦住的、
  哪些只是约定。
- **`docs-link-integrity` 一次扩到全仓（含包内文档）。** 本次未采纳：把范围放大到未取证的语料，
  首批红灯会把一项正确的校验拖成噪声源。边界写在模块注释里，扩大留作独立决定。
- **给总账条目加「必须引用 ADR」的规则。** 未采纳：P-03 与 P-09 两条的机制就是门禁本身，
  强行要求 ADR 链接会逼出无意义的引用。链接可达性已由 `docs-link-integrity` 覆盖。

## Consequences

- **正面**：
  - `pnpm run gate` quick 由 28 项升到 **32 项**，新增四项都在提交前就会跑；
  - 死链 6 → **0**，此后新增死链在提交前被拦住；
  - 「教训」第一次有了一个会自己报错的家：条目点名不存在的门禁，或不再被任何入口链接，即红灯；
  - 修正了 `AGENTS.md` 一处已经存在一段时间的死指针（「见第 4 节」）与一处过度声明。
- **负面 / 边界**：
  - `docs-link-integrity` 的范围限于 `docs/` 与仓库根两份 Markdown，**不含包内文档**，
    锚点也不解析——它不构成「全仓链接都可达」的证明；
  - 总账的「不复述 ADR 数字」只有评审、无强制（文档里已显式标注，不伪装成红线）；
  - 门禁多两项各自起一次 `node --test` 子进程（各约 0.1 s）。
- **实施状态（如实记录）**：
  - 反向自测的**恒真桩突变已实测**：把 `pitfalls-playbook.test.mjs` 里一条断言改成必红后，
    门禁 `pitfalls-playbook-selftest` 立刻判红并报出失败用例名；还原后 15/15 绿。
  - **真实语料突变已实测**：把总账里一条 ADR 链接改成不存在的编号后，门禁
    `docs-link-integrity` 判红并报出 `docs/pitfalls-playbook.md:41: 链接不可达
    （adr/ADR-0699.md → docs/adr/ADR-0699.md）`；还原后 32/32 绿。
  - 总账自身被门禁 `pitfalls-playbook` 校验通过（9 条条目，机制全部指向真实存在的门禁或脚本）。
