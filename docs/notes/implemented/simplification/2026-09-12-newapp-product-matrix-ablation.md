# 产品矩阵剪枝：一次以「卸载」为手段的消融实验（ADR-0045）

关联 ADR-0045。本文只记**为什么这么定、量到了什么**；判据的机器化版本在
`scripts/gates/worktable-fence.mjs`（结构）与 `scripts/acceptance/worktable-fence-live.mjs`（实况），
页面读数在 `scripts/acceptance/newapp-products-live.mjs`。

## Problem

用户点开侧边栏「新应用」，看到 25 张卡里 24 张写着「尚未产品化」，判断是「这个插件太重了」，
要求：只保留已经产品化的产品 + 改用大卡片的矩阵形式。「新应用」这一页是本次唯一的战场。

本仓库当时维护着一个 1.4 MB client、8 条 HTTP 路由 + 1 条 WebSocket 升级路由的第三方插件
`dsh-worktable`（工作台 / 控制室），外加 1,268 行守卫件。用户随后把目标说全了：
**工作台与控制室的 UI 组件全部清除，「我只要一心把『新应用』这个页面做好」**。

所以真正要回答的不是「页面怎么改」，而是：

> 这堆东西里，**哪些与目标函数有关**？

## Decision

**用消融实验回答，而不是用审美回答。** 对每个可消融单元：记录基线 → 消融 → 量同一个读数 →
差异即该单元的贡献。目的不是「看看删了会不会坏」，而是把「太重」从感觉变成一张表。

### 基线（Step 0，全部为实测读数）

| 读数 | 命令/来源 | 值 |
| --- | --- | --- |
| 矩阵页卡片数 | `GET /api/dsh-newapp/products` | **25** |
| 其中未产品化占位 | 逐卡 `declared` | **24** |
| `declaredCount` | 同上 | **1** |
| newapp client 自身体积 | `lib/client.js` | **92 KB** |
| worktable client 体积 | `lib/client.js` | **1.4 MB**（23,483 行） |
| worktable 路由 | host bundle 的 `path:` 字面量 | **8 HTTP + 1 WS** |
| 为其维护的守卫件 | 4 个文件 | **1,268 行** |

### 消融表与实测结果

**A 组 — 页面自身（自研包，零补丁成本）**

| # | 消融单元 | 消融后读数 |
| --- | --- | --- |
| A1 | 未声明目录成卡 | 25 → **1**（M1 = 0 占位，M2 = 1 = 1） |
| A2 | 卡主键 = 工作目录 | 一产品一卡，渲染键 `<dir>::<id>` |
| A3 | `.rows` flex 列 | `.grid` + `repeat(auto-fill, minmax(280px, 1fr))` |
| A4/A5/A6 | projects + layouts + 已死的 `agents` | **M6 = 0**（worktable 读取点归零） |
| A7 | `card.undeclared` / `blocked.*` / `row.*` / `degraded.*` 文案 | 死文案清除；`sources.ts` 358 行整体消失 |

**B 组 — `dsh-worktable`（卸载即零补丁剪枝）**

| # | 消融单元 | 结果 |
| --- | --- | --- |
| B1/B2 | profile `dependencies` + `bundles` | 两处摘除，`pnpm install` 后 `pnpm-lock.yaml` 归零 |
| B3 | 8 条 HTTP + 1 条 WS 路由 | 随插件卸载不再注册 |
| B4 | vendor 树 / pin / 补丁 | **保留**（可逆性凭据） |
| B5 | 4 个守卫件 | **语义翻转**，不删 |

### 两条被实验**证伪**的直觉（这才是消融实验的价值）

1. **「卡片的点开路径依赖 worktable」——假的。**
   `src/client/launcher.ts` 走的是官方 `sessions.create` + `connection.api.agentPresets`；
   README 里「工作台已验证的三连」说的是**技法的出处**，不是运行时依赖。
   证据：A 组全部消融后，M1–M6 全部成立。
2. **「要剪工作台就得改它的代码」——假的，而且方向错了。**
   改上游源码会把补丁面从「一处路由注册文本」膨胀成「大面积源码改写」，
   上游每升一次级都要重付一次；而卸载**零补丁**拿到全部诉求。
   剪枝的正确形态是「不装载」，不是「装载一份被改小的」。

### 卸载安全性（实测，非推断）

- 全仓 grep：worktable 路由/存储键的消费者只剩 `dsh-newapp-local` 与其自身守卫件——而
  `dsh-newapp-local` 的读取点已在 Step 1 删除。
- 那 10 个工作台项目**不随卸载消失**：`/api/worktable/workspaces` 读的是官方
  `ctx.workspaceRegistry`（回退 `~/.dsh/storages/workspace.json`），不是 worktable 私有存储。

### 顺序依赖（Step 1 必须先于 Step 5）

卸载后 `/api/worktable/workspaces` 会死。若页面里那段项目列表还在，它会挂上一条**永久**
降级告示「工作台项目（dsh-worktable 未安装，或还没有建过项目）」——正好是用户嫌的那种「重」。
所以「删读取点」必须**先于**「卸载」。

### 判据的翻转，而不是删除

四个守卫件（1,268 行）不删，语义从「守护已安装」翻成**断言未安装**。理由：
上一版判据（31 条实况 + 锚点 + 撞名）每条都在回答「运行时装载的那份产物拦不拦得住」；
插件不装载了，那个问题没有主语。继续断言它，就是 ADR-0009 说的「一个事实的第二处家」——
它会一直绿，并且一直让人以为这条链路还在。

翻转后的门禁判三件事：**别装回来**（dependencies / bundles / node_modules 三处）、
**资产还在**（vendor + pin + 补丁）、**pin 没漂**。

### 一条被实测抓到的中间态

摘掉 `dependencies` 与 `bundles` 之后，`pnpm install` **并没有**删掉
`node_modules/dsh-worktable` 那个符号链接。产物还在、仍可解析、`bundles` 里的旧条目仍能命中。
所以门禁必须三处都判——只判 `package.json` 会漏掉这个状态。这条已固化成自检用例
`node_modules 里的残留必须被拒绝`。

## Alternatives considered

| 方案 | 为什么没选 |
| --- | --- |
| 保留 worktable，只改页面 | 达到 M1–M5，但 1.4 MB client 与 9 条路由（含任意文件写入与交互式 shell）留在机器上。用户明确说「不需要」。 |
| 下载 worktable 源码、删组件后重新打包 | **与目标零相关却代价最高**：补丁面从一处文本膨胀成大面积源码改写，上游每次发版都要重锚。 |
| 只从 bundles 摘掉、保留 node_modules | 实测的中间态（见上）。判据必须三处都查。 |
| 以 `status === 'ready'` 过滤 | 被漂移实测否决：`KOL-Hunter/product.json` 的 `statusReason` 已与运行时不符，让一句会过期的手写文案决定产品显不显示。 |
| 未产品化目录改可折叠分组 | 用户裁决「彻底消失 + 一行计数」。 |
| 卸载时连资产一起删 | 不可逆。用户裁决保留。 |
| 把 24 张占位卡保留但置灰 | 页面仍然「重」，且用户看到的第一眼仍是 24 条噪声。 |

## Consequences

**正面**

- 页面从「25 张卡 / 1 张可用」变成「1 张卡 / 1 张可用」，卡片数 = 已声明产品数。
- 工作台与控制室的 UI 从本机消失：1.4 MB client 不再加载、9 条路由不再注册。
- newapp 自身 client 92 KB → **71.5 KB**；`sources.ts`（358 行）与其测试整体消失。
- 补丁面不增长：卸载不碰上游一行，上游发版无需重锚。

**负面 / 代价**

- **部分取代 ADR-0028 与 ADR-0033 第 6 条**（两篇正文已标注）。ADR-0033 其余决策不受影响。
- 本机不能再从页面进入工作台项目（10 个项目数据仍在，只是不再展示）。
- ADR-0029/0030 的 31 条栅栏实况判据作废；栅栏作为「同类第三方插件的模板」的结论不因此失效。
- **页面上只剩 1 张卡**是诚实读数，不是缺陷。网格用 `auto-fill` 写就是为了随声明增长。

**后续动作**

- M3（真实网格列数）必须在**真实 Chrome** 里量：jsdom 不做布局，`getBoundingClientRect()` 恒为 0。
  真实数据只有 1 个产品，故该判据由**合成夹具**承载，并配反向对照（1 张卡的夹具下列数断言**必须失败**）。
- 实况卸载判据需要**一次重启**才落到进程里：磁盘侧三处皆无时，运行中的实例仍会应答那 9 个入口。
  探针把这一态记成退出码 **3**（restart-required），不记成失败，也不用绿色假装已经改变。
