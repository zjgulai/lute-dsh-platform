# ADR-0041 · 已安装的技能本体就是分类的运行时家；归位与接线必须分开显示

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（要求设置页新增「算法技能」页并按 4 面 / 责任域 / 岗位下钻）+ agent（实测后提出三条）
- 决策记录：[Note](../notes/implemented/capability/2026-09-12-algo-skills-surface.md)

## 背景

1338 张论文技能卡已按组织分类法归位，分类写在每张卡自己的 frontmatter 里
（[ADR-0031](ADR-0031.md)），但**没有任何界面渲染这份分类**：卡在技能选择器里是一串平铺名字，
语料未能归类的 11 张卡与没有供给的 2 个岗位在结构上无处可站，而「归位」与「preset 是否接线」
被默认当成同一件事——实测两者对 1001 张卡并不重合。

要新增一个承载它们的设置页，必须先回答三件事：分类在**运行时**的家在哪、页面报什么数、
以及唯一的那次写能写到哪。

实测（50 个 preset 的 `material_skill_names` 对 taxonomy 的 151 条责任名）：

```
覆盖 151/151，且每个责任名唯一属于一个岗位（50 岗 × 3 名，无重复归属）
4 面分布 5 / 35 / 5 / 5　·　50 岗　·　1338 张卡　·　已归位 1327 / 未归类 11
本岗已接线 326　·　接线到别岗 23　·　完全未接线 978　·　空白岗位 2
```

也就是说连接键 `卡的 l3_business → 岗位` 完全由**已安装的运行时状态**闭合，不需要第二份分类表。

## 决策

**1. 分类的运行时家是「已安装的技能本体」，不是任何包的数据目录。**

新页只读两处：`~/.dsh/.agent-presets/agt-*/manifest.json`（面 / 责任域 / order / 本岗责任名 /
标准产物 / 考核口径 / 岗位头像）与 `~/.dsh/skills/p2s-*/SKILL.md` 的 frontmatter。
不读 `dsh-paper2skills/data/classification.json`，也不生成第二份 taxonomy 副本。
`taxonomy.json` 保持唯一事实源（[ADR-0009](ADR-0009.md)）。

代价必须记账：本页因此看不到 `confidence` 与 `fills_gap` 审计——那些事实只在分类资产里。

**2. 归位与接线是两个字段，页面必须分开显示。**

卡归哪个岗位由分类决定；preset 是否挂载它由 `scripts/role-presets` 的人工映射表决定。
两者对 1001 张卡不重合。任何把二者合并的显示方式，都会让 978 张完全未接线的卡看起来像是
有一条通向模型的路径。

**3. 页面只读；唯一的写（模型调用开关）收窄到 `p2s-` 卡。**

`disable-model-invocation` / `user-invocable` 的语义与 `dsh-overseas-skills` 逐字一致
（A1：一个开关只控模型调用，「/」菜单恒可见）。但名字校验额外要求 `^p2s-`：
安全的 kebab 名字不等于本页拥有的卡，`~/.dsh/skills` 里同时住着手工撰写的技能。

**4. 那次写只动值，不动拼法。**

流水线把 frontmatter 的标量写成 JSON 带引号（`"true"`），手写技能写裸值（`true`），
两者对页面读取器和宿主加载器是同一个布尔。页面因此**按文件原本的拼法回写**这两个键
（键不存在时写裸值），并保留 frontmatter 块的行尾。可检验的承诺是一句话：
**点开再点回去，磁盘上的字节一模一样。** 否则 1338 张里 1337 张会在被点过一次之后
悄悄脱离安装器写出的格式，而「用户点错了」与「有人手改过」就此无法区分。
备选「照流水线的规范统一写成带引号」被否：那会让 1 张裸值卡与任何手写卡反向偏离。
证据（含先红后绿的失败清单）见决策记录 Note。

## 备选方案

- **扩展现有 `dsh-paper2skills`**：数据零拷贝，但要把纯管线包改成运行时插件（动 `exports` 主入口、
  加 `cordis.patch.yml`、进 profile 依赖），且 `file:` 链接会暴露 20MB 的 `data/`+`generated/`；
  页面属 `surfaces` 组而该包在 `capabilities` 组（[ADR-0011](ADR-0011.md)）。
- **挂进 `dsh-role-matrix-local`**：最小改动，但会把 1338 张卡的分类事实搬进第二个包。
- **沿用出海技能的「生成 catalogue」形态**：生成物会成为 taxonomy 的第二份副本，
  而运行时状态本来就能闭合这条 join。
- **跨包共享一个渲染器**：客户端模块加载器支持（`<id>/client` 与裸包名归一到同一 exports），
  机制可行；但 [ADR-0035](ADR-0035.md) 的结论是「正面接线、反面效果」，在效果翻盘前
  把出海技能页也绑到同一结构上不划算。两个页面因此同构但各自独立。
- **逐级懒加载**：负载更小，但要 1338 次往返或在展开时闪；实测全树 848 KB / 7.9 ms，
  一次拉完更简单。

## 后果

正面：1338 张卡第一次有组织形状；两类结构性缺口有一等位置；归位与接线的落差第一次可见；
新包零跨包依赖，`pnpm run gate` 15/15 绿。

负面：页面看不到 `confidence` / `fills_gap`；面下的责任域是**切片**（4 面下 12 个切片 vs
分类法 8 个不同责任域，两个数都报以免误读）；只扫 `p2s-` 卡。

> 装载方式更正（2026-09-12）：本节初稿写「装载需要宿主重启」，实测**不需要**——`dsh-market`
> 的 toggle 走热挂载（`restart:false / refresh:true`，`activation.state=live`），落盘只有用户
> patch 层 2 行，后续启动由 bundle 层正常加载。见 [ADR-0042](ADR-0042.md)。

后续：用户目视验收本页后，再启动出海技能按 场景 → 4 面 → 岗位 的重构，以及 1338 张卡的优化方案。
