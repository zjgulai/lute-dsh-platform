# ADR-0029 · 主题 Token 的判据要两侧共同证伪：真实 CSS 引擎 + 真实供给函数

- 状态：accepted
- 日期：2026-09-12
- 决策者：agent（取证后提出；范围与取舍已在决策记录里实测支撑）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-theme-token-verdicts-two-sided.md)

## 背景

ADR-0028 把「无硬色值（只走 `--dsw-alias-*`）」从口头验收变成了门禁项 `theme-tokens`。
该门禁的「已定义」是**静态文本提取**：对应用目录 grep `--dsw-x:`，对本仓库 `src/` 正则
找 `"--dsw-x":` 字面量。继续查它的判据本身，实测到两个结构性缺口（取证见 Note）：

1. **命名空间只覆盖了 `--dsw-`。** 官方主题同时供给 `--ds-font-family-code`、
   `--dsh-scrollbar-thumb`，而本仓库确实在用 `--ds-font-family-code`。旧口径下，
   一个 `--ds-` 前缀的错别字门禁看不见、页面照走字面兜底——还是静默失败。
2. **「门禁说已定义」有两种理由，失效方式不同。** 官方 CSS 声明可能被级联吃掉；
   本仓库的 JS 供给由 `buildThemeTokenOverrides(settings)` 的**返回值**决定，
   而门禁的判据只是「字面量在源码里出现过」——写在永不进入的分支里也照样命中。

两类错的方向相反：**假阳性**会训练人忽略输出，真正的违规藏进噪音；**假阴性**会让人去
「修」根本没坏的东西。

## 决策

1. 门禁命名空间从 `--dsw-` 扩到平台自身的 `--dsw-` / `--ds-` / `--dsh-`（`NAMESPACE`），
   引用侧与定义侧同步扩。组件**局部**变量（`--appearance-*`、`--card-tint` 这类在同一个
   文件里自定义自用的名字）**不收**——收进来只会造一批假阳性。
2. 新增按需验收探针 `scripts/acceptance/theme-tokens-live.mjs`：真实 Chrome + 逐字取自
   产物的主题样式表 + 逐字调用 `buildThemeTokenOverrides`，与门禁判据逐条对照，分歧按
   「官方声明」与「自家供给」两路分别点名。
3. 探针必须带**仪器自检**（正控必须解析成功、负控必须解析为空、切主题确实生效），
   任一条不成立即 **exit 2** 且不出结论。
4. 报告把「解析成功」与「在这一态里真的产生了一个面」分开：与抽屉底色同色的 token 单独标注。

## 备选方案

- **只扩命名空间，不做探针**：最便宜，但治不了缺口 2——门禁在结构上看不见它。
- **把探针做成门禁项**：它需要 Chrome 与已安装的应用。做成门禁项后在缺这些的机器上
  要么不可用、要么静默跳过，等于把「已验收」变成「没验」。故与 `patch-anchors` 同一性质，
  保持为按需验收产物。
- **直接打开实况 GUI（`http://127.0.0.1:43120`）验**：实测 `/` 与 `/api/...` 均返回 401
  （浏览器信任栅栏要求已配对设备凭证）；要打开就得先在用户**正在运行**的实例上完成配对，
  既侵入用户环境，又把「验 token」与「验实况页面」两件事混在一起。
- **在探针里重写一份 token 清单**：违反 ADR-0009，且清单从建好那一刻就开始漂移。

## 后果

- 正面：引用 90 → 91、官方已定义 358 → 393、自家已定义 66 → 67，
  **自家字面量扫描与真实供给函数的输出首次完全一致（67 = 67）**；
  `gate --mode full` 17/17 退出码 0；探针 91 个引用 token 两条供给路径零分歧。
  变异测试证明探针非空转（门禁通过而探针 exit 1 并逐字点名）。
- 负面：探针不进 `pnpm test`，是**按需验收产物**，不会自动阻止回归；它测的是「产物里的
  样式表在真实 CSS 引擎下如何解析」，不是实况页面，后者仍挂 C4。
- 后续动作（**未在本 ADR 处理**）：探针暴露出一条产品事实——官方浅色主题的
  `bg-base` / `bg-layer-1..3` 全部解析成同一个白，浅色靠边框与阴影表达立面。本包两个只靠
  底色、没有边框的药丸因此在浅色下与抽屉底色同色。官方自己的 `.pill` 用的是同一个 token
  且同样无边框，故未单方面改动；该事实已进入探针报告（`newappFlatWithSurface`），
  待实况验收（C4）时一并定夺。
