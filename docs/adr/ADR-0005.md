# ADR-0005 · rc.1 基座迁移立项（LUTE 2.0.0）

- 状态：accepted
- 日期：2026-09-10
- 决策者：用户（lute）+ agent（3 轮 12 项决策，Noema 已存）

## 背景

LUTE 当前基座为 DSH Desktop 2.0.4 + @deepseek-ai/dsh-* 0.1.2-alpha.1（129 包齐锁）。上游 anywhere-labs/dsh-desktop 已于 2026-09-03 发布 v2.0.5，运行时整体切换至 0.1.2-rc.1（官方自认「很多插件不可用」）；npm 生态 6/13 个 profile 插件的最新版已放弃 alpha.1。逐文件核实：LUTE 的关键补丁（P0-1/2/3/4）在 rc.1 上全部未被上游修复，升级不减少补丁量、只改变锚点。D 轨道（rc-eval，完全隔离）已完成 P0 验证：24 bundles 整树 0 error、旧数据投影 248 项重建、上游 4 项高危 issue 复现实验未触发、16 个本地插件无需大规模移植（唯一产物：dsh-overseas-skills files 清单 bug，PR #1 已提交）。

## 决策

**将基座整体迁移到 DSH Desktop 2.0.5 + runtime 0.1.2-rc.1，作为独立大版本 LUTE 2.0.0 一次到位交付**（基座迁移 + 补丁全量重锚 + 打包流水线 + 客户升级安装器同版发布）。

核心条款（详见 docs/research/04-upgrade-plan.md）：

1. **版本策略**：DSH 基线字段 2.0.4 → 2.0.5；CFBundleVersion 后缀 `2.0.5-lute.2.0.0`；ShortVersionString 保持 2.0.5 对齐。
2. **补丁处置四类**：保留重推（P0-1/2/3/4/7、UI-3/4、PR-1/2/5、LB-1~3、chatui、skill-title、clipboard、品牌、apply-patches.mjs）/ 语义重推（P0-8、UI-1，D 轨道专项验证后定稿）/ 换上游实现（P0-6 回移 master local-window-policy.ts）/ 不动（P0-5）。
3. **必踩坑 SOP**：预设平面包直补重做（profile override 对预设平面失效）；cordis 层 2 处直补在 4.0.2/loader 1.0.3 上重推；profile 必须保留 `autoInstallPeers: false`（rc 生态 peer 范围在 npm 上不可解析，实证）。
4. **数据迁移**：alpha.1 → rc.1 会话/存储已验证可读（投影层）；客户安装器升级路径带备份/回滚/TCC 重授权引导。
5. **发布门禁**：rc-compat-matrix 全绿 → 旧数据可读 → L1-L4 冒烟（新锚点集）→ 生产 2.0.4 对照基线稳定 → 客户灰度名单 1 周 → 全量。

## 备选方案

- A 冻结（维持 alpha.1）：被否决——生态漂移持续，6 个插件已无 alpha.1 新版本。
- C 选择性吸收（只回移特性不换基座）：被否决——用户选择整体升级作为终态；D 轨道先行验证吸收了 C 的渐进精神。
- 直接追 master（2.0.6-dev）：被否决——master 9-09 有 revert 波动、破坏性更新月内 4 次；待 2.0.6 稳定后再评估增量。

## 后果

- 正面：重新回到生态主流线；获得上游安全模式/快速恢复/恢复助手修复等能力；未来插件可直接用 rc 版。
- 负面/代价：35 文件/32 锚点全量重推（约 1-2 周核心工作）；vision-router/noema 跨代 peer 需持续观察；#865/867 spill 行为留 P1 冒烟验证。
- 后续动作：见 docs/research/07-patches-manifest-v2-draft.md（重锚清单）与 04-upgrade-plan.md §6 WBS。
