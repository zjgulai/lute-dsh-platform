# ADR-0046 · 可选服务只能用 `ctx.get` 读（裸读会抛，`?? 兜底` 是假兜底）；Remote 三元组必须按位传参并读回 `ok:false`

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（报「点击卡片的会话显示：打开失败：cannot get property "sessions" without inject」）+ agent（现场取证、契约比对、变异验证）
- 决策记录：[Note](../notes/implemented/contract/2026-09-12-newapp-card-open-context.md)

## 背景

产品矩阵那张卡（深链星探 KOL Hunter）点下去报：

```
打开失败：cannot get property "sessions" without inject
```

`product.json` 的 `statusReason` 早已写明「入口面板的客户端服务尚未打包安装，卡片点开暂走第 2 级回退」，
所以走的是第 2 级（新建会话）。第 2 级第一行是：

```ts
const sessions = context.sessions ?? lookup(context, 'sessions')
```

这一行**看起来**是「先试属性、再试 `get`」的双重兜底，实际两半都不成立：

1. **`context.sessions` 不是一次查询，是一次抛。** `dsh-newapp-local` 的客户端半边声明
   `inject = ['slots', 'locale']`，而 cordis 的上下文是 Proxy：读**未声明**的服务时，
   `ReflectService.handler.get` 走完 waterfall 后 `throw new Error('cannot get property "…" without inject')`
   （实测位置：`@deepseek-ai/cordis/lib/index.js` 的 `ReflectService.handler`）。
   抛发生在**求值左操作数的过程中**，`??` 的右半边永远没有机会执行。
   `ctx.get(name)` 才是 cordis 文档明示的「read a service from the store without the inject requirement」。
2. **`lookup()` 本来就是那个安全的读**（内部包了 `ctx.get`，且 try/catch），
   它被写在 `??` 右边，于是被左边那一下抛彻底短路。

同一次排查还查出第 2 级的第二、第三处独立缺陷，它们都在第一处修好之后才会显形：

- **传参形状错。** 生成的客户端契约是 `select: (agentId: SessionId, agentPreset: string)`；
  网关 `prepareInvocation` 按**下标**取参（`descriptor.parameters.forEach((parameter, i) => args[parameter.wire] = values[valueIndex++])`），
  且先校验 `values.length === expected`。旧代码传一个对象 `{ sessionId, agentPreset }`，
  在网关就被判 `expected 2 argument(s), got 1`——**即使服务存在也送不到宿主**。
  且键名也不是 `sessionId`：wire 名是 `agentId`。旧写法能通过全部单测，是因为替身 `select` 是 `vi.fn()`，不校验实参形状。
- **返回值没读。** `select` 返回 `RemoteResult`：业务失败是**返回值** `{ ok:false }`，不是抛异常。
  旧代码 `await select.call(…)` 之后不看结果，于是「岗位没选中」也会打印
  `已新建会话（目录 …，岗位 agt-033）`——在用户唯一会去核对的字段上说了假话。

修复前的判据全绿：包内 107 条测试通过、`pnpm run gate` 15/15、`/api/dsh-newapp/health` 200、
`/api/dsh-newapp/products` 正常返回 `declaredCount: 1`。**绿是因为没有一条判据能让它红**：
`launcher.spec.ts` 的每个用例都传**普通对象**当上下文——没有 Proxy 就不会抛，
`context.sessions` 只是 `undefined`，兜底照跑。那一行在生产里唯一不可执行的写法，
正是单测里唯一无法执行的写法。

## 决策

**1. 可选服务一律用 `ctx.get(name)` 读，禁止裸属性读。**
`ProbeableContext` 类型里**不再出现任何服务属性**，只留 `get` 与 `logger`——
让「裸读」在这份实现里连编译都写不出来，而不只是靠自觉。

**2. 这条纪律的判据必须落在真 cordis 上下文里。**
新增 `tests/launcher-context.spec.ts`：用真的 `Context` 起一个 fiber（`fiber.runtime` 有值才复现抛），
第一个用例先断言**抛本身**（`cannot get property "sessions" without inject`），
证明夹具确实在复现生产；后续用例才断言三元组跑通。
把实现改回裸读，该文件立刻转红并抛出**与用户报告逐字相同**的错误串。

**3. Remote 调用按生成契约的**位置与序号**传参，并读回 `ok:false`。**
`select(agentId, agentPreset)` 两个位置参数；返回值两种形状都要认
（`{ ok }` 与 `{ result: { ok } }`），`ok:false` 时把原因带进那句 note。

**4. 「没读到」不是「没有这个能力」。**
服务缺失时 `run()` 返回可打印的 `{ ok:false, note }`（`没有 sessions 服务，无法新建会话。`），
仍然不以 rejection 形式抛出——沿用 [ADR-0038](ADR-0038.md) 在宿主半边定下的同一条纪律。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| **A. 把 `sessions` 写进 `inject = ['slots','locale','sessions']`** | 与工作台客户端同形，且属性读不再抛。但它把「可选」变成「必需」：cordis 的 `inject` 语义是「全部可用才装载」，客户端半边就绪更早于会话服务时会**整个插件不装载**，连不依赖会话的卡片一起消失。且契约要求 `dsh.client.inject` 增列 `@deepseek-ai/dsh-api-session-controller`，为一个「读不到就报一句」的能力扩大装载依赖。否决。 |
| **B. 只把裸读包进 try/catch** | 能挡住抛，但把「读不到」与「读到了但形状不对」压成同一个分支；且留着 `context.sessions` 这个写法，下一个插件照抄。ADR-0038 已经因为同一个原因把「尽力而为的查询」定成默认。否决。 |
| **C. 用 `window.__dshSessions` 之类全局兜底** | 工作台客户端确实挂了这些全局（`window.__dshOpenSession` 等），但它们不是契约，只是那个包的副作用；依赖它们等于把「能不能开会话」押在另一个插件的实现细节上。否决。 |
| **D. 只修第一处，`select` 的两处先记 TODO** | 第一处修好后用户会看到「已新建会话（岗位 agt-033）」——而岗位可能根本没选中。这是**用一次修复掩盖一次假成功**，比原来的显式报错更坏。否决。 |
| **E. 借 `dshmarket` 热挂载把修复推进运行中的实例** | 该机制为「本进程新装插件」而设，会插入一个新的 loader 入口；本插件已由 profile bundle 层插入同一 id，重复插入是硬启动失败。否决。 |

## 后果

**正面**

- 点卡片能真正开会话：`create({cwd})` → `select(agentId, agentPreset)` → `open(id)`，
  且岗位选中失败会在 note 里说出来，不再打印假成功。
- 「可选服务」这条纪律有了机器判据：`tests/launcher-context.spec.ts`（真 cordis 上下文）。
  这类 bug 此前在本仓库已犯过一次同形错误（[ADR-0038](ADR-0038.md) 的 `remoteWebUiPairing`，
  当时它以「403 分支不可达、实际 400」的形态出现），本 ADR 把两处收敛成同一条结论。

**负面 / 代价**

- 新增 1 个测试文件与 1 个 devDependency 用途（`@deepseek-ai/cordis` 本来就在 devDependencies 里，无新增依赖）。
- 客户端半边体积 71.5 KB → 72.7 KB（多出的部分是失败原因的描述函数）。
- `Preset 未安装` 时卡片仍会开会话（只是岗位是默认值）——这是 `hasPreset` 的既有语义（roster 读不到时从宽），
  本次不动；但它现在会**说出来**。

**后续动作**

- 客户端改动要生效需要重载页面（客户端 bundle 由宿主按 rev 下发）；若本机装载层不重新读取，
  需重启 DSH Desktop——**只有重启能改变运行中实例已装载的东西**，这一点与磁盘是否已修好无关。
- 同类裸读排查：`packages/**/src/client/*` 里除 `slots` / `locale` / `connection` 以外不应出现服务属性读。
