# ADR-0053 · 岗位能力事实读它的家（preset manifest + 技能本体），不派生第二份清单

- 状态：accepted
- 日期：2026-09-12
- 决策者：agent（实施取证与落盘；用户批准「一口气推完」的范围）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-composer-role-capabilities.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0019（官方 UI 改写锚禁止钉哈希）、ADR-0041（已安装技能本体是运行时家）、ADR-0014（门禁硬门槛 + 只减不增的豁免）

## 背景

输入框下方要新增一面「这个分身能做什么」的导引（`.scratch/newapp-midcol-design/plan.md`
R1–R8）。设计阶段定下的 R5 是：由 `scripts/role-presets/generate.mjs` 同源派生一份
`preset-capabilities.json`（身份行 + 3 组业务技能 + 供给 + 场景手册），并新增一条门禁校验
「派生物 ≡ 51 个 preset 同步」。

实施启动时读代码发现两件事：

1. 派生**已经发生过**：`generate.mjs` 把 `skill-map.json` 的 `kind` / `note` / `supply`
   连同 `subset`、`gaps`、`material_skill_names` 一起写进每个 preset 的
   `manifest.json` 的 `x_lute.skills` 段。
2. 这份文件**已经有人在读**：`dsh-role-matrix-local/src/collect.ts` 就是靠它渲染岗位矩阵面板的。

也就是说，R5 要求的「派生物」若是新写一份 JSON 落进仓库，那不是派生，是**第三份副本**。

## 决策

**能力数据不落副本：宿主路由现读现投影。**

- 新路由 `GET /api/dsh-role-matrix/capabilities?preset=agt-NNN`（与 `list` / `health` 同一
  路由族、同一信任栅栏），由 `src/capabilities.ts` 读 `~/.dsh/.agent-presets/<id>/manifest.json`
  的 `x_lute` 与 `material.playbooks` 投影出身份、组、供给与场景手册。
- 技能**显示名**读技能本体 `~/.dsh/skills/<id>/SKILL.md` frontmatter
  （`title` → 描述首句 → id）。这是读，不是副本（ADR-0041）。
- 岗位判定统一读官方会话投影 `agentPreset`（spike②），`ROLE_PRESET_ID` 正则从 `collect.ts`
  导出复用，不再抄第二份。
- 渲染面为 `dsh-role-matrix-local` 的第三个面（前两个是侧栏入口与矩阵抽屉）：共享挂载核心
  `shared/client/hero-entry-core.ts` + 包内 React 行。挂载锚只用官方语义属性，零哈希（ADR-0019）。

## 备选方案

- **按 R5 字面派生 `preset-capabilities.json` + 门禁校验同步**：否。门禁无法重新生成它
  （材料根在仓库外），只能在本机存在 `~/.dsh/.agent-presets` 时比对，机器上没有就跳过；
  且新写的 preset 会静默渲染空面，直到有人记得跑生成器。
- **把能力明细并进既有 `list` 路由**：否。本功能每次只需要当前那一个 preset；合并会让矩阵
  面板每次刷新多背 50 份技能明细。
- **读 `agent.cordis.yml` 的真实装配行**：否。装配行只有 `skill-subset` 的 id 并集，没有
  「平台技能服务哪条业务技能、覆盖到什么程度、边界在哪」这层信息。
- **预填走 DOM 写入 / `execCommand`**：否。composer 是 Lexical contenteditable，戳
  `textContent` 会让编辑器模型与像素分叉，用户发出去的内容与他看到的不一致；宁可自报
  「预填不可用」。

## 后果

- **正面**：漂移在结构上不可能；新增/删除 preset、改映射、装卸技能，下一次请求即新事实；
  矩阵面板与 hero 行共用同一个读与同一条 id 边界；实况探针在真实安装上 16/16
  （50 preset / 151 组 / 650 供给 / 0 undefined）。
- **代价**：宿主路由每次现读一个 ~60KB manifest 加 N 个 `SKILL.md`（本地 loopback，
  量级可接受；将来卡顿则加按 mtime 的缓存，不动数据链）。
- **风险**：本面依赖官方 DOM 形状与 `conversation.input.shell(id)`（后者是 `for(ctx)` 的
  实现细节，非文档面）。上游一改即降级；两条实况探针 + 单元测试把「降级」钉在**自报**上
  （`<html data-dsh-hero-entry>` 诊断属性 + `console.warn`），不允许静默消失。
