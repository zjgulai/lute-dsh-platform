# ADR-0028 · 启动器只拥有「连接」，不拥有事实；侧边栏启动位与官方键各占一半

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（lute 提出融合需求）+ agent（取证后提出边界）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-newapp-launcher-join-not-facts.md)

## 背景

用户要求把上游 `dsh-worktable`（工作台，Agent 级项目容器）与本机平台融合：官方
「新会话」按钮**缩小一半**，另一半放自建按钮，**名为「新应用」**，两者**平行对齐**，
并交付一个「应用矩阵」抽屉。

需求里有一个必须先回答的问题：**「应用」这个东西在本机的数据里到底存在吗？**

实测（逐字读三处来源，非推断）：

| 看似是「应用」的东西 | 实际拥有者 | 形态 |
| --- | --- | --- |
| 岗位 / 角色 | 官方预设名册（`@deepseek-ai/dsh-agent-presets`），由 `dsh-role-matrix-local` 发布 | `~/.dsh/.agent-presets/agt-NNN/` |
| 项目 / 工作区 | `dsh-worktable`（第三方，本仓库以 vendor pin 安装） | `GET /api/worktable/workspaces`：`global.workspaceIds`（**列表与次序**）+ `tables.workspaces[id].title`（名字） |
| 项目覆盖层 | 同上 | `localStorage['dsh.worktable.projects.v1']`——**只是覆盖层**（order / nameOverrides / hidden / removed / lastUsed），不是列表 |
| 布局预设 | `dsh-worktable` | `localStorage['dsh.worktable.split.v2']` |

> **2026-09-12 更正（本 ADR 初版把项目那一格写成了 localStorage，是错的）**：上表第 2 行
> 原本写 `localStorage['dsh.worktable.projects.v1']`。实机核对工作台自己的
> `fetchSessionGroups()` 后确认：**列表来自 HTTP 路由**，localStorage 只是在它之上的覆盖层。
> 覆盖层的 `order` 在用户没手动拖过卡片时就是 `[]`，所以「把覆盖层当列表读」在一台
> **明明有 11 个工作区**的机器上得到 0 个项目——本项目里真实发生过，症状是抽屉里只有岗位、
> 没有工作台项目。取证不完整就会以这种方式伪装成「本机没有项目」。

**没有任何一处存着「应用」。** 官方「新会话」起的是一个**空**会话：它不知道「项目」；
工作台不知道「岗位」。所谓「应用」= **岗位 × 项目的连接**，而连接此前没有任何面能渲染
——不是没渲染好，是**没有一个面同时看得见两半**。

同时，侧边栏的「启动位」只有一个band：官方 CSS 实测 root 为 `flex-direction: column`，
`newSession` 是 `flex: none; height: 38px; margin: 0 2px 8px` 且**无显式 width**（靠
stretch 撑满）。再加一行就把它变成两行，并把下方工作区浏览器推下去。

## 决策

**1. 启动器（`dsh-newapp-local`）只拥有连接，不拥有事实。**

- 岗位从 `dsh-role-matrix-local` 已发布的 `GET /api/dsh-role-matrix/list` 读；
- 项目**列表**从工作台已发布的 `GET /api/worktable/workspaces` 读，`localStorage` 的项目键
  只当**覆盖层**（改名 / 隐藏 / 移除 / 最近使用）；布局预设从 `localStorage['…split.v2']` 读；
- **对工作台只有读路径，连被禁用的写路径都没有**；
- 「应用」这个连接**不被存储在任何地方**。删掉本插件，不丢任何事实。

由此推出一条硬纪律：**本包不得重新扫描预设目录，也不得复刻工作台的存储格式**——
两者都会立刻构成 ADR-0009 意义上的「第二份事实之家」，且第一份一改就漂移。
本条的**对偶**同样硬：**读取时必须复刻拥有者自己的取数方式**（用哪个路由、哪个键、什么
优先级）。写错来源与另起一份事实是同一个病的两面——前者表现为「本机没有项目」，
后者表现为两个面各说各话。

**2. 降级必须按来源逐条点名，不得合并成一句「加载失败」。**

两个半边的拥有者不同、安装状态互相独立，用户对「岗位名册缺失」与「工作台缺失」的
下一步动作**也不同**。抽屉渲染的是缺席来源清单（含 owner 与它拥有的事实），不是
一个空网格——空网格与「本机真的什么都没有」在视觉上不可区分。

**3. 启动位与官方按钮平行各占一半，用内联样式表达，不用样式表规则。**

`2 + W + 2`（官方 2px 侧边距）`+ 2 + W + 2`（自建键）`= 100%` ⇒ `W = calc(50% - 4px)`；
上提量取官方键自身的纵向推进（height + margin-bottom），**运行时由
`getBoundingClientRect()` 算出，不写魔数**。内联必胜的依据是实测：官方样式表里
`!important` 出现 **0 次**。

**配套硬约束（由真实浏览器实测反推得出，不是审美偏好）**：自建键的 `margin-bottom`
必须等于官方键的 `margin-bottom`（当前 8px）。flex 列里这一对的总贡献是
`官方(38+8) + 自建(-46+38+B) = 46 + (B-8)`；`B = 0` 会让文档流**少推进 8px**，下方工作区
顶部上移 8px 并静默长高（实测 `regionArea top 120 → 112`）。**这条 jsdom 结构上查不出
——它不做布局**，因此该几何契约由 `scripts/geometry-probe.mjs` 驱动真实 Chrome 守着
（18 项断言，真实盒子读数）。

**4. 收起态不硬分，降级为堆叠。**

收起 rail 的内容宽只有 36px，而图标 18px；硬分得 ~17px/键会切掉图标。这是几何硬
约束，不是偏好。

**5. 锚点失效必须自报，不得静默缺席。**

外壳若改名或重构了 `newSession`，插件在 `<html data-dsh-newapp-degraded="…">` 上
自报并响亮告警。ADR-0019 禁止的是**把哈希写进产品代码**，不是**必须去解析哈希**：
本包选择侧用子串选择器 `[class*="newSession"]`（CSS-module 本地名完整保留，跨代成立），
覆盖侧走内联样式，**根本不碰哈希**。

## 备选方案

- **给启动器自己的数据源**（自己扫 `~/.dsh/.agent-presets`、自己解析工作台存储）：
  立刻产生第二份事实之家，且工作台是第三方包、其存储格式随时可能变。**否决。**
- **再加一行插件行**（沿用既有 `before` / `after` 家族块）：实现最省，但把「启动」
  拆成两行、推下工作区浏览器，并暗示两步操作（先选会话类型再选应用）。**否决。**
- **搬动 / 替换官方按钮节点**：触碰 React 的 reconciliation，且违反「不搬动官方 DOM」
  的既有纪律。**否决。**
- **把工作台底部区块（`sidebar.footer.action`）隐藏后由抽屉完全接管**：见 D-B 决策，
  本 ADR 不定夺归属，只要求「不写工作台状态」。
- **用样式表规则而非内联样式表达半宽**：位置规则可被外壳下一次构建失效，且需要拼类名
  选择器；内联既必胜又不碰节点身份。**否决。**

## 后果

- **正面**：融合不引入任何新的数据所有权，也不引入新的写路径；两个上游任一被卸载，
  抽屉降级为另一半而不是报错；启动器永久免疫「谁的存储格式对了」这类问题。
- **负面**：抽屉的能力上限由两个被连接的面决定——想让它显示岗位的详细清单，就得先让
  名册发布那些字段（或跳转到拥有它的面）。这是刻意的：**连接不得伪装成拥有**。
- **负面**：`GET /api/worktable/workspaces` 的响应形状、`localStorage['dsh.worktable.projects.v1']`
  的覆盖层字段、以及 `['…split.v2']` 是本包与工作台之间的**全部耦合面**，且工作台是第三方包。
  上游改字段名时本包会静默读到空——因此契约测试逐字钉住这些形状（`tests/sources.spec.ts`），
  改键名会在测试里红，而不是在用户那里表现为「本机没有项目」。**这条负面在初版里被低估了**：
  当时以为「钉住键名」就够了，但真正的风险不只是键名，还有**选错来源**——键名一个字都没错，
  仍然可以是错的那一份。
- **纪律**：以后任何「聚合多个已有面」的新面，先回答「它拥有哪一份事实」；答案是
  「都不拥有」时，本 ADR 就是先例——包括必须提供逐源的降级说明。
