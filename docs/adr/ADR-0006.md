# ADR-0006 · 上游版本跟进策略（月度观察窗）

- 状态：accepted
- 日期：2026-09-10
- 决策者：用户（lute）+ agent（复盘决策：月度观察窗）

## 背景

DSH Desktop 上游节奏极快：2.0.4（08-28）→ 2.0.5（09-03）→ master 2.0.6-dev（领先 138+ commits，含 local-window-security-policy、selective-ASAR 等）；破坏性更新月内 4 次，9-09 出现整体 revert 波动。LUTE 2.0.0 刚完成对 2.0.5/rc.1 的全链迁移（35 补丁重锚），追赶快车会反复消耗重锚成本。

## 决策

**月度观察窗策略**：

1. 上游新稳定版（如 2.0.6）发布后，**观察 2 周**不动作（等社区报障与修补稳定）。
2. 观察期后按「红线触发制」决定是否跟进：
   - **红线（必须跟进）**：安全类修复（本地对应补丁存在时记录对比结论）、恢复/白屏等高危 issue 修复、rc 生态插件大面积放弃当前运行时（D 轨道复检证据）。
   - **非红线**：只做「选择性回移」（修复/特性以补丁形式回移到当前基座，D 轨道增量验证），不做整体大版本迁移。
3. **大版本整体迁移**（如 3.0.0）仅由客户需求驱动立项，复用 2.0.0 的 P0-P5 全链 SOP。
4. 每次跟进动作复用：rc-eval 隔离轨道 + patches-manifest 重锚 SOP + verify-patches 漂移探测 + smoke 矩阵。

## 备选方案

- 紧跟节奏：被否决——重锚成本与上游波动不成比例。
- 冻结：被否决——生态漂移（alpha.1 教训）与安全补丁会累积。

## 后果

- 正面：稳定优先，重锚成本可控；安全红线有保障。
- 负面：与上游新特性存在最长 ~1 个月延迟（由红线制兜底）。
- 后续动作：2.0.6 发布时启动观察窗（记录观察结论到 docs/research/ 新条目）。
