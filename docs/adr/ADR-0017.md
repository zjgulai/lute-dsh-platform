# ADR-0017 · 包的类型检查必须指向内建运行时的类型，而非应用内打包产物

- 状态：accepted
- 日期：2026-09-11
- 决策者：用户（lute）+ agent（三期实测后提出）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-11-lute-refactor-three-phase.md)

## 背景

三期把「脚本能真实运行」写入门禁（`scripts-runnable`）后，实测暴露三处此前**从未运行过**的 typecheck 与四处 test 失败：

- `dsh-theme-local`、`dsh-loopx-plugin` 的 `typecheck` 脚本执行即 127——它们没有安装 `typescript`，脚本只是文本，从未真正运行。
- `dsh-deepresearch-local` 的 `typecheck` 实测退出码 2（真实类型错误）。
- `dsh-browser-local` 的 11 个测试套件全部收集失败：`src/token.ts` 依赖 `@deepseek-ai/dsh-home-paths`，而该包在 `node_modules/@deepseek-ai` 下是指向应用包目录的**相对符号链接**，包目录从 1 层移到 3 层后链接失效。

进一步实测发现定位类型检查目标时的根本障碍：**应用内打包的 `@deepseek-ai/*` 不携带类型声明**（`dsh-client-ui-theme/lib/` 只有 `client.js` 与 `index.js`，无 `lib/types/`），而 `package.json` 的 `exports` 仍声明 `types` 字段指向不存在的文件。因此即便把 `typescript` 装上，`tsc` 也只能得到 `any` 或报 `TS7016`——**无法对 DSH API 做真实类型检查**。

对照发现：内建运行时 `vendor/dsh-desktop/vendor/dsh-runtime/0.1.2-rc.1/*.tgz` **包含完整类型声明**（实测 `deepseek-ai-dsh-client-ui-theme-0.1.2-rc.1.tgz` 内含 `package/lib/types/client/*.d.ts`）。

## 决策

**包的类型检查以「内建运行时的类型」为准，不以应用内打包产物为准：**

1. 需要 DSH API 类型的包，从 `vendor/dsh-desktop/vendor/dsh-runtime/0.1.2-rc.1/*.tgz` 安装对应依赖（自包含、可复现、与交付运行时同版本），不依赖 `/Applications/DSH Desktop.app` 的路径。
2. 类型检查配置统一采用 `module: ESNext` + `moduleResolution: Bundler`——DSH 包的 `exports` 用条件 `types` 映射，`NodeNext` 会解析到无类型的 `lib/*.js`（实测：切到 Bundler 后 `TS7016` 从 10 个降到 0）。
3. **不得**用「脚本存在」冒充「类型检查可用」：`scripts-runnable` 在 `full` 模式真实运行每个包的 `typecheck` 与 `test`，脚本缺失执行体（127）或运行失败都算失败。
4. 尚未补齐的包按 ADR-0014 登记豁免（带 owner 与期限），逐包收敛。

## 备选方案

**沿用应用内打包产物的路径（`/Applications/DSH Desktop.app/...`）。** 被否决——应用包不含类型声明，且路径与机器、安装位置绑定，既不可复现也不可移植。

**为每个包手写 DSH API 的本地 `.d.ts` 声明。** 被否决——手工维护的类型副本会与上游漂移，且 20 个包各写一份等于制造 20 份事实源；类型必须来自运行时本体。

**从 npm 安装 `@deepseek-ai/*`。** 被否决——与仓库红线「只用内置 alpha SDK，不引入 npm 发布线（防双实例）」冲突。

**放弃 DSH API 的类型检查，只检查包内自有代码。** 被否决——包内代码的价值恰在于与 DSH API 的交互边界，放弃该边界等于放弃类型检查的主要收益。

## 后果

- 正面：类型检查首次具备真实语义——检查的是与交付运行时同版本的 API 契约；`dsh-browser-local` 的符号链接失效问题被顺带定位并修复（9 个套件 111 项测试恢复通过）。
- 负面/代价：每个包多一层「从内建 tgz 安装依赖」的步骤；运行时版本升级时需随 pin 一起更新。豁免清单在三期结束时从 11 条扩展到包含新发现的既有债务（`dsh-theme-local` 类型错误、`dsh-browser-local` 的 2 个测试文件引用已移除的 `@deepseek-ai/dsh-host-apiproxy`）。
- 后续动作：按豁免清单逐包补齐；`dsh-browser-local` 的两个测试文件（850 行，覆盖真实能力）需查清 rc.1 中 `createApiProxy` 的替代并迁移，不得删除。
