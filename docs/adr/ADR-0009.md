# ADR-0009 · 文档消费者与语言策略：主脊柱中文单语 + 客户链独立用户向文档

- 状态：accepted
- 日期：2026-09-11
- 决策者：用户（lute）+ agent（grill-me 决策树 Q3）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-11-lute-refactor-three-phase.md)

## 背景

上游 harness 对每篇文档强制双语配套（`.md` + `.zh.md` + `.i18n.yaml`，由 `verify-translation-pairing` 与 `check:bilingual-docs` 机器校验）。本仓库现状是四套文档体系并存（`docs/` 18 项、各插件 `docs/`、`_doc-notes/` 草稿、`doc/` HTML 站），且存在同一事实的重复副本（白屏手册两处同名同 SHA `dddfb43fd62c`）。按 ADR-0004 的交付形态，客户拿 pkg 双击安装，真正需要面向外部的一层只有安装与使用说明。

## 决策

**文档按消费者分两层，主脊柱中文单语，仅客户链出独立用户向页面：**

1. **主脊柱（内部维护者 + AI Agent 消费）**：中文单语，三层结构——根 `AGENTS.md`（每会话常驻规则）→ `docs/architecture.md`（有序地图）→ `docs/notes/`（决策记录）+ 各能力组 README（包契约）。
2. **客户链（外部消费）**：仅「安装 / 使用 / 故障排查」一条链出独立用户向页面（`packaging/INSTALL-CARD.md` 及其延伸），保持可交付给无技术背景客户。
3. **不做双语**：不引入 `.zh.md` / `.i18n.yaml` 配套与配对门禁。
4. **同一事实只有一个 home**：其余位置只留相对 Markdown 链接，由门禁校验链接可达。

## 备选方案

- **A 只服务内部**：被否决——客户交付链确实需要一页安装卡与使用说明，归入插件文档会破坏客户可读性。
- **B 全量双语**：被否决——按上游体量设计的机器校验与翻译流程，对本仓库无对应外部需求，纯增成本。
- **C 保留现状四套体系**：被否决——正是重复副本与失实表述的成因。

## 后果

- 正面：文档维护成本与真实读者匹配；去重后有明确的「改一处足够」的更新路径。
- 负面/代价：若未来出现海外协作者或英文客户，需要为对应链路补英文版本；决策记录（Note/ADR）一旦被外部引用，翻译成本由引用方承担。
- 后续动作：一期完成三层脊柱与去重（见 `.scratch/lute-refactor/spec.md`）；门禁新增「事实源去重清单」与「文档链接可达」两项校验。
