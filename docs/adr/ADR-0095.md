# ADR-0095 · 第三方 intake 以版本化 source ID inventory 和互斥终态闭合

- 状态：accepted
- 日期：2026-09-16
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/contract/2026-09-16-third-party-intake-accounting.md)
- 相关：ADR-0014（门禁硬门槛）、ADR-0052（第三方技能来源）、ADR-0094（canonical gate result）、总账 P-29

## 背景

`build-third-party-intake.mjs --check` 曾先比较生成文件并打印成功，之后才追加 accounting problems；因此
`pm` 实际被算成 `63 + 6 + 3 = 72 ≠ 69`、`mp` 被算成 `5 + 32 + 29 = 66 ≠ 37`，命令仍退出 0。
根因不是单一加法错误，而是 `alreadyInstalled` 被追加到 `skip` 后又独立计数，且校验、成功输出与写入顺序反了。

## 决策

1. 增加受版本控制的 `third-party-source-inventory.json`，逐 repo 保存 upstream source ID set 与
   `alreadyInstalled` ID set。该清单只证明本批分类集合，不冒充 commit、digest 或不可变 provenance；后者仍归
   SEC-RT-002 / DEC-009。
2. `imported`、`skipped`、`alreadyInstalled` 是三个互斥终态。`third-party-skip.json` 只保留真正 skipped；
   builder 先按 `${repo}:${sourceName}` 检出各集合内部 duplicate，再做 overlap、missing、unexpected 与逐 ID 守恒，
   不允许 `Map` / `Set` 静默吞掉重复值。
3. 所有输入结构、命令映射、分类 accounting 与现有输出漂移检查都发生在成功文案或写入之前。根 gate 以
   106 个 upstream ID 加 1 个结构/生成一致性对象记账：当前 canonical 结果为 107/107、0 skip、0 failed；
   mandatory input 缺失或 JSON 损坏 fail-closed。
4. `--check` 全路径只读。生成模式只在零问题后，把完整 JSON 写到目标同目录的独占临时文件，`fsync` 后
   `rename` 原子替换并同步目录；任何校验或写入错误都不得改变既有目标，也不得打印成功。
5. fetcher 同步识别三种终态；`alreadyInstalled` 不再借占位 `dir` 混入 `skip`。上游同 repo 出现重复末级
   source name 时直接失败，因为 name 不再能作为唯一 ID。

## 备选方案

- 只把 accounting 段移到成功输出之前：仍保留重叠终态与重复计数，否决。
- 继续把 already-installed 当一种 skip reason：无法证明三个业务终态互斥，且会再次重复加总，否决。
- 只比较总数：删一项再补一个未知项可维持数量不变，否决；采用逐 ID 双向差集。
- 每次从 mutable `HEAD` 自动更新 inventory：会把未经评审的上游变化自动吸收，并误称 provenance，否决。
- 直接覆写目标后再校验：失败会留下半更新或错误清单，否决；采用同目录临时文件 + rename。

## 后果

- 当前分类变为 `pm 69 = 63 imported + 3 skipped + 3 alreadyInstalled`、
  `mp 37 = 5 + 3 + 29`；每个 source ID 恰好一个终态。
- 清单变化必须同时说明 upstream ID、终态和理由；同总数替换、重复、重叠、漏项与未知项都返回非零。
- 原子替换只覆盖本卡的正常生成路径；单 case fixture 隔离由 QG-006A 收口，聚合并发、SIGTERM 与跨 checker 零副作用仍由 QG-006B 收口。
- 本卡没有联网取件、没有安装技能、没有改 `~/.dsh`，也没有把 mutable GitHub HEAD 提升为受信来源。
