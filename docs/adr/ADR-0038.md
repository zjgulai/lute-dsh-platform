# ADR-0038 · 共享来源栅栏的判据必须是「拒绝」，不是「抛异常」；配对服务查询一律尽力而为

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（要求「以真实 curl 负向探针验收」）+ agent（M2 实况探针压出）
- 决策记录：[Note](../notes/implemented/contract/2026-09-12-shared-fence-deny-not-throw.md)

## 背景

`shared/host/pair-access.ts` 是三张「面向宿主路由的插件」共用的来源栅栏（`dsh-role-matrix-local`、
`dsh-newapp-local`、`dsh-skill-center-local`）。它的第二条放行路径是「已配对设备」：读
`ctx.get('remoteWebUiPairing', false)`，读不到就退回**属性读** `ctx.remoteWebUiPairing`。

cordis 对「未 inject 的服务」的属性读**是抛异常的**（`cannot get property "…" without inject`，
`@deepseek-ai/cordis` lib/index.js 的 ReflectService 代理陷阱）。本包**故意不 inject** 这个服务
——它的存在意义就是「没有 remote-web-ui 也能用」——于是**每一个非回环请求**都会在栅栏里抛：

```
isPairedOrLoopbackAllowed → ctx.remoteWebUiPairing → throw
→ 路由 handler 抛 → dsh-host-webserver 捕获 → 400（空 body）+ 每条请求一条错误日志
```

**实况读数（2026-09-12，运行中的实例）**：

| 路由 | 栅栏实现 | `Sec-Fetch-Site: cross-site` |
| --- | --- | --- |
| `/api/dsh-role-matrix/list` | 本共享栅栏 | **400**（异常被兜住） |
| `/api/dsh-newapp/health` | 本共享栅栏 | **400** |
| `/api/dsh-skill-explorer/health`（npm 第三方包） | 各自实现（同形） | **400** |
| `/api/worktable/health` | 独立的补丁栅栏 | **403** ✓ |
| `/api/nope-xyz-123`（不存在） | 平台 `/api` 前缀栅栏 | **403** ✓ |

拒绝本身**成立**（400 ≠ 200），这正是它活了这么久没被发现的原因；**不成立的是「判决出自栅栏」**：
`403 forbidden: loopback-only` 这条分支在生产里**不可达**，被拒的响应体是空的、无法区分于畸形请求，
且任何「捕获后继续」的上层实现都会把它变成真正的绕过。

单测没拦住它，因为三处栅栏测试用的都是**普通对象**替身（`paired['remoteWebUiPairing'] = …`）——
那是**真实 cordis 上下文永远不会有的形状**。只有真起 HTTP 服务、用真 curl 发请求，才会走到
代理陷阱那一条路径。

## 决策

1. **栅栏的失败态是「拒绝」，不是「抛」**：配对服务查询一律包在保护里；读不到、读抛异常、
   `isPairedDevice` 自身抛异常，三种都收敛为 `false`（= 回环以外一律不许进）。
2. **两条查找路径都保留且都加保护**：`ctx.get(name, false)`（普通替身与显式注册）与属性读
   （cordis 代理）。前者优先，后者兜底。
3. **栅栏契约的验收必须包含「真 cordis 上下文 + 真 HTTP 事务」**：合成 req 对象与普通对象
   ctx 只能证明纯函数的分支，证明不了「判决会不会在到达 handler 之前抛掉」。
4. 形状相同的**第三方包**（`@linxin666/dsh-client-ui-skill-explorer` 一类的 npm 包）不在本仓库内，
   不修；但读数记在 Note 里，供上游或替换决策使用。

## 备选方案

- **给插件加 `inject: ['remoteWebUiPairing']`**：否决。会把「没有 remote-web-ui 也能装」这条
  能力变成硬依赖（cordis 的 inject 会等待服务，服务永不出现则整行不进 fiber），
  代价远大于收益。
- **只在路由层包 try/catch**：否决。栅栏有 3 个消费方、共 9 条路由；在每个 handler 里包是
  把同一个判决复制 N 份，而正确的家只有一处（ADR-0009）。修在共享层，一处生效三处。
- **保留 400 不动，因为它同样拒绝**：否决。「意外拒绝」与「判决拒绝」的差别是：
  前者依赖上层的 catch 语义，后者是栅栏自己的语义。安全组件的正确性不能建立在
  别人的异常处理策略上。
- **顺手改第三方包**：否决。npm-pinned 包不在本仓库（ADR-0010/0012），改它违归属契约。

## 后果

**正面**：三张插件的 9 条路由恢复「403 + 可读原因」；被拒请求不再产生错误日志；
栅栏契约第一次被真实 HTTP 事务证伪过（`pnpm run accept:newapp-products` 阶段 B 六条）。

**负面/代价**：多了一层 try/catch（判据本体没变复杂）；`findPairing` 会做两次查找，
在「服务确实已注册」的路径上有一次多余读（代价可忽略，且它换来的是「代理形状与普通对象形状都工作」）。

**后续动作**：任何新增「可选服务」的共享判据都适用本条——**可选 = 读不到就按最保守的结论走，
且读不到这件事本身不许是异常**。同形的第三方包读数留在 Note 里。
