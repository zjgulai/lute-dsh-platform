## 背景

ADR-0048 收尾时留了下一入口：**「带编号的旧富代码代（41 个目录、中位 373 行）没有任何卡在引用
——它可能是唯一还活着的真实现」**。本轮按这个入口动手，写了一条命令给全部证据的取证脚本
（`.scratch/p2s-two-trees/dossier.py`，九项检查），结果**入口里两个前提都不成立，
而第三个——真正的那个——比入口假设的大一圈**。

### 一、「没有任何卡在引用」是假的

上一轮写过「卡的 `code_path` **838/838 全指向**后者（无编号脚手架代）」。穷举一遍：

| 落点 | 张数 |
| --- | ---: |
| 指向**编号树** | **18** |
| 指向无编号树 | 820 |
| 无 `code_path` | 500 |

**18 条反例**。全称断言又一次是假的，而且是同一类错：把「绝大多数」写成「全部」，
没做穷举。这条写进 ADR 是为了下次不再犯——**凡「全 X 都 Y」的句子，必须先跑一次计数。**

### 二、编号树与无编号树不是「两代同批技能」

按技能目录名求交集，两棵树**只重叠 1 个**（`category_compliance_prescan`）：

| | 顶层目录 | 技能目录 |
| --- | ---: | ---: |
| 编号树（`01-因果推断/` … `23-运营财务/`） | 17 | **41** |
| 无编号树（`supply_chain/` … `mas/`） | 23 | 1,012 |

上一轮那个「41 个目录、中位 373 行」的数**是对的**，但它描述的是一个混合总体——
41 个目录干净地裂成两半，零例外：

| 分组 | 张数 | 带年份后缀（`_2024`/`_2025`…） | 行数中位 |
| --- | ---: | ---: | ---: |
| **有**同名卡 | 19 | **0** | 181 |
| **无**同名卡 | 22 | **22** | 597 |

所以编号树里其实是两类东西：19 个「按技能名抽的实现」与 22 个「按论文抽的试点」。
它们的 `model.py` 抬头都写着 `Auto-extracted from: paper2skills-vault/<域>/<卡 id>.md`
——**是 vault 的下游，不是上游**。方向与入口的假设相反。

### 三、真正的发现：完整实现一直在，只是没人看 git 历史

上一轮 ADR-0048 写下「**预览是这份代码唯一存世的地方**」。这一轮的第一件事就是核它，
**它也是假的**，而且错因很具体：

**iCloud 工作区的 vault 已经不是文本了。** `paper2skills-vault/` 下 1,545 个 `.md` 里，
**1,353 个是二进制容器**（32 字节头 `88 7d 1c …` + 到第 1024 字节的零填充 + 高熵正文，
正文熵 6.9 bits/byte），只有 192 个还是真文本。改写时间落在 2026-07 之后最早那次提交之后
（`mtime` 被保留成原值，所以只看时间戳会误判）。`brctl` 对该路径报
`Client zone not found`，也不是未下载占位符。

**但同一个仓库的 git 历史里，全部 1,338 张卡都是明文。** HEAD 是
`4a4fa0d4`（2026-07-17，提交信息「… → 1338 Skills / 14901边」），按域名解析
`vault/<src_domain>/<card id>.md`：**1,338/1,338 全部定位到，1,272 张有代码段。**

连通性也是可证的一条：**卡面那 60 行节选就是 vault 代码的开头** ——
以节选为 oracle 去选围栏，**1,262 张命中且偏移恒为第 1 行，零例外**。

### 四、恢复出来的东西是可用的

| | 卡面节选 | vault 完整代码 |
| --- | ---: | ---: |
| 可 `ast.parse` | 808 / 1,258 | **1,248 / 1,258（99.2%）** |

**443 张是「节选被截断而失败、完整代码却能解析」**——ADR-0048 报的「457 张不能直接运行」
正是这一批，而它们可修。

两个体量口径必须分开说，别混：**实际恢复并落盘的 1,302 张合计 253,648 行**；
上表那个「可解析」比较的是**两端都有的 1,258 张**（卡面有节选且 vault 有 ③ 段代码）；
另有 1,281 张「vault ③ 段里有代码」合计 252,823 行——它含那 21 张节选对不上、最终未采用的卡。

## 决策

### 1. 恢复管线读 git 历史，不读工作区

新增 `scripts/build-source-code.py`：一律经 `git cat-file` 取 `$P2S_VAULT_GIT`（默认 iCloud
仓库）在 `$P2S_VAULT_REV`（默认 HEAD）的明文。**读到二进制容器就响亮失败**
（`looks_like_container()`），不静默产出一堆乱码。

选取口径不用启发式：**以卡面节选为 oracle** —— 逐个围栏做「节选是否为该围栏的连续行前缀」
判定，命中即取。这是自校验，不是猜。

**两条判据要分清**（本轮自证时真撞过一次）：只看 `## ③` 段内的最大围栏 → **1,252** 张命中；
扫整张卡的所有围栏 → **1,262** 张。差 10 张，两条都对，只是问的问题不同。
管线用后者（宽判据），因为要恢复的是「卡里那份代码」，而不是「⑧ 段那个容器里的代码」。
两个数在本 ADR 里各归各位，不可互换。

### 2. 三档如实分层，不把没有校验的混进有校验的

| 档 | 张数 | 含义 |
| --- | ---: | --- |
| `oracle` | **1,262** | 卡面节选已校验为完整代码的开头（`prefix@1`） |
| `unverified` | 40 | 卡面无节选，无 oracle 可校验，取的是最长围栏 |
| `unrecovered` | 36 | 15 张 vault 里压根没围栏；21 张节选与 vault 代码对不上 |

`unverified` 必须在卡面与安装校验两处都写明「**未经交叉核对**」，不许混进确证集。

那 21 张对不上的是**真实的代际差异**，不是抽取 bug：例如
`Skill-Compliance-Scored-Guardrail-Orchestration` 的卡面节选是一句
`from paper2skills_code.compliance.… import (`（「引用模块」式的另一代写法），
vault 里则是 44 行的实现。**源站那一代卡与 vault 那一代不是同一批产物。**

### 3. 完整实现落 `references/implementation.py`，不内联进 SKILL.md

总量 252,823 行 ≈ 7.7 MB ≈ **2.0M tokens**，而 SKILL.md 有 12KB 硬上限——内联不可行。
好在包内**本来就有这个形态**（长节选落 `references/code.md`），且安装器会递归拷
`references/`，因此装配器落盘即等于装进技能库，**安装器零改动**。

文件形状刻意与语料编号树 `model.py` 一致：**5 行 `#` 溯源抬头 + 正文**（正文首行 = 第 6 行）。
用 `#` 注释而非 docstring，是为了不占「第一条语句」的位置（原作若以
`from __future__ import …` 起头也不受影响）。

有了它之后 `references/code.md` 被取代：那 17 张原本要落 `code.md` 的卡现在都落
`implementation.py`（实测 `code.md` 计数归零）。

### 4. 出口脱敏抽成 `lib/secret-scrub.js`，两条写盘路径共用

实测差距是真的：**卡页八段里只有 1 张卡带真实 API Key，而 vault 的完整代码里有 3 张**
（`Skill-FActScore-Claim-Verification-Pipeline`、`Skill-RankGPT-Listwise-Reranking`、
`Skill-iText2KG-Schema-Free-KG-Induction`，同一个 key）。原先把模式表内联在装配器里，
恢复出来的第二条路径就会把 key 写进技能库。抽成模块后两处共用，并补了 12 条单测
（原先零测试）。

### 5. 订正 ADR-0048 的两条全称断言

- 「838/838 全指向无编号树」→ **18 张指向编号树**。
- 「预览是这份代码唯一存世的地方」→ **完整实现在 vault 的 git 明文里，1,302 张可恢复**。

卡面口径随之改写：⑦ 段不再说「完整实现不在本包内」，而是
「**本节的完整实现在同目录的 `references/implementation.py`（N 行）**，下面 60 行是它的开头」；
且**截断的是节选、不是那份实现**，两者必须分开说。`verify-install.mjs` 同时断言
「索引说有实现却没有文件」与「⑦ 段退回旧说法」两种情况都报错。

## 备选方案

- **只写诊断、不落地恢复**：完整实现虽已找到却没进技能库，等于把一个可修的缺陷留在原地。
  否决。
- **把完整代码内联进 SKILL.md**：2.0M tokens、且 12KB 上限是硬约束。否决。
- **用一个新目录装代码**（如 `code/`）：`references/` 是包内既有形态且安装器已递归拷贝，
  新造一个目录要多改安装器与校验器。否决。
- **放宽 ③ 段标题判据来抽取**（把 `## ③ 代码模板` 放宽到「标题含『代码模板』」）：
  试过，反而更差——段边界用 `^#{1,N}` 判定时，**Python 注释 `# 说明` 会被当成标题**，
  段体被截断，命中数从 1,262 掉到 1,246。oracle 判据没有这个问题。否决。
- **按 basename 解析 vault 卡**：vault 里 119 张卡在不同域下有同名副本（其中 18 张在
  `<域>/00-知识库-Skill卡片/` 下是旧副本），按 basename 取会静默拿到旧副本——
  实测把 16 张**本有代码**的卡判成「无代码段」。改为优先取**域根**那一份后，
  1,338/1,338 全部落到域根、歧义清零。否决按 basename。

## 后果

**正面**

- 443 张「节选不能解析」的卡，其完整实现现在装进了技能库且可 `ast.parse`。
- 40 张「卡页压根没发布代码」的卡，现在有了实现（标 `unverified`）。
- 脱敏从「1 条路径、零测试」变成「1 个模块、两条路径共用、12 条单测」，并挡住了 2 个
  原本会漏进技能库的 key。
- 卡面不再对读者说「完整实现不在本包内」——那句话已被证伪。

**代价与边界**

- 新增对 `$P2S_VAULT_GIT` 的**构建期**依赖（iCloud 上的语料仓库）。仓库不在时
  `build-source-code.py` 响亮失败；但装配器**不阻断**——索引 `data/code-recovery.json`
  入库，正文 `generated/source-code.json` 是派生物，缺正文只少装 `implementation.py`，
  且会在 `assemble-report.json` 的 `problems` 里报出。
- **vault 工作区已被改写为二进制容器这件事必须记住**：任何直接读
  `paper2skills-vault/**.md` 的脚本（含未来新写的）都会拿到乱码。恢复路径只有 git 历史。
- 36 张仍未恢复。其中 21 张是源站卡与 vault 卡的真实代际差异，**不是本包能修的**——
  要修得回到生成那一代卡的上游。
- `generated/source-code.json`（7.7 MB，含未脱敏原文）**不得入库**；出口只有一个
  （`lib/secret-scrub.js`）。

**后续动作**

- 编号树那 22 个「按论文抽的试点」（中位 597 行）至今没有任何卡在引用，
  与这 1,338 张卡是什么关系仍未查清——但它们不是实现来源（vault 才是），优先级降低。
- `paper_to_skills` 仓库顶层有明文 RSA 私钥 `DDDD.pem`（**未入 git**，实测 `git ls-files` 为 0）。
  与本包无关，但既然看到了就记一笔。
- **`.scratch/**` 在根 `.gitignore` 里是白名单**（`!.scratch/**`），所以取证脚本与快照
  会被 `git add -A` 带走。本轮就踩到：自证脚本里曾写死那个真实 API Key，
  另有更早两个 scratch 快照（`.scratch/p2s-optimize/cards.before.json`、
  `.scratch/paper2skills-preset-skills/data/cards.json`）各含 3 处。
  三处均已就地脱敏；`git log -S` 确认该 key **从未进过本仓库历史**。
  取证脚本今后一律现取样本，不写死凭证。
