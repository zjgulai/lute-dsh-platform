# ADR-0072 · 岗位白名单是授予，不能被技能文件的开关否决；产物用生成期判据钉住这个不变量

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：用户（「有些卡片无法被打开」的反馈 + 本轮对「先定语义再落机制」的批复）+ agent（本次取证、判定与落地）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-13-preset-skill-grant-semantics.md)
- 相关：ADR-0031（全库 `disable-model-invocation: "true"` 与「可见性只经白名单开放」）、ADR-0070（同一场诊断的真值归属与词表；本条是它的效果层另一半）、ADR-0014（门禁是硬门槛）、ADR-0061（本机使用外部产品走 profile 本地装配）

## 背景

`dsh-skill-subset` 的正向注册是
`modelInvocable = respectFileFlags ? !parsed.disableModel : true`，50 个 `agt-*` 岗位预设生成时
写的是 `respectFileFlags: true`（I3 立项，目的为「设置页开关在 preset 会话内同样生效」）。
而 ADR-0031 让语料 1338 张卡**一律**写 `disable-model-invocation: "true"`（全局模型目录体积）。

两者相乘：**白名单被它自己挂载的卡否决**。实测改前 50 个岗位的 439 个白名单位里
**275 个（62.6%）是不可被模型调用的**，**没有任何一个岗位全部生效**；agt-001 的 8 个里 6 个失效。
注册过程不报错、不写日志、界面两边都正常——仪器全绿而能力已死。

这两句话在语料全库 model-off 的前提下不可能同时成立：ADR-0031 要「岗位装配是唯一授予通道」，
I3 要让「用户级开关在岗位会话里有最终决定权」。必须选一个。

## 决策

1. **产物选「授予」**：生成的 `agt-*` 预设改用 `respectFileFlags: false`。
   岗位装配由岗位自己负责；设置页开关管的是**岗位之外**的会话。该值由生成器里唯一的常量
   `SUBSET_RESPECTS_FILE_FLAGS` 决定，它同时决定渲染进 preset 的值与判据算法——
   改它不会得到静默失效，而是立刻得到一次红灯。
2. **加一条生成期「白名单生效性」判据**：逐张核对白名单技能在产物语义下是否真的可被模型自动调用，
   有死位即 `exit 1`，并打印两条出路（改语义，或打开这些卡的文件开关）。它与既有的
   「悬空引用」判据并列：悬空 = 名字指向不存在的技能；死位 = 技能存在、注册成功、永不被挑中。
3. **判据管不变量，不管旗标值**：手写的 `bobo-cto` 预设名单几乎全是文件已开的手写技能，
   `respectFileFlags: true` 在那里既生效又有意义，因此**不动它**。要守的命题是
   「每个预设必须交付它声明的卡」，而不是「旗标必须为某个值」。
4. **语义变了，界面的话必须跟着变**：算法技能页对「本岗装配但文件为关」的卡，
   不得再说「模型不会自动调用」，而要说清范围（本岗会话照常自动调用；开关管岗位之外）。

## 备选方案

- **打开那 275 张卡的文件开关。** 被否为主路径：要改用户语料（本轮全程未碰）；会让这些卡进入
  每一个会话的模型目录，正是 ADR-0031 要避免的；且它是不可逆的数据改动，而生成器一行可逆。
  作为判据允许的第二条出路保留。
- **连 `bobo-cto` 一起改成 `false`。** 被否：那里 I3 无害且有用，改它没有证据支撑——
  为整齐而削弱一个用户级开关的实际效力。
- **只加判据不改语义。** 不可能：门禁是硬门槛（ADR-0014），常驻红灯等于把已决策的事故挂成故障。
- **改插件的默认值。** 被否：`dsh-skill-subset` 是跨产物共享的契约，本轮的产品取舍不属于它。

## 后果

- **正面**：439 个白名单位不再有因文件开关而死的（275 → 0）；判据可证伪（把常量翻回 `true`
  实测打印死位清单并 `exit 1`）；页面口径与产物语义一致。
- **负面 / 边界**：**设置页开关在岗位会话里不再有最终决定权**——用户关掉某张卡，挂载它的岗位
  会话仍会自动调用它。这是本条明确买下的代价，页面上必须说清。
  `bobo-cto` 有 7 条白名单指向不在 `~/.dsh/skills` 的技能（重注册时 ENOENT 告警，但因在白名单里
  而未被 `hideOthers` 遮蔽，今天无害），属于待清的账。
- **后续动作**：若要重开 I3（设置页开关在岗位会话内也生效），**必须同时**处置那 439 个白名单位的
  数据——判据会强制两件事一起做。
