# ADR-0003 · 版本策略：单平台版本 vX.Y.Z + 插件 package.json 对齐

- 状态：accepted（原文未入库，本篇为证据重建）
- 日期：2026-09-06
- 决策者：用户（lute）
- 原文：从未提交到仓库；本篇依据 `README.md`「版本与发布」节、`packaging/CHANGELOG.md` 与 `docs/release-process.md` 重建。

## 背景

平台由 20 个独立插件 + 打包流水线组成，各插件有自己的 package.json 版本。客户需要唯一可识别的交付版本，而插件间需要能独立演进。

## 决策

**平台侧使用单一版本号 `vX.Y.Z`（git tag = 打包版本），各插件 package.json 与之对齐**；CHANGELOG 双轨汇总（根 `CHANGELOG.md` + `packaging/CHANGELOG.md`），BUILD 号标识每次打包以防同名多代混淆。

## 备选方案

- 每个插件独立语义版本、平台版本另行推导：被否决——客户无法从下载文件名判断包含哪些能力。
- 完全统一（所有插件共用平台版本）：被否决——会抹掉各插件自身的演进历史。

## 后果

- 正面：交付版本单一可读；插件保留自身历史。
- 负面/代价：需要一处机制保证「对齐」不是口头承诺。实测该承诺已漂移（20 个插件实测 15 个不同版本值），该缺口由 ADR-0012 的身份元数据与 ADR-0014 的门禁正式接管。
