# ADR-0023 · 删除被会话引用的 preset：默认值先迁移、归档先验字节、损失需显式接受

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（lute）——**在拿到完整影响面数字后明确选择接受损失**
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-preset-cleanup.md)

## 背景

用户要求：只保留 50 个新岗位 preset 与系统自带 4 个，**其余卸载删除干净**。

清理前用户预设根共 56 项：50 个 `agt-*` + 6 个历史遗留 preset
（`ai-product-developer`、`brand-marketing-growth`、`dsh-motion-deck-studio`、
`llm-wiki-fullstack`、`overseas-finance`、`product-video-director`）+ `.DS_Store`。

两条**必须先处理的连带影响**，任一条漏掉都会造成不可逆后果：

1. **`~/.dsh/settings.yaml` 的 `agent-presets.default` 指向 `ai-product-developer`**，
   正是待删项之一。源码语义（`dsh-agent-presets` 的 `defaultId`）：
   *"The preset id mounted when a caller names none. **Missing at mount time fails loud.**"*
   —— 不迁移默认值就删，任何「不指定 preset」的建会话路径都会失败。
2. **32 个既有会话的创建事实里写着这 6 个 preset id。** 首条记录
   `{"type":"session",…,"agentPreset":"<id>"}` 是 deep-frozen 的；恢复时
   `composeAgent(presetId)` → `resolve(id)` 抛 `agent-preset/not-found`，**没有回退**。
   删除等于让这 32 个会话永久打不开。

（本项目 2026-09-11 已经踩过一次同一坑：删掉 15 个 preset 后，28 个会话 resume 失败。
本次是在有预检工具的情况下第二次面对它。）

## 决策

**被会话引用的 preset 可以删，但必须走三道路径，且损失必须由用户在看到数字后显式接受。**

1. **默认值先迁移，后删除。** 顺序不可颠倒：中间态若存在，任何不指定 preset 的建会话都会 fail loud。
   本次改为 `cordis`（系统自带、`order: 4`、常驻可用）。
2. **归档先验字节。** 删除前逐目录 `diff -r` 比对归档件，6/6 必须逐字节一致才允许继续。
3. **引用面预检即门禁。** `scripts/role-presets/scan-session-refs.mjs --would-remove <ids>`
   命中即退出码 1。本次它**确实拦住了**，用户在看到 32 会话 / 539,683 条记录 / 1,281 条用户消息
   之后，明确选择「删，接受会话损失」——这条决策因此是有据的，不是默认通过。
4. **该门禁不进 `pnpm run gate`。** gate 校验的是仓库产物；会话引用面是**部署态**事实，
   随本机会话历史变化，把它塞进仓库门禁会让 gate 因与本仓库无关的状态而红。
   它是**删除操作前的操作纪律**，不是提交门禁。
5. **影响面必须实测，不能推断。** 见「后果」中对「34 个无 preset 会话」的纠正。

## 备选方案

**保留这 6 个 preset（只在选择器里多 6 项）。** 用户已获知该选项及其代价，选择不保留。

**只保留被引用的那几个。** 无效——6 个全部被引用，等价于「不保留」。

**直接删，不跑预检。** 被否决——那正是 2026-09-11 那次事故的做法。

**把 `--would-remove` 接进 `pnpm run gate`。** 被否决，理由见决策 4。

## 后果

- **正面**：用户预设根从 56 项收敛为 **50 项，全部 `agt-*`，`001–050` 连续无缺，无隐藏项**；
  `.DS_Store` 一并清除；可用 preset 合计 54（50 用户 + 4 系统）。
  删除前归档 6/6 逐字节一致，随时可用 `restore-presets.mjs` 拿回。
- **负面（已显式接受）**：**32 个会话永久无法恢复续聊**（17 + 7 + 5 + 1 + 1 + 1），
  数据仍在磁盘上、内容不丢，只是 resume 会抛 `agent-preset/not-found`。
  扫描器现在会把这 32 个标为 `✗ 失效引用`。
- **纠正了一个我先前给出的错误论断**：我此前说「34 个无 `agentPreset` 的会话会用默认 preset」。
  实测（逐会话解首帧读 `origin`）：**34/34 全部是 `origin: "subagent"`**——
  subagent 走父方 `composeFrom` 组合，**根本不读 `agent-presets.default`**。
  因此默认值迁移的真实影响面是「未来不指定 preset 的建会话」，
  而不是那 34 个会话；现存 271 个会话中**没有任何一个**会解析默认值。
  这个错误论断源自我自己写的扫描器把它标成了「用默认」——**工具的错误措辞变成了我的错误事实**。
  已修正：`session-refs.mjs` 采集 `origin`，扫描器如实报告
  `无 agentPreset 34（subagent 34）`。
- **仍未验证**：`cordis` 作为默认值在**新建不指定 preset 的会话**这条真实路径上未被端到端跑过；
  仅验证了它存在于 shipped 根、可被 roster 解析（`user=50 shipped=4 可用合计 54`）。
