# ADR-0022 · 岗位头像走官方 `icon` 字段，图标库是唯一事实之家

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（lute）+ agent（**在纠正自身错误结论之后**提出）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-preset-avatar-contract.md)

## 背景

50 个岗位 preset 建好之后，卡片没有头像。用户要求「给 50 个 Preset 岗位卡片加上头像，
和之前的 Preset 的卡片头像保持一致性」。

调研阶段我得出过一个**错误结论**：「官方 UI 对 `icon` 字段零消费，写进 `preset.yml` 就是死数据」。
依据是一次 grep——用的是 `.\{45\}icon.\{45\}`，**要求两侧各 45 个字符**。真实渲染点长这样：

```js
row.icon ? jsx("img", { className: "bC90nG_cardAvatar", src: row.icon, alt: "" }) : null
```

`icon` 后面只有 37 个字符就换行了，**匹配不到，被静默丢弃**。于是我把「grep 没找到」
当成了「官方的行为」。这个错误结论被写进了**三个地方**：`generate.mjs` 的文件头注释、
`generate.mjs` 里 `icon: null` 的行内注释、`collect.ts` 的模块注释——并且据此向用户
推荐了「只写 manifest.json，不写 preset.yml」。

用户的原始要求恰恰是「和之前的 Preset 保持一致」，而旧 preset 的头像**一直是显示着的**。
若按那个错误推荐执行，才会真的造出死数据——正好是我声称要避免的东西。

读源码后，三层链路全部确认：

| 层 | 位置 | 行为 |
| --- | --- | --- |
| 解析 | `dsh-agent-presets/lib/index.js` `readPresetMetadata()` | `...record.icon === void 0 ? {} : { icon: record.icon }` |
| 传输 | 同文件 `remoteExportList()` | `...preset.icon === void 0 ? {} : { icon: preset.icon }` |
| 渲染 | `dsh-client-ui-agent-preset/lib/client.js` | `row.icon ? jsx("img", { className: "bC90nG_cardAvatar", src: row.icon })` |

且 `bC90nG_cardAvatar` 的样式是为这套图标量身定制的：
`width:52px;height:52px;border-radius:12px` 加品牌绿 `#58B848` 描边环与辉光——
与 `lute-brand-icons` 生成的绿色方形徽章严丝合缝。

（附带纠正：`dsh-agent-presets/lib/types/metadata.js` 是一份**陈旧的声明副本**，
其中 `readPresetMetadata` 确实没有 icon；运行时走的是 `lib/index.js` 的 bundle 版。

## 决策

**`preset.yml` 的 `icon` 是官方显式消费的显示字段，岗位头像写在这里；图标库是这条事实的唯一之家。**

1. **两处都写，但只有一个源。** `preset.yml` 的 `icon` 与 `manifest.json` 的 `icon` 由生成器写入
   **同一个字符串**。官方预设卡片读前者，自建矩阵面板也读前者（不读侧车），
   因此「官方卡片」与「矩阵卡片」在结构上不可能显示不同的脸。
2. **图标 id 就是 preset id。** `lute-brand-icons` 的 catalog 条目直接用 `agt-001..agt-050`，
   所以岗位 ↔ 头像**不需要第二张映射表**——图标库自己就是映射（ADR-0009）。
3. **缺头像即失败，不静默降级。** 生成器查不到图标就抛错并指路 `build.js`；
   静默写 `null` 正是「50 张卡片没头像」这个缺陷本身。
4. **头像纳入机器契约。** `verify-lossless.mjs` 增加 L10：`preset.yml` 必须有 `icon`、
   必须是内联 SVG data URI、必须与图标库及 `manifest.json` 三者同一字符串、且 50 枚互不重样。
5. **分层纠正。** `lute-brand-icons/scripts/build.js` 里硬编码的 `LIVE_MAP`（直接改
   `~/.dsh/.agent-presets`）被移除：图标库只负责「图标库」这一件事，不该反向依赖 DSH 部署布局，
   也不该在 preset 改名/删除后静默 no-op。

新增的 50 枚头像**只用 `generator.js` 既有词汇**（20 发型 / 7 配饰 / 10 衣领 / 46 胸口徽章）
组合而成，没有新增一行绘图代码；同一责任域内徽章互不重复。

## 备选方案

**只写 `manifest.json`（我最初的错误推荐）。** 被否决——官方卡片不会显示任何头像，
与用户「和之前的 Preset 保持一致」的原意正好相反。

**只写 `preset.yml`。** 未采纳——侧车不写并不会让官方卡片出问题，
但会让两个消费方各自持有一份可能漂移的真相，而 L10 的「三处同一字符串」断言正是为了钉死这点。

**50 枚全部新画（新增绘图代码）。** 未采纳——既有词汇的组合空间（发型×肤色×配饰×衣领×徽章）
足以让 50 个岗位在同一家族风格下清晰可辨，新画只会引入风格漂移风险。

**沿用旧 6 个 preset 的图标复用策略（一个图标配多个 preset）。** 未采纳——
旧库只有约 48 个语义角色图标而岗位有 50 个，且 3 个财务岗、2 个服务岗会撞在一起；
「一人一脸」在 50 个岗位的矩阵里是可辨识性的下限。

## 后果

- **正面**：50/50 preset 的 `preset.yml` 与 `manifest.json` 都带 `icon`，与图标库逐字符一致，
  50 枚互不重样；`verify-lossless.mjs` **4060 条断言全绿**（L10 贡献 151 条），
  L10 经变异测试证明会咬（抽掉 icon 行 → 2 条红；换成别人的头像 → 1 条红；复原 → 全绿）。
  图标库 184 → 234 枚，双主题总览已重建。
- **同时修掉的真实缺陷**：矩阵面板标题写「四平面 × **八**责任域」，统计行却显示
  「**12** 个责任域」——`totals.domains` 数的是（平面×责任域）树节点，
  而经营与组织/财务与合规/数据与AI运行三个域合法地跨平面出现。
  已改为数**材料定义的去重责任域**（8），树节点仍为 12，两者各自说实话；补了回归测试。
- **代价**：每个 `preset.yml` 从 3 行变成 4 行，单文件增大约 3.8 KB（内联 SVG 的 base64）。
  50 个合计约 190 KB——可接受，且这正是官方卡片渲染头像所需的形态。
- **仍未验证**：面板头像的**视觉**验收。浏览器桥本次不可用，此项留给真人看一眼。
  官方预设卡片的头像在**不重启**的情况下就应生效（`list()` 不做记忆化，每次从磁盘读），
  但矩阵面板读的是插件 host 侧的 `collect.ts`，**需要重启 DSH 才生效**。
- **教训（已写入 Note）**：**grep 的输出格式本身会制造假结论。**
  带上下文宽度的模式（`.\{N\}…`）会静默漏掉短匹配，而「没匹配到」与「不存在」在输出上无法区分。
  本次的补救是：凡是要据以下结论的检索，必须用能区分二者的方式复核（读源码 / 数总数 / 看行号连续性）。
