# ADR-0104 · Codex Desktop 视觉语法的默认主题与渐进式页面迁移

- 状态：accepted
- 日期：2026-09-17
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-17-codex-default-visual-system.md)
- 相关：ADR-0019（官方 UI 锚）、ADR-0098（Settings Shell 作用域）、P-25、PROD-UX-001

## 背景

当前项目各页面的颜色、卡片、间距、抽屉和设置体验缺少统一语法，呈现出旧后台感、卡片过多、层级混乱、
信息密度不一致和业务色廉价等问题。用户希望借用当前 Codex Desktop 的商业感、层次感和空间结构，
但明确保留 LUTE/DSH 的品牌标识、产品名称、业务语义与业务色。

项目又不是单一 SPA：多个 surface 通过独立 package 和 slot 注入运行，Settings Shell、主题包和页面包的
边界已经存在。一次性重写信息架构或新建第二套设计系统，会把视觉迁移变成路由、数据和运行时的高风险改造。

## 决策

1. 第一阶段只统一视觉调性，不改变业务信息架构、入口语义、数据契约、路由、slot、权限或 vendor 基座。
   目标视觉语法为「基础画布 → 内容面板 → 顶层抽屉/弹层」三层结构；装饰性卡片移除，只有承载语义、
   状态或操作边界的内容才使用卡片。
2. 默认体验采用系统跟随，并同时支持浅色、深色和跟随系统。默认调色板由 `dsh-theme-local` 的语义 token
   单一持有：浅色以 `#F6F7F4` 画布、`#FFFFFF` 内容面板、`#F1F4EF` 侧栏、`#1E221F` 前景和可访问的
   LUTE 绿色 `#347A2F` 为基线；深色以 `#171A17` 画布、`#202420` 内容面板、`#191C1A` 侧栏、
   `#F1F4F0` 前景和 `#58B848` 强调色为基线。业务色只用于强调、选中、主操作和状态，不铺满大面积背景。
3. 字体使用系统无衬线字体，代码和元数据使用等宽字体；建立四级信息层级、中高工作密度、统一间距/圆角/
   控件/边界/动效规则，并为 `prefers-reduced-motion` 提供静态降级。页面只能消费已有语义 token，不能为
   单页重新发明颜色或另起 token owner。
4. `dsh-theme-local` 负责 token、主题设置和默认预设；`dsh-ui-polish-local` 保持现有受限的壳层校准职责，
   不扩张成新的 design-system runtime；各 surface package 只负责组合页面结构和消费 token。
5. Settings 作为第一份规范样本：固定分组导航 + 单滚动内容区、标题/说明、扁平表单行、统一右侧抽屉和
   明确的危险区。当前工作树中已有的 Settings Shell 变更作为基线保留，后续视觉校准只能在其 parser-owned
   marker 和独立 AX 契约之内进行，不覆盖、回退或绕过它。
6. 页面迁移按风险和复用价值分批：先完成 token/双主题/默认风格与 Settings，再迁移抽屉和 Composer/空会话，
   然后迁移 Team Hub、Role Matrix、Skill Center、Run Center、Task Board、My Quotes、Theme Studio 等页面。
   每批都用自动化检查、固定状态截图和人工视觉评审闭环；没有 live GUI 证据时只能标记为
   `instrument verified, live unverified`。

## 备选方案

- 复制 Codex Desktop 的具体页面、品牌色或私有实现：会损害 LUTE/DSH 的品牌和业务语义，且违反基座与官方 UI
  锚边界，否决。
- 每个页面独立配色和独立 spacing：短期改动快，但会继续产生页面之间不统一和层级漂移，否决。
- 新建一套独立 design-system runtime：会增加运行时、发布和 token 双源；现有 `dsh-theme-local` 已足以承载
  第一阶段，否决。
- 一次性重排全部信息架构并迁移所有页面：风险面过大，无法把视觉问题与业务行为问题分离，否决。
- 继续使用当前蓝色默认主题或只支持深色：不能满足品牌色、浅色/深色/系统三态和默认风格要求，否决。

## 后果

- 新默认主题、Codex 风格预设与系统跟随策略有一个可测试的 token owner；页面可在不改变业务契约的前提下
  逐批获得统一的颜色、层级和密度基线。
- 当前第一批已落地主题默认调色板、Codex 预设对齐测试，以及 Settings Shell 对主题语义 token、单一内容滚动区、
  180ms 动效和 reduced-motion 的接入；`dsh-theme-local` 与 `dsh-settings-shell-local` 的 typecheck、测试、
  build 和相关 token acceptance 已通过。生成的两个 client bundle 与 source map 属于本次构建产物变更。
- Settings 内各业务 section 的标题/说明、扁平表单行和危险区仍按页面逐步迁移；抽屉、Composer 和其他业务页面
  尚未因此自动完成迁移。Settings bundle 已按 tmp+mv 同步到当前 loadpoint，并已在 2026-09-17 按用户授权重启
  DSH Desktop。重启后的 `pnpm run accept:settings-shell` 已通过：导航校准 raw=226 AX px / 188 CSS px，18 项
  导航独立滚动，末项 39.53 CSS px，面板 950.4 CSS px，分组标题 5/5，Settings 已关闭。此前的
  `nav-candidate-missing` 根因是两列 flex 几何未固定；本次补齐面板宽度、让内容列允许收缩并消费
  upstream 已定义的 188px 导航轨道，Shell 不重复改写该校准宽度。
- 本批初始 quick gate 曾为 76/78 通过、2 项环境跳过、0 项失败；本 ADR 不放宽门禁，也不把其他未提交改动
  归因于本次 UI 迁移。修正导航宽度归属后，Settings criteria 已独立 9/9 通过；最新聚合 gate 的剩余失败是
  共享工作树中另一个任务新增 ADR-0105 的索引与 Note 链接未完成（`adr-index`、`docs-link-integrity`），不属于
  本 ADR 的 UI 改动范围。
- 不新增 dependency，不修改 vendor、数据、路由、slot 或权限；后续若需要改变这些边界，必须另行决策并重新
  进行分阶段验收。
