# ADR-0066 · 安装向导必须自己定位载荷，且失败必须给出读数：`Setup.app` 不能假设「同级就是安装包」

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：agent（本次线上反馈、机制定位与修复设计）
- 决策记录：[Note](../notes/implemented/surface/2026-09-13-setup-app-payload-locator.md)
- 相关：ADR-0043（失败必须给出为它负责的读数）、ADR-0057（产物要么缺席要么完整）、ADR-0063（固定证书签名与未公证面）、ADR-0065（运行中替换 app bundle 的白屏红线）、ADR-0009（一份事实只有一个家）

## 背景

2026-09-13 线上反馈：客户在挂载的 dmg 里双击 `LUTE Setup.app`，点「开始安装」后报
**「未找到 install.sh（请从完整安装包运行本程序）」**。安装无法进行，而这句话没有给出任何可查的读数。

机制：向导的定位逻辑只有一条路径——`Bundle.main.bundleURL.deletingLastPathComponent()`
（bundle 的上级目录），并要求该目录下的 `install.sh` 带可执行位。三种真实情况都会失败：

1. **App Translocation（Gatekeeper 路径随机化）**：本包未公证，dmg 从网络下载后带
   `com.apple.quarantine`；用户**从挂载的 dmg 里**双击向导（正是我们文档教的流程）时，macOS 会把
   **只有 app bundle 自己**复制进 `/private/var/folders/.../AppTranslocation/<UUID>/d/` 这个随机只读
   镜像再从那里启动。bundle 的上级于是成了那个随机目录，真正的 `install.sh` 还留在 `/Volumes/…` 上。
   Apple DTS 说明该行为「具体触发条件未公开」，且**没有任何受支持的办法从被重定位的路径反推原路径**。
   这一条不是个案：它命中每一个「下载 dmg → 挂载 → 双击向导」的用户。
2. **用户把 `LUTE Setup.app` 拖出 dmg**：同级确实没有载荷。
3. **`install.sh` 在、但可执行位在转存途中丢了**（第三方解压工具 / 网盘中转 / Windows 转存）。
   而向导是用 `/bin/bash <path>` 执行脚本的——**根本不依赖可执行位**，那道检查是白加的。

出货物本身无问题：挂载 2.3.0 dmg 实测卷根 `install.sh` 为 `-rwxr-xr-x`，`LUTE Setup.app` 就在旁边；
`LUTE-Setup.swift` 自 09-06 基线以来未改动。缺陷在**向导对运行环境的假设**，以及**失败时不给读数**。

## 决策

1. **载荷定位改为多候选搜索**：同级目录 → 挂载卷（`/Volumes/*`，逐个子目录）→ `~/Downloads`、`~/Desktop`；
   候选须满足**载荷指纹**（`install.sh` 与 `DSH Desktop.app.tar.gz` 同时存在且可读——只有 `install.sh`
   的目录不算完整包），并按 `VERSION` 里的 `LUTE_VERSION` 与向导自身版本匹配来消歧（多候选无匹配时取版本最高者，
   并在读数里念出其余候选）。搜索面可用 `LUTE_SETUP_SEARCH_ROOTS` 覆盖，供自测指向临时目录。
2. **脚本检查从「可执行」改为「存在且可读」**：执行方式是 `/bin/bash <script>`，可执行位不是必要条件；
   用更严的判据去否决一个本来能跑的情况，是把可修的问题说成不存在。
3. **失败必须给出读数**（ADR-0043）：向导在任何定位失败时打印自身 bundle 路径、是否被 AppTranslocation
   重定位、本程序版本、搜索过的全部目录、每个候选被接受/拒绝的理由，并给出「复制终端命令」与「打开终端」
   两个兜底按钮——不再是一句无法下手的话。被重定位但定位成功时也如实说明（否则用户会以为是故障）。
4. **新增无界面诊断模式 `--print-payload-root`**：打印同一组读数并退出（找到返回 0，未找到返回 3）。
   存在的理由是判据必须可被脚本测——只能靠人双击看窗口的判据，等于没有判据。
5. **该判据进门禁**：`packaging/scripts/setup-app-locate-test.sh` 造出上述三种布局（含 translocation 布局）
   与两种负例（无候选 / 残缺载荷），由 `scripts/gate.mjs` 的 `setup-app-locate-test`（`setup-app-locator`）
   硬校验；缺 `swiftc` 即红（附 `xcode-select --install` 的处置），不静默跳过。
6. **客户侧安装事实的家 = `packaging/INSTALL-GUIDE.md`**（用户版安装手册）：逐步操作、授权两项、
   失败对照表、卸载/回退。它**随包分发**（`assemble.sh` 注入 `{{VERSION}}` 后写入 payload 根），
   并登记进 `TCC_GUIDANCE_SURFACES`——新增一处会教用户授权的出货面，必须同时进那份清单，
   否则就是新增一处「写错了也没人说」的地方（ADR-0009）。

## 备选方案

- **只改善文案**（告诉用户「请用终端安装」）：不改假设，则「双击向导」这条路永远不可用；而它正是
  面向无终端客户的那条路。否决。
- **在向导里内嵌 `install.sh`**：脚本本身 17 KB，可以内嵌；但载荷是 640 MB 的四个 tar.gz，仍须定位
  它们，问题只是从「找 install.sh」变成「找 payload」，没有消除。否决（可作为将来的瘦身项）。
- **改用 `.pkg`（Installer 自带载荷，不受 translocation 影响）**：交付形态刚在 2.2.0 收敛到 DMG 单一格式，
  且 pkg 需要 Developer ID 才有像样的信任面。否决。
- **要求用户先把 dmg 内容拷到本地再双击**：实验与文献都表明隔离属性会跟着走，拷贝到 `~/Downloads`
  仍可能被重定位——给出一个「有时管用」的步骤比不给更坏。否决。
- **把可执行位检查保留为「数据完整性信号」**：它确实能反映转存途中的损坏，但那应当由 `SHA256SUMS`
  承担（载荷自带），不该由一个会挡住安装的前置检查兼职。否决。

## 后果

- 「双击向导」这条路对未公证包也变得可用：重定位下的载荷由挂载卷搜索找回，向导第一行会打印
  「安装包：…」让用户看得见它做了什么。
- 定位面变宽 = 可能选中**另一个仍挂载着的旧版 dmg** 里的载荷。已用版本匹配收窄（无匹配时取版本最高并
  在读数里念出其余候选）；残余风险是「同时挂着两个同版本 dmg」，此时取先遇到的那个，读数里可见。
- 多了一条门禁依赖 `swiftc`（Xcode 命令行工具）。这是本项目既有的构建前提（`build-setup-app.sh` 同样需要），
  但**首次出现在门禁里**：机台没有命令行工具时 `pnpm run gate` 会红，处置已写进 remediation。
- 自测脚本已含负例（无候选 / 残缺载荷）作为反向对照：把定位器换成恒真桩，这两条会红。
- 已发出的 2.3.0 / 2.3.1 仍带旧向导；对这两版的客户处置写进安装卡「未找到安装包」那一行
  （终端一条命令，或装 2.3.2+）。
