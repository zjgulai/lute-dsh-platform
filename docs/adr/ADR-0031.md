# ADR-0031 · 技能分类必须与岗位矩阵同构；缺口认领必须与分类落点自洽

- 状态：accepted
- 日期：2026-09-12
- 决策者：agent（取证后提出；判据已被 1338 张真实卡实测证伪并修正两次）
- 决策记录：[Note](../notes/implemented/capability/2026-09-12-paper2skills-preset-skills.md)

## 背景

把 paper2skills 的 1338 张技能卡装进技能库并供 50 个岗位 preset 装配时，有两个必须先答的问题：

**问题一：技能按什么分类？** 语料自带 25 个技术域（因果推断 / 供应链 / 标签工程 …），但平台的
「岗位责任」用的是另一套语言——材料 D-021 的组织拓扑：4 面 / 8 责任域 / 151 细分业务。两套语言
各说各的，「技能供给」与「岗位责任」就是两本对不上的账：某个细分业务到底有没有技能供给、
哪个岗位缺、缺多少，都算不出来。

**问题二：怎么判断某张卡补上了平台的某个缺口？** 平台登记了 9 个「无供给」缺口
（依赖协调 / 异常冻结与恢复 / 数据管道 / 容量管理 / 证据复核 / 纠正预防措施 / 安全事件处理 /
抽样审计 / 利益冲突检查），它们正是 ADR-0021 要求显式披露的那类事实。

## 决策

**1. 技能分类严格取自岗位矩阵的拓扑，不另造一套。**

- L1 = `organization-graph.json` 的 `planes`（4 面），L2 = `domain_views`（8 责任域），
  L3 = 每个岗位 `role-catalog.skills[]` 的 **151 个细分业务名（逐字，不改写、不新造、不合并同义词）**。
- 一张 skill 挂 1–3 个 L3；**树的主归属由首个 L3 唯一决定**，其余 L3 照常记录并参与供给覆盖统计。
- **跨面多挂是合法供给，不是错误。** 实测 1338 张里 269 张（20%）天然跨面：一张合规监控卡确实
  同时服务 `独立控制/产品准入核对`（法规影响侧）与 `业务运营/规则监测`（平台规则侧）。

**2. 缺口认领必须与卡的 L3 落点自洽，分三档。**

9 个缺口**本身就是 151 条 L3 里的名字**（`数据管道` = AGT-046 清源的一个细分业务，`容量管理` =
AGT-049 稳行的一个细分业务）。因此「这张卡补上某缺口」必须与「这张卡被分到了哪些 L3」对得上：

| 档 | 判据 | 下游含义 |
| --- | --- | --- |
| **strong** | 缺口名就是本卡的某个 L3 | `skill-map.json` → `kind: direct` |
| **adjacent** | 缺口名不是本卡 L3，但本卡至少一个 L3 与缺口**同属一个 L2 责任域** | `kind: partial` |
| **dropped** | 跨责任域且未挂该 L3 | 虚报，丢弃但保留在 `fills_gap_dropped` 供审计 |

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 用语料自带的 25 个技术域做分类 | 实现最省事，但技术域回答不了「哪个岗位缺技能」，供给与责任永远对不上账。**技术域改作正交属性 `p2s_src_domain` 保留**，不参与分类 |
| 允许多主归属（一张卡同时挂在 2 个 L2 树下） | 覆盖统计更"全"，但目录树、preset 装配、卡面分组都需要唯一归属，多主会让"这个技能属于谁"变成每次都要解释的问题 |
| 缺口只按语义相似度认领（子任务自由判断） | 实测 **41% 虚报**：工厂**产能**卡认领 `容量管理`（矩阵里指 AI 运行容量）、供应链**单点依赖**卡认领 `依赖协调`（矩阵里指跨角色能力编排）、平台账号关联风控卡认领 `利益冲突检查`（矩阵里指关联交易审查） |
| 不允许跨面多挂 | 实测 24 域 1296 张卡报出 266 项"失败"——**判据错、数据对**。该判据已废 |

## 后果

**正面**

- 151 个 L3 的供给覆盖表可以机械算出来：**134 有供给，17 零供给**。17 条空白不是"没找到卡"，
  而是**论文语料结构上不可能覆盖**——硬件研发/工业设计 9 条（AGT-009/010/011/012/013）、
  B2B 商务 3 条（AGT-025）、人事与内控 2 条（AGT-004/005）、生产现场 1 条、术语治理 1 条。
  这份清单本身就是要走公司 SOP 或另造卡的部分。
- 9 个缺口关闭 8 个（strong 178 + adjacent 32 条供给）；**`利益冲突检查` 保持空白**——
  8 个源域独立扫描 1338 张零候选，如实保留比凑数重要。
- 认领虚报被机械拦下 124 条：模型不再对不具备的能力宣称"我能"（ADR-0021 的披露规则落到可计算）。

**负面 / 代价**

- 语料里确实无法归入 151 条任何一项的卡（实测 11 张：AI 伦理 / EU AI Act / ESG 碳披露 10 张 +
  平台评价与口碑管理 1 张）**照常安装但无家可归**，被单独放在 `未归类（矩阵空白）`，不进任何
  preset。这暴露了矩阵本身的两处欠缺（硬件/工程类、AI 治理类细分业务）——是否补 L3 属材料侧决策。
- 分类正确性依赖子任务的语义判断，故每次重跑都要过 `classify-check.mjs`（逐域 id 同序同集、
  L3 逐字命中、空 l3 必带理由、缺口白名单）。

**后续动作**

- 新增技能一律 `p2s-` 前缀 + `disable-model-invocation: "true"`（全局模型目录已占约 7.2 万字符）；
  可见性只经 preset 的 `skill-subset` 逐岗白名单开放。
- 源站 `playbook/skills/*.html` 是唯一权威卡源（iCloud 工作树的 1356 个 `.md` 全是加密态，不可用）；
  重跑前先过 `extract-cards.mjs` 的 1338 断言。
- 装配器带 **密钥脱敏闸门**：实测全库有且仅有 1 张卡（`Skill-FActScore-Claim-Verification-Pipeline`）
  的代码模板硬编码了真实 API Key，装配时拦下 3 处。
