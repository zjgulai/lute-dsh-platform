# ADR-0026 · 对官方 UI 的样式覆盖必须与注入顺序无关

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（lute 报障）+ agent（定位根因后提出）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-root-brand-hero-override-cascade.md)

## 背景

用户报障：点开新会话，输入框上方的 `Preview` 角标错位（与品牌句重叠）。

根因不是选择器失效（ADR-0019 的锚点解析正常，实测 `anchors resolved`），而是
**级联顺序依赖**：插件的覆盖规则与官方规则**特异性完全相同**（都是单类名 0-1-0），
谁在 `<head>` 里靠后谁赢。

- 官方：`.zNic4G_headline{grid-template-columns:34px auto auto}`（34px 是给官方 34px 小鱼标留的轨道）
- 插件：`.zNic4G_headline{grid-template-columns:auto}` + `.zNic4G_headlineText{display:none}`

插件的锚点样式标签在 `apply()` 首次同步时即创建（此时官方样式标签可能还没注入，
规则内容为空），此后只更新 `textContent`、**位置不再变化** → 一旦官方 HeroShell
标签后到，官方规则就反压回来。品牌槽实际宽约 397px，被塞进 34px 固定轨道后溢出，
落到 `previewBadge` 的 `grid-area:1/3` 上。

离线复现（真实官方 CSS + 真实 DOM 结构，Chromium 实测）：

| 顺序 | 计算值 `grid-template-columns` | 角标位置 |
| --- | --- | --- |
| 官方后到（敌意） | `34px 0px 63.58px` ← 官方赢 | x=712，与品牌句重叠 −165px |
| 插件居末 / 带 `!important` | `397.36px 0px 57.34px` ← 插件赢 | 间距 17px，整组中心 = 输入框中心 |

## 决策

**凡覆盖官方样式的声明，一律与注入顺序解耦**，两道保险同时上：

1. `buildBrandCss()` 生成的覆盖声明带 `!important`（hero 的 `display` /
   `grid-template-columns`，统计条的 `max-height` / `opacity`）。
2. `watchAnchors()` 每次写入后把锚点样式标签移到 `head` 末尾
   （`appendChild` 移动既有节点），保证同特异性下恒在其后。

配套：`test/live-anchors.spec.ts` 新增真实产物 seam 用例，把「先装插件、后注入官方
样式」的敌意顺序固化，修复前必红。

## 备选方案

- **只用 `!important`**：能过本次，但把「赢」完全押在声明级；保留标签居末可让
  未来新增的、忘记加 `!important` 的规则也自动处于胜位。
- **只移标签位置**：仍依赖「官方标签之后必有一次写入」；若官方标签在最后一次写入
  之后才出现（本次即此情形），依旧会输。故两道都要。
- **提高选择器特异性（`.A.A{}`）**：可行，但把胜负建立在选择器形状上，且对数字
  前缀的 `[class~="…"]` 回退形态要重复处理，可读性更差。
- **改用 `nth-child` 结构选择器做主路径**：ADR-0019 已否决（结构变更同样脆弱且
  会无声误命中），此处不重启。

## 后果

- **正面**：覆盖结果与两侧加载次序无关；同类「静默反压」不会再复发。
- **代价**：覆盖声明带 `!important`。若官方某天对同一属性也用 `!important`，需重新
  评估（当前官方 HeroShell 无 `!important`，`accept:root-brand` 会先报警）。
- **验证**：Red/Green 各一次（摘掉制品里的 `!important` → 新用例失败
  `expected '.zNic4G_headlineText { display: none;…' to contain '!important'`；恢复 →
  13/13 全绿）；`pnpm run accept:root-brand` 全 PASS（含排版三项）；`pnpm run gate` 13/13。
- **后续动作**：官方 hero 若重命名模块或改造栅格，仍走 ADR-0019 的 drift 降级路径；
  本 ADR 只约束「覆盖规则怎么写」。
