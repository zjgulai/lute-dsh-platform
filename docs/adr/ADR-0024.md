# ADR-0024 · 上下文压缩加固：容量表实测 + 摘要路由解耦 + 确定性压缩按需切换

- 状态：accepted（2026-09-12）
- 决策记录：[Note](../notes/implemented/capability/2026-09-12-context-compaction-hardening.md)

## 背景

跨模型切换与中转站（硅基流动）场景下，DSH 的自动上下文压缩频繁失效，表现为「上下文溢出、回合中止」。取证锤实为四个独立缺陷叠加，全部发生在官方 `compaction-basic` 链路内，不涉及本仓库自研代码。

## 决策

1. **容量表以 provider 实测值为唯一真相源**。`llm-pi-ai` 路由必须显式声明每个模型的 `contextWindow`，并设 `defaultContextWindow` 兜底；禁止依赖 pi-ai 的 `262144` 默认值，也不采信官方文档标称值（实测 `GLM-4.5-Air` 文档 131K / provider 实际 98304，`GLM-4.5V` 文档 131K / 实际 65536）。
2. **压缩阈值按「估算口径」折算**。`token-meter` 用 `chars/4` 估算，中文实测 1.81 chars/token（低估 2.21 倍），故 `thresholdRatio` 必须按低估倍数折算，不得直接按目标上下文占比设置。
3. **摘要调用固定到大窗口的独立路由**，永不复用对话路由。摘要请求会携带完整 system + tools + 全部历史，用已满上下文的对话模型做摘要必然二次溢出并自锁。
4. **引入零模型调用的确定性压缩后端（`@aiwayds/dsh-dcp`）作为按需切换的加固模式**，承载它的预设副本 `lute-cordis` 不设为默认。
5. **不因压缩问题改动 harness 核心**。「provider 溢出报文不被 `isContextWindowExceededError` 识别」与「cordis 类预设的进程级 inspect provider 单例冲突」两条属上游缺陷，走 issue 提报，不走 profile override 打补丁。

## 备选方案与否决理由

- **改 `dsh-llm` 的溢出正则（profile override）**：否决。核心包补丁会与 `vendor/dsh-desktop.pin`、门禁锚点、上游观察窗三重机制冲突（ADR-0008 / ADR-0006），且修的是上游该修的地方。
- **把 `lute-cordis` 设为默认预设以全局启用确定性压缩**：否决。发行 `cordis` 的 `tool-cordis` 行注册进程级单例 inspect provider，同进程第二个 cordis 类预设挂载必然回滚（已用逐字未改动的对照副本证伪归因），代价是失去 `cordis_mount` 自我改造能力。
- **只用 LLM 摘要、不上确定性后端**：否决。`summarization produced no text summary content`（模型用 tool call 回答压缩指令）与 `truncated at the token cap` 两类失败无法用配置消除，确定性后端把整类故障归零。

## 影响

- 长中文会话与频繁切模型场景下不再出现「压缩从不触发 → provider 拒绝 → 回合中止」。
- 多一个按需切换的预设（`lute-cordis`），使用上需明确「结构改造用创造模式、长会话用压缩加固模式」。
- 增设一条对外部插件 `@aiwayds/dsh-dcp` 的运行时依赖（版本已锁 `0.11.0`，回滚为删依赖 + 删预设目录）。
