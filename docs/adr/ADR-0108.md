# ADR-0108 · 抽屉页面共享行为与控件收口

- 状态：accepted（2026-09-17）
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-17-drawer-control-contract.md)
- 相关：ADR-0104（Codex Desktop 视觉语法）、ADR-0027（模态浮层 top layer）、ADR-0107（管理与研究型页面）

## 背景

New App、Role Matrix 和 Skill Center 已经分别具备自己的抽屉实现，但动作按钮、搜索/筛选、列表条目、空态、
错误态和窄屏降级仍有细微差异。它们共同位于 DSH Desktop 的侧边入口，视觉差异会被用户直接感知为页面不统一；
同时三个包的 top-layer、数据读取、状态操作和业务入口都已经有独立契约，不能通过重写运行时来统一。

## 决策

1. 三个 surface 只在自身 CSS 与视觉合同测试中收口：统一 32–36px 控件命中区、focus-visible、禁用/错误/成功
   状态、180ms 动效、reduced-motion、窄屏单列和扁平内容面板；不修改 TSX 业务状态、API、路由、slot、权限或 vendor。
2. New App 与 Role Matrix 继续使用已验证的 dialog top layer，不添加竞争性的 z-index；Skill Center 保留其现有
   右侧抽屉宿主，只改面板内的层级和可达性表现。
3. 产品/角色/技能目录中的圆角或徽标只有在表达状态、数量或操作边界时保留；目录本体优先使用列表、分组和当前项
   轨道，避免装饰性卡片堆叠。

## 备选方案

- 把三个包重写成新的共享 UI runtime：否决，会引入第二个 token/runtime owner。
- 统一提高所有 overlay 的 z-index：否决，无法替代 top-layer 语义，并会重新制造 Settings/Popover 层级竞争。
- 只做颜色替换：否决，不能解决控件命中区、焦点、空态和窄屏行为不一致。

## 后果

三个抽屉的视觉和控件合同更接近 Codex Desktop，且现有业务入口和运行时契约保持不变。包级验证已完成；
装载点同步后仍需一次统一 Desktop 重启、浅/深/系统状态、键盘与固定截图验收。Skill Center 的视觉合同测试
是新增的独立测试文件，必须随包保留。
