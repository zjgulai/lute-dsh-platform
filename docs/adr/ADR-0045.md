# ADR-0045 · 产品矩阵只列已产品化的产品、一张大卡一个产品；工作台与控制室的 UI 全部卸载（部分取代 ADR-0028 与 ADR-0033 第 6 条）

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（要求「新应用」页只保留已经产品化的产品、改成大卡片矩阵形式，并「把 dsh-worktable 相关的工作台和控制室的 UI 组件全部清除掉」）+ agent（一次现场取证、两轮共 7 项裁决）
- 决策记录：[Note](../notes/implemented/simplification/2026-09-12-newapp-product-matrix-ablation.md)

## 背景

用户点开侧边栏「新应用」，看到的是**一列 25 张卡，其中 24 张写着「尚未产品化」**，
判断是「这个插件太重了」，要求两件事：只保留已经产品化的产品、改用大卡片的矩阵形式。

现场取证（逐字实测，非推断）：

| 读数 | 来源 | 值 |
| --- | --- | --- |
| 矩阵页卡片数 | `GET /api/dsh-newapp/products` | 25（`declaredCount: 1`） |
| 未产品化占位卡 | 同上，逐卡 `declared` | 24 |
| 该产品状态 | `KOL-Hunter/product.json` | `draft` |
| 扫描根 | profile patch `productRoots` | `[/Users/lute/project]` |

**用户的直觉准确，但指错了插件。** 这一页由 `dsh-newapp-local` 渲染（client 92 KB），
不是 `dsh-worktable`（client 1.4 MB / 23,483 行，在这页里只贡献一段标注「另一份事实，只读」
的项目列表）。`dsh-worktable` 的 host 半边另有 8 条 HTTP 路由 + 1 条 WebSocket 升级路由
（`/write` 是任意文件写入、`/term` 是交互式 shell），本仓库为它维护 1,268 行守卫件。

两处必须先纠正的既有决策：

- [ADR-0028](ADR-0028.md)：「没有 `product.json` 的目录**照样列出**并标「尚未产品化」：
  丢掉它会让一个用户知道存在的项目看起来像被删了。」
- [ADR-0033](ADR-0033.md) 第 6 条：「没有 `product.json` 的目录显示「尚未产品化」而不是消失。」

用户已知情并显式选择推翻。本决策不偷偷删代码，而是登记修订（见「后果」）。

另有一处**已漂移的事实**，它排除了一个看似合理的口径：`KOL-Hunter/product.json` 的
`statusReason` 写着「入口面板的客户端服务尚未打包安装，卡片点开暂走第 2 级回退」，
但 `KOL-Hunter/lib/client.js` 实测已 `ctx.provide('kol-hunter-workbench', …)`
且已装进 profile 并进了 bundles——**那张卡现在走的是第 1 级「打开」**。
`status` / `statusReason` 是手写字段，已经漂移过一次。用户据此排除了
「以 `status` 为过滤器」的方案：那等于让一句会过期的文案决定产品显不显示。

## 决策

**1. 卡片的键是产品，不是工作目录。**

一个产品一张卡；目录降为卡上的元信息（它是会话打开的位置，是真信息，但不再决定卡片数量）。
渲染键取 `<dir>::<product id>`——product id 由产品作者自定、不保证全机唯一，目录也不能单独作键
（一个目录可以声明多个产品）。

**2. 没有 `product.json` 的目录不再是卡片，但仍然被计数。**

这一页只摆「已经产品化」的东西，默认视野里没有任何占位。
但目录**不能从报告里消失**：`ScanReport.undeclaredCount` 承载「扫了多少个目录、其中多少个没声明」，
空态与页脚各说一次。少了这个计数，「一个目录都没扫到（配置错）」与「扫到了但都没声明」
就是同一个读数——那正是 ADR-0028 当初想守住的东西。**计数保住了这个区分，只是不再为它花掉 24 张卡。**

**3. 默认视野宽度下用网格大卡，不用一列。**

`repeat(auto-fill, minmax(280px, 1fr))`：列数随视口走，卡片保持尺寸。
每张卡给齐六项：名称 / summary / 状态 / 岗位 / 版本 / 功能数，外加所在目录。

**4. 「已产品化」的判据是「有可用的 `product.json`」，不是 `status` 字段。**

理由见背景里的漂移实测：`status` 会过期，`product.json` 在不在不会。

**5. `dsh-worktable` 从本机卸载，工作台与控制室的 UI 一并清除。**

两处 UI 都是这一个插件注册的——`sidebar.footer.action`（id `dsh-worktable`，工作台侧边栏入口）
与 `shell.overlay`（id `dsh-worktable-split`，控制室分栏浮层）。卸载即两处同时消失，
**零补丁、不碰上游一行**。

剪枝以「卸载」实现，不以「改上游代码」实现：改代码会把补丁面从「一处路由注册文本」
膨胀成「大面积源码改写」，上游每升一次级都要重付一次；而用户的全部诉求
（页面只留已产品化产品、侧边栏不再有工作台入口）靠卸载就**全额**拿到。

**6. 消融顺序有依赖：先删读取点，后卸载。**

卸载后 `/api/worktable/workspaces` 会死。若页面里那段项目列表还在，它会挂上一条**永久**降级告示
「工作台项目（dsh-worktable 未安装，或还没有建过项目）」——正好就是用户嫌的那种「重」。
所以「删掉页面里所有 worktable 读取点」必须**先于**「卸载」。

**7. 卸载保留资产，守卫件语义翻转（不是删除）。**

`vendor/dsh-worktable`、`vendor/dsh-worktable.pin`、`dsh-patches/worktable-fence/` 全部保留：
资产是这条决策可逆的唯一凭据，删掉它想回退就得重新 clone + 重新锚补丁。
四个守卫件（1,268 行）不删，语义从「守护已安装」翻成**断言未安装**。

**8. 上一版栅栏门禁的判据作废。**

那 31 条实况判据、锚点判据、撞名判据全部在回答「运行时装载的那份产物拦不拦得住」。
插件不装载了，那个问题没有主语；继续断言它，就是 ADR-0009 说的「一个事实的第二处家」——
它会一直绿，并且一直让人以为这条链路还在。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| **A. 保留 worktable，只改 newapp 页面** | 达到 M1–M5，但 1.4 MB client 与 9 条路由（含任意文件写入与交互式 shell）留在机器上。用户明确说「不需要」，否决。 |
| **B. 下载 worktable 源码、删掉工作台/控制室组件后重新打包** | 让补丁面从「一处路由注册文本」膨胀成「大面积源码改写」，上游每次发版都要重锚。**与本决策的目标零相关却代价最高**，否决。 |
| **C. 只从 bundles 摘掉、保留 node_modules** | 实测过的中间态：摘掉 dependencies 与 bundles 之后 `pnpm install` 并不会删掉 `node_modules` 里的符号链接，产物仍在、仍可解析。判据必须三处都查。否决。 |
| **D. 以 `status === 'ready'` 过滤产品** | 被 §背景 那处漂移实测否决：这是让一句会过期的手写文案决定产品显不显示。 |
| **E. 未产品化目录改为可折叠分组** | 用户裁决为「彻底从页面消失 + 一行计数」，否决折叠。 |
| **F. 卸载时连资产一起删** | 不可逆。用户裁决保留资产。否决。 |

## 后果

**正面**

- 页面读数从「25 张卡 / 1 张可用」变成「1 张卡 / 1 张可用」；卡片数 = 已声明产品数（M2）。
- 工作台与控制室的 UI 从本机消失：1.4 MB client 不再加载、8 条 HTTP + 1 条 WS 路由不再注册
  （含任意文件写入与交互式 shell 的安全面）。
- newapp 自身 client 从 92 KB 降到 71.5 KB，`sources.ts`（358 行）与其测试整体消失。
- 补丁面不增长：卸载不碰上游一行，上游发版无需重锚。

**负面 / 代价**

- **部分取代 [ADR-0028](ADR-0028.md) 与 [ADR-0033](ADR-0033.md) 第 6 条**：两篇的
  「未声明目录显示为占位而不是消失」在本页不再成立，已在两篇正文标注。
  ADR-0033 的其余决策（`preset` 必填、卡片字段）不受影响。
- 卸载后本机不能再从页面进入工作台项目。10 个既有工作台项目**不丢**——
  `/api/worktable/workspaces` 读的是官方 `ctx.workspaceRegistry`，不是 worktable 私有存储；
  但本页不再展示它们。
- ADR-0029/0030 的 31 条栅栏实况判据作废。栅栏机制本身仍是**同类第三方插件的模板**
  （ADR-0030 的结论不因此失效），只是不再有在跑的实例守护。
- **页面上只剩 1 张卡**是诚实读数，不是缺陷：`declaredCount: 1`。网格用 `auto-fill`
  写就是为了让它随用户后续声明更多目录自然长起来。

**后续动作**

- 矩阵页的真实网格列数必须在**真实 Chrome** 里量（jsdom 不做布局，`getBoundingClientRect()` 恒为 0）。
  因真实数据只有 1 个产品，该判据必须由**合成夹具**（3–4 个临时产品目录）承载；
  配反向对照：拿只有 1 张卡的夹具跑，列数断言**必须失败**。
- `docs/catalog/packages.md` 与 profile 装载清单随下次 `gen-catalog` 刷新。
