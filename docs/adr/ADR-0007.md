# ADR-0007 · 二开平台重构级别：三期推进（骨架 → 结构收敛 → 契约与清账）

- 状态：accepted
- 日期：2026-09-11
- 决策者：用户（lute）+ agent（grill-me 决策树 Q1，全 C 确认）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-11-lute-refactor-three-phase.md)

## 背景

对当前二开仓库（20 个插件 / 2,755 文件 / 125,580 行）与上游 DeepSeek Harness（64 能力组 / 10,303 文件 / 215 个门禁脚本 / 2,920 篇 Agent Notes）做交叉对比后，实测确认缺三根工程骨架：无根级聚合门禁与 CI（20 插件中 11 个无 test、12 个无 typecheck）、无包平面（20 个平铺目录、6 种命名空间、15 个版本值）、无文档脊柱（四套文档体系并存且有重复副本）。同时仓库正处于 DSH 2.0.5 灰度窗口（ADR-0005、ADR-0006）。

## 决策

**以三期推进完成重构，每期独立可验收，且不得与灰度窗口的发布动作叠加：**

1. **一期（骨架）**：harness 只读参照系 + 三层文档脊柱 + 事实源去重 + 包身份元数据 + 聚合门禁骨架（含只减不增的豁免文件）。不动代码结构。
2. **二期（结构收敛）**：20 个插件按能力组归位 + 生成式目录墙 + 门禁接 git 钩子 + 引入 lint 规范。
3. **三期（契约与清账）**：typecheck/test 逐包补齐至全量硬门槛、豁免文件清空、历史 ADR 归档、资产分级处置。

每期开工前确认范围，结束时以真实命令输出（Red/Green、构建、浏览器验收）作为验收证据。

## 备选方案

- **A 全量同构重构**：一次性把目录、命名、测试、文档对齐上游形态。被否决——估算 6-10 人日以上且与灰度窗口叠加，风险叠加且中途无机器兜底。
- **B 最小治理**：只补 AGENTS.md 与单一门禁，目录与代码形态一律不动。被否决——命名与结构漂移会持续，且门禁缺少可依附的包平面。
- **D 先重构代码、后补门禁**：被否决——正是当前债务的成因路径（先有实现、无验证）。

## 后果

- 正面：每期结束时仓库的可验证性单调上升；一期即可让基座升级与补丁重锚从人工核对转为机器校验。
- 负面/代价：三期总周期拉长（预估 3 周量级），期间存在「骨架已建、存量未补齐」的过渡态，需以豁免文件显式登记为债。
- 后续动作：一期范围与验收见 `.scratch/lute-refactor/spec.md`；配套决策见 ADR-0008 ~ ADR-0015。
