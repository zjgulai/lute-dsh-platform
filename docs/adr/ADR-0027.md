# ADR-0027 · 模态浮层必须进入浏览器 top layer，不参与 z-index 竞争

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（lute 报障）+ agent（定位根因后提出）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-role-matrix-top-layer-drawer.md)

## 背景

用户报障：岗位矩阵面板打开后，**右上角的关闭 ✕ 被一个外来图标部分遮挡，点不动**。

平台是约 20 个独立编写的插件拼起来的，**彼此之间没有任何层级约定**。实测（逐个读
profile 里已装插件的源码，非估计）：官方客户端 UI 用 10/20/30/100/1000/1100；
`dsh-context` 200/1000；`dsh-file-upload` 200；`dsh-univer-office` 1200/1300/1400；
`dsh-wanzh-hulian` 右侧面板 **2500**；skill-explorer 9999；task-board 20000；
`dsh-team-hub` 常驻胶囊 **99999**；`dsh-my-quotes` 面板 **2147483000**；
`dsh-pocket` **2147483647**。

而岗位矩阵抽屉是 `z-index: 60` —— 比官方自己的菜单（100）还低，比十个已装浮层低。
这不是「差一点」，是**在一个没有秩序的空间里随便挑了一个数**。

## 决策

**需要「盖住全应用」语义的面板，一律用 `<dialog>` + `showModal()` 进入 top layer，
不再用 `z-index` 表达模态。**

配套三条硬约束：

1. `.root:not([open]) { display: none }` 必须显式写回。任何给 `dialog` 加
   `display:flex` 的铺满式重置都会覆盖 UA 的 `:not([open])` 规则，漏掉即「关不掉的
   幽灵面板」。
2. `showModal()` 失败要**响亮降级**（置 `open` 属性 + `console.error`），不得静默：
   无 `open` 的 `<dialog>` 是 `display:none`，静默失败等于白屏。
3. 模态必须有 **≥2 条独立关闭路径**（✕ / 点遮罩 / Esc）。✕ 是用户直觉，另两条是
   「✕ 被什么东西挡住」时的保险——本次故障正是丢在这条保险上。

## 备选方案

- **把 z-index 调到比对手大**（2600、2147483001…）：仍是下注，且必须随别人的改动
  重新下注；`dsh-pocket` 已占到 2147483647，这条路没有终点。
- **改成非模态右侧停靠**：用户照样会被浮层盖住，还丢掉模态语义，并与
  `dsh-better-sidebar` 的右侧面板争地盘。
- **要求其它插件让路**：其中多数是 npm 安装的第三方，不归本仓库管，不可执行。
- **自建层级约定并广播给所有插件**：正确的长期方向，但需要生态配合；本 ADR 只解决
  「模态怎么保证在最上」，把「非模态浮层之间怎么排队」留给后续。

## 后果

- **正面**：模态面板**在结构上**不可能被任何 z-index 盖住，与装了什么插件无关；
  一次性消灭整类「点不动」故障。
- **负面**：抽屉打开时会盖住所有插件浮层（包括用户自己开着的其它面板），「两个面板
  并排看」不再可能。这是模态的正确语义，但值得对用户明说。
- **纪律**：以后新增任何「遮罩式」面板，先问「`showModal()` 能用吗」；只有在确实要
  与其它浮层共存时才退回 z-index，并在该处写明为什么。
- **未决**：插件生态仍缺一套共享层级约定（本 ADR 不提供）。
