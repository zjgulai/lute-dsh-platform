# ADR-0032 · 跨框架注入的共享核心：「未挂载」只有一种表示，且其注入契约必须在真框架环境证伪

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（lute 要求「新应用」并排按钮落地）+ agent（探针取证后定位）
- 决策记录：[Note](../notes/implemented/contract/2026-09-12-sidebar-entry-null-pane.md)

## 背景

`shared/client/sidebar-entry-core.ts` 是本机三个受管包共用的侧边栏入口注入核心
（`dsh-newapp-local` / `dsh-role-matrix-local` / `dsh-skill-center-local`，经
`scripts/sync-shared.mjs` 生成 15 个字节相同的副本）。它向官方侧边栏注入一个**不由
React 拥有**的 DOM 行，靠 `MutationObserver` 自愈官方重渲染带来的位移。

「新应用」并排按钮是它的第一个 `position: 'split'` 消费方。并排几何的验证件
`scripts/geometry-probe.mjs` 在真 Chrome 里 18/18 通过——但它的 fixture 是**静态
HTML，页面里没有 React**，因此**永远不可能发生重渲染，也就永远不可能发生位移**。
而核心的全部自愈逻辑，恰好只对重渲染有意义。

补上真 React 环境的探针（`scripts/reconcile-probe.mjs`）后，**立刻测出一个真缺陷**：

`sidebarRoot()` 的声明返回类型是 `HTMLElement | undefined`，实现却写

```ts
return logoOwner ?? (column.firstElementChild as HTMLElement | undefined)
```

`firstElementChild` 的类型是 **`Element | null`**——这不是笔误，是 `??` 的右操作数本来就
可能是 `null`。而本模块的**五个调用点全部只判 `undefined`**（`root === undefined` /
`root !== undefined`），于是 `null` 每一种判据都通不过、又一种都没被拦住。

实测后果（真 React 18.3.1，见 Note 的读数表）：

- 侧边栏面板**存在但暂时为空**（整面板拆除与重建之间的那一帧）时，`sidebarRoot()`
  返回 `null`，守卫被绕过，核心**从 MutationObserver 回调里抛出 TypeError** 到宿主页面；
- 更重的是，卡住的值就是 `null`，于是后续每一次 mutation 都在同一个 `!== undefined`
  判据上再次抛出：**入口行在整面板重建、外加五次进一步重渲染之后仍不回来**
  （实测 7 次未捕获异常，一个 mutation 批次一次）。这不是「控制台多了条错误」，
  是**功能永久丢失**，只有整页刷新才能恢复。

用户可见形态与代码形态之间隔着一个探针：静态 fixture 与 jsdom 各自只能证明一半
（前者能测布局、测不了协调；后者能测协调、测不了布局），而**恰好在两者都不覆盖的
那一格上，缺陷活了下来**。

## 决策

**1. 共享注入核心的「未挂载」状态只有一种表示：`undefined`。**

`null` 不得出现在该契约里。修法是把类型谎言改掉（`?? undefined` 归一化），**不是**
在每个调用点补 `!= null` 双判——后者把谎言留在类型里，下一个调用点还会踩，而 ADR-0009
要求的是一份事实只有一个家。

**2. 跨框架注入的契约必须在真框架环境里证伪，且探针必须自带「先证明危险真实发生」。**

`scripts/reconcile-probe.mjs` 因此带三条硬要求：

- **结构取自 shipped bundle，不手抄**：侧边栏的 children 数组、
  `Tooltip` 用 `cloneElement` 而不加 DOM 包装、气泡是锚点的**瞬态兄弟**——三条都在运行时
  从官方 bundle 里读出来并断言（`assertBundleShape()`），结构一变就**响亮失败**而不是
  静默失效。与 `geometry-probe.mjs` 拒绝手抄样式表是同一条理由。
- **仪器自检**：每条自愈断言都配一条**同步读数**，证明位移真的发生过。
  本探针的 S1 就是这么被自己的仪器**证伪**的——原以为 tooltip 气泡会楔进按钮与入口
  之间，实测 React 的插入参照是它**自己**的下一个兄弟（`regionArea`），气泡落在入口
  **之后**，位移根本没发生。错的期望被删掉、改写成实测次序，而不是把一条永远是绿的
  断言留在套件里。
- **未捕获异常本身就是断言**（S8）：插件往宿主页面抛异常是独立的缺陷，不该只以
  堆栈形式出现——它必须是一个**有名字的失败**。

**3. 变异测试与真环境探针一样是交付物的一部分。**

喂未修的核心给同一套探针，必须转红；喂修好的，必须转绿。两侧都跑过才算验收。

## Alternatives considered

- **A. 在每个调用点补 `!= null` / `== null` 双判。**
  否决：契约的谎言留在类型里，下一个调用点还会踩；而且五个判据各自表述一次「未挂载」，
  正是 ADR-0009 意义上的多份事实之家。
- **B. 在 `tryPlace` 与两个观察者回调外面包一层 `try/catch` 作为唯一修法。**
  否决：它把一次可诊断的契约违背变成静默降级，且完全不解决类型不诚实——`root` 仍会
  永久卡在 `null`，只是不再抛了。作为纵深可以，作为修法不行。
- **C. 在静态 fixture 里放一个手写的 React 替身。**
  否决：手写替身会与真 reconciler 静默漂移，测试的是我对 React 的假设——正是
  `geometry-probe.mjs` 拒绝手抄样式表的同一条理由。
- **D. 只把用例放进 vitest（jsdom）。**
  否决：vitest 环境没有布局，也没有真 reconciler 的提交顺序；而且让单测依赖 shipped
  bundle 会把环境耦合塞进快套件。两者的分工**互补而非替代**：单测钉契约（毫秒级、
  零依赖），探针钉真环境行为（需装好的 app）。
- **E. 把 reconcile 探针也塞进 `pnpm run gate`。**
  否决：它依赖已安装的 DSH Desktop（读官方 bundle）。门禁是硬门槛（ADR-0014），
  引入一条「机器上没装 app 就红」的判据会让门禁变成环境的函数。它保持按需验收件，
  与 `geometry-probe.mjs` 同级。

## Consequences

**得到**：三个消费方（15 个生成副本）在侧边栏拆除/重建时不再把 TypeError 抛进宿主页面，
也不再永久丢失入口行；「未挂载」在共享层只有一种表示；跨框架注入的契约第一次有了能在
真 React 下证伪的仪器，且仪器自带防空转的自检。

**代价**：① 探针依赖已安装的 DSH Desktop 与 React 版本，CI 上只能在装了 app 的机器跑
（与 `geometry-probe.mjs`、`accept:*` 同级，不进 `pnpm run gate`）；
② `assertBundleShape()` 在官方 bundle 结构变化时会**响亮失败**，需要人工重锚——
这是刻意的：静默失效的探针比没有探针更危险；
③ jsdom 不测布局，因此本探针**不**断言任何像素，几何仍只有 `geometry-probe.mjs` 说了算。

**回滚**：`sidebarRoot()` 归一化是单行改动；探针与单测是新增文件，删除即回到原状。
