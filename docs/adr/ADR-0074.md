# ADR-0074 · 技能出货面 =（被引用集 ∪ 产品级白名单）− 受限许可；落位树必须逐名等于选择结果

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：用户（「那就一起打包吧」——对「这 15 个工程技能要不要一并进包」的批复）+ agent（本次取证、判定与落地）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-13-shipped-skills-allowlist.md)
- 相关：ADR-0073（同一批次的前一条：预设出货面改白名单 + 守卫看见打包后的载荷——**本条的触发条件正是它**）、ADR-0009（一份事实只有一个家）、ADR-0056（出货树机器路径只减不增）、ADR-0031 / ADR-0041 / ADR-0052 / ADR-0053（技能分类与岗位接线）、ADR-0072（岗位白名单是授予）

## 背景

### 触发条件：排除一个预设，掉出 15 个技能

ADR-0073 把本机自有的机器人助理智能体预设 `bobo-cto` 排除出出货面之后，重切 2.3.3 的技能数
从 **349 掉到 334**。掉出的 15 个是：

```
agent-browser                 handoff
code-review                   improve-codebase-architecture
codebase-design               macos-harness
diagnosing-bugs               resolving-merge-conflicts
domain-modeling               simplify-codebase
dsh-plugin-acquire            wait-what
git-guardrails-claude-code    writing-for-agents
grilling
```

读数（`node packaging/scripts/select-skills.mjs --report`，两种 `PRESET_ROOT` 对照）：

| `PRESET_ROOT` | 被引用 | 实际出货 |
| --- | --- | --- |
| 本机 `~/.dsh/.agent-presets`（含 `bobo-cto`） | 350 | 349 |
| 出货 `$SP/presets`（51 个，无 `bobo-cto`） | 335 | **334** |

15 个的引用者**只有** `bobo-cto` 一个——它们从来没有被产品显式要过，只是被顺带引用。

### 为什么这是缺陷，而不是「规则的正确结果」

出货规则当时是「被出货预设引用 + 无受限许可」。按这条规则算，334 是正确结果。但同族的
工程工艺技能本来就在出货面里：`tdd`（agt-013）、`to-spec`（agt-012）、`to-tickets`（agt-009）、
`write-spec`（agt-009）、`prototype`（agt-013）、`research`（agt-048）。**产品拿到的是「一半工艺层」**，
而分界线画在哪，取决于打包那台机器的引用图恰好长成什么样。

根因与 ADR-0073 同源、形态更隐蔽一层：那里的出货边界是**一个目录列表**（本机有什么就发什么），
这里的出货边界是**一张引用图**（谁引用了就发谁）。两者都是「机器状态」，都答不了
**「产品要不要发它」**这个问题。引用图能证明「有人用」。

## 决策

1. **技能出货面 =（被引用集 ∪ 产品级白名单）− 受限许可名单**，实现在
   `packaging/scripts/select-skills.mjs`，新增配置 `packaging/shipped-skills.json`。
   白名单只记**产品意图的增量**，不记全量清单——全量清单仍是引用图的第二份事实（ADR-0009）。
2. **白名单自己要防腐烂，四种形态一律判否**：
   - 登记的名字在本机候选集里不存在 → `exit 1` 并点名（登记与实际不符的名单会腐烂成谎话）；
   - 登记的名字同时命中受限许可名单 → `exit 1`（「要发」与「禁发」是两个相反结论）；
   - 条目缺 `why` → `exit 2`（登记而不写理由的名单，过一版就没人敢删了）；
   - **白名单文件本身缺失 → `exit 2`，不得按「空名单」继续**（这是它最容易静默失效的形态：
     按空名单跑 = 15 个技能无声少发，而装配照报成功）。
   每次装配（`--copy`）与盘点（`--report`）都打印两条读数：**救回未被引用几条**（这份名单存在的
   全部意义）、**其中几条已被引用图覆盖**（冗余但合法，是它的腐烂信号，必须可见）。
3. **落位树必须逐名等于选择结果**（`--check` 的语义扩展）：少一个 → 判否并写明「静默少发」；
   多一个 → 判否（多出来的东西没有任何判据要它）；混进受限技能 → 判否。`--copy` 阶段若某个
   选择结果的源在根里找不到，**中止**而不是 `continue` 跳过。
4. **判据配反向自测并进门禁**：`packaging/scripts/select-skills-test.sh`（S1–S9、P1、M1），
   挂 `gate:shipped-skills-scope-selftest`，每次 `pnpm run gate` 都跑。

## 备选方案

- **维持 334，让产品显式点名要发的那几个。** 部分采纳但方向相反：本 ADR 做的正是「显式点名」，
  区别在默认面——用户批复是「一起打包」，即 15 个全要。若将来要缩，删 `allow` 条目即可，
  且「删掉后掉出的是谁」由同一条判据当场报出来。
- **把 15 个技能接到某些 `agt-*` 岗位的 `skill-map.json` 上。** 被否：那是**改岗位能力面**，
  会顺带改变岗位的 `manifest` 与 ADR-0072 的「白名单生效性」判据读数。产品意图（要不要发给客户）
  与岗位接线（某个岗位用不用它）是两件事，用一个机关表达两件事，下次改一边就会静默改另一边。
- **把 `bobo-cto` 请回 `allow`，一切照旧（52 预设 / 349 技能）。** 被否：它是**本机自有**的机器人
  助理智能体，其预设正文引用的材料根 `/Users/lute/project/BoBo` 在客户机上不存在——发出去是一个
  装上了但指向空材料的预设。用户 2026-09-13 已明确它不参与打包。
- **给 `select-skills` 存一份全量白名单（349 条）。** 被否：那是 ADR-0009 意义上的第二份事实，
  会随引用图与岗位接线漂移，而漂移是静默的。
- **让 `--check` 只看受限许可（不改语义）。** 被否：那样「选择说发 N 个、树里只有 N−1 个」
  没有任何判据看得见——而**静默少发与静默多发是同一类事故**，且本条的 A/B 对照读数
  （349 / 334）正是靠逐名比对才做得出来。
- **用环境变量 `REPO_MAPS` 让自测能替换仓库映射文件。** 被否：自测夹具改用 `zzfx-` 前缀的
  假技能名即可获得确定性，不必为测试在生产脚本上开一个能让「被引用集」失真的口子。

## 后果

- **正面**：
  - 出货技能面回到 **349**，而这次的 15 个是**显式表态**的结果，不是引用图的副产品；
    「救回未被引用 15 条」是装配日志里的一等读数。
  - 白名单的四种腐烂形态各有反向用例钉住（`S2`/`S3`/`S4`/`S5`），并有恒真桩突变（`M1`）
    证明 `S1` 钉的是「白名单参与选择」这条判据本身。
  - 落位树与选择结果的逐名比对，把「静默少发」这一类事故第一次变成红灯。
- **负面 / 边界**：
  - 多一份要维护的表（15 条、每条带 `why`）。这是有意买的代价：产品意图必须有一次表态，
    而不是由引用图代答。
  - 冗余条目会长期存在（岗位也在用同一批技能），所以「冗余」是**告警式读数而不是失败**——
    它治的是腐烂，不是重复。
  - `--check` 变成逐名判等后，它只对**本次选择结果**有意义；对历史版本的出货树跑它必然判否。
- **后续动作**：
  - 重切 2.3.3（同名归档，`--force`）——用户确认尚未外发，且本次是第二次重切。
  - `grill-me` / `grill-with-docs` / `ask-matt` 等**转发器**技能仍不在出货面内：本次批复只覆盖
    掉出的 15 个，未覆盖「同族但从未进过出货面」的那些。是否补齐属产品决定，单独立项。
  - 若将来 `select-presets` 再排除任何一个预设，**先跑 `--report` 看掉出谁**，再决定要不要
    往 `shipped-skills.json` 加条目——本条 ADR 的读法就是为这个动作写的。
