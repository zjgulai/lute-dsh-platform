# ADR-0035 · 技能效果的断言必须有实测背书；改动须过 held-out 验证门，未过门一律回滚

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（授权跑 L6 路由实测与 L7 SkillOpt）
- 决策记录：[Note](../notes/implemented/capability/2026-09-12-paper2skills-effect-eval.md)
- 关联：[ADR-0031](ADR-0031.md)（分类与缺口判据）、[ADR-0014](ADR-0014.md)（门禁是硬门槛）

## 背景

[ADR-0031](ADR-0031.md) 把 1338 张论文技能卡按岗位矩阵装进技能库并接进 50 个 preset。那一轮验证到的是
**结构性与保真性**（L1–L5：装了多少、字段对不对、字节有没有少），**没有验证效果**：
技能挂上去之后，岗位分身的产出是变好还是变坏，当时没有测，也不在那一轮的范围里。

用户随后授权补 L6（路由与执行实测）与 L7（SkillOpt 轨迹优化）。实测结果两条：

1. **路由面是干净的**：134/151 的 L3 供给本岗可达、越岗暴露 0/374、分类字段零漂移；
   40 例真实抽样里正样本 top-1 97.4%（keyword）/ 89.7%（situational），负向真实误召 5.0%。
   5 次错选里 4 次选中了同 L3 的孪生卡，1 次答 none。

2. **效果是负的**：给模型一张技能卡后，业务交付物得分**下降**（holdout Δ −0.95，符号检验 p=0.084；
   同一实验另一次 p=0.0038），六个对比方向全部一致。机制是卡把答案从「经营方案」拉向「方法说明」——
   模型把论文实验条件的参数原样搬进交付物当业务取值。

3. **一次「显然的修复」被实测证伪**：按上述机制，在纯合成字段 `## 边界与不做` 加了一条全局的
   「参数移植纪律」，重装配重安装后重跑。结果是**差距变大不是变小**（holdout −0.95 → −1.10，
   train −0.55 → −1.15）。硬证据：该条款让 **26/40** 份产出挂上「待标定 / 需重新标定 / 临时默认值」
   这类对冲措辞（其他三臂 **0/40**），长度与量化判据数都没变——它把「敢下判断的方案」变成了
   「处处留白的说明」，正是要修的那个毛病。

第 3 条是这次真正的教训：**在提示词/文档文本上做「显然更好」的改动，是可以净负的，而且负得可测。**

## 决策

**一、凡是「这个技能/这段描述/这条规则会带来 X 效果」的断言，必须有实测背书。**
没有实测就不写「有效」「提升了」这类话；只能说「已装上」「结构校验通过」。说与不说之间没有中间档。

**二、效果实测的判据事前定死，事后不许挑分母。** 三条最低要求：

| 要求 | 为什么 |
| --- | --- |
| **双臂对照** | 单臂分数是绝对分，「这分算高吗」永远说不清；差值才是可判读的量 |
| **盲判 + 位置偏差检验** | 判分者知道出处就会偏；顺序会偏。本次实测：control 作 X 与作 Y 的领先量逐位相同（各 1.17），位置效应 ±0.25 成对抵消——这个检验必须做，做了才能说「不是顺序造成的」 |
| **held-out 门** | 在一半任务上改好、在另一半上没改好，就是没过门。本次补丁在两侧同时变差，门直接判死 |

**三、未过门的改动一律回滚，不保留「也许有用」。** 回滚要留可复核的证据，不是口头复原：
本次复核了 `grep -rl 参数移植纪律 ~/.dsh/skills | wc -l` → `0`、20 张卡 `cmp` 逐字节一致、
`verify-install.mjs` 应装 1338 / 已装 1338 / 问题 0。

**四、报告必须自带噪声尺度。** 判分者是人或模型都有噪声：本次实测**同一批 control 文件在两轮里被判出
12.75 与 13.45**（差 0.60～0.70）。所以低于这个量级的 Δ 一律写成「不可分辨」，不写成「略有提升/下降」。

## 备选方案

| 方案 | 为什么不选 |
| --- | --- |
| 只跑单臂、看绝对分 | 无法判断「13/15 分算不算好」；也没有对照说明这张卡到底贡献了多少 |
| 用判分者的自然语言结论当证据（「判官说 A 更好」） | 判官意见是数据不是结论；必须折成可检验的量（Δ + 符号检验 + 分层），否则无法区分真实差异与判官噪声 |
| 补丁过训练侧就上线 | 本次正是这个情境：train 与 holdout 同时变差，只看 train 会误判为「没效果」，实际是「更差」 |
| 把补丁留着并加注「效果待观察」 | 违反 ADR-0014「门禁是硬门槛」的精神；且实测已证明它是负向的，留着就是已知有害 |
| 因为结论不好看，把 L7 记为「未运行」 | 见 AGENTS.md「不接受口头验收」。跑出来是负的也要写，负结论才是这次最有用的产出 |

## 后果

**正面：**

- 技能库现在有了唯一的、可复现的效果数字之家（`docs/eval-report.md`），结构面与效果面分得清。
- 「加一句免责条款」这类直觉修复被证明会反向放大问题，后续对合成字段的任何改动都必须先过门。
- 判据与噪声尺度都写进了报告，后来者不必重新发现「判官噪声有多大」。

**负面 / 代价：**

- 结论是负的：**按当前合成规范，技能卡降低业务交付物质量**。技能库的接线价值（缺口关闭 8/9、
  本岗可达 134/151）与它的效果价值是两件事，前者成立不代表后者成立。
- 20 张卡的样本量下，Δ 的点估计精度是 ±0.6～0.7，`treat` 臂的 p 值在 0.0038 与 0.084 之间摆动。
  「更差」这个方向站得住，「差多少」站不住。

**后续动作（需人拍板，见 eval-report §6）：**

1. `何时不用` 的跨岗指引（1450 条里 801 条点名本岗调不到的技能）要不要改——涉及 S2 级重跑。
2. 678 对同 L3 孪生共现要不要合并——材料侧决策，不是技能库侧。
3. 跨 L3 语义近邻检测要不要进装配器——现有静态检查抓不到这一类误召。
4. **技能卡的正确用法要不要写进 preset 的 persona**：机制指向的不是改卡而是改**用卡的姿势**
   （先拿方法、再翻成经营方案）。这条在 preset 侧就能验，成本远低于重跑 S2。
