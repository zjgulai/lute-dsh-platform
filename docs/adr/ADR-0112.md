# ADR-0112 · 出货技能面不携带 `__pycache__` 字节码

- 状态：accepted（2026-09-17）
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/packaging/2026-09-17-skill-surface-pycache-exclusion.md)
- 相关：ADR-0056（机器路径只减不增）、ADR-0074（技能出货面选择：引用集 ∪ 白名单 − 受限）

## 背景

2.5.0 装配 r4 全绿后，对 `skills-presets.tar.gz` 做解包深检（守卫管不到 tarball 内部的二进制内容），
发现 7 个技能带 **18 个 `__pycache__/*.pyc`**。`.pyc` 的 `co_filename` 字段钉死源文件在构建机上的
**绝对路径**（`/Users/lute/...`）——这是 ADR-0056 机器路径红线的漏网载体：文本面的一切 grep 守卫
都读不到字节码里的路径。基线核对：2.4.1 release DMG 内同一 tarball 同样带这 18 个 pyc（历史既有，
非 2.5.0 回归），客户机上 Python 报 traceback 时会原样吐出构建机路径；且 cpython-312/314 字节码
在客户机解释器版本不匹配时只是死重。

## 决策

1. `select-skills.mjs --copy` 的 `cpSync` 加 filter：源路径任一段为 `__pycache__` 即不拷贝
   （净化出货副本，不动源树——源树里的 pyc 是解释器合法缓存）。
2. `--check` 同步新增判据：落位树里出现任何 `__pycache__` 条目即红。拷贝侧 filter 只保证
   「这次拷贝不带」；源树哪天再生成 pyc（有人手动跑过技能脚本）要靠校验侧拦住——
   两个机制缺一不可（「知道」要变成「拦住」）。
3. vendor 面（`dsh-overseas-skills/scripts/__pycache__/build_preset_catalog.cpython-314.pyc`，
   同为 2.4.1 历史既有）本轮**不**随动：它是无构建脚本的历史产物（stale lib 家族尾债），
   单独登记已知残留，避免本轮范围膨胀。

## 备选方案

- 在 `machine-path-baseline.json` 登记容忍：拒绝——这是在「明知载体」上盖容忍章，与 ADR-0056
  「只减不增」方向相反；且 2.4.1 已带不构成继续带的理由。
- 装配前删除源树 pyc：拒绝——修改源树（`~/.dsh/skills` 是运行时状态），拷贝侧过滤等效且无副作用。
- 打 tar 后 post-process 剔除：拒绝——晚于事实的单点修补，且 tarball 内改写无守卫闭环。

## 后果

- 2.5.0 起出货技能面 0 个 pyc（r5 实测：解包全树 `find -name '*.pyc'` = 0，技能 435 + preset 52 全数落位）。
- 源树 pyc 再生会在装配 `--check` 步骤显性红，不会再静默出货。
- 绿色验证：fixture Red/Green（带 pyc 树 → 判据红；净化拷贝 → check 绿）+ r5 真实装配全绿。
- 尾债不变：vendor 面 1 个 stale pyc 留待 overseas-skills 尾债族一并处理。
