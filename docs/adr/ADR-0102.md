# ADR-0102 · 门禁的分母必须由「被检查对象的完整集合」推出，而不是由「恰好读到的东西」推出

- 状态：accepted（2026-09-17）
- 决策记录：[2026-09-17-gate-scope-is-the-denominator](../notes/implemented/contract/2026-09-17-gate-scope-is-the-denominator.md)
- 关联：[ADR-0063](ADR-0063.md)（仪器假绿）、[ADR-0094](ADR-0094.md)（三态读数）、[ADR-0014](ADR-0014.md)（变更包硬门槛与豁免只减不增）、[ADR-0101](ADR-0101.md)（同族：交付清单侧的完整性判据）

## 背景

QG-003 / QG-004 / QG-005 三张卡各自被实测出一个 Red，形状不同、根因是同一个：

| 卡 | 实测的 Red（2026-09-17） | 读数 |
|---|---|---|
| QG-005 | 本地 `main` 超前 `origin/main` 两个提交、两个包被改 | 旧 `changedPackages` 射程 = **空集**（`main...HEAD` 在 main 上是自比较）；31 个 untracked 文件全不在集内 |
| QG-003 | 23 个带 `dsh.bundle.patch` 的候选 | 门禁报「核对 21 个」并 `passed=true`——2 个候选从分母里消失 |
| QG-004 | profile 的 `package.json` 写成截断的 JSON | 三个 profile 门禁**全部绿**：`files-sync` 一个字不报，`bundle-sync` 自述「对比 0/0 个 file: 依赖」 |

三者的共同点：**射程变小与「没有问题」在读数上同形**。旧实现各自有不同的收缩路径——
自比较的 diff 表达式、读不到就 `continue`、把 JSON 解析失败吞成 `{}`——但结果一样：
少看的那部分不会让任何东西变红，只让报告里的数字更小，而那个数字当时**没有任何东西在核**。

## 决策

三处判据统一改成「**分母 = 被检查对象的完整集合**，每一个对象必须落在且只落在一个桶里」
（`expected = checked + skipped + failed`），并且**空射程与「都合格」必须是两种读数**：

1. **`changed-packages`（QG-005）**：射程由 `merge-base(HEAD, 基线)` 加四类工作树来源
   （committed / staged / unstaged / untracked）求并集得出，rename 同时映射旧、新路径。
   基线解析顺序为 CI 事件 SHA（`DSH_GATE_BASE_SHA`，必须可达且确为 merge-base）→ 分支
   upstream → `origin/main`；**刻意不包含本地 `main`**（与 HEAD 常常是同一个对象，落回它
   就是自比较）。基线不可解析一律判红，绝不退化成空集。根治理文件变更按已登记规则
   归类，工作区级文件把射程扩到全部包。
2. **`plugin-entry-contract`（QG-003）**：入口**按清单解析**（`exports['.']` 的条件目标
   依次 `import`/`default`/`require`/`node` → `main`），并跟随 `export * from` 转出口；
   候选被分成 `plugin-apply` / `plugin-service` / `library` / `unresolved` 四种，**四种都进
   分母**，后两种判红（判红文案写明两种可能，由人决定）。`apply` 型核对 inject 名单与
   **未加 `try` 防护**的 `ctx.<服务>` 属性访问；`service` 型核对 inject 是否为 **static** 字段。
3. **`profile-*`（QG-004）**：期望集从「这份 profile 声明了什么」推出——受管包按
   **完整相对路径**（`packages/<组>/<包>`）后缀对齐，不按 basename（basename 撞车时两个包
   会互相顶替）。manifest 解析失败**直接判红**；期望集里的包在目标目录缺失**判红**而不是
   `continue`；三个断言面（metadata / files / bundle）共用同一个期望集、各自结账。
   **只允许一种 skip**：profile 根整体不存在。

三处共同的记账契约：结果按 QG-001 的规范三态给出对象级账目，`expected` 是分母、
`skipped` 必须是带类型的显式跳过（`typedSkips`），空射程只能报 `skip` 不能报 `pass`。

## 备选方案

- **只加断言、不改记账**：例如在 `changedPackages` 里补一条 `git ls-files --others`、
  在 `profile-*` 里把 `catch {}` 换成 `console.warn`。否决：射程收缩本身仍然不产生读数，
  下一次换一种收缩方式（换个 diff 表达式、换个 `continue` 条件）依然静默。
- **按卡各写一套断言与各自的测试**：否决。三张卡的 Red 是同一根因的三个实例，
  分头修会让「分母 = 完整集合」这条契约散落在三处，下一张卡再遇到就只能靠纪律守。
- **扩大判红面来兜底**（例如把「受管包没被这份 profile 声明」也判红）：否决。
  本机 profile 裁剪是合法的，把合法状态判红只会换来一条豁免，而豁免会让真信号一起失效
  （ADR-0014 的豁免只减不增正是为了这个）。因此「受管但未声明」只进读数。
- **引入 YAML / ES 模块解析依赖**：否决。判定器保持无新增依赖的最小解析器，
  并且**不认识的形态一律判红**（`unresolved`），而不是当成「没有这个东西」。

## 后果

- 三处判据现在都会在射程收缩时判红，并点名是哪个对象掉了。
- `plugin-entry-contract` 从**从未接线**（模块存在、无人 import）变成 required gate 的一项，
  并带一个反向自测项。此前它是「写了但从没跑到」的形态（P-04）。
- `changed-packages` 在无改动时由老式 `pass`（被规范化成 `checked=1`）改成 `skip`——
  「没看」不再被记成「看过且没问题」。
- 代价：三处都要求判定器接受**注入的读取器**（`readText` / `exists`），装配处负责提供。
  这是 QG-006A 的隔离契约，测试因此可以在内存树上跑，不必造真文件树。
- 遗留边界（已写进各自模块注释，不留给人推断）：模板字面量插值里的 `ctx.x` 看不见；
  `new URL(..., import.meta.url)` 之外用变量拼路径的包内数据文件不在 QG-013 的判据面内；
  `plugin-service` 只核对 inject 的字段形态，不核对它要哪些服务。
