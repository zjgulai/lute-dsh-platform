# ADR-0065 · 生产模式禁用 HMR 热更：运行中替换 app bundle 导致的整屏白屏按机制修复，安装器替换前必须退出运行实例

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：agent（本次实测、定级与守卫设计）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-13-hmr-production-guard.md)
- 相关：ADR-0008（基座只 pin 不改）、ADR-0014（门禁是硬门槛）、ADR-0056（DMG 发布 SOP）、ADR-0063（固定证书签名——本 ADR 附带确认了「对已装 app 直接手术主进程/宿主侧文件会破坏 seal，必须重签」）

## 背景

2026-09-13，`assemble.sh` 重打包产物在应用运行中被替换到 `/Applications/DSH Desktop.app`，随后出现**整屏白屏**：宿主日志零报错、`startup.jsonl` 记 `rendererStatus: healthy`，但窗口纯白。`Cmd+R` 重载 renderer 即恢复，排除 combo rev 失配（那是关机态改字节的机制）与 root 槽竞态（该形态右侧面板正常）。

机制：宿主 `dsh-client-hmr` 无条件 stat-poll 每个 client bundle，变化即 re-hash 并推 `rebuilt` SSE 帧；renderer 收到帧即对每个插件执行 `invalidate → prefetch → refresh` 热更。生产模式没有 dev:web 的完整热替换 runtime，50+ 插件同时热更时渲染器崩溃。放大因素：2.0.5 重打包后 electron-runtime 分块的 `console-message` 转发补丁丢失，renderer 崩溃在宿主日志零痕迹。

## 决策

1. **机制层**：`dsh-client-hmr` host 侧 `rehash` 加生产守卫——`process.defaultApp !== true && process.env.DSH_DEV !== "1"` 时只推进 watch 基线、不 re-hash、不推 rebuilt 帧；下次完整重启从新字节重新 compose。`DSH_DEV=1` 为逃生门。
2. **流程层**：`packaging/installer/install.sh` 新增 0b 步骤——替换 `/Applications` 前检测并退出运行实例（15 秒超时，未退出即中止）；SOP（`docs/sop/dmg-release.md`）同步补检查项、红线与异常表。
3. **可观测性层**：`electron-runtime-*.js` 恢复 `console-message` 转发（兼容新旧 Electron 事件签名）。
4. **打包基线**：以上两补丁固化为幂等脚本 `dsh-patches/runtime-guards/apply-fixes.sh`，接入 `assemble.sh`（brand-replay 后强制重放，缺失即失败），随包分发至 `tools/runtime-guards/`，登记进 `patches-manifest-v2.md`。
5. **签名纪律**：对已装 app 直接改 unpacked 主进程/宿主侧文件会破坏 seal（2.0.5 固定证书下 `codesign --verify --strict` 实测失败），必须用 `LUTE Code Signing` 证书重签恢复；今后此类改动只走「打包时重放 + 统一签名」。

## 备选方案

- 只改 renderer 端（忽略帧）：治标，宿主仍 re-hash 推帧、manifest 与页面脱节。
- 改 vendor 源码：违反 ADR-0008，否决。
- profile override 改宿主核心包：宿主内置包不走 loader overlay，不可靠。

## 后果

- 生产环境不再有任何运行中热更能力（本就无 dev:web runtime，属预期）；开发模式行为不变。
- `assemble.sh` 对 runtime-guards 脚本存在性硬失败——守卫视为发货必需品。
- 补丁锚点随基座版本可能漂移；升级后跑 `--verify-anchors` 体检，漂移时手工适配。
- 本机 app 已重签恢复；TCC 授权因固定证书身份不变而延续（ADR-0063 路线）。
