## 背景

ADR-0047 收尾时留了下一入口：**「787 条悬空代码路径 + 461 张截断代码」**，并断言两者
「都需要 `paper2skills-code/` 源树」。本轮按这个入口动手，第一件事是复核它的两个数 ——
**两个前提都不成立**，而且都能复现地说明错在哪。

### 一、「787/805 悬空」量错了基准，且数本身不复现

上一轮是拿 `/Users/lute/project/paper_to_skills/paper2skills-code/`（**199 个 `.py`**）当基准量的。
那棵树是残缺副本；全量树在 iCloud（`~/Library/Mobile Documents/com~apple~CloudDocs/paper_to_skills/`，
**15,694 个 `.py`，0 个未下载占位符**），且本地那棵是它的**严格子集**（本地独有目录 **0** 个）。

| 基准 | 树内 `.py` | 838 条路径解析 | 悬空 |
| --- | --- | --- | --- |
| 本地 `project/paper_to_skills` | 199 | 22 | **816** |
| iCloud 全量 | 15,694 | **838** | **0** |

两个基准下都**复现不出 787**（本地基准是 816）。所以那条断言整个作废，不是「方向对但数不准」。

### 二、源树里没有那份代码：同名不同物

拿到全量树后发现更要紧的事 —— **路径解析成功，并不等于找到了卡里那份代码。**

树里并存两代：

| 代 | skill 目录数 | `.py` 行数中位 | 脚手架命中率 |
| --- | --- | --- | --- |
| 带编号（`01-因果推断`/`04-供应链`…，旧·富代码） | 41 | 373 | **0/41** |
| 无编号（`logistics`/`supply_chain`…，新·脚手架） | 1,017 | 70 | 772/1017（**76%**） |

而卡的 `code_path` **838/838 全指向无编号那一代**。把卡里预览的 `def`/`class` 名拿到整棵树里找：
**召回 25.0%**（962/3,854），**746 张卡（64%）零命中**。逐个对照 `logistics/3d_bin_packing_optimization`
更直白：卡里 60 行是 FFD 装箱算法（`class Item` / `get_rotations()`），树里同名目录只有 72 行
通用脚手架（`generate_logistics_data` / `run_analysis`），SKILL 抬头一样、正文无关。

**同一个技能名下放着另一份代码，比悬空指针更危险**：悬空会响亮报错，同名会静默给错。

### 三、截断是真的，但「补不回来」的原因变了

源站对代码预览设的是**硬上限**，不是偶发截断：

- 源站自述行数（`<span class=code-meta>60 行 · 可运行</span>`）**最大 60**，1,150/1,338 张正是 60，无一超过。
- 我方卡转发后：**457/1,279 张 Python 节选连 `ast.parse` 都过不了** —— 断点切在语句中间。
- 卡页还声明「代码块数量：N」（最多 6），而每卡实际只发布了 **1** 个融合节选。

所以上一轮「要修需要源树」的方向是错的：源树取到了，但**它里面不是这份代码**。⑥~⑦ 那批
富领域实现（抬头写 `Author: paper2skills / Date: 2026-06-06`）已被 6 月 22 日的脚手架重新生成覆盖 ——
`git log -S'def run_analysis(data)' -- paper2skills-code/` 只有一条提交 `75344064`，
`git log -S'class OWLClass' -- '*.py'` 全历史为空。**预览是这份代码唯一存世的地方。**

### 四、卡面的三处声明与实物不符

| 卡面声明 | 实测 |
| --- | --- |
| 段名「⑦ 代码模板」 | 是**节选**：源站上限 60 行，1,150 张顶在上限上 |
| 「N 行 · **可运行复制**」 | 457 张不能直接运行，复制即 `SyntaxError` |
| 「代码块数量：N · 路径：`paper2skills-code/…`」 | 806 张在承诺一个代码位置；该树不在本包内，且同名不同物 |

## 决策

### 一、⑦ 段改名「代码节选」，卡面按**实测口径**渲染，不转发源站自述

新增 `lib/card-render.js#renderCodeSection()`（纯函数，有单测），逐卡渲染三件事 + 一条转述：

1. 明说「本节是源站卡页的代码预览节选，不是完整实现」；
2. 源站 60 行上限 + 本卡是否**已顶到上限**（顶到 = 其余代码源站未发布）；
3. 这段节选**能不能解析**（`ast.parse` 通过 / 在断点处被截断、不能直接运行 / 非 Python 不做断言）；
4. `路径：` 只作**转述**，并写明「该代码树不在本包内，本包无法据此校验其内容」。

源站自述原文不丢：留在 `data/code-availability.json` 的 `raw_meta` 里，审计随时可回看。
**理由**：忠实转发一句被证伪的自述，是把源站的问题搬进技能库。

### 二、判据入 `data/code-availability.json`，并给上限加双向守卫

`scripts/build-code-availability.py` 从卡自身复算（不依赖外部树，不依赖网络）：
`declared_lines` / `lines` / `capped` / `parses` / `syntax_error` / `declared_blocks` / `path` / `raw_meta`。

上限判据用**源站自述行数**而不是内容行数 —— 内容行数会因尾部换行在 58–60 间浮动，
而「N 行」是源站自己的口径。两处守卫：

- 有卡自述 > 60 行 → `exit 1`（源站口径变了，不许静默漂移）；
- **没有任何卡顶到上限** → `exit 1`（判据失效，而不是「真没截断」）。

`--check` 断言磁盘产物与脚本一致，由 `test/code-availability.spec.mjs` 在 `pnpm test` 里跑。

### 三、装了库的卡面由 `verify-install.mjs` 守住

新增 `checkCodeSection()`：卡面**不得**出现源站那句「可运行复制」，且有代码时必须同时说清
「节选 + 上限 + 能否解析」三件事。三种合法形态：正文带代码 / 代码移入 `references/code.md`
（口径随代码一起进参考文件）/ 卡页本就没抽到代码。

### 四、判据先验伪，再报数

- **红测**：把 5 条新判据喂给上一轮的实现（`fenceCodeIfNeeded`，原样重建），
  **5/5 红**；喂给新实现 5/5 绿（`.scratch/p2s-code-recovery/red-old-impl.mjs`）。
- **校验器验伪**：往一张已装卡注入「可运行复制」并抹掉口径，`verify-install.mjs` 报出 2 项问题；
  恢复后 0 问题。

## 备选方案

- **按 `路径：` 把树里的代码补进卡里**：树里那份是**脚手架**，补进去等于用一份无关代码
  冒充本卡的实现，比现在的节选更坏。已否决。
- **把树或路径排除在卡外，删掉 `路径：`**：那是源站的溯源记录，删掉就丢了一条线索。
  改为「转述 + 声明不在本包内」。已否决原方案。
- **把 461/457 张不可解析的节选删掉，只留有代码的**：删掉的是**唯一存世的实现线索**，
  且读者能从节选看到算法结构。改为如实标注「不能直接运行」。已否决。
- **卡里嵌源站绝对路径（iCloud）**：那是作者机器的私有位置，对任何别的读者都是断链，
  比悬空更差（看起来像能打开）。已否决。
- **修 ⑦ 段沿用 `fenceCodeIfNeeded` 只补围栏**：围栏补了，但卡面仍在说「可运行复制」。
  围栏解决的是「缩进看不见」，本轮要解决的是「声明是假的」。已由 `fenceCode()` 取代。

## 影响

正面：

- 卡面三处假声明 **清零**：1,338/1,338 张 ⑦ 段标题改为「代码节选」，
  「可运行复制」出现次数 **1,283 → 0**（实测已装库 **0** 处）。
- 每张卡现在自带「能不能直接跑」的答案（实测已装库）：**814** 张明说语法完整（但仍未必可独立运行）、
  **455** 张明说不能直接运行（同状况另有 2 张移入 `references/`）、**4** 张标注为非 Python 片段、
  **55** 张明说未附代码、**10** 张代码移入 `references/code.md`。
  上限口径分桶：**1,140** 张明说已顶到上限、**133** 张明说未到上限。
- 「路径」从一句承诺变成一条**自带边界**的转述。
- 上限判据有双向守卫，源站口径变了会响亮失败而不是静默漂移。

代价与边界：

- **代码一行没多**：源站只发布了 60 行，本轮不新增任何实现。
  461/457 张不可解析的根因在源站截断，本包无法补 —— 这一点 ADR-0047 说对了结论、
  说错了理由（不是「源树没拿到」，是「源树里不是这份代码」）。
- 口径文字约 +500 B/卡，**移入 `references/code.md` 的卡 5 → 10 张**（超 12 KB 才外移的门槛没变）。
- 逐字节保真不再是一句笼统的话，拆成三类（实测已装 1,338 张）：
  **1,082 逐字节相同** · **188 仅末尾一行纯空白差**（源站被截断的第 61 行残留缩进，
  装配按段落 `.trim()` 时去掉，无语义内容）· **3 处刻意的密钥脱敏**（`SECRET_PATTERNS`）。
  非空白、非脱敏差异 **0**。ADR-0047 那句「逐字节相同 1,283/1,283」应以此为准。
- 本包整体仍是 **untracked**（`?? packages/capabilities/dsh-paper2skills/`），改动未提交。
- 回滚：`staging/backup/skills-p2s-pre-rebuild.tar.gz`（上一轮的 1,338 张，3.47 MB）。

后续：

- 「把 60 行节选变成可运行实现」需要重跑 6 月 6 日那一代生成器，而它的产物已被覆盖、
  生成器不在任何一棵树里（`grep -rl 'code_preview'` 在 `paper_to_skills/` 下零命中）。
  这是一条**独立的、口径完全不同**的工作（要从论文重生成代码），不属本轮。
- 带编号的旧富代码代（41 个目录、中位 373 行）**没有任何卡在引用**。它与 1,338 张卡
  是什么关系（早于批量生成？被取代的试点？）未查清，可能是下一轮的入口。
