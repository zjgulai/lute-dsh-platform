## 背景

「出海技能」页（`packages/capabilities/dsh-overseas-skills`）此前的分类轴是 **8 大场景 / 28 细分场景**
（延续 [ADR-0041](ADR-0041.md) 提到的同一套技能目录），页面能回答「这个技能属于哪类业务」，
答不了「它服务于组织里的谁」——组织骨架（4 面 / 8 责任域 / 50 岗位）在页面上完全不可见。

用户的要求是**照算法技能页的分类标准重构**，但换入口：L1 场景 → 4 面 → 责任域 → 岗位。
在动手前先量了既有事实：把 `scripts/role-presets/skill-map.json`（151 条中文责任名 → 技能供给，
喂 50 个 preset 的**接线**）反查成「技能 → 岗位」，222 个出海技能里

```
有岗 135　无岗 87　跨多岗 61　岗位有供给 48/50（AGT-005、AGT-049 零供给）
```

**87/222（39%）没有岗位可站**，而这份表的本职是接线、不是归位。用户据此选择先补全判定再重构页面。

## 决策

**1. 归位判定是新增事实，必须有它自己的家，且不得顺手改接线。**

`packages/capabilities/dsh-overseas-skills/manifest/role-assignments.json` 是唯一事实源，
`lib/role-map.js` 由 `scripts/build_role_map.py` 从它编译而来（与 `lib/catalog.js` 同样的
「manifest 事实 / lib 产物」分工）。每条挂载带 `source`：`skill-map`（继承既有接线表的人工先验）
或 `assigned`（本轮判定新增），并保留该条的证据与删除理由。

不写进 222 个已安装技能的 frontmatter（会被上游重导覆盖，且等于越权改他人资产）；
也不扩写 `scripts/role-presets/skill-map.json`（那会连带改动 50 个 preset 的接线）。

**2. 判定必须可机械复核：每条挂载给两条逐字证据，编造即红。**

每条 `技能 → 岗位` 必须附 `from_skill`（该技能文本中的连续子串）与 `from_role`（该岗位
mission / artifact / 责任名中的连续子串）。校验脚本断言二者都是**原文连续子串**、责任名逐字属于
该岗三条之一、岗位 id 在 50 个之内、同岗不重复挂载、≥3 岗不得标 high，
并且**既有映射被删除时必须写明理由**（静默删除直接判错）。
判定分 10 批执行（每批 22–29 条），全部一次通过校验。329 条挂载里 197 条继承既有接线表、
132 条是本轮新增；另有 24 条既有先验被**显式删除**（涉及 20 个技能），每条都写了删除理由。

**3. 四层下钻，且三条计数必须与用户对得上。**

树的形状是 L1 场景 → L2 面 → L3 责任域 → L4 岗位 → 技能卡。因为一个技能可以同时归多个岗位
（本轮 251 条里有 82 条跨岗，最多的一条例外挂到 6 个岗位），所以：

- **卡片数 ≠ 行数**（222 张卡渲染成 319 行）——页面两个数都写，否则「319 张技能」是假读数；
- **零卡岗位**与**未归岗技能**必须有一等位置（诊断条 + 场景内的「未归岗」分组），
  没有位置就等于不存在（[ADR-0041](ADR-0041.md) 的同一课）；
- **归位 ≠ 接线**照旧分开显示：卡片挂在本岗下是归位，本岗 preset 是否真挂载它是接线，
  两者不一致的地方（接线了但未归本岗）单独成条列出。

**4. 层头像（4 面 + 8 责任域）在两个包里各烘一份，靠跨包断言防漂移。**

两个页面分属不同插件、都要能独立渲染，因此 `lib/layer-icons.js` 是从 lute-brand-icons 的同一份
品牌清单里按同一组 brandId 烘出来的第二份字节。代价由测试兜底：本包断言 12 条 data URI
与 `dsh-algo-skills-local` **逐字节相等**，不一致即红。

## 备选方案

- **页面直接用既有接线表反查**（最小改动）：省一轮判定，但 87 个技能无处可站、61 个跨岗由接线
  语义决定而非归位语义——用户已明确否掉这条。
- **把判定写进技能 frontmatter**：页面零成本读取，但 222 个技能是 Accio 导入的他人资产，
  上游重导会覆盖；且违背「一份事实一个家」——判定属于页面侧的分类，不属于技能本体。
- **扩写 `skill-map.json`**：会改 50 个 preset 的 skill-subset 接线，把「归类」与「接线」两件事
  绑死，而 [ADR-0041](ADR-0041.md) 的教训正是这两件事必须能分开看。
- **责任域只做面内的分组标题（三级）**：视觉更紧凑，但用户明确选了四级下钻。
- **让 AI全栈 29 条也进场景树**：它们没有场景轴（分类是 fs-*），本轮的判定已产出备用，
  但页面挂法未定，故保持在原分组视图里，不进树。

## 后果

正面：251 条技能第一次有可复核的岗位归属（有岗 217 / 329 条挂载，比既有 135 条翻一倍多）；
「归位 vs 接线」的落差在页面上可见；AGT-025（零售渠道与B2B拓展）从零卡变有卡；
零卡岗位从 2 个缩到 1 个（AGT-005 内控审计与独立复核仍无供给）；判定过程与证据全部入库可审计。

负面：判定是**语义判断**，其中 48 条标为 `low`、180 条标为 `medium`（跨岗或链到使命而非责任名）仍待人工复核；
同一张卡多岗导致 319 行 > 222 张卡，页面必须解释这个差；12 枚层头像存在两份字节，
防漂移完全依赖那条跨包测试；AI全栈 29 条的判定暂时只入库、不上面。

后续：用户目视验收本页；之后再谈 1338 张 p2s 技能的优化方案（用户已列出第三步）。
