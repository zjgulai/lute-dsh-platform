# ADR-0064 · shell 变量名边界纳入门禁：`$VAR` 紧跟多字节字符是硬故障，不是风格问题

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：agent（本次实测、定级与守卫设计）
- 决策记录：[Note](../notes/implemented/contract/2026-09-13-shell-var-multibyte-guard.md)
- 相关：ADR-0014（门禁全量硬门槛；新校验一律阻塞）、ADR-0057（「靠人记得不是工程解，机读判据才是」的原始出处）、ADR-0009（一份事实只有一个家）

## 背景

### 一次装配中断暴露的是一类问题，不是一处笔误

2026-09-13 首次装配 2.3.0，跑到 §5「装配安装器与工具」时退出码 1：

```
build-setup-app.sh: line 43: APP<坏字节>: unbound variable
```

出错行是：

```bash
say "编译完成: $APP（身份：${LUTE_SIGN_IDENTITY}）"
```

成因不是拼错变量名，而是 bash 的词法：`（` 的字节 `EF BC 88` 被 `/bin/bash` 3.2.57 当作标识符字符**并入变量名**，于是引用的是从未定义过的「`APP（`」。脚本开头是 `set -euo pipefail`，未定义变量直接终止进程。

实测（构建机同版本 bash）：

```
$ APP=/tmp/x bash -c 'set -u; echo "$APP（身份：y）"'
/bin/bash: APP?: unbound variable          ← 复现
$ APP=/tmp/x bash -c 'set -u; echo "${APP}（身份：y）"'
done: /tmp/x（身份：y）                     ← 加花括号即解
```

### 全仓扫描：4 处现场，其中一处最凶

对全仓 `*.sh` 与「非 `.sh` 但带 shell shebang」的文件逐字节匹配 `$[A-Za-z_][A-Za-z0-9_]*` 紧跟码点 ≥ 0x80，得到 4 处**参与展开**的命中（另有 3 处只在注释里，注释不参与展开，无害）：

| 位置 | 形态 | 后果 |
| --- | --- | --- |
| `packaging/scripts/build-setup-app.sh:43` | `$APP（` | 本次装配中断的直接成因 |
| `packaging/scripts/release-publish-guard-test.sh:107` | `$RC，` | 断言**失败分支**自身炸掉，测试报不出真实原因 |
| `packaging/scripts/release-publish-guard-test.sh:131` | `$RC，` | 同上 |
| `packaging/installer/pkg-postinstall.sh:46` | `$RC）` | **错误报告行**自身炸掉，客户看到的是无关的 unbound variable 而非原始安装失败原因 |

最后一条是这类缺陷的典型形状：它只在**已经出错**的路径上执行，于是把一个可读的错误替换成了一个误导性的错误。

### 「知道」已经存在，但没有变成「拦住」

`packaging/scripts/ensure-signing-identity.sh:27` 里早就写着：

> `$IDENTITY」` 会被解析成变量名 "IDENTITY」" 并报 unbound variable。

即这条陷阱在本仓库有**成文的认知**，却仍然被新写了 4 次。这与 ADR-0057 处理「产物原子就位」时得出的结论同构：把一条必然发生、失败时又具误导性的缺陷，记在人的记性上不是工程解。

## 决策

1. **新增门禁校验 `shell-var-multibyte`，命中即红（阻塞）**，登记进 `scripts/gate.mjs` 的 `CHECKS`。判定逻辑是纯函数 `checkShellVarAdjacentMultibyte`，落在 `scripts/gates/checks.mjs`，随 `pnpm run gate`（quick 模式）执行——本校验只读文本、无外部依赖，没有理由推迟到 `full`。

2. **判定规则必须精确到「是否参与展开」**，否则硬门槛会被假红污染：
   - **注释不算**：`#` 在未加引号且位于词首时才开始注释；`STAGING=""   # 已属于 $REL…` 这类行尾注释里的写法不报。
   - **位置参数不算**：`$1（` 中 bash 只按数字取参，`（` 不会被并入，故判定正则要求标识符首字符为 `[A-Za-z_]`。
   - **只扫 shell**：本陷阱是 bash 词法问题；其他语言里两个字面量相邻不会出事，不扩大到全仓文本。

3. **修复 4 处现场，统一改为 `${VAR}` 形式**（随本 ADR 同批提交）。加花括号把变量名边界钉死，是这一族写法唯一无歧义的表达。

4. **同一提交附 Note 记录取证过程**，并按 ADR-0009 让 ADR 与 Note 互链。

## 备选方案

- **只修 4 处，不加门禁。** 零新增成本，但本仓库对同一问题的既有判据（ADR-0057）已经否决过这个形状：一条已经写进注释的认知都没能拦住 4 次新犯，说明问题不在认知而在强制力。
- **全仓统一补花括号（纯风格化），不做语义判定。** 会让 3 处无害的注释命中也被要求改写，且「注释里的示例」本身有说明价值——`ensure-signing-identity.sh:27` 那条注释正是在解释这条陷阱。为了整齐而删掉解释，得不偿失。
- **用 `shellcheck` 兜。** 本机未安装（`command not found`），未实测其对这一形态的判定；且引入一个仓库外二进制会让门禁多一个非仓库内、版本不受控的依赖。仓库既有的门禁风格是自带纯函数 + `node:test`，本校验沿用同一形状。
- **写成 git pre-commit 钩子。** 钩子可被 `--no-verify` 绕过、且不进版本库的强制面；本仓库的既有契约是「一条命令给证据」（ADR-0014），门禁是那个唯一的强制面。

## 后果

- **正面**：这一族「变量名被后续字符吞掉」的缺陷从此不可能再进入树干；其中收益最大的两处（错误报告路径）原本会把真实故障替换成误导性故障，属于排障成本被静默放大的那一类。校验是纯文本、零外部依赖，运行成本可忽略。
- **负面**：门禁多一条要维护的判定；注释/位置参数的边界规则需要随 bash 行为演进复核（当前规则按 `/bin/bash` 3.2.57 实测标定，本仓库出货脚本正跑在该版本上）。
- **后续动作**：① 本 ADR 落盘时 2.3.0 尚在装配中，四条现场修复的**实际效果**由该次装配的完成情况验证（首轮中断于 §5，本轮应通过 §5）；② 若将来出现 `${VAR}` 之外的合法写法（如 `$VAR'` 单引号紧邻），按「命中即红」处理并在本 ADR 追加说明，不放松为警告。
