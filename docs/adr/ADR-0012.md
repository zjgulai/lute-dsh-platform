# ADR-0012 · 包名不改、目录名归一、新增身份三元组门禁

- 状态：accepted
- 日期：2026-09-11
- 决策者：用户（lute）+ agent（grill-me 决策树 N3）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-11-lute-refactor-three-phase.md)

## 背景

实测当前 6 种命名空间并存：`dsh-*`（多数）、`@deepseek-ai/dsh-*`（auto-compact、deepresearch）、`@yuxianglin/*`（browser）、`@furongjun1999/*`（memory）、`@etony668/*`（task-board），以及无包名的目录 `dsh-skill-title-fix`。`private` 标记同样混乱：8 个标 `private: true`，其余未标但实际都不发布 npm，唯一带 `publishConfig` 的是 `dsh-loopx-plugin`。（**2026-09-11 时序注记**：此处列举的是归位前的现状；`dsh-skill-title-fix` 那一项已于同日作为已完成的补丁项目归档出工作树——其补丁已列入 [patches-manifest-v2](../..//dsh-patches/patches-manifest-v2.md) 并逐项验证通过。）包名被三处运行时机制盯着——live profile 的 `file:` 依赖、profile 内的硬链接 inode、宿主补丁的锚点文字。

## 决策

**不改包名，目录名按 ADR-0011 归组统一，并把命名分叉登记为显式元数据 + 门禁：**

1. 目录名按能力组路径统一（`packages/<group>/<pkg>/` 形态中的组与目录名）。
2. **包名保持不变**——外部来源的包名不动；自研包补 `private: true` 以免误发布。
3. 每个受管 `package.json` 新增身份三元组：`luteOrigin`（`self` / `internalized` / `npm-pinned`）、`luteOwner`、`lutePublish`（`true` / `false`）。
4. 新增门禁 `verify-package-identity`：缺字段、取值非法、`npm-pinned` 出现在仓库内、`lutePublish: true` 但未标 `private: false` 均拒绝。

## 备选方案

- **A 目录名与包名同步改名**：被否决——会打断 live profile 的 `file:` 依赖、打破硬链接 inode、并使 35 个补丁中涉及包名的锚点文字失效，风险与收益不成比例。
- **B 包名全不动、不建元数据**：被否决——命名空间分叉仍无记录，无法阻止继续新增。
- **D 统一改名为单一前缀（如 `@lute/dsh-*`）**：被否决——与 A 同风险；且会把内部化包的「上游来源」信息抹掉，削弱退役判断依据。

## 后果

- 正面：命名分叉从「混乱」变为「有记录的显式事实」；新增包无法再引入无来源命名；内部化包保留上游来源，便于上游修复后退役。
- 负面/代价：包名与目录名不一致成为长期事实（需在组 README 与目录墙中显式对照）；未来若真需改名，仍需承担一次 profile 重装重链成本。
- 后续动作：一期为自研层包写入三元组并落门禁；二期在目录墙中呈现「目录名 ↔ 包名 ↔ 来源」对照表。
