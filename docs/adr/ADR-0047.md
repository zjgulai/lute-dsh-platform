## 背景

1338 张 p2s 技能卡在 `~/.dsh/skills/p2s-*/` 供 50 个岗位 preset 装配。用户要求给出「1338 张卡的优化方案」。
动手前先做只读体检（`.scratch/p2s-optimize/`），结论是本轮最重要的发现：

**三个全库级缺陷各自只由源码里的一行造成，而缺陷的载体是流水线，不是那 1338 个文件。**

| # | 位置 | 那一行 | 实测后果 |
| --- | --- | --- | --- |
| A | `extract-cards.mjs` `strip()` | `.replace(/[ \t]+/g, ' ')` 对整段文本生效，含 `<pre><code>` | 1338/1338 张卡的代码最大缩进恒为 **1**（`=0` 的 0 张、`>1` 的 0 张）→ 2,580,415 B（23% 语料）不可解析；而卡片上印着「可运行复制」 |
| B | 同上 | 实体表只列 `&#39;`，源站写的是 `&#x27;` | 689/1338 张（51%）代码残留 HTML 实体 |
| C | `assemble-skills.mjs` `isPlaceholder()` | `if (t.length < 40) return true` | **1,440 处真内容被判为占位**并替换成同一句假话；其中 1,041 处是论文出处（arXiv ID 通常 10–30 字）、171 处 ROI 数字、168 处算法名、60 处问题陈述 |

C 的判据可以自洽反证：已装库里只剩 8 张 ⑧ 有真内容，恰好是唯一 ≥40 字的（4–6 个 arXiv ID）。
`docs/test-report.md` 记的「跳过 4,520 处占位段落」= 3,074 真占位 + 1,440 误判 + 6 处双重计数，
数字一直是对的，只是**没人拆开过这 4,520 里有多少是真的**。

同时发现：`scripts/role-presets/verify-lossless.mjs` 的 L1–L10 测的是 **50 个岗位 preset**
（其 L8 只断言「引用的技能存在」），**没有任何一层门禁测过这 1338 张卡的内容**。
本仓库已发生 4 次「提升来自修门禁而非改资产」，故这次先给这两个脚本补 0 → 19 条回归测试。

出处是另一半问题。`generated/cards.json` 里 1,049 张卡带 arXiv ID（1,152 个去重），
但 `data/arxiv-metadata.json` 对账后：81 张是 `2305.12345` 这类占位号（`2305.12345` 被 **19 张卡**共用），
抽样实查 6 个「唯一号」4 对 2 错 —— `Skill-3D-Bin-Packing-Optimization` 的 `2406.12089`
是凝聚态物理论文《Many-Body Quantum Geometric Dipole》。

## 决策

### 一、A/B/C 三行改在流水线里，重跑，不手改 1338 个文件

- A：`<pre>` 块先取出、后放回（`lib/html-text.js` 的 `PRE_RE` 守卫），块内只解实体去标签，**不压空白、不并空行**。
- B：实体解码改为通用数字引用（`&#\d+;` 与 `&#x[0-9a-f]+;`），`&amp;` 最后解以免二次解码。
- C：判据**只留「拼法」一条，不含长度**（`lib/card-render.js` 的 `isPlaceholder`）。
- 附带：`fenceCodeIfNeeded()` 给 ⑦ 段补 ``` 围栏（源站是 `<pre><code>`，抽文本时围栏信息丢失，
  实测 1338 张卡一个反引号都没有）；占位说明改为**按段落各说各的**
  （原句「实际输入/输出规格见下方『输入 / 输出契约』」在论文出处、ROI、算法逻辑这三类上共 432 处是错的）。

两个纯函数拆到 `lib/html-text.js` / `lib/card-render.js`，可测；这两个脚本此前**测试覆盖为 0**。

### 二、出处按档位渲染，**不做无差别还原**

把「主题对不对」与「这个号能不能单独采信」拆成两个正交的量（`data/provenance.json`，入库）：

- `grade`：VERIFIED / LIKELY / UNDECIDABLE / MISMATCH / NOT_FOUND / NO_ID
- `flags`：`fake_pattern` / `not_found` / `shared_by_N` / `id_vs_named_conflict`

⑧ 段按 grade 分行文：已核验的给出号 + 论文标题；错配的点名「这个号其实是哪篇」并判**无论文来源**；
UNDECIDABLE **不做断言**（判不了 ≠ 判为假）。

**理由**：还原一个指向别的论文的号，比留空更危险 —— 它看起来像一个可点开的出处。

### 三、判据必须先自测再报数

- 真值来源：`paper2skills-vault/` 有 41 张卡的 `paper_id` 过了逐字引文门禁。
  在它们上判对 **38**（VERIFIED 32 + LIKELY 6），假阴性 3（**7%**）。
- 抽样复核：随机 12 张 MISMATCH 逐个人判 **12/12 判对**；随机 8 张 VERIFIED **8/8 判对**。
- 故报 **MISMATCH 计数 515，真值约 485**（计数偏高约 7%，是判据自身的假阴性，不是资产变差）。

## 备选方案

- **只修机器（甲）**：最快拿到干净语料，但修完之后 1,049 张卡会带着一批真假掺半的 ID 出现在卡片上，
  看起来像真的。已否决。
- **无差别还原 1,041 个 arXiv ID**：等于把 p2s 项目自己封堵过的 `G2-BASIS-CONTRADICTION`
  （G2 漏洞 #10）在技能库里重演。已否决。
- **收缩供给（丙）**：把 1338 当候选池，按 L7 实测效果只保留真正接线的子集。规模太大，
  且它依赖的 L7 结论（给卡后交付物反而更差，holdout Δ −0.95）只是 20 张卡的抽样，不足以支撑动 50 个 preset。
  用户选择先做乙，此路径保留待议。
- **逐张手改 1338 个文件**：三行改完重跑即可拿到同样结果，手改无法复核也无法重放。已否决。

## 影响

正面：

- 假占位句 **4,514 → 0**；⑦ 代码最大缩进中位 **1 → 12**（缩进 >1 的卡 0 → 1,246）；
  残留 HTML 实体的卡 **699 → 0**；⑦ 补上 ```python 围栏 0 → 1,274。
- 装在盘上的 ⑦ 代码可解析率 **8% → 64%**（105 → 818 张）。
- 出处第一次变成可信的六类账，而不是「有 / 无」。
- `data/provenance.json` 有 `--check`，`pnpm run verify:provenance` 可复现。

代价与边界：

- **461 张卡的代码仍不可解析，且不是本流水线的责任**：抽取结果与源站 `<pre>` **逐字节相同
  （1,283/1,283）**，源站卡页把代码截断在 **60 物理行**（965 张正好 60 行）。
  要修需要 `paper2skills-code/` 的原始文件，而卡里的 `路径：` 指针 **787/805 悬空**（源树只有 199 个 `.py`）。
- 289 张卡（21%）确实没有出处，不是被清掉的，是源站就没抽出来。
- 143 张（10%）判不了 —— 卡片标题几乎全中文、可判英文 token 少于 2 个。判据选择**不做断言**，留给人工。
- 本包整体仍是 **untracked**（`git status` 显示 `?? packages/capabilities/dsh-paper2skills/`），
  本次改动尚未提交。
- 回滚：`staging/backup/skills-p2s-pre-rebuild.tar.gz`（1,338 个 SKILL.md，3.47 MB）。
