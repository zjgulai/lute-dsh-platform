# ADR-0110 · 视觉收口与 hand-written / compiled artifact owner 边界

- 状态：accepted（2026-09-17）
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-17-surface-visual-closeout-and-artifact-boundary.md)
- 相关：ADR-0104（Codex Desktop 视觉语法）、ADR-0109（Settings 内容面板与跨 surface 浮层层级合同）

## 背景

统一视觉扫描发现三类仍会造成产品方言漂移的问题：Agent Team Recipes 的 sticky footer 使用渐变，
Deep Research 的项目卡通过 inline `--card-tint` 轮换硬编码颜色，Team Hub Admin 的退出入口同时存在
inline 样式和 stylesheet 规则。与此同时，UI-506 的 source/build owner 追踪确认，Task Board、My Quotes、
LoopX、UI Polish 没有可在本仓库重建的 source/build 链；Wanzh 的 client 则是仓库明确以 `allowJs + checkJs + noEmit`
维护的手写 bundle。

## 决策

1. Agent Team Recipes footer 只使用 `--dsw-*` 语义背景和边界，保留 sticky 行为；Deep Research 项目卡使用中性
   panel token 与业务强调 token，移除 `CARD_TONES` 和 `--card-tint`；Team Hub Admin 的 visual style 全部归 stylesheet，
   HTML 不再承载 inline visual style。
2. Wanzh 的 `lib/client.js` 按 hand-written client source 维护，允许在不改变 DOM、API、路由和业务交互的前提下做
   CSS 合同修复：`whRightPanel` 使用低于 Settings root 的 semantic drawer layer，顶条使用业务色纯色，不再用渐变。
3. Task Board、My Quotes、LoopX、UI Polish 继续作为 compiled-only / 不可本地重建 artifact 管理；本轮只保留已验证
   产物和合同测试，不直接把 bundle 反推成源码，也不宣称 source/build owner 已恢复。后续若要继续深度迁移，必须先由 owner
   提供 source、生成命令和 artifact 校验链。
4. 所有新增层级必须能说明与 Settings 的相对优先级；本地 drawer fallback 低于 Settings modal/root layer，不修改 vendor。

## 备选方案

- 保留三处 legacy visual style：拒绝，会让同一视觉合同拥有多个事实源。
- 用新的 design-system runtime 包住这些页面：拒绝，`dsh-theme-local` 已是唯一 token owner。
- 直接从 compiled-only bundle 反推 source 或继续大范围手改：拒绝，无法建立可重建、可审计的交付链。
- 让 Wanzh drawer 继续使用 raw `2500`：拒绝，Settings 与右侧 surface 的相对层级不可解释且会回归遮挡。

## 后果

Recipes、Deep Research、Team Hub Admin 与 Wanzh 的 source/artifact 视觉合同更加单一，右侧 Wanzh drawer 不再覆盖
Settings 的本地 modal/root 层。UI-506 的边界被明确记录：四个 compiled-only 包仍是后续 source-owner 工作，不阻塞本轮
已完成的可维护 source/hand-written surface 收口。所有改动写入工作区但尚未提交；最终 live GUI、主题三态、键盘、
reduced-motion 和固定截图仍需目标 Desktop 43120 恢复且 macOS 解锁后验证。
