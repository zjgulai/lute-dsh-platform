# ADR-0015 · 决策记录双轨分职：ADR 时间线 + 本地 Notes（强制留痕）

- 状态：accepted
- 日期：2026-09-11
- 决策者：用户（lute）+ agent（grill-me 决策树 N6）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-11-lute-refactor-three-phase.md)

## 背景

用户要求「每一个决策要进行 ADR 记录」。当前仓库已有 6 篇 ADR（`docs/adr/`），但另有两套并行体系：各插件 `docs/` 内的业务决策（如万物互联 D1-D5、AI 全栈 ADR-0001~0007）与 `_doc-notes/` 草稿。上游 harness 的对应机制是 Agent Notes（2,920 篇，`{lifecycle}/{class}/yyyy-mm-dd-topic.md`，含 proposed / implemented / rejected / archived 四生命周期与六类分类，并要求非机械改动必须同 PR 附一篇、`## Alternatives considered` 强制存在、格式由 `verify-agent-note-format` 门禁）。

## 决策

**保留 ADR 作为编号时间线，同时引入本地 Notes 承担「为什么与放弃了什么」，两者双向互链并由门禁强制：**

1. `docs/adr/`：保留 `ADR-NNNN` 编号体系，承担**编号时间线 + 稳定链接锚**职能（满足「每项决策一篇 ADR」）。本次重构决策为 ADR-0007 ~ ADR-0015。
2. `docs/notes/`：本地决策记录目录，形态为 `{lifecycle}/{class}/yyyy-mm-dd-topic.md`，`lifecycle ∈ {proposed, implemented, rejected}`，`class ∈ {feature, bug-fix, simplification, architecture, process, testing}`；正文必备 `## Problem` / `## Decision` / `## Alternatives considered` / `## Consequences`。
3. **强制留痕**：非机械改动必须同 PR 附一篇 Note（新建或更新已有的归属 Note）。
4. **双向互链**：ADR 头部登记其 Note 路径，Note 头部登记其 ADR 编号；门禁校验互链可达、ADR 编号连续、索引与文件一致。
5. 历史 6 篇 ADR 本次**不动**，三期做一次带映射表的批量归档。

## 备选方案

- **A ADR 全量迁移为 Agent Notes 格式**：被否决——需重写 6 篇并修复全部入站链接（`docs/README.md`、`architecture.md`、各插件文档、`CHANGELOG`），约 1 人日成本，且会丢失既有 ADR 编号这一稳定锚。
- **B 只用 ADR**：被否决——ADR 缺少「决策被推翻 / 归档」的生命周期，也没有「备选方案强制存在」的机器校验，而这两点正是今天债务的成因（决策无记录 → 同一问题反复返工）。
- **D 只用 Notes、取消 ADR**：被否决——与用户明确要求（每项决策一篇 ADR）冲突，且 Notes 的路径命名不如编号适合作为长期引用锚。

## 后果

- 正面：一次投入最小即同时满足 ADR 编号要求与「改动必须留痕」的强制机制；ADR 的稳定锚与 Note 的完整上下文各司其职。
- 负面/代价：两个目录需要维护互链一致性（由门禁兜住）；撰写成本从「可选」变为「必需」，机械改动需明确判定边界（判定标准写入根 `AGENTS.md`）。
- 后续动作：一期落地 `docs/notes/` 目录与门禁校验项；本次决策自身作为首篇 Note 记录（`docs/notes/implemented/architecture/2026-09-11-lute-refactor-three-phase.md`）。
