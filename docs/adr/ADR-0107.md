# ADR-0107 · 管理与研究型页面统一采用内容面板语法

- 状态：accepted（2026-09-17）
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-17-management-research-surface-visual-contract.md)
- 相关：ADR-0104（Codex Desktop 视觉语法）、ADR-0098（Settings Shell 作用域）、ADR-0104 执行台账 G-CODEX-UIUX-001

## 背景

第一轮抽屉与内容页面迁移后，Team Hub 管理界面、Agent Team Recipes 和 Deep Research 仍各自使用不同的
卡片、按钮、状态和弹层语法。它们的业务数据流、权限、研究状态和导入校验都已有独立契约，直接重排信息架构
会把视觉改造与业务风险混在一起。

## 决策

1. Team Hub admin UI、Agent Team Recipes、Deep Research 只改用户可见的布局表现和样式，分别保持现有
   API、认证/权限、RPC、recipe schema、研究状态机、路由与 slot 不变。
2. 三类 surface 统一使用「基础画布 → 内容面板 → 顶层 modal」层级：管理页以扁平列表和显式状态为主，Recipes
   将来源与预览/校验分栏，Deep Research 将 library、plan、investigate、report 统一到内容面板和 modal
   语法；在窄屏下退化为单列。
3. 新增样式优先消费现有 `--dsw-*` 语义 token，控件高度、焦点环、180ms 动效和 `prefers-reduced-motion`
   行为遵循 ADR-0104。Team Hub 是独立零构建 admin 页面，因此只在自身 stylesheet 内提供与该语法对齐的
   `--dsw-*` 别名和显式 `data-theme` 钩子，不新增 DSH runtime 或第二个应用级主题服务。
4. 只有三个包都完成包级验证、装载点同步和统一桌面 live 验收后，才将 B3 标记完成；静态测试不冒充浏览器
   截图或人工视觉验收。

## 备选方案

- 为每个页面引入新的共享 UI runtime：否决，会违反 `dsh-theme-local` 的单一 token owner 边界并增加发布面。
- 直接重写 Team Hub、Recipes 或 Deep Research 的信息架构：否决，会同时改变业务入口、数据/状态语义和视觉表现。
- 只调整颜色而保留各页面的卡片、胶囊和弹层方言：否决，不能解决层级混乱、密度不一致和管理操作不可辨识。

## 后果

- 三类页面可在不改变业务行为的前提下共享同一套空间、控件、状态和动效语言；窄屏和减少动效偏好有明确降级路径。
- Team Hub 仍需独立浏览器实机截图确认显式主题钩子；三包的统一 DSH Desktop live 验收、固定截图归档和
  聚合 gate 归因仍是后续批次工作。
- 生成的 package bundle 与装载点同步必须在所有 B3 代码合并到工作树后一次完成，不允许以中间产物重启验收。
