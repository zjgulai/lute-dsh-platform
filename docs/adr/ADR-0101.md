# ADR-0101 · 交付白名单（`files`）的完整性判据从「装载点侧」补到「交付清单侧」

- 状态：accepted（2026-09-16）
- 决策记录：[2026-09-16-package-delivery-allowlist-coverage](../notes/implemented/contract/2026-09-16-package-delivery-allowlist-coverage.md)
- 关联：[ADR-0009](ADR-0009.md)（一份事实一个家）、[ADR-0015](ADR-0015.md)（决策留痕）、[ADR-0100](ADR-0100.md)（同批发现本缺口的那一次）

## 背景

`dsh-wanzh-hulian` 的 `files` 清单漏了 `lib/atomic-store.js` 与 `lib/oauth-flow.js`，
而 `lib/index.js` 正在 import 它们。这是 P-24 的第二次复发，而两项既有机制当时全绿：

- `profile-files-sync` 只对 `files` 清单里**声明过**的文件说话，清单外的文件它不看；
- `profile-bundle-sync` 判「装载点上缺不缺、字节一致不一致」，而装载点当时**有**这两个文件
  （上一批手工同步补过）。

两项都从**装载点侧**量「现在有什么」，没有一项问「按清单物化之后还会有什么」。

影响面不止发布：2026-09-16 实测（真实 `pnpm`，隔离临时根）**`pnpm` 对 `file:` 依赖遵守
`files` 白名单**——`files: ["lib/a.js"]` 的包安装后 `node_modules/<pkg>/lib/` 里只有 `a.js`，
未声明的 `lib/b.js` 与顶层 `undeclared.txt` 都不出现，且 `npm pack --dry-run --json`
对同一 fixture 给出同一集合。因此缺件命中的是**本机装载点的全新安装**，
而全新安装路径上没有任何同步步骤可以补救。

## 决策

新增门禁 `package-files-coverage`：**包里运行时模块图上的每一个文件，都必须落在该包
`package.json` 的 `files` 白名单射程内**。判据面是从声明入口
（`main`、`exports` 的每个字符串叶子、`bin`、`dsh.bundle.patch`）出发的**静态可达闭包**，
扩展规则含静态相对 `import`/re-export/`require`/字面量 `import()`，以及字面量
`new URL('./x', import.meta.url)`（后者正是 P-24 最初丢掉 `lib/lint-preset.mjs` 的那条路径）。

一并确定五条口径：

1. **判据面取「运行时模块图」，不取「`lib/` 顶层所有 bundle」。** 后者在
   `profile-bundle-sync` 里是对的（那个判据要的是「装载点上哪些文件必须字节一致」，宁可过宽），
   搬到「白名单是否漏件」上就是假红：`dsh-paper2skills` 的 5 个 `lib/*.js` 是包内
   `scripts/`、`test/` 用的开发期模块，包没有 `main`、没有 `dsh` 字段、也不是任何 profile 的
   `file:` 依赖。**同一份规则在两个目的下不是同一个判据。**
   闭包之外、`lib/` 顶层的 bundle 只作为读数进 `note`（不判红、不判 skip）。
2. **判定器与真实 npm 全等，不自创 glob 语义**：`files` 射程只实现本仓库实际出现的形态，
   并由真实 `npm pack --dry-run --json --ignore-scripts` 对**全部**受管包逐文件校准；
   门禁本身保持不联网、不 shell 出外部工具。
3. **「不适用」不得写成 skipped 也不得写成判红**：没有 `files` 白名单的包不存在
   「被白名单漏掉」这一失效模式。唯一能把运行时文件挡在交付之外的是 ignore 文件，
   故只回答那一个问题——核对 ignore 文件（窄子集；未建模形态 fail-closed 成类型化 skip）
   能否命中任何运行时文件：命中不了进 `note` 读数，可能命中或形态未建模才 skip。
   写成 skipped 会把 `gate:strict` 永久拖红，而永久红灯的噪声最终会让真信号一起被忽略。
4. **`main` 与 `package.json`/`README*`/`LICEN[CS]E*` 属于 npm 的 always-included
   集合**（实测确认），即使不在清单里也不算漏件——避免假红，不是放宽判据。
5. **判据面必须由外部注入文件读取器**（`readSource`）：判定器是纯函数，不自行读盘。
   读不到被访问文件的源码时**判红**（闭包不完整不得当作「这个文件没有 import」）。
   这条纪律同时是 QG-006A 的隔离契约。

## 备选方案

- **塞进 `QG-004`（profile sync 覆盖率）**：拒绝。QG-004 从 profile 侧量「比了几个包」，
  本项从交付清单侧量「白名单漏没漏运行时文件」，互补不重叠；且本项不需要 profile 存在、
  不读 `$HOME`，混卡会被「profile 不存在就 skip」一起跳过。
- **判据面取「`lib/` 顶层所有 bundle」**：被真实假红否决（见决策 1）。这条路会让门禁
  一上线就背着一个豁免，而豁免是判据腐烂的起点。
- **门禁里直接调 `npm pack`**：与仓库既有约定冲突（`dependency-reproducibility` 明写
  「只解析已提交的文本，不 shell 出 pnpm、不联网」）。代价是自己实现 glob 射程，
  由校准测试补上那一环。
- **实现完整 gitignore 语义**：拒绝，那是一整块需要独立校准的规则面；窄子集 +
  未建模形态 fail-closed 已能把「没建模」与「建模了且没命中」分开。

## 后果

- 交付白名单漏件在提交前判红，判红信息点名包与文件，并明确引向「加进 `files`」
  而不是「去补装载点」；P-24 里那句「仍然未落地的机制」被替换为真实门禁名。
- 仓库新增 2 个门禁项（`package-files-coverage` 与其 selftest）；判据面对当前工作树
  给出 124 个运行时文件的 checked，0 fail、0 skip。
- 一条**已知未建模**的边界被写进模块注释而不是留给读者推断：用变量拼路径读取的包内数据文件
  （如 `join(PKG_ROOT, 'data')`）本项看不见。当前仓库里此类文件都在 `files` 里有声明，
  因此不影响结论。
- 校准测试依赖本机 `npm` / `pnpm`；两者不可用时显式 skip 并说明「没有校准任何东西」，
  不静默通过。
