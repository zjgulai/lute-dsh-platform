# ADR-0040 · 开发脚本起的子进程必须是**真 node**：`process.execPath` 在 pnpm 下是宿主 Electron，且它「退出码 0 却没有输出」

- 状态：accepted
- 日期：2026-09-12
- 决策者：agent（第四次踩到同一根因后取证提出）
- 决策记录：[Note](../notes/implemented/contract/2026-09-12-node-interpreter-not-execpath.md)

## 背景

开发脚本起冷进程子探针的标准写法是 `execFile(process.execPath, [script, ...])`。
**这个写法只在父进程是 node 时成立**，而本仓库的验收探针全部是在 `pnpm run` 下跑的。
实测：

```
$ node -e 'console.log(process.execPath)'            # /opt/homebrew/.../bin/node
$ pnpm exec node -e 'console.log(process.execPath)'   # /Applications/DSH Desktop.app/Contents/MacOS/DSH Desktop
```

pnpm 生命周期下整条进程链是**宿主 Electron 以 `ELECTRON_RUN_AS_NODE` 身份**跑起来的，
于是 `process.execPath` 是 Electron 可执行文件。拿它执行子脚本，Electron 不认为自己在当
node，而是**再开一个 app 实例**：单实例锁之下它把 argv 交给已在运行的主实例、**立刻以 0
退出**。父进程看到 `退出码 0 + stdout 空 + stderr 空`。

**这个形状的危害不是让探针变红，而是让它变成一句没有信息量的话。** 它与「子探针什么都
没说就正常结束了」完全一样，于是读者只能自己去复现一遍才知道是哪种。

同一个根因在本仓库此前已被**各自就地绕过三次**——`scripts/gate.test.mjs` 的
`resolveNode()`、`dsh-agent-team-gui-local` 的 quality helper、`dsh-team-hub` 的
typecheck——每次都是**一处**私有的 `which node` 兜底。第四次没人接：
`scripts/acceptance/newapp-products-live.mjs` 的 `default-scans-nothing` 连续多轮被记成
「(无响应)」，而前一轮的「修复」把它误诊为**管道上的异步写竞态**（那个 hazard 真实存在，
但它不是主因），因此只在直接跑 `node` 时验证——**恰好绕开了唯一能复现它的调用方式**。

## 决策

**1. 一份事实一个家：`scripts/lib/real-node.mjs`。** 导出 `nodeCommand() → {command, env}`、
`electronNodeEnv()`、`isElectronNode()`、`describeNodeCommand()`、`assertNodeUsable()`。
实现取 `ELECTRON_RUN_AS_NODE=1` 而不是「回 PATH 上找 node」：不需要任何查找、保证是同
一个运行时，且对**真正的 node 无害**（一个它不认识的普通环境变量），所以两种父进程下
返回同一形状，调用方不需要分支。`command` 与 `env` 是同一件事的两半，**必须整对拿走**。

**2. 判据机器化：门禁项 `node-interpreter`。** 扫描 `scripts/**` 与
`packages/**/scripts/**`（`packages/**/lib/` 是产物，不扫；`scripts/lib/` 是源码，**要**扫）：
`spawn / spawnSync / execFile / execFileSync / fork` 的第一个实参是 `process.execPath` 即违规；
写了 `nodeCommand().command` 却没有 env 半也违规。唯一豁免是 `real-node.mjs` 自己。

**3. 判据必须先剥注释与字符串。** 「门禁把不是代码的东西当代码读」当天出现了三次：
`theme-tokens` 读注释里的 token 名、`node-interpreter` 读**自己 JSDoc 里**举的反例、
`node-interpreter` 读**自己测试夹具里的字符串**。故 `blankStringsAndComments` 与
`blankComments` 一并落在 `scripts/lib/strip-comments.mjs`；`theme-tokens` 用后者
（它的判据依赖字符串里的 token 名），`node-interpreter` 用前者。

**4. 仪器要自证。** 探针的阶段 A 加一条 `node-interpreter` 仪器自检，判据是
**子进程有没有输出**而不是退出码——只看退出码的自证会被这个 bug 本身骗过去。

**5. 「只有重启才能改变的事实」是第三种状态，不是红也不是绿。**
`accept:newapp-products` 的阶段 D 打运行中的实例：路由未加载（401）与栅栏答 400 都
只说明**实况跑的是旧产物**。退出码改为三态：`0` 全绿 / `1` 有真失败 /
**`3` 阶段 A–C 全绿但阶段 D 因宿主未重启无法判决**。判为 3 还需一条独立证据——
阶段 B 里**本进程现装的产物**对同形状请求答 403。真失败优先于 3。

## 备选方案

- **A. 继续各写各的 `which node` 兜底。** 否决——已被绕过三次，第四次就没人接了；
  而且「PATH 上的 node」不保证是同一个运行时。同一事实三个家正是 ADR-0009 要禁的形态。
- **B. 只修探针，不加门禁。** 否决——这个 bug 的失败模式是**沉默**，没有机器判据的
  话，下次仍会以「(无响应)」的形式活过好几轮（本轮就是）。
- **C. 生成一个 shim 可执行文件，让 `command` 单独就永远正确。** 否决——需要落一个临时
  文件并在整个进程生命周期内维持它；返回值里带 `env` 已经把「两半」这个事实表达清楚了，
  再用规则二把「只拿一半」变成门禁违规即可。
- **D. 把阶段 D 的 400 照旧记成失败。** 否决——没有任何读数为这个「失败」负责，
  它把「没验证过」伪装成「验证不过」，而两者需要的动作（重启 vs 改代码）完全不同。
  同理也不压成 0：那是假绿。
- **E. 把 `lib` 一起放进全局跳过集（第一版就是这么写的）。** 否决——那会让
  `scripts/lib/` **整个不被扫描**，于是「豁免 real-node.mjs」成了死代码而看起来像在正常
  豁免。这个假绿是被本项自己的用例⑤逼出来的。

## 后果

**得到**：冷进程探针的解释器在两种父进程下都正确；`accept:newapp-products` 的
`default-scans-nothing` 在 `pnpm run` 下 **3/3 通过**（此前偶发失败、且只在 pnpm 下复现）；
门禁项 `node-interpreter` 覆盖 82 个开发脚本并修掉 3 处真实违规；「注释/字符串不算代码」
这一事实从两个门禁的两份实现收敛到一个家；`test:gate` 由硬编码清单改为 glob，不再随
新增测试漂移。

**代价**：① `packages/**/tests/**` 与包内 `src/` 的同类用法（如
`dsh-team-hub/src/service-*.mjs` 把 `process.execPath` 当默认参数写进 plist/unit）**不在本项
范围内**——它们的修法是「调用方必须显式传 node」，属于另一个决定，已知未修并登记为开放项；
② `blankStringsAndComments` 是状态机不是解析器，反引号模板里的 `${…}` 不做嵌套解析、
正则字面量不识别，表现为**假阴性**（由跑真实产物的验收探针兜）；
③ 门禁的 `node-interpreter` 只保证「忘了这件事不再是一个安静的选项」，不保证所有解释器
用法都对。
