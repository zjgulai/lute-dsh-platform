# ADR-0039 · 语义 Token 的三条法则；门禁的「引用」只认 `var()`

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（第三期「对齐语义 Token 与 LUTE 品牌」的范围）+ agent（实测后提出）
- 决策记录：[Note](../notes/implemented/contract/2026-09-12-theme-token-three-laws.md)

## 背景

第三期开工时，`dsh-newapp-local` 的抽屉样式表里有 **47 处硬色值**，另有 1 处
`--dsw-font-mono`。后者是上一轮把幻觉 token `--dsw-font-family-mono` 改过来的结果——
**改完之后依然是错的**：

```
$ pnpm run accept:theme-tokens
✗ 未解析（走字面兜底）  --dsw-font-mono  浅 rgba(0, 0, 0, 0) / 深 rgba(0, 0, 0, 0)
```

静态门禁说它「已定义」（本仓库主题插件的映射里有这个名字），真实引擎两态都解析不出——
`var()` 静默走字面兜底。也就是说：**门禁的「已定义」与「页面拿得到」是两件事**，而当时
的写法让两者看起来是一件事。

同一轮还测出，门禁的**引用收集器**把两类不是引用的东西算成了引用：

```
--dsw-font-mono               ← packages/surfaces/dsh-newapp-local/src/client/newapp.module.css
--dsw-alias-fill-tsp-secondary ← packages/surfaces/dsh-newapp-local/src/client/newapp.module.css
```

而这两个名字在该文件里**只出现在注释里**（`code: 0 / whole-file: 2`，实测）。后果是荒谬的：
按规格写「这个名字弃用了，别再用」这句话本身，就让那个名字**重新变成一个必须存在的
token**——写文档反而造出违规，与 ADR-0015「非机械改动必须留痕」直接冲突。

## 决策

**1. 自研 UI 的颜色遵守三条法则。** 它们各自对应一次已经付过代价的静默失败：

| 法则 | 内容 | 违反时的样子 |
| --- | --- | --- |
| 一 | 只引用**官方主题包 CSS 里声明过**的名字 | 名字看似有效，实际永远走字面兜底；深色主题下等于没有底色 |
| 二 | 兜底字面 = **该 token 实测的浅色读数** | 兜底是猜测，缺 token 时降级到一个没人验过的颜色 |
| 三 | 品牌色**不是**主题色：LUTE 绿是字面量，且只住在**一个**声明块里 | 状态用了品牌色（说不出「成功」），或同一个绿散落十几处各自漂移 |

品牌块的**唯一例外**是「固定品牌底上的文字」：它用官方**静态**白
`--dsw-static-neutral-bluish-00`（实测两态都是 `rgb(255,255,255)`），而不是任何
inverted-label 别名——别名在深色主题会翻成深色，绿底上直接消失。

**2. 门禁的「引用」只认 `var()` 里的名字，且先剥注释。** 定义（`--dsw-x:` /
`"--dsw-x":`）不是引用；注释里的名字不是引用。

**3. 排版走官方字号简写。** 官方阶梯是
`xxxs-11 / xxs-12 / xs-13 / s-14 / m-18 / l-20 / xl-24`，每个都自带
`font-family`、`font-size`、`font-weight`、`line-height`——「字号行高成对」就是它们。
**名字里的数字会撒谎**（`--dsw-font-m-18` 实测是 `500 16px/28px`），以值为准。

## 备选方案

- **A. 只修样式表，不动门禁。** 否决——那样「注释造违规」会一直存在，而它惩罚的正是
  规格要求的留痕行为；本轮我自己就一头撞上（改完 CSS 后探针多报 2 条未解析）。
- **B. 把门禁收紧成「必须官方已定义」，不再接受本仓库主题插件的供给。** 否决——主题插件
  的职责就是供给 alias 层，它会定义官方没有的名字，这是它的正当行为；一刀切会把供给方
  自己的定义判成违规。
- **C. 品牌绿也做成 token（`--dsw-alias-brand-primary`）。** 否决——它实测是
  `neutral-bluish-1000`（近黑），是「反色实底」语义，不是绿色；用它会让 LUTE 的品牌识别
  消失。品牌绿按品牌走字面量，状态按状态走 `state-success-*`。
- **D. 保留上一轮的 `--dsw-font-mono`，理由是「主题插件里确实有」。** 否决——「供给方
  写了」不等于「页面拿得到」。实测两态都解析为空。改走官方声明的
  `--ds-font-family-code`（同一份事实的官方家）。
- **E. 用 `color-mix()` 派生品牌色的透明度变体。** 否决——更简洁，但失败模式是静默的：
  引擎不支持时整条声明在 computed-value 阶段失效，而 `var()` 的兜底**不会**救它。所有
  透明度变体写成 `rgba()` 字面量，全部住在品牌块里。

## 后果

**得到**：抽屉样式表的 47 处硬色值收敛为 11 个品牌字面量（一个声明块）；`newapp` 引用的
30 个 token **全部**在真实引擎两态解析成功（`accept:theme-tokens` 退出码 0，上一轮是 1）；
一条 9 用例的永久测试锁住这三条法则（含 3 个变异体转红）；门禁不再把注释和定义当引用，
`--dsw-font-mono` 的引用数从 2 归零；基线删掉 1 条（8 → 7）。

**代价**：① 使用 `font:` 简写会重置 `font-family` 与 `font-variant`，所以
「简写 + 覆盖」的顺序是硬约束（已有用例守着），写反了是**合法 CSS 且静默无效**；
② 门禁不再计入写在裸字符串里的引用（`setProperty('--dsw-x')` 这类），本仓库当前没有
这种写法，真出现时由跑真实引擎的 `accept:theme-tokens` 兜；
③ 品牌块用双选择器（`.root, .entry`）——抽屉与侧栏行是两个没有共同祖先的子树，
  这是让「只有一处字面量」成立的代价。

**未做**：`dsh-role-matrix-local` / `dsh-skill-center-local` 各尚有 ~115 处硬色值（本轮
只修了基线里指名的那一处）。它们是前几期的存量，不在第三期的融合范围内，登记在
[.scratch/dsh-worktable-fusion/spec.md](../../.scratch/dsh-worktable-fusion/spec.md) 的开放项。
