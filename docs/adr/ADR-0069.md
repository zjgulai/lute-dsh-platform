# ADR-0069 · 「输入监控」不是必需项：授权判据不得把一条**未经验证**的事实钉进出货面

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：用户（「之前遗留的 TCC 的问题，请深度检查并修复」）+ agent（本次取证、判定与落地）
- 决策记录：[Note](../notes/implemented/contract/2026-09-13-tcc-input-monitoring-not-required.md)
- 相关：ADR-0063（换签名身份；本条更正了它实施过程中写进去的一条事实）、ADR-0068（同一场事故的前半段：死授权检出）、ADR-0009（一份事实只有一个家）、ADR-0014（门禁是硬门槛——包括它也会把错的东西钉死）

## 背景

### 同一天里的第二次错：第一版修的是错法，不是事实

ADR-0063/0068 的处理过程中，出货指引从「屏幕录制 / 辅助功能 / **自动化**」改成了
「辅助功能 / 屏幕录制 / **输入监控**」。改动的依据是当时直读系统库看到的三行：

| service | 当时的读法 |
| --- | --- |
| `kTCCServiceAccessibility` | 2（允许） |
| `kTCCServiceScreenCapture` | 2（允许） |
| `kTCCServiceListenEvent` | 2（允许） |

但**「库里有这一行」不是「这一项必需」**：那一行是有人（早先的指引、或一次探针）请求过才存在的。
当时的 Note 把这一点写得很清楚——「『输入监控』是否真为必需**未定**……未定之前指引保持三项，
宁可多授一项，不可漏授一项」，并写明要用一次真实授权做实验。

**这句话没有生效，而且失效的方式值得记录**：门禁 `tcc-pane-guidance` 被同时加上，
其规则是「凡提到授权与面板名的行，**必须**含『输入监控』」。于是一条自我约束（「未定之前保持三项」）
被翻译成了一条强制校验，六个出货面 + 它的单测一起把这条未定的事实钉死。此后任何人**改对**都会判红。

### 2026-09-13 15:41 的判定实验

用户在**新身份**的 app 上只授予「辅助功能」+「屏幕录制」两项，第三项按指示**故意不碰**。读数：

- `macos-harness doctor`：`accessibility: true`、`screen_recording: true`、**`post_events: true`**；
- 同一时刻的系统 TCC 库里，`kTCCServiceListenEvent` **一行记录都没有**。

两个读数是同一次采样，互相印证：**`post_events` 由「辅助功能」承载**。
源码同证：`macos_harness/macos.py` 里该项读的是 `CGPreflightPostEventAccess()`，全库**没有任何**
`kTCCServiceListenEvent` 引用，并自报 `"input_monitoring_required": false`。

### 代价不是「多授一项」那么轻

「输入监控」在 macOS 上意味着**读取全部按键**。此前指引让用户去授它，等于：

- 让用户白给一个高敏权限；
- 让用户以为不授它键盘鼠标类能力就不工作（而这正是最容易被误诊的失败形态）；
- 把一条错的事实写进**权威用户手册**（`INSTALL-GUIDE.md` 第 6 节授权表）。

### 顺带取到的那条先例（另一半）

同一次实验还回答了一个更早的问题：自签身份的授权要求，tccd **会原样保存**。用户在界面上重授后，
库里存下的两条要求逐字为：

```
identifier "ai.deepseek.dsh.desktop" and certificate leaf = H"ba3372a39bf4fe09e467ab8565cfb3a0166babbe"
```

**身份型、无 cdhash**——ADR-0063 的「绑证书不绑字节」在自签前提下站得住，此前「没有先例可援」
的担忧可以放下。这一条回填在 ADR-0063。

## 决策

1. **必需面板是两项**：辅助功能、屏幕录制。「输入监控」列入**非必需**，出货指引不再要求用户授予它，
   并明确写出「**不要**去授」——因为老的文档已经让一部分用户授过了。
2. **判据必须能同时读「必需」与「非必需」，并只用前者下结论**：`tcc-grant-status.sh` 的必需项
   （两点）参与死授权/有效/关着的判定与退出码；非必需项（`ListenEvent`、`SystemPolicyAllFiles`）
   只保证「库里有残留」这件事看得见。把非必需项算进结论，会让一条与自己无关的残留把安装收尾
   变成「检出死授权、去重授」——正是本 ADR 要消除的**假的警报**。
3. **门禁改判**：`tcc-pane-guidance` 不再要求写「输入监控」，改为**禁止**把「输入监控」或
   「自动化」写成待授项；要讲清这两件事就加否定词（「不要授权自动化」「输入监控并非必需」）。
   `dmg-readme-tcc-panes` 的必需面板同步改为两项。**单面板的行不判红**——逐行强制写全两项会把
   「进辅助功能面板把开关关掉再打开」这类正确排错句判红，判据一旦开始冤枉人，人就会绕过它；
   完整性只由权威 README 那一处守。
4. **取数接口唯一，且列为 ASCII**：`tcc-grant-status.sh --format=tsv` 是唯一的机读契约
   （6 列，第 2 列 `required`/`optional`）。`verify-tcc-runtime.sh` 删掉自带的那份读库实现，
   改为调它取数（ADR-0009）。判据在读不懂的格式上必须 **fail-closed**。
5. **「无记录」与「判不了」是两个状态，都不是「死授权」**：库里没有该行 = 从未授权过；
   有行但要求解不出 = 判不了（退出 4）。工具（`csreq`）的错误文本绝不参与判定。
6. **一条未验证的事实不得写进出货面，也不得由门禁强制**：凡「未定」项，只能登记在 Note/ADR 与
   待办里；要写下结论，先拿到一次真实读数。ADR-0014 让门禁成为硬门槛，本条补上它的反面：
   门禁同样会把**错的**东西钉死，所以进门前必须先验证。

## 备选方案

- **保持三项，「宁可多授一项，不可漏授一项」。** 被否：多授的不是一个中性的权限，而是读全部按键；
  且证据方向明确（无记录 + 读数 true）。「宁可多授」在没有成本时是稳健，在有成本时是欠债。
- **把 `ListenEvent` 从读取列表里彻底删掉。** 被否：残留应当**看得见**（今天库里也确实还留着
  `SystemPolicyAllFiles` 的滞留行），只是不参与结论。删除会让「用户按老文档授过一项」这件事
  从所有读数里消失。
- **只在 `verify-tcc-runtime.sh` 里就地补一行 if，修掉那个假阴性。** 被否：那个假阴性的真正成因是
  「同一份读库逻辑有两份实现，只有一份有测试」。补丁救得了这一行，救不了这个结构；改为委托唯一实现。
- **只改文档，不动门禁规则。** 不可能：旧规则会立刻把改对的文档判红——判据成了错误事实的守门人。
  两者必须同一次改，且测试里的旧断言也要一起改（它们正逐字断言着那条错的事实）。

## 后果

- **正面**：
  - 用户少授一项高敏权限，`INSTALL-GUIDE` 第 6 节从三项表变成两项表；
  - 六个出货面、门禁规则、门禁单测、两个 shell 自测同一次对齐；
  - 验收脚本少了一份**没有测试的**读库实现，它的三种缺失形态（无记录 / 解不出 / 不满足）各有明确结论；
  - 上次修 `verify-tcc-runtime.sh` 时留下的假阴性（把「从来没有授权」报成「需重授一次」）被同一批测试抓住。
- **负面 / 边界**：
  - 本结论的依据包含 harness 自报的 `input_monitoring_required: false`。**上游若改为 true**
    （即 DSH 真的要做全局按键监听），本条必须重开：那时授「输入监控」才是必需的。
  - 非必需项在库里滞留会让面板上多出一个「已开启」的项，本 ADR 明确它无害且不参与判决。
  - `--format=tsv` 是新增契约，旧的三列格式会被判「形态未知」——这是有意的 fail-closed，
    但任何**外部**消费该输出的脚本需同步。
