# ADR-0050 · 代码围栏按「宽松枚举候选 + 语法定终点」抽取，不按 Markdown 配对

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（同意把「源站卡与 vault 卡是不是同一批产物」列为下一入口）+ agent（剖析与取证）
- 决策记录：[Note](../notes/implemented/capability/2026-09-12-paper2skills-fence-candidates.md)
- 订正：[ADR-0049](ADR-0049.md) 的「那 21 张是真实的代际差异」（见本篇「背景 · 一」）

## 背景

ADR-0049 收尾时留了下一入口：**「那 21 张『源站卡 ≠ vault 卡』的代际差异」**，
判据是「源站 ⑦ 段节选不是 vault 任何围栏的行前缀」。入口里那句话本身是对的读数，
但**归因错了**，而且顺着它摸到的第二件事比入口大。

### 一、21 张里 19 张的实现一直在 vault 的 HEAD 里

先把判据本身重做了一遍。旧正则：

```python
FENCE_RE = re.compile(r'```[ \t]*(?:python|py)?[ \t]*\r?\n(.*?)```', re.S)
```

两个缺陷，各自造成真实损失：

1. **不锚行首**。前一个围栏的**收尾** ```` ``` ```` 会被当成开栏，配对整体错位；
   被错位吞掉的那个开栏，再也不会作为候选出现。`Skill-Context-Kubernetes-KB-Orchestration`
   的 ③ 段有 338 行实现，旧正则一个都没取到。
2. **只认 `python`/`py` 标注**。而源站发布的是卡里**第一个**块，不问语言：
   `Skill-MAS-Orchestrator` 首块就是 ```` ```bash ```` 的 `cd … && python orchestrator.py`，
   于是节选在候选集里根本不存在。

用与路径无关的判据（扫全部历史 7,385 个相关 blob，不沿单一路径回溯）复核：
**21 张里 19 张的代码就在 vault 的 HEAD 里**；4 张是「首块是 bash 运行方式」；
**只剩 2 张是真正的源站独有**——它们的节选在本仓全历史里一次都没出现过，
在本地那棵可读树里也只出现在 playbook 的 HTML 自己身上。

> 附带一条方法教训：本轮第一次跑出来的结论是「20/21 在历史里命中」。
> **那是错的**——当时自己写的节选提取与管线口径不一致，退化成了「匹配一个空行」，
> 几乎对任何围栏都命中。加了两组对照（阳性：oracle 抽样必须全中；阴性：节选尾接垃圾行
> 必须全不中）才把它抓出来。**先证明判据能报「否」，再相信它报的「是」。**

### 二、更贵的一条：6 张已「确证」的卡其实是被截断的

卡里的 Python 会把**整张 markdown 卡**塞进三引号字符串：

```python
skill_content = textwrap.dedent('''
# Skill-Test
## ③ 代码模板
...''')
```

那串里就有 ```` ``` ````。旧判据在那里提前收尾，于是「节选是围栏开头」这条 oracle
**照样成立**——节选确实匹配上了——但取到的围栏只有真身的一小段。
`Skill-Skill-Card-API-Serving` 取到 66 行，真身 **443 行**；`Skill-Argos-Agentic-Anomaly-Detection`
取到 160 行，真身 389 行。

**这是 oracle 判据本身的盲区**：它只校验**起点**，管不了终点。

### 三、试过并否决的两条路

- **严格按 Markdown 配对**（开栏↔下一个整行 ```` ``` ````）：`Skill-BERT-SRL-Event-Frame-Extraction`
  第 188 行有一个孤立的裸 ```` ``` ````，严格配对会让它把后面的 ```` ```python ```` 开栏吞成收尾，
  **374 行实现整块消失**。目标是「把 Python 实现找出来」，不是还原文档结构。
- **降级路径也用宽松候选**：宽松候选在围栏不闭合的卡上会一路吃到后面的正文。
  想用 `ast.parse` 兜住——**兜不住**：`## ④ 技能关联`、`### 前置技能` 都是合法 Python
  **注释**，实测 15 张卡因此把整段正文当成了实现。

## 决策

### 1. 候选 = 宽松枚举边界，不配对

每个**行首** ```` ``` ```` 行（可带语言标注）都是一个**边界**；相邻两个边界之间就是一个候选块，
语言取开边界上的标注。开栏、收栏一视同仁，不判断谁配谁 —— 是不是真实现交给 oracle 判定。

### 2. oracle 候选不问语言，但**结果**必须是 Python

源站发布的是第一个块，所以匹配要在全部候选里做。但交付物是 `references/implementation.py`，
只有 Python 块能当结果。命中非 Python 块时记 `EXCERPT_MATCHES_NON_PYTHON_FENCE` ——
那张卡发布的是「运行方式」，不是实现。**不伪装成「没找到」，也不硬塞进 `.py`。**

### 3. 终点按语法定：从同一始点取「最长且能 parse」的区间

起点由 oracle 定，终点由 `ast.parse` 定。**一个都不 parse 时退回「到下一个边界为止」的自然块，
绝不退回最长的那段**——卡尾常跟着 `- **优先级**：⭐⭐⭐⭐⭐…` 这类正文，退回最长就等于
把散文当实现交付（实测 5 张卡的尾行正是这种散文）。

### 4. 节选被从行中间切断时，用一档更弱但明示的判据

源站自己那份节选抽取器也踩了行内 ```` ``` ```` 的坑，把预览**从行中间**切断
（`Skill-CodeRAG-Repository-Level-Retrieval` 的节选末行停在 `code_blocks = re.findall(r'`）。
此时「前 N-1 行逐行相等 + 第 N 行是前缀」仍可判，但标成 `prefix@1+partial`，
并在安装校验里用**同一口径**复核。

### 5. `offset` 改为**实测**值，那条守卫才有意义

`prefix_offset()` 原本 `return 0 if … else None`，而调用方写死 `offset = EXPECTED_OFFSET(=1)`。
于是索引里的 `offset` 看起来是量出来的、实际是常量，守卫
`if oracle_off != {EXPECTED_OFFSET}` **永远不可能触发**——它是同义反复，不是检查。
现在返回实测行号，守卫才真的在守。

### 6. 降级路径保持改前语义，改动不外溢

`unverified` 仍取「最长的 Python **成对**块」，不额外加 `ast.parse` 门槛。
加了门槛会凭空丢掉 5 张原本已交付的卡（如 EvoSC 的 6 行块）——那是另一件事，
不混进「修围栏判据」这一改里。`parses` 字段照旧如实记录。

### 7. 加 `--check` 与 `--selftest` 两个不写盘的模式

索引决定①每张 skill 的 ⑦ 段怎么写、②要不要落 `implementation.py`。改了判据却忘了重跑，
正文与索引就会各说各话。`--check` 重算后逐卡对账（含 `stats` 与 `note`）；
`--selftest` 是围栏判据的回归用例（行内 ```` ``` ```` / 孤立裸 ```` ``` ```` / bash 首块 /
行中切断 / 实测偏移）。两者都由 `test/source-code.spec.mjs` 调用。

## 备选方案

- **启发式找出代码段边界**（按缩进、按空行、按行长相）。否决：卡里代码块与正文的
  边界是**作者写的围栏**，有精确信号可用时不该退回启发式。
- **把非 Python 首块也当实现交付**。否决：`references/implementation.py` 会变成
  `cd x && python y.py`，`parses=False`，读者复制即错。
- **对不闭合的围栏做「修复」**（猜一个收尾位置）。否决：那是**编造**，不是恢复。
  15 张这类卡如实记 `NO_PAIRED_PYTHON_FENCE`。
- **把 `unverified` 也加上 `ast.parse` 门槛**。否决（本轮）：会凭空丢 5 张已交付的卡，
  属于另一件事。

## 后果

正面：

- `oracle` 确证集 1,262 → **1,277**；落盘 `implementation.py` 1,302 → **1,317** 张
  （253,648 → 259,365 行）；已恢复且可 `ast.parse` 1,277 → **1,297**。
- 未恢复 36 → **21**，且每张都带**准确**的原因码（不再把「判据漏读」写成「代际差异」）。
- **0 张原本确证的卡掉出**；540 张卡的 `fence_index` 因候选枚举变密而位移，**正文一字未动**。
- 6 张被截断的卡取回真身（最大一张 66 → 443 行）。
- 两条新守卫：记账不变量（有节选的卡必须恰好落进三个出口之一）、`offset` 实测校验。

代价与边界：

- **21 张仍未恢复**：15 张围栏不闭合、4 张首块是 bash 运行方式、2 张源站独有（非本包可修）。
- **20 张已恢复但 `ast.parse` 不过**：源码本身写坏了（全角括号 `（`、全角冒号 `：`），
  **是源的问题，不是抽取的问题**。索引如实记 `parses=False`，已从 25 张降到 20 张。
- 围栏枚举变密使 `fence_index` 语义变化（不再是「第几个 Markdown 围栏」，而是
  「第几个候选块」）。它只作定位线索，不参与任何断言。
- **全称断言又一次翻车**：本篇入口那句「源站卡 ≠ vault 卡」在 ADR-0049 里被写成结论，
  实际是判据的产物。凡写「全 X 都 Y」先跑计数——这是本仓第三次栽在同一处。
