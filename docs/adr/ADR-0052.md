# ADR-0052 · 第三方技能入库不保留 `.git`，且必须挂岗或显式归为通用型

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（选定 B 策略；定「每个进来的 skill 必须有岗位归属或归为通用型」规则）+ agent（取证与落盘）
- 决策记录：[Note](../notes/implemented/capability/2026-09-12-third-party-skill-intake.md)

## 背景

把第三方技能 `lieflat-charts`（5236★，PolyForm Noncommercial）接入本机时，暴露出两件此前没有成文规则的事。

**其一：入库动作与上游版本控制天然冲突。**
技能目录的既有机制是 `git clone` 到 `~/.dsh/skills/<name>/`。但入库必须改写 `SKILL.md` frontmatter
（补中文 `title`、`user_summary`、`user_try` 与溯源 `metadata`），实测安装后 `git status` 即为：

```
 M SKILL.md
?? README.usage.md
```

于是 `git pull` 必然在 frontmatter 处冲突，每次更新都要 `git stash` + 重放本地字段。这不是一次性的
安装麻烦，而是一个**每次更新都会复发**的结构性摩擦。

**其二：技能可以「装上了但没归属」。**
`lieflat-charts` 装好后在 DSH 会话技能目录里可用，但在出海技能页的策展目录里**不存在**——
`grep -i lieflat manifest/*.json` 零命中。原因是宿主 `buildScenarios` 用 `skill.subcategory` 过滤
`manifest/skills.json` 的 `SKILLS` 才能匹配到分组，manifest 里没有条目就根本不出现。
即「能装」与「有归属」是两条独立通路，前者不蕴含后者。

用户随后确立规则：**每一个进来的技能都必须落到岗位归属，或明确归为通用型。不允许既无岗位、也无通用分型的裸条目。**

## 决策

**一、技能目录不保留 `.git`。**
第三方技能以纯目录形态安装（下载上游 tarball 解压，不留版本控制元数据）。代价是失去内置版本控制，
改由「**锚定 commit SHA 记入该技能的接口文档** + 上游 tarball 版本化」承担可复现与回滚。
`lieflat-charts` 已按此执行（删除 `.git`，释放 18 MB）。

**二、入库必须二选一：挂岗，或显式通用分型。**
`manifest/role-assignments.json` 的条目必须满足：

- **挂岗**：`roles[]` 非空，且 `responsibility` 逐字属于该岗三条责任之一；`from_skill`/`from_role`
  必须是两侧原文的连续子串（防伪造）；≥3 岗时不得标 `high`。
- **通用型**：`roles: []` **且** `no_role_kind` ∈ `GENERIC_METHOD` / `TOOL_ONLY` / `OUT_OF_SCOPE` / `OTHER`，
  **且** 必须写 `no_role_reason`。

判别口径：**技能是「产出业务结论」还是「只做呈现/转换」**。前者挂岗，后者 `TOOL_ONLY`。

**三、入库六步固化为 SOP**（`dsh-overseas-skills/docs/maintenance-sop.md` §12）：
形态判定 → 来源留底 → 补齐元数据 → 场景归位 → 岗位归属或通用分型 → 重建/验收/生效。

## 备选方案

- **A 保留 `.git`，更新时 `git stash` + 重放本地字段**：可保住 `git log` 与一键 `git pull`，
  但把「记住重放哪几个字段」变成永久人工负担，且漏做一次就冲突。用户选定 B。
- **把本地改动做成独立的 overlay 文件（不改上游 SKILL.md）**：可以同时保住 `.git` 与可更新性。
  但 DSH 的技能发现只认 `<dir>/SKILL.md` 单一 frontmatter，没有 overlay 机制；实现它等于改基座，
  被仓库红线排除。
- **不写 frontmatter，只写 manifest**：实测无效——`title`/`user_summary` 由技能页读 SKILL.md 侧，
  且会话技能目录也不显示中文名。两道都要写。
- **不挂岗也不给分型（保持裸条目）**：被用户显式否决，规则即为本 ADR 第二条。
- **为第三方技能在 manifest 里另立一套平行结构（区分「自研 81 系」与「引入」）**：语义上更干净，
  但要改动 taxonomy/role-assignments/skills 三处 schema 与全部消费方，收益不抵本轮成本；
  已改为在 `SKILL.md` 的 `metadata.source: third-party` 里标注来源，不动 manifest schema。

## 后果

**正面**

- 更新不再有 frontmatter 冲突；代价（失去 `git log`）由文档记录的 SHA 补上。
- 归类规则可机器校验：包契约门已含「meta 计数与 manifest coverage 一致」「归位表形状合法」
  「`lib/role-map.js` 是 manifest 的精确投影」，裸条目与非法分型会被门禁挡下。
- 入库路径成文（SOP §12），不再依赖本次会话的记忆。

**代价与约束**

- 去 `.git` 后**无法 `git diff` 看出上游改了什么**；升级时只能整体覆盖 + 重放字段。
  升级流程已写进该技能 `README.usage.md` §2.2（含备份、重放、`validate.mjs` 校验）。
- 锚定 SHA 存在文档而非版本库，**文档丢失即失去可复现性**。
- 本轮 `lieflat-charts` 判为 `TOOL_ONLY`，**在出海技能页不显示任何岗位**。这是刻意的：
  它输入任意数据、输出单文件 HTML，不选品、不诊断、不归因。同组 `ecommerce-sales-dashboard`
  挂 AGT-021/AGT-003 是因为它自带业务口径——两者不能因为「都出报表」而抄同一答案。
- 许可证是业务决策而非技术决策：该技能为 PolyForm Noncommercial，**对外商业交付超范围**；
  上游 issue #17（企业内部使用是否可行）至今无回复。本 ADR 只保证该事实被留档，不代替授权。
