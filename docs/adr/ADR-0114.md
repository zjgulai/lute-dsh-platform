# ADR-0114 · 补丁里的环境常量必须随基座形态一起被判定（P0-8 退役 + 会话迁移器 title 准入）

- 状态：accepted（2026-09-17）
- 决策者：用户（lute）+ DSH 基座迁移轮
- 决策记录：[Note](../notes/implemented/packaging/2026-09-17-resource-path-reachability-and-v0-title-admission.md)
- 相关：ADR-0005（补丁登记）、ADR-0008（基座只 pin 不改）、ADR-0014（门禁硬门槛）、ADR-0058（同号归档）、ADR-0075（判据射程）、ADR-0102（判据的分母与四态）

## 背景

2026-09-17 装完 LUTE 2.5.0（DSH 2.0.10 基座）后应用直接进入恢复模式：

```
dsh-plugin-desktop: plugin tree failed to load: failed to import loader entry llm-pi-ai
  (@deepseek-ai/dsh-llm-pi-ai): Cannot find module
  '<Resources>/app.asar.unpacked/node_modules/@earendil-works/pi-ai/dist/api/anthropic-messages.lazy.js'
```

这次事故暴露**两条**独立缺陷，且都不在「补丁有没有打上」这个维度上。

**其一：一条被基座迁移作废的环境常量，照样绿着出厂。**
P0-8 补丁（写于 2.0.5/asar 基座）把 pi-ai 懒加载模块的路径写死：

```js
const PI_AI_API_DIR = `${process.resourcesPath}/app.asar.unpacked/node_modules/@earendil-works/pi-ai/dist/api`;
```

2.0.10 起官方产物改为 **no-ASAR**：`Contents/Resources/app/` 是普通目录，既没有 `app.asar`
也没有 `app.asar.unpacked`。该字面量因此必然悬空，而**没有任何判据会报**——因为
`packaging/verify-patches-v2.sh` 对它的断言是：

```sh
ck "P0-8 pi-ai 磁盘化" "$NM/dsh-llm-pi-ai/lib/index.js" "PI_AI_API_DIR"
```

这条判据量的是**补丁的身份标记**（常量名在不在文件里），不是**那条路径在产物上能否解析**。
于是「补丁在」被读成「能力能跑」，锚门全绿、装配全绿、装到机器上才炸。

**其二：LUTE 自己写进 v0 会话的扩展成员，会让 LUTE 自己的会话读不出来。**
会话迁移器 `dsh-session-format-v0-to-v1` 对 `skill-catalog` 的条目做**精确成员**校验
（只有 `name` + `description`）。而 LUTE 的 skill-title 扩展从 2.0.5 起就在
`catalogSourceEntries()` 里额外写入 `title`（并随 `entries` 一起持久化进会话事件）。
基座升到 2.0.10 后，v0→v1→v2→v3 的迁移链第一次真正跑起来，于是**整条会话**被拒绝：

```
refuses this format v0 Session: user/message 13 source entries[0] has unexpected member "title"
```

实测射程（本机 470 份 v0 会话）：修前只有 **74 份**能迁移，**396 份**被这一条卡死；
修后 **469 份**通过（余 1 份是另一个独立缺陷，见「后果」）。

## 决策

**1. P0-8 整体退役，把解析交还给 Node。**
删除 `packaging/patches/nm/@deepseek-ai/dsh-llm-pi-ai/lib/index.js.patch`。上游那三行本就用包自身
`exports` 的静态 import（`@earendil-works/pi-ai/api/anthropic-messages.lazy`），由 **Node/Electron
自己的解析器**处理——asar 与 no-ASAR 两种布局它都认。**不新增任何路径常量**：环境事实的合法家
是解析器，不是插件源码里的字面量。

**2. 会话迁移器准入可选 `title` 成员（带类型校验）。**
在 `packaging/patches/nm/@deepseek-ai/dsh-session-format-v0-to-v1/lib/index.js.patch` 中：
`skill-catalog` 条目的 `exactRecord` 增加可选成员 `title`，且 `title` 若出现必须是字符串。
**保留**该成员而不是把它从产物里删掉——迁移的 identity edge 原样保留已列出成员，
所以 `title` 会无损进入 v1，LUTE 的中文技能标题不受影响（实测 870 个 title 全部存活到当前 v3 产物）。

**3. 新增门禁 `resource-path-reachability`（+ 反向自测），补上「路径必须在产物上真实可达」这一面。**
它扫描产物里出厂会被补丁改到的两处（`lib/` 与 `node_modules/@deepseek-ai/**`），抽出**路径形态**的
资源根字面量，按产物真实形态判定可达性。判据的边界写死为「只钉路径」：
`String.replace` 的替换值与正则字面量里的同名字符串（`main.js` 的
`.replace(/app\.asar(?!\.unpacked)/g, "app.asar.unpacked")` 是合法 no-op）**不得判红**——
仪器假红与假绿一样贵。射程为空的树按**未核实**计数，不并进「已核实」。

**4. `verify-patches-v2.sh` 的 P0-8 断言改为钉上游静态 import + 否定式断言**（不得再把
`app.asar.unpacked` 写进路径），并补上迁移器两条断言。

## 备选方案

- **保留 P0-8 但改成布局自适应**（`existsSync` 判 unpacked，否则落 `Resources/app`）：
  否决。它把**一个可以在解析器里解决的事**留在插件源码里，还引入一条在 no-ASAR 产物上
  **永远走不到的分支**（P-04 形态：写了但从没跑到）。且 2.0.5 的 asar 产物已不是本次出货面，
  那条分支无法再用真产物验收。
- **只在门禁里加「路径存在性」检查，不改 P0-8**：否决。门禁应当**拦住**缺陷，而不是替缺陷说话；
  悬空的常量本身必须删。
- **迁移器改为「宽容未知成员」（把 `exactRecord` 放宽成不校验额外键）**：否决。v0 迁移器的
  封闭成员清单是它有意的 Alpha 策略（未知事件类型/成员必须让迁移失败而不是猜），全放开会让
  **真正损坏的产物**也静默通过。只准入 `title` 这一个已知扩展，并保留其类型校验。
- **让会话不再写 `title`（改 `catalogSourceEntries`）**：否决。那等于为了迁就跑通而砍掉一个
  已上线的用户可见能力（技能中文标题），且历史 396 份会话里的 `title` 已经落盘，删不掉。
- **把 `title` 塞进 `description` 或别的既有成员**：否决。语义错位，且会让目录 digest 与
  现有落盘事实不一致。

## 后果

- 本机 470 份 v0 会话：**74 → 469** 可迁移；被此缺陷卡死的 396 份全部恢复。
- 2.5.0 与 staging 树各修一处后，`pnpm run gate` 的 `patch-anchors`、
  `resource-path-reachability`、`resource-path-reachability-selftest` 全绿。
- **两处修复都落在运行时层（NM patch）而非宿主源码**，因此不触碰 app 内 `lib/**` 分块；
  app 的代码签名封条**在本轮之前就已破损**（安装器会改写 `app.asar.unpacked` 原生 UI 页，
  `refresh-app-brand.sh` 已记载这是设计），故两处修复不改变封条状态；TCC 仍是身份型授权，不受影响。
- **未决尾债（不在本次射程）**：仍有 1 份 v0 会话以另一条消息被拒——
  `cannot safely transform unclassified message source`（`session-6d32eef5`）。它与 `title` 无关，
  需要单独定位那条 message source 属于哪个扩展后另开决策。
- **未决尾债（判据射程）**：`resource-path-reachability` 只钉**已经发生过一次的那个形状**
  （把 `app.asar*` 当路径的字面量）。把路径两段拼接、或先存进变量再传，能绕过它；
  它不假装守住全称，残留缺口写在模块头部。
- staging/2.4.1 是 ASAR 布局且核心文件在 `app.asar` 内，当前扫描面读不到其 `.js`，
  如实报「未核实」而非判红——已打 tag 的版本由产物自身负责（ADR-0067 / ADR-0075）。
