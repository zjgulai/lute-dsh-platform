# ADR-0061 · 新应用抽屉同时兼容 `ctx.agentPresets` 与 `connection.api.agentPresets`；深链星探走本机装配而非出货 preset

- 状态：accepted
- 日期：2026-09-13
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-13-newapp-agentpresets-channel-and-kol-hunter-local.md)
- 相关：ADR-0045（`kol-hunter-workbench` 服务已存在）、ADR-0056（出货 preset 不烘焙外部产品行；本机装配层是授权路径）、ADR-0046（可选服务读取纪律）、ADR-0009（一份事实只有一个家）

## 背景

用户要求「侧边导航栏的新应用按钮下的应用」稳定运行，并特别提到要完善「深链星探 KOL Hunter Agent」。

排查发现三件事混在一起：

1. **`dsh-newapp-local` 的 launcher 只认 `connection.api.agentPresets`。** 这条路径在 typert 桥接形态的 shell 上工作；但当前 DSH 基座把 host 服务直接镜像到 `ctx`（`sessions`、`locale` 等都已走这条路径），`agentPresets` 也出现在 `ctx` 上。launcher 没探测 `ctx` 时，会错误地认为 preset 选择器不可用，导致卡片点了没反应。
2. **`KOL-Hunter/product.json` 的 `statusReason` 与事实漂移。** ADR-0045 已实测 `KOL-Hunter/lib/client.js` 通过 `ctx.provide('kol-hunter-workbench', …)` 注册了入口面板服务，但 `product.json` 仍告诉用户「入口面板尚未安装，暂走回退」。这会降低用户信任，也让卡片状态语义混乱。
3. **ADR-0056 把 KOL-Hunter 从出货 preset 移出后，本机没有恢复装配层。** `agt-033` 组合里不再有 `product-kol-hunter`，L2 产品技能 `kol-hunter-candidate-screen` 不会随 preset 加载。结果是：即使面板能打开，产品内部技能也调不到。

## 决策

1. **launcher 按 shell 代际选择岗位设置路径。** 先探测是否存在可调用 `select` 的 `agentPresets` 通道（载体可能是 `ctx.agentPresets`、`connection.api.agentPresets` 或 `connection.remote.agentPresets`）。若存在，走旧 triple `create({cwd}) → agentPresets.select(sessionId, preset) → sessions.open`；若不存在，走当前 DSH 基座支持的路径 `sessions.create({ cwd, agentPreset: preset }) → sessions.open`。这是 ADR-0046「可选服务读取纪律」的延伸：不能假设服务只从一个载体来，也不能假设所有 shell 都支持同一种 preset 设置方式。
2. **把通道探测结果写进 `localStorage`，键为 `dsh-newapp-probe`。** 该 probe 在 `prime()` 时执行一次，不抛异常；下次诊断可直接从渲染进程 leveldb 读取，不必让用户打开 DevTools 复制对象。probe 只记录布尔/键名，不含凭据或会话内容。
3. **新应用抽屉解析 `entryService` 扁平字段。** 服务端把 `entry.service` 扁平化为 `entryService`（ADR-0045），解析器必须优先读它，并在使用扁平字段时忽略嵌套 `entry.action`，避免服务名正确但 action 被旧值覆盖。
4. **KOL-Hunter 的 `product.json.statusReason` 改为事实描述。** 明确入口面板服务 `kol-hunter-workbench` 已随包安装，draft 状态只反映功能完整度，不再把「走第 2 级回退」作为当前行为。
5. **本机通过直接编辑 `~/.dsh/.agent-presets/agt-033/agent.cordis.yml` 恢复 KOL-Hunter 装配，不出货。** 在 skill-subset 后插入产品行 `- id: product-kol-hunter / name: 'dsh-kol-hunter-local'`，并提供 `scripts/mount-local.mjs` 以便 preset 重生成后快速恢复。该改动只在本机运行时 preset 生效，不进仓库、不进 `PRODUCT_MOUNTS`、不进 `assemble.sh` 的出货树，符合 ADR-0056 的「本机装配层」设计。
6. **更新项目级与用户级 `AGENTS.md`**，把以下四条变成常驻规则：
   - 外部产品包不进出货 preset，本机使用走本地装配；
   - `dsh-newapp-local` 按 shell 代际选择 preset 设置路径；
   - 读取可选 host 服务时须探测多个载体并以方法存在性为准；
   - DMG 打包发布必须按 `docs/sop/dmg-release.md` 执行。
7. **新增 `docs/sop/dmg-release.md`**，把 ADR-0056/0057/0058 的打包经验沉淀为可重复 SOP。

## 备选方案

- **把 KOL-Hunter 重新写回 `scripts/role-presets/generate.mjs` 的 `PRODUCT_MOUNTS`。** 否决：这会复活 ADR-0056 诊断出的跨项目机器路径依赖，客户机没有 `/Users/lute/project/KOL-Hunter` 时 preset 加载失败并进入恢复模式。
- **让 launcher 完全切换到 `ctx.get('agentPresets')` 并删除 `connection.api` 路径。** 否决：旧 shell 仍通过后一条路径暴露服务，删除 fallback 会在另一部分用户机上制造回归。
- **不写 localStorage probe，只依赖 console.log。** 否决：重启后日志丢失；leveldb 中的 localStorage 是更稳定的诊断面，且 probe 内容不含敏感信息。
- **把 DMG SOP 合并进 `packaging/README.md`。** 否决：README 已承载历史与架构说明，SOP 需要被 CI 和人类按步骤执行，独立文件更易校验、打印和链接引用。

## 后果

**正面**

- 新应用抽屉在当前 shell 与 typert 桥接形态 shell 上都能正确找到 preset 选择器。
- 深链星探在本机运行时可稳定打开入口面板并调用产品内 L2 技能。
- ADR-0056 的出货约束未被破坏：仓库内 `PRODUCT_MOUNTS` 仍为空，profile 本地装配是运行时行为。
- 项目级与用户级 AGENTS.md 同步了本次形成的三条规则，后续 agent 会话能直接拿到上下文。
- DMG 打包发布有独立 SOP，新人可按文档复现。

**负面 / 待办**

- `localStorage` probe 只在 `prime()` 执行，如果抽屉从未被打开则不会写入；后续可考虑在 `apply()` 也做一次只读探测，但需避开 `connection` 尚未就绪的时序。
- profile 本地装配目前靠直接编辑 `~/.dsh/.agent-presets/agt-033/agent.cordis.yml` 实现，运行 `scripts/role-presets/generate.mjs` 会重写该文件。已提供 `KOL-Hunter/scripts/mount-local.mjs` 用于快速恢复；若需要在多台机器复现，应另立 ADR 讨论「本地产品目录模板」或「产品市场侧载」机制。
- KOL-Hunter 的 `status: draft` 未变；功能完整度提升是另一项独立工作。
