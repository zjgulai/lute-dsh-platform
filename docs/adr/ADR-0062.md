# ADR-0062 · 新应用抽屉增加「业务系统」第二分区：外链只由宿主打开且只接受 slug；本包从此拥有一份 catalog（部分修订 ADR-0045）

- 状态：accepted
- 日期：2026-09-13
- 决策者：用户（要求把 `lute-tlz-dddd.top/systems.html` 的全部卡片链接「以类似卡片的形式存放到新应用中，并按照当前的岗位角色来分类」，并追加约束「卡片必须精美，并且保障品牌一致性」）+ agent（动工前一次取证、四项分叉裁决）
- 决策记录：[Note](../notes/implemented/surface/2026-09-13-newapp-systems-section.md)
- 相关：ADR-0045（**部分修订**：产品分区目标函数不变，抽屉增加第二分区）、ADR-0009（一份事实只有一个家）、ADR-0043（失败要给出为它负责的读数）、ADR-0054（交付判据是装载点字节）、ADR-0033（产品卡 preset 必填，本轮不受影响）、ADR-0039（语义 token 三法则，本轮卡片样式照办）

## 背景

用户要求把路特主域名下的 31 个系统入口，以卡片形态收进 DSH 桌面端的「新应用」，分类轴由源页面自带的 5 类改为**本机的 50 个岗位角色**。

动工前取证到四件事，每一件都会单独改变方案：

1. **源页面要登录，且不含岗位数据。** `POST /portal/session` 换取会话后取到 31 张卡（31 个唯一域名），字段为中文/英文名、中英简介、类型 chip、技术标签、动作文案、外链。分类只有 `data-category` 五类，**页面上没有任何岗位字段**——岗位归属只能是人的判断。
2. **31 个目标全是外部域名**，没有本地目录、没有 preset、没有 `entry.service`，在既有三级判据 `planOpen()` 下全部落到「不可用」。
3. **本机壳拒绝外链拉起浏览器。** 应用产物的 `setWindowOpenHandler` 对 http/https 一律 `deny`（P0-6v2），只放行 `mailto:`。仓库既有的 `<a target="_blank">` 写法在这个壳里点了没有反应。
4. **ADR-0045 刚把该面剪枝**为「只摆已产品化产品」，并删除了 24 张点不开的占位卡。

## 决策

1. **抽屉分两个分区，两个分区各自有目标函数。** 上分区「产品」按 ADR-0045 原样不变（一卡一产品、未产品化占位卡数 0、六项字段、点开三级）；下分区「业务系统」只列外部系统，**不产生任何禁用卡**。ADR-0045 的 M1/M2 只对上分区生效。落点选扩展 `dsh-newapp-local` 而不是新建插件，因为用户的原话就是「存放到新应用中」，且剪枝针对的是**占位噪音**（点不开的卡），与全是可点开卡的新分区不冲突。

2. **两份开卡契约，不合并成一个联合类型。** `planOpen()` 逐字不变；系统走独立的 `planOpenSystem()`，只有 `{level:0, kind:'url'}` 与两个禁用原因（`no-href` / `no-opener`）。理由：产品的禁用来自「本机没装」，而系统不存在「本机没装」这个状态；合并会诱使「给没有工作目录的东西返回 `session`」这类错误复用。两个分区的按钮文案也不同（产品是「打开 / 开会话」，系统是站点自己的动作文案），避免用户分不清哪个按钮会把他带离本应用。

3. **外链只能由宿主打开，且路由只接受 slug。** 新增 `POST /api/dsh-newapp/open-system`，body 为 `{"slug": "<catalog key>"}`；**客户端永远不传地址**，宿主用 slug 在自己打包进产物的 catalog 里解出地址，再以 argv 传参、不经 shell 地启动平台打开器（darwin `open` / win32 `rundll32 url.dll,FileProtocolHandler` / linux `xdg-open`）。未知 slug 一律 404。**这条是对 P0-6v2 意图的正面实现**：路由不是「打开任意 URL」的原语，客户端能请求的范围恰好就是那 31 条已审阅的地址。

4. **本包从此拥有一份数据：外部系统 catalog。** 它落在 `src/catalog/` 的三份文件里，三个家互不覆盖：`systems.json`（机器写，身份，由 `sync-systems.mjs` 生成且必须幂等）、`role-map.json`（人写，岗位归属 + 每条的判断理由，永不自动覆盖）、`reachability.json`（带日期的巡检读数，由 `probe-systems.mjs` 写）。`tests/contract.spec.ts` 里「本包不拥有任何数据源」的断言按新事实重写为「恰好拥有一份，加第二份必须是有意的决定」。凭据只从 DSH 凭据服务或环境读取，脚本不写凭据。

5. **catalog 随构建内联，不做运行期文件读取。** 实测装载点包只带 `lib/` + `cordis.patch.yml` + `README.md`，产物的运行期 import 仅 node 内建；运行期读文件会指向不存在的路径，且失败模式是「profile 同步后出现一个空分区」。代价是宿主半边体积 8 KB → 71 KB（gzip 20.5 KB），认账。

6. **面板打开时零网络请求。** 可达性只在离线脚本里测，结果带日期写进 catalog，卡片把它读作「某日的读数」。在渲染路径上发请求会让抽屉在断网时变空、在站点抖动时变慢。

7. **岗位归属是多对多，但一个系统只出现一次。** 主岗位决定分组，兼属岗位是卡上的 chip 并参与搜索命中。不认识（roster 里没有）的岗位照常渲染并标记，不隐藏——隐藏会让一次 preset 改名看起来像系统被删了。

8. **卡片的品牌一致性由既有门禁强制，不靠肉眼。** 新样式遵守 `tests/stylesheet.spec.ts` 的三条 token 法则（颜色字面量只住品牌块、`var()` 兜底 = 浅色实测读数、字号只走官方简写阶梯），并新增 `.sysCard:focus-visible` 的焦点可见与 reduced-motion 覆盖。源站图标不复制标记，由同步脚本拆成封闭词汇后渲染成真实 React 元素。

## 备选方案

- **31 份 `product.json` + 给 `planOpen` 加外链档**：改动最小、复用最多，但抽屉里会出现 31 个「不是 Agent 的产品」，`product.json` 的语义与「点开直接跑」的承诺同时被稀释。
- **新建独立插件 `dsh-systems-map-local`**：零 ADR 冲突，但侧边栏再多一个入口，且牺牲用户明确说过的「一个入口装下全部」。
- **挂进 `dsh-role-matrix-local` 岗位矩阵**：分类轴天然是岗位，但会破该插件「只读预设目录」的声明边界。
- **`<a target="_blank">` / `window.open`**：实测被主进程拒；且仓库里已有的这种写法在本壳上同样是静默失效。
- **复用 `@deepseek-ai/dsh-native-command` 的 `openNativePath` 或 `session.openWorkspacePath`**：前者接文件路径（Windows 走 `Invoke-Item`、WSL 要 `wslpath` 转译），后者会先把参数按会话工作目录解析——两者对 URL 都是错的用法。
- **每次打开抽屉实时抓取**：把面板可用性绑到站点登录态与网络状态上。
- **岗位映射由脚本按关键词推导**：源页面没有岗位数据，推导等于把猜测写进一份会被当事实读的文件。

## 后果

- **正面**：31 个系统入口进入本机启动面，按 14 个岗位分组、覆盖 23/50 个岗位（页脚如实报数）；外链有一条被单独审阅、只认 catalog 键的宿主通道；产品分区的行为与目标函数零变化；catalog 可离线复跑且幂等，站点漂移以 `git diff` 呈现。
- **负面**：宿主半边体积涨到 71 KB；`dsh-newapp-local` 从「不拥有任何事实」变成「拥有一份 catalog」，这是一个需要被记住的身份变化（README 与 Note 均已写明）；岗位映射是人的判断，需要人复核。
- **门禁契约被本次修订**：`tests/contract.spec.ts` 的路由表钉死断言与「本包不拥有数据源」注释按新事实重写（钉死保留）。
- **待办（未宣称完成）**：宿主半边改动需重启应用才落进程，重启后的实况 UI 读数（31 张卡、14 个分组、点开进默认浏览器）尚未取得。
