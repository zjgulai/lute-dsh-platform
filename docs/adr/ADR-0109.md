# ADR-0109 · Settings 内容面板与跨 surface 浮层层级合同

- 状态：accepted（2026-09-17）
- 决策者：用户（lute）+ agent
- 决策记录：[Note](../notes/implemented/surface/2026-09-17-settings-content-and-layer-contract.md)
- 相关：ADR-0104（Codex Desktop 视觉语法）、ADR-0098（Settings Shell 归属与校准）、ADR-0108（抽屉控件合同）

## 背景

Settings 已经修复了右侧 sidebar 的遮挡，但内容列仍依赖上游组件各自定义滚动、控件和分隔，窄窗口下容易出现
导航挤压、多个滚动容器和页面密度不一致。与此同时，Skill Center 的 `z-index:9999` 与 Deep Research 的
固定 `100/110` 会让不同 surface 形成互相竞争的浮层方言。

## 决策

1. `dsh-settings-shell-local` 只在 parser-owned `data-dsh-settings-shell-root` 下统一 `panel → content → header/options`
   结构；`options` 是唯一内容滚动区，增加主题 token、表单输入基线、焦点、禁用态、分组分隔和窄屏降级。
2. Settings shell 不覆盖业务 section 已有的按钮几何、switch 尺寸或状态色；按钮行为和 section-owned visual semantics
   仍由各 section 负责，shell 只提供低风险的继承、输入和焦点基线。
3. Skill Center、Deep Research 只把 raw z-index 收口为各自作用域内的语义层级变量，并使用低于 Settings root 的回退值；
   不新增 runtime、路由、slot、权限或 vendor 修改。
4. compiled-only surface 不直接手改作为后续源代码恢复 Ticket；本决策不以手工修改编译产物替代源码可维护性。

## 备选方案

- 直接改 vendor SettingsRoot 或其 CSS-module：拒绝，会破坏基座只读边界并依赖不稳定哈希。
- 用一个全局按钮选择器强制所有 Settings section 的尺寸：拒绝，会覆盖 switch、图标按钮和 section-owned action geometry。
- 继续为每个 surface 维护独立 raw z-index：拒绝，会复现 Settings、右侧 sidebar 与 modal 的层级竞争。
- 直接手改 Task Board/My Quotes/Wanzh/LoopX 的 compiled-only bundle：拒绝，先恢复源码入口或构建链。

## 后果

Settings 在宽屏、窄屏和主题状态下拥有明确的内容滚动边界；Skill Center 与 Deep Research 的浮层层级不再使用
目标明确的 raw 值，且 Settings root 仍保持最高本地 modal 优先级。包级测试、typecheck、build 和 CSS 合同已完成；
profile sync、统一重启后的 live GUI、截图、键盘与 macOS 解锁后的人工视觉验收仍是后续 gate。
