# ADR-0070 · 技能「开没开」的真值只有一个家：技能文件；面向使用方的词必须自解释

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：用户（「这些名词使用方都看不懂……还有些卡片无法被打开」）+ agent（本次取证、判定与落地）
- 决策记录：[Note](../notes/implemented/surface/2026-09-13-skill-invocation-truth-and-vocabulary.md)
- 相关：ADR-0031（全库 `disable-model-invocation: "true"` 的来源与意图）、ADR-0041（算法技能页与「那次写只动值，不动拼法」）、ADR-0014（门禁是硬门槛，也会把错的事实钉死）、ADR-0009（一份事实只有一个家）、ADR-0061（本机使用外部产品走 profile 本地装配）

## 背景

「设置 → 算法技能」的两条使用方反馈（词看不懂、开关像被冻结）在诊断中拆出三个独立缺陷：
技能中心面板的开关**真的会弹回去**（77 张卡）、算法技能页**全库默认关却从不解释**、
以及 preset 白名单被文件开关**反向否决**（275/439 个白名单位失效）。取证与读数见 Note。

其中一条是结构性的，本 ADR 只钉这一条：**同一张卡的开/关状态，被三个层次各自回答了一遍**
——技能文件、运行时注册表（可被预设作用域的遮蔽注册覆盖）、以及面板的显示。
三者不一致时，界面选谁都不算错，除非先定下「谁是真值」。

实测的不一致形态（`code-review`，文件说开、面板说关、接口说开、写盘写的就是文件）：
用户点一下开关，亮一下，重渲染又灭回去——一个**承诺了却做不到**的开关。

## 决策

1. **技能文件是调用状态唯一的真值来源。**
   宿主级技能管理器（`dsh-skill-center-local`）合并注册表时，**扫描到的条目保留自己回答过的字段**：
   `provider` 与 `disable-model-invocation` / `user-invocable` 推导出的两个开关。
   注册表只允许补 `whenToUse` / `title`，并照旧贡献它独有的条目（bundled / runtime）——
   那些没有文件，不适用本条。
   判据的依据是**优先级已经定过**：扫描到的条目是同名冲突的胜者，胜者不该被落败者改写。

2. **预设作用域内的遮蔽注册是合法的，但不得冒充全局事实。**
   `dsh-skill-subset` 的 `hideOthers`（默认开）在**它自己的 preset 会话里**是对的：
   岗位会话只该看见本岗那几张卡。本条不要求改它，只要求全局管理器不把它的回答
   当成「这张卡开不开」。两个问题必须分开回答，混在一起就会得到今天这个弹回去的开关。

3. **面向使用方的词必须自解释，且定义了的文案必须被渲染。**
   - 统计口径改为业务白话，并且解释要**在页面上**（常显一段），不能只挂在 tooltip 上：
     使用方的反馈就是「看不懂」，而没有人会去悬停一个自己还没打算在意的数字。
   - **矛盾状态必须明说**：卡被本岗装配、但模型不会自动调用时，卡上直接标出原因并指向开关。
   - `chip.off` 在 `locales.ts` 里定义了却从未被渲染（全仓零引用）——**定义了但没接线的文案
     与没写一样，而且更坏：它让人以为已经解释过了。** 这条已落成机制，不只是约定：
     `packages/surfaces/dsh-algo-skills-local/tests/copy-wiring.spec.ts` 要求 locales 里
     每个键要么被渲染、要么登记在**只减不增**的清单里（照 `scripts/gates/exemptions.json`
     的规矩），双向不等即红灯。

## 备选方案

- **改查询姿势：`registry.snapshot()` 带作用域参数，绕开预设遮蔽。** 被否：遮蔽在宿主级快照里
  已经可见（读数是 `provider: runtime`），不是查询方式问题；而且技能中心是全局管理器，
  它没有、也不该有预设身份。改合并规则不依赖调用方。
- **关掉 51 个预设的 `hideOthers`。** 被否：那会让 50 个岗位会话各暴露 1600+ 张卡，
  正与 ADR-0031 的意图相反。作用域内遮蔽是对的，错的是它泄漏进全局显示。
- **开关改成写注册表。** 不可能：注册是插件的运行时行为；且那样开关的语义就从
  「这张卡开不开」变成「这次会话开不开」，换掉了它承诺的东西。
- **把面板改成「一律显示注册表的回答」。** 被否：那正是今天的 bug；而且它会让反向的错也成立
  （注册表能把文件已关的技能显示成开着）。
- **批量翻转 1338 个卡的文件开关，让开关看起来都对。** 被否：那是产品决策而非 bug 修复。
  全库默认关是 ADR-0031 写下的取舍（模型目录约 7.2 万字符），要改就得连白名单语义一起重新设计。
- **只改文案，不碰真值归属。** 被否：留着一个会弹回去的开关，文案再好也只是把问题说圆。

## 后果

- **正面**：
  - 面板显示与写盘指向同一个事实（文件），两个方向都修：不再把开着显示成关，
    也不再能把关着显示成开。
  - 合并规则的两个方向各有一条测试**先红后绿**钉死；「注册表独有条目保留自己的开关」
    作为反向保护同批落地（否则修法会退化成「一律取文件默认值」，把 bundled/runtime 条目压平）。
  - 算法技能页的四个词换成业务白话，每个数字带一句短解释，页面另有一段口径说明。
- **负面 / 边界**：
  - 遮蔽在预设作用域内依然存在，这是设计；面板不再替它兜底，因此
    **「面板显示开着」不再等价于「在某个岗位会话里模型会自动调用它」**。
    这个差别现在是显式的两个问题，而不是一个词里混着的两个事实。
  - 本条**没有**解决白名单失效（275/439，见 Note 缺陷 C），也没有动算法技能页的数据。
  - 修复落在仓库 fork；运行中的技能中心仍是 npm 包（同一处缺陷），投递路径待决。
- **后续动作**：
  - 缺陷 C（白名单被文件开关否决）与技能中心的投递路径，各需一次决策并各自留痕。
  - 文案接线判据（`copy-wiring.spec.ts`）目前只在算法技能页包内；若别的面也出现
    「定义了没渲染」，把它提升为仓库级门禁，而不是各包各写一份。
