# ADR-0013 · 资产分级处置：删除 / 归档出工作树 / 纳入版本管理

- 状态：accepted
- 日期：2026-09-11
- 决策者：用户（lute）+ agent（grill-me 决策树 N4）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-11-lute-refactor-three-phase.md)

## 背景

实测仓库内积累了三类噪音资产，且与白名单式 `.gitignore` 相互作用后状态自相矛盾：

1. 根级 46 个游离文件（均未被跟踪），含误重定向残渣 `extract.jsnecho`、`extract.jsnnode`、`patch-index.mjsnecho`、`patch-index.mjsnnode`、`patch-toggle.mjsnecho`、`patch-toggle.mjsnnode`、`restart.shnbash`，以及 15 个一次性补丁脚本与 12 个预览 HTML。
2. `.gitignore` 白名单中 5 个路径在磁盘上不存在：`dsh-noema-local`、`dsh-bridge-protocol-local`、`dsh-browser-extension-local`、`archify-local`、`deepseek-harness-studio-presets`。
3. 42 个已跟踪文件命中 `.gitignore`（tracked+ignored 漂移），含 `dsh-memory-local/src/*.orig`、`dsh-patches/archive/**/*.orig` 等备份文件。
4. 大体量游离资产：`v4-ten-contact-sheet.html`（32.9MB）、`project-management.univer`（192KB）、`_attic/`（32 项）。

## 决策

**按资产价值分三档处置，不可逆操作前先归档、且归档必须离开工作树：**

| 档 | 处置 | 对象 |
| --- | --- | --- |
| 直接删除 | 删除 | 0 字节误重定向残渣（`*.jsnecho` / `*.jsnnode` / `*.shnbash`）、已被插件目录取代的一次性根级补丁脚本（`patch-*.js`、`fix-*.js`、`build-*-avatars.js` 等） |
| 归档出工作树 | 移至 `~/project/_archive/Magpie-Horch-<日期>/`，仓库内仅留 3 行 README 指向 | `v4-ten-contact-sheet.html`、`project-management.univer`、预览 HTML 群、`_attic/` 全量 |
| 纳入版本管理 | 移入受管目录并去掉 `.gitignore` 冲突 | `*.orig` 备份 → `docs/verify/orig-backups/`（消除 tracked+ignored 漂移态） |

同时清除 `.gitignore` 白名单中的 5 个幽灵路径，并删除与实际策略冲突的冗余规则。

## 备选方案

- **A 全部删除**：被否决——`_attic/` 与整幅设计预览可能仍有回溯价值，删除不可逆。
- **B 全部冻结保留**：被否决——噪音会继续淹没真实资产，且 32.9MB 文件持续拖慢工具链。
- **D 归档保留在工作树内**（如 `_attic/` 原地冻结）：被否决——白名单式 `.gitignore` 会继续把工作树内归档当噪音处理，等于没治；且大文件仍在仓库目录树内参与 glob、搜索与打包扫描。

## 后果

- 正面：工作树回到「全部内容都有明确归属」的状态；tracked+ignored 漂移归零；工具链扫描体积显著下降。
- 负面/代价：归档出工作树后，历史资产的检索需离开仓库进行；一次性脚本删除后如需恢复须依赖会话记录或 git 历史（多数本就未被跟踪，故不可恢复——故仅删 0 字节残渣与被取代者）。
- 后续动作：三期执行处置；执行前先产出待删清单逐项确认（不可逆操作需用户逐项拍板），并归档完毕后再执行删除。
