# ADR-0105 · CI 的判据面必须能被离线证伪：workflow 契约静态校验 + 干净 HOME 干跑，且不得把「未验证」说成「已建立」

- 关联：[ADR-0102](ADR-0102.md)（分母由被检查对象的完整集合推出）、[ADR-0103](ADR-0103.md)（见证与进程级回收）、[ADR-0063](ADR-0063.md)（仪器假绿）、[ADR-0094](ADR-0094.md)（三态读数）、[ADR-0040](ADR-0040.md)（真 node 判据）

## 背景

QG-007 的目标是「由独立 runner 在 PR/main 上执行门禁，不能依赖开发者本机结果」，卡面同时写了两条硬要求：

- Red：「**根仓库无可验证 workflow run 或 PR 不触发目标 checker 时，不得引用本机 gate 结果宣称 CI 已建立**」；
- 证据层级：「L1 workflow 静态校验；L2 fork/受控 PR run；L3 main required run。**开发机日志只能作为诊断，不是 CI 证据**」。

执行本卡时的环境事实必须先说清楚，因为它决定了这一轮能做到哪一层：

| 事实 | 读数 |
|---|---|
| 仓库里**没有任何 workflow** | `.github/` 只有 `pull_request_template.md` |
| GitHub 不可达 | `git ls-remote origin main` → `Failed to connect to github.com port 443 after 75002 ms` |
| 容器运行时不可用 | Docker CLI 在，但 daemon socket 不存在（`~/.docker/run/docker.sock` 不存在） |

所以 L2/L3 **在本轮不可获得**。这恰好是卡面 Red 条款描述的情形：没有可验证的 run 时，唯一可接受的做法是把 L1 做到最实，并把「未验证」标出来——而不是拿本机 `pnpm run gate` 的结果去说 CI 已经建立。

## 决策

### 1. workflow 的契约由一个**离线**判据守着，而不是靠人工读 YAML

新增 `scripts/gates/ci-workflow.mjs` 与门禁项 `ci-workflow-contract`：它审 `.github/workflows/gate.yml` 的结构与命令，判据包括

- 必须有 `quick`（PR + push）与 `full`（push-only，`if` 里排除 `pull_request`）两个 job —— 因为 full-only 的 8 项检查在 PR 上不跑，少了 `full` 就等于它们在 CI 里不存在；
- 每个 job 必须有数值型 `timeout-minutes`、门禁步骤（`node scripts/gate.mjs --mode …`）、**其后的** `--attest` 见证、`if: always()` 的 evidence 上传；
- 顶层必须有只读 `permissions`、`concurrency.cancel-in-progress`、钉住的 `NODE_VERSION` / `PNPM_VERSION`；
- 任何位置不得出现 `continue-on-error`、`|| true` / `|| exit 0`、`secrets.*`、机器路径（`/Users/…`、`/home/…`、`$HOME/.dsh`、`~/`）；
- 依赖安装步骤必须存在；第三方 action 必须钉版本且在登记白名单内。

### 2. 判据自己带证据层级，不允许被读成「CI 已验证」

`checkCiWorkflow` 的返回值里固定带 `authority: 'L1-static'`，门禁项的 `note` 里也必须出现「静态审计，不等于 CI 已验证」。反向自测里有一条专门钉住它：读数里**不得**出现 `CI-verified` / `L3` / `required check` 这类越权声明。

### 3. 自己写一个极小的 YAML 子集读取器，而不是引依赖

仓库刻意没有 devDependencies；为了读一个文件而扩大供应链面不划算。`parseWorkflowYaml` 只认块映射、块序列、块标量、行内 `{}` / `[]`、标量与 `${{ … }}`，**读不懂就抛错**——「没看懂」绝不能降级成「没问题」。实测它挡下了三类坏结构（键后已有值却又缩进子块、不支持的指令行、锚点/别名），并把原因报在违规文本里。

### 4. 用干净 HOME 干跑，把「干净 runner 上会发生什么」变成读数

L2 不可得，但「干净 runner 上哪些项没有射程」是可以离线量的：把 `HOME` / `TMPDIR` / `DSH_PROFILE_DIR` 指向空目录再跑一轮门禁，逐条记下 skip 的**类型化理由**。这条干跑同时是**判据自检**：它当场抓出 `skill-lines.test.mjs` 的 S2/S3 也在读真实 `homedir()`。

### 5. 「可选环境缺失 = 明确 skip」是既有契约，不新增例外

干净环境下的 9 项 skip 全部带类型化理由（`profile 根不存在`、`用户预设根不存在`、`预设目录不存在`、`扫描面为空`…），并且 note 明确写「**未核对任何预设**（不是「都健康」）」。这是 ADR-0094 / ADR-0102 的既有形状，本卡只需确认它在干净 runner 上**真的**这样表现——确认的方式就是 §4 的干跑。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 不写 workflow，等能推送时再说 | **否**。卡面的 Red 条款说的正是这种状态，而它能被离线判据拦住的那些事故（无 `full`、`continue-on-error`、浮动版本）恰恰是最常见的几种 |
| 用 `npm i yaml` 解析 workflow | **否**。为一个文件扩大供应链面；且子集读取器读不懂时会抛错，比「支持全部 YAML」更保守 |
| 只写 workflow，不加判据 | **否**。没有判据的 workflow 会在几个月后被某次「顺手改成 `continue-on-error`」悄悄削弱，而门禁读数是绿的 |
| 报 L2/L3 为「已完成」并引用本机 gate 输出 | **否**。这正是卡面 Red 条款禁止的那句话 |
| 起 Docker 做 L2 干跑 | **本轮不可得**：daemon 未运行。已记入未完成项，不是被忘记 |

## 后果

正面：

- CI 的契约从「一份 YAML」变成「一份被 27 条反向自测守着的判据」；变异覆盖 21 种具体事故（缺 job、缺 timeout、缺见证、缺上传、缺权限、缺并发取消、`continue-on-error`、`|| true`、secrets、机器路径、未钉版本、错误 mode、未登记 action、坏结构、空文件…）。
- 干净 runner 的行为从「猜想」变成读数：9 项按类型化 skip，其余通过；每一条 skip 理由都写明了「未核对什么」。
- 干跑当场抓出两处判据读环境：`skill-lines.test.mjs` 的 S2/S3 默认读 `homedir()`，在没有 `~/.dsh/skills` 的机器上走早返回分支而红——而那台机器上「三条技能线还不存在」是正常事实。S2–S7 现在全部注入合成 HOME。
- 顺带修掉一个聚合层缺陷：`normalizeGateResult` 遇到混合了两份合同的读数（同时带 `status` 与 `passed`）时报「result schema invalid」，**完全不提 `passed`**。现在点名到字段，并补了正反两条例。

负面与已知边界：

- **L2/L3 未取得**：没有可验证的 workflow run。本轮所有 CI 结论的证据层级都是 L1。
- 判据不保证把「任何非 YAML」都报成解析失败：`quick:` 下挂一个缩进的标量序列会被本子集解析成「一个没有字段的 job」，于是报的是「缺少 timeout-minutes」（仍判红，且具体，只是措辞不同）。这条边界写在反向自测的注释里，而不是假装没有。
- workflow 里 `pnpm-lock.yaml` 被白名单式 `.gitignore` 忽略（ADR-0102 已记录），所以 CI 上**可能没有锁文件**：工作流用 `if [ -f pnpm-lock.yaml ]` 显式分流并打印 notice，而不是假装做了锁文件安装。依赖可复现性由 `deps-reproducible` 门禁单独判定。
- Node 版本钉在 `22.19.0`：它与 `engines.node`（`^22.19.0 || >=24.0.0`）相容，但**没有在本机验证过**该版本能跑通全部门禁（本机是 26.0.0）。这是 L2 的第一件事。
- 本机的 `pnpm` 是 11.8.0（观测值），workflow 钉的就是它；换版本要同时改 workflow 与文档。
