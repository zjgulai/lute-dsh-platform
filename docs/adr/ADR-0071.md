# ADR-0071 · 复发故障总账：教训必须点名**真实存在**的机制，可信度由门禁守

- 状态：accepted（2026-09-13）
- 日期：2026-09-13
- 决策者：用户（「将今天的正轮对话中遇到好的地方和发现的新的 bug 进行深度蒸馏和总结」）+ agent（本次归并、取证与落地）
- 决策记录：[Note](../notes/implemented/contract/2026-09-13-pitfalls-playbook.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0014（门禁是硬门槛）、ADR-0015（决策记录双轨）、ADR-0064（P-03 的实例：知道写在注释里，没变成拦住）、ADR-0068（P-02 的实例：只读状态的一半）

## 背景

### 一天的产出不是 31 个提交，是不到十类会复发的根因

2026-09-13 当天落库 31 个提交、16 篇 Note、7 篇 ADR。把修掉的缺陷按**根因**而不是按事件归并，
只剩不到十类，而其中三类在当天各复发了两次以上：未验证的事实被钉进出货面（ADR-0069）、
「知道」没有变成「拦住」（ADR-0064）、一条事实多个家却只改了一处。

真正的缺口不是「这些教训没被记下来」——它们全都进了 ADR 与 Note，写得很详细。
缺口是：**它们散落在几十篇文档里，按时间排列，而复发是按根因发生的。**
下一次开工的人不会去读 16 篇 Note 才动手；于是他换一个外壳，把同一个根因再犯一遍。

已有的先例证明这个形态可行：[dsh-desktop-white-screen-playbook.md](../dsh-desktop-white-screen-playbook.md)
是全仓唯一一处**按故障类组织**的文档，被列进 `docs/README.md` 的「故障排查（优先看）」，
它确实在被使用。

### 总账有一个固有死法：它会腐烂成一份说谎的清单

按根因组织的清单要靠自觉维护：条目里点名的机制会被重命名、被删除，或者一开始就写成了一个
**从来没有存在过**的名字（「有门禁守着」这类自我安慰）。而没有任何东西会因此停下来——
它读起来完全正常，甚至比真实情况更让人放心。这恰好就是本次要记的 P-03 本身。

所以本 ADR 的实质不是「建一个文档」，而是**给这份文档装一副牙**。

### 顺带取到的两组读数

1. `AGENTS.md` 的常驻规则写着「链接可达性由门禁校验（ADR-0009）」，而在本次之前，
   真正被校验的只有 ADR ↔ Note 那一条链路。
2. 实测 `docs/` 与根两份 Markdown 共 419 条相对链接，**6 条是死的，且全部是同一形态：层级写错**。
   最刺眼的一组是同一天、同一模板写出的 5 篇 Note，其中 4 篇把 `docs/adr/ADR-00XX.md`
   写成了 `../../adr/ADR-00XX.md`（Note 住在 `docs/notes/<lifecycle>/<class>/` 下，正确上溯是三层）。
   死指针的危害不是「点不开」，而是把「这里没有依据」伪装成「这里有依据，只是我没点」。

## 决策

1. **新建 `docs/pitfalls-playbook.md`，作为「复发故障」的唯一 home**，按**根因类**组织（不按日期、
   不按事件）。条目四段固定：症状 / 根因类 / 已落地机制 / 下一版默认动作。
   事实（哪一次、什么读数、怎么修的）留在 ADR / Note / SOP，本页只写「模式 + 机制名 + 链接」
   （ADR-0009）。
2. **条目的机制必须点名**：写入 `gate:<门禁名>` 或 `script:<路径>`，二者至少其一。
   没有名字的机制说明等于没写。
3. **新增门禁 `pitfalls-playbook`**，四件事一起校验：四段结构齐全且非空；每个 `gate:<名字>`
   必须存在于**实时**注册表（`gate.mjs` 把 `CHECKS.map(c => c.name)` 传进来，条目点名一个被改名
   或删掉的门禁会立刻红灯）；每个 `script:<路径>` 必须真实存在；编号自 `P-01` 起连续。
   另外要求 `AGENTS.md` 与 `docs/README.md` **都**回引本账——没入口的总账等于不存在。
4. **新增门禁 `docs-link-integrity`**：校验 `docs/` 全部 Markdown 与仓库根两份的相对链接可达。
   刻意**跳过**代码块与行内代码（模板占位符与写法示例不是链接目标）——一项会误报的校验
   很快会被当成噪声关掉；也刻意让**空输入判红**，因为「收集器失效」是本项唯一的真空绿路径。
5. **两条校验各配反向自测并挂进门禁**（`pitfalls-playbook-selftest` / `docs-link-integrity-selftest`），
   自测里必须含一次**恒真桩突变**：把机制换成永远成立的免责话、把链接换成必然不可达的路径，
   校验必须失效。判据自己也要被证伪——子进程走 `scripts/lib/real-node.mjs` 的 `nodeCommand()`，
   否则在 pnpm 下它会「退出码 0 且没有输出」，测试一条没跑也判绿（ADR-0040）。
6. **修掉本次取证中发现的 6 条死链**，并修正 `AGENTS.md` 里两处不成立的指引：
   「见 architecture.md 第 4 节」（该章节不存在）改为第 0 节；「链接可达性由门禁校验」从
   局部事实变成全局事实（由第 4 条兑现）。
7. **新增条目的门槛**：同一根因**复发过两次**，或第一次的代价大到不允许发生第二次。
   落笔前回答三句：症状能不能被机器判出？拦住它的机制**叫什么名字**？下一个人该先做什么？

## 备选方案

- **用 `.learnings/`（`self-improvement` 技能的默认形态）。** 被否：它会造出**第二个事实家**
  （违反 ADR-0009），而且**没有门禁守它**。今天的教训里正有一条是「知道写在注释里、没变成拦住」，
  再建一个没人守的目录等于当场再犯一次。
- **只写一篇 Note，不加新文档。** 被否：它会被同日 16 篇 Note 淹没，下次开工的人翻不到。
- **只把教训回填到各自的 home（ADR 后果段 / SOP / architecture 红线），不建总账。** 部分采纳
  （本次确实回填了 SOP 与常驻规则），但不足以解决问题：回填纠正的是**分散的事实**，
  没有回答「下次从哪一眼看全」。
- **把总账并进 `docs/architecture.md`。** 被否：地图页的定位是「有序地图：组合、能力归属、
  扩展点与门禁契约」，把按根因组织的故障清单塞进去会同时破坏两页的定位。
- **给「不复述 ADR 数字」也加一条机器校验。** 不可行：判断「这句话是不是给同一条事实再造了一个家」
  需要语义理解，静态文本判不出。故把它写成文档头部的**显式约定并标明「无强制」**——
  P-03 要求的诚实读法就是：哪些是**拦住**的，哪些只是**约定**，必须分开说。
- **把 `docs-link-integrity` 一次扩到全仓（含包内文档）。** 本次未采纳：范围一旦放大到未取证的
  语料，首批红灯会把一项正确的校验拖成噪声源。边界写在模块注释里，扩大留作独立决定。

## 后果

- **正面**：
  - `pnpm run gate` 的 quick 模式由 28 项升到 **32 项**，且新增的四项都在 quick 面内
    （提交前就会跑）；
  - 死链由 6 条降为 **0**，此后新增死链会在提交前被拦住；
  - 「教训」第一次有了一个**会自己报错**的家：条目点名一个不存在的门禁即红灯；
  - `AGENTS.md` 的两处不成立的指引被修正——其中「见第 4 节」是一个已经存在一段时间的死指针。
- **负面 / 边界**：
  - `docs-link-integrity` 的范围限于 `docs/` 与仓库根两份 Markdown，**不含包内文档**
    （各包的 `docs/`、`packaging/` 下的 Markdown），故它不构成「全仓链接都可达」的证明；
    锚点（`#section`）也不解析。
  - 总账的「不复述 ADR 数字」只有评审，**无强制**；文档里已显式标注，不伪装成红线。
  - 门禁多两项各自起一次 `node --test` 子进程（各约 0.1 s），开销可忽略但确实存在。
  - 总账的条目会随仓库演进而需要维护（机制改名时同步改条目）——这正是它要付的代价，
    也是第 3 条把它变成红灯而非警告的原因。
- **后续动作**：
  - 本次蒸馏出的其余根因（未验证的事实被钉进出货面 / 仪器假绿 / 写了但从没跑到 /
    隔着解释器写字面量 / 把平台行为当常量 / 一条事实多个家 / 用纪律守只有机制能守住的东西）
    已按 P-01 ~ P-08 落账，各自点名了当下真实存在的机制。
  - `docs-link-integrity` 是否扩到包内文档，作为独立决定另行评估。
  - 每次归并出一类新根因（或已有根因再次复发）时，往总账加一条——这是它保持有用的唯一方式。
