# ADR-0002 · DMG 发布：GitHub Releases 附件 + release/ 哈希清单

- 状态：accepted（原文未入库，本篇为证据重建）
- 日期：2026-09-06
- 决策者：用户（lute）
- 原文：从未提交到仓库；本篇依据 `packaging/sign-and-dmg.sh`、`packaging/release/<版本>/`、`docs/release-process.md` 与 ADR-0004 重建。

## 背景

二进制交付物不适合进 git（体积大、每次构建都产生新字节）。客户需要一个可校验、可回滚的下载渠道。

## 决策

**发布走 GitHub Releases 附件，二进制不进 git**：构建产物落在 `packaging/release/<版本>/`，附 `SHA256SUMS`（dmg）与 `PKG-SHA256SUMS`（pkg）校验清单；`release/` 目录本身不入库。后续以 pkg 为主交付（双击向导，面向无终端客户），dmg 为备用。

## 备选方案

- 二进制入库：被否决——仓库膨胀，且每次构建都污染历史。
- 自建下载服务：被否决——需要额外运维，且 GitHub Releases 已满足校验与回滚需求。

## 后果

- 正面：校验清单可公开核对；回滚即下载历史版本。
- 负面/代价：发布强依赖 GitHub 可达；本地需保留 release 目录用于复现（由白名单式 `.gitignore` 排除）。
