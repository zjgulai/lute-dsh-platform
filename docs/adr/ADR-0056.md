# ADR-0056 · 出货的 preset 不烘焙外部产品行；出货树的机器路径只减不增

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（DMG 2.2.0 打包前裁定 K4：KOL-Hunter 本次不随包）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-shipping-surface.md)
- 实施记录（打包面加固六项）：[Note](../notes/implemented/architecture/2026-09-12-packaging-surface-hardening.md)
- 相关：ADR-0033（产品 = 项目目录里的声明 + 实现包；**产品代码留在各自项目，本仓库不吞并产品**）、ADR-0036/ADR-0037（产品行由 `generate.mjs` 的 `PRODUCT_MOUNTS` 渲染并挂到岗位组合，本 ADR 修订其「本机产品已烘焙进出货 preset」的隐含前提）、ADR-0009（一份事实只有一个家）、ADR-0014（豁免只减不增）、ADR-0055（依赖不得指向机器路径，本 ADR 把同一判据从「包清单」扩到「出货树」）

## 背景

DMG 2.2.0 打包前的 MECE 诊断（`.scratch/pre-dmg-diagnosis/diagnosis-report.md`）在「产品内容与范围」维度查出一条跨项目依赖，逐层取证后它牵出两个更一般的结论。

**一、`agt-033` 的 preset 把一个**别的项目**烘焙进了出货物。**

`scripts/role-presets/generate.mjs` 的 `PRODUCT_MOUNTS['agt-033']` 渲染出：

```yaml
- id: product-kol-hunter
  name: 'dsh-kol-hunter-local'
```

而 profile 里这个包的依赖是 `file:/Users/lute/project/KOL-Hunter`——既不在本仓库，也不在 vendor 抽取的前缀表内（`assemble.sh` 只认 `file:../../../project/Magpie-Horch/` 与 `file:/Users/lute/project/Magpie-Horch/`），也不被 `rewrite-file-deps.mjs` 重写。实测：23 条 `file:` 依赖里它是**唯一**漏网的一条，而 `install.sh:150` 的 `--check` 又被 `|| true` 吞掉。

**二、这不是「某条路径没处理」，而是「补前缀」这个修法本身不够。**

同一族缺陷在本轮诊断里出现三次，每次都是「本机可解、客户机必错、且静默」：

| # | 事实 | 为什么它逃过了所有检查 |
| --- | --- | --- |
| 1 | `dsh-kol-hunter-local = file:/Users/lute/project/KOL-Hunter`（仓库外） | 前缀表外 → 不抽取、不重写、`--check` 也只看 `file:./vendor/` |
| 2 | `cordis.patch.yml` 的 `ui-newapp-local.productRoots: [/Users/lute/project]` | `assemble.sh` 只 sed 了 `$DSH_HOME`（`<home>/.dsh`），另一个前缀没人管 |
| 3 | 插件脚本/文档写死 `/Users/lute/project/Magpie-Horch/...`（历史，已部分修） | 没有任何机读判据把它们当缺陷 |

**三、ADR-0033 已经给了答案，只是没人执行：产品代码留在各自项目。**

## 决策

1. **出货的 preset 不烘焙任何外部产品行。** `PRODUCT_MOUNTS` 置空并保留机制（渲染函数、注释、断言都不删）。理由不是风格：产品行是**硬依赖**——客户机上装不到那个包，该岗位组合就装载失败（`plugin tree failed to load` → 恢复模式），而本仓库无法保证任何客户机装过某个外部产品。
2. **本机要用自己的产品，走本机装配，不写回出货物。** 需要时给本机加一层不进仓出货物的本地装配；把某台机器的产品目录写回 `PRODUCT_MOUNTS` 是不可接受的形态。
3. **KOL-Hunter 随本次移出产品面**：`PRODUCT_MOUNTS` 清空（重生成 50 个 preset）、profile 的 `dependencies` 与 `dsh.profile.bundles` 去掉该包、node_modules 副本移出、profile 锁文件重算。产品目录本身（`/Users/lute/project/KOL-Hunter`）原样留在项目里，不受影响。
4. **机器路径的两个前缀都参数化**：`$DSH_HOME_DIR` → `__DSH_HOME__`、`$LUTE_PROJECT_ROOT`（默认 `$HOME/project`）→ `__LUTE_PROJECT_ROOT__`；安装侧两个占位都替换，替换后若仍有占位残留即报错。
5. **出货树的机器路径只减不增**：新增 `packaging/scripts/scan-machine-paths.mjs` + `packaging/machine-path-baseline.json`，在 `assemble.sh` 签名**之前**对 `$BUNDLED`（≡ `profile.tar.gz` 内容）扫描。基线缺失即失败（不静默通过）；出现基线外命中即失败；基线里扫不到的条目只提示「可下调」。判据与 ADR-0014 的豁免同构：**只减不增**。

## 备选方案

- **把 KOL-Hunter 纳入本仓库并 vendor 化**（曾作为推荐）：直接违反 ADR-0033 §1「本仓库不吞并产品代码」，且要把一个 `status: draft` 的 M1 试点连同 90M 开发目录（含 `kol-select-src/node_modules` 88M）搬进仓库。放弃。
- **只把实现包入库、声明留在项目里**：技术上可行（L2 技能是包内自带、运行时确实不读产品目录），但它把「声明 + 实现包同在产品目录」这条 ADR-0033 的结构拆开，需要改 ADR；且客户机上那张卡仍然要客户自己有产品目录才出现。放弃作为本次形态，保留为后续候选（需另立 ADR）。
- **保留 `PRODUCT_MOUNTS` 但在打包时剥掉这一行**：能出干净的包，但会让「本机真值」与「出货真值」分叉，且第二份剥离清单会漂移（ADR-0009）。放弃。
- **只补前缀表（把 KOL-Hunter 路径也加进 `OLD_PREFIXES`）**：治当次不治类。轮诊断里它出现三次，正是这个修法的产物。放弃；改为「参数化 + 机读守卫」。
- **让 `install.sh` 的 `--check` 继续 `|| true`**：已被同一轮诊断列为静默点（客户机装完才知道坏）。放弃。

## 后果

**正面**

- 出货 preset 不再要求客户机存在任何外部产品；`agt-033` 在客户机上不再有悬空挂载面。
- 出货树机器路径从「靠人记得改」变成「机读、只减不增、基线缺失即红」。
- 两个占位语义清晰：`__DSH_HOME__` = 数据根，`__LUTE_PROJECT_ROOT__` = 项目根；安装侧替换残留会报错。

**负面 / 代价**

- **本机 agt-033 失去 KOL-Hunter 的产品行**（`verify-lossless` 全绿，但本机那张卡的 L2 技能不再注册）。要恢复需引入本机装配层（决策 2），本轮未做。
- 基线仍含 39 条存量命中（文档、测试夹具、构建产物里的源映射注释、`node_modules/.pnpm` 内部状态等），**不是零**。它们由守卫看住不再增长，逐条清理排进后续（P2）。诚实记法：本 ADR 的判据是「只减不增」，不是「清零」。
- 出货树的扫描给 `assemble.sh` 增加约 10–15 秒（`grep -rlFI` 扫约 1G，实测 475M 用 6.7s）。

**后续动作**

- P2-1：逐条清理基线里的存量命中（先清 `lib/` 内的注释与文档，再评估测试夹具是否改为中性 fixture 路径）。
- P2-2：把 `scan-machine-paths.mjs` 扩到 app 侧（`app.asar.unpacked`）并另立基线。
- P2-3：若确需向客户演示某产品，另立 ADR 讨论「随包的产品目录」形态与体量治理。
