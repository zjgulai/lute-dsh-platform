# ADR-0113 · 供应链不可变性固化（SEC-RT-002）

- 状态：accepted（2026-09-17）
- 决策者：用户（lute）+ 三无 · Agent全栈专家
- 决策记录：[Note](../notes/implemented/security/2026-09-17-sec-rt-002-immutable-supply-chain.md)
- 相关：ADR-0008（基座只 pin 不改）、ADR-0014（门禁是硬门槛）、ADR-0095（第三方技能分类守恒）、DEC-009（分级准入 + Quarantined 默认隔绝）

## 背景

在安全强化第一期审计中，发现多处动态拉取与未锁版本的供应链隐患：
1. `dsh-wanzh-hulian` 默认 MCP 配置使用 `npx -y` 动态执行 `shopify-mcp`、`@getnote/mcp` 与 `oauthCmd`，未锁定精确版本，且存在 `@latest` 风险。
2. `dsh-loopx-plugin` 的 `LOOPX_REQUIREMENT` 使用范围依赖 `loopx>=0.5.4`，且在 `pip install` 中传入 `--upgrade` 标志，导致在线漂移与依赖不确定性。
3. `dsh-overseas-skills` 第三方技能拉取脚本 `fetch-third-party-skills.mjs` 在 trees API 及 raw 取件中依赖浮动指针 `HEAD`，且取件只做文件大小比对，无法防范内容篡改或 HEAD 指针位移导致的时序攻击；`import-fullstack.mjs` 中存在未受控的 `/tmp/mattpocock-skills/skills` 回退路径。

## 决策

1. **MCP 服务器全面版本固化**：
   - `dsh-wanzh-hulian` 中 `shopify-mcp` 强制锁定为 `shopify-mcp@1.0.8`。
   - `@getnote/mcp` 强制锁定为 `@getnote/mcp@1.7.2`。
   - `oauthCmd` 强制锁定为 `npx @getnote/cli@1.7.2 auth login`，全库严禁出现 `@latest`。
2. **LoopX 运行时依赖固化与离线保护**：
   - `LOOPX_REQUIREMENT` 锁定为精确版本 `loopx==0.5.4`，去除 `loopx>=` 范围。
   - 去除 `pip install` 中的 `--upgrade` 标志，增加 `--no-deps` 标志，防止静默拉取外部未受控传递依赖。
3. **第三方技能来源绑定不可变 Commit 与双重 Digest**：
   - 清单中所有第三方仓库必须显式声明 40 位十六进制不可变 Git commit SHA（`phuryn/pm-skills` 锁定至 `8607e3b077817f89bf4a9b623246219734ac3be0`；`mattpocock/skills` 锁定至 `74ca5fe077456a0b3b2f5310cf9430999fd0b5fd`）。
   - `fetch-third-party-skills.mjs` 全面移除所有 `HEAD` 引用， trees API 与 raw 下载统一走不可变 Commit。
   - 实行双重哈希校验（SHA-256 与 Git blob OID）：不仅比对文件 byte length，还必须严格验证 Git blob OID。
   - `import-fullstack.mjs` 彻底剔除 `/tmp/` 本地未版本控制的回退路径，`pipeline.sh` 移除 `|| true` 静默吞错。
4. **门禁与自动化校验闭环**：
   - 新增 `immutable-supply-chain` 门禁与 `immutable-supply-chain-selftest`，由 `pnpm run gate` 强制阻塞任何未来引入的浮动依赖或 HEAD 引用。

## 备选方案

- 仅在文档中约定不使用 `@latest` 和 `HEAD`：拒绝——依赖人工记忆必然复发（ADR-0057），必须形成机读门禁与确定性锁死。
- 保留 `/tmp` 作为开发机临时缓存：拒绝——开发机环境各异，`/tmp` 属于未受版本控制的不可见依赖源，易引发假绿与环境漂移。

## 后果

- 系统构建与技能拉取完全具备可重现性与不可变性。
- 门禁总数增加至 92 项（quick 门禁涵盖并验证通过）。
- `packages/capabilities/dsh-overseas-skills` 单元测试数量更新为 116 项并全绿。
