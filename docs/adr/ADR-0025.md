# ADR-0025 · `webServer.register` 一次只收一条路由；传数组会静默失效

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（lute 报障）+ agent（定位根因后提出）
- 决策记录：[Note](../notes/implemented/contract/2026-09-12-role-matrix-route-registration.md)

## 背景

`dsh-role-matrix-local` 的岗位矩阵面板上线后，点开显示「读取失败：HTTP 404」。
宿主侧探针的读数自相矛盾：

```
/api/dsh-skill-explorer/health   → 200   ← 同前缀、同栅栏机制的插件，正常
/api/dsh-role-matrix/list        → 401   ← 本插件
/api/definitely-not-a-route-xyz  → 401   ← 对照：不存在的路径也是 401
```

**401 与「路径根本不存在」不可区分**，因为 `/api` 上有一条 `kind: "prefix"` 的总闸
（`dsh-client-connection`）：它先做连接级鉴权，拒绝时写 `401 unauthorized` 并 `return`。
未注册的 `/api/*` 全部落到这条 prefix 路由上，看到的正是 401。

逐层排除后，根因是宿主入口里的一行：

```ts
ctx.effect(() => webServer.register(routes as unknown[]), 'role-matrix-local: routes')
```

而平台侧的真实签名是**单数**（`dsh-host-webserver`）：

```js
register(route) {
  const table = route.kind === "exact" ? this.exact : this.prefixes;
  if (table.has(route.path)) throw new Error(`webserver: duplicate ${route.kind} route "${route.path}"`);
  table.set(route.path, route);
  return () => { table.delete(route.path); };
}
```

把数组交给它，会**逐级走完而不报错**：

| 读取 | 数组上的值 | 后果 |
| --- | --- | --- |
| `route.kind` | `undefined` | `!== "exact"` → 落进 **prefix 表**而非 exact 表 |
| `route.path` | `undefined` | `table.has(undefined)` 为假 → **重复检查不可能触发** |
| `table.set(undefined, 数组)` | — | 静默写入，返回一个能用的 disposer |

于是两条 `exact` 路由从未进入 exact 表：请求落到 `/api` 总闸 → 401。
**没有任何异常、日志或启动期告警。**

值得记下的是它为什么能活过整个开发过程：

- 单测 `routes.spec.ts` 直接调 `handler(req, res)`，**绕过了 `register`**；
- 契约测试只断言源码里**出现** `webServer` 和 `register` 两个字符串，**没有跑注册**；
- 我的临时验证脚本用的替身是 `register: (routes) => { push(...routes) }`——**替身比真实契约更宽松**，
  于是缺陷在替身里天然不可见。

## 决策

**`webServer.register` 必须逐条调用，一条路由一次；且凡是驱动宿主注册的测试，
其替身必须复刻真实签名，不得更宽松。**

1. **逐条注册。** 与 `dsh-skill-center-local`、`dsh-bridge-browser` 保持同一写法：

   ```ts
   ctx.effect(() => {
     const disposers = routes.map((route) => webServer.register(route))
     return () => { for (const dispose of disposers) dispose() }
   }, '<plugin>: routes')
   ```

2. **替身即契约。** 驱动 `apply()` 的测试里，`register` 替身必须拒绝非单条路由输入
   （数组 / null / 非对象），并断言每次调用的 `kind` 与 `path`。
   「替身宽容 → 真实静默失败」是本条 ADR 记录的主要教训。
3. **契约测试不得只断言字符串存在。** 断言「源码里有 `register` 这个词」
   无法区分正确调用与完全错误的调用。

## 备选方案

**只在插件里修，不立规则。** 未采纳——`register` 的静默失败模式不是这一个插件的私事，
它是任何在此平台上注册宿主路由的人都会踩的同一个坑，且踩中时没有任何信号。

**给 `register` 加运行时校验（传数组即抛）。** 属于平台侧改动；
`webServer` 是官方 `dsh-host-webserver` 的 Service，基座只 pin 不改（ADR-0008）。
真要做只能作为上游建议提出，不在本仓库的可改范围内。

**把 `/api` 总闸的 401 与「未注册」区分开。** 同样是平台侧行为，同上。

## 后果

- **正面**：面板恢复可用（重启后生效）；`dsh-role-matrix-local` 单测 30 → **31**，
  新增的一条**真正驱动 `register`** 并复刻真实签名。经变异测试证明会咬：
  把注册改回数组形式 → 该用例红并报 `webServer.register expects one WebRoute, not an array`；
  修复后 → 全绿。
- **代价**：无。这是一行改动。
- **排查成本记录**：从「HTTP 404」到根因耗时约一小时，其中绝大部分花在
  **排除掉五个看似合理的假设**（`/api` 前缀被平台保留、`cordis.patch.yml` 未生效、
  `engines.dsh` 版本门槛、插件 host 半未加载、clientModules 与宿主树解耦）。
  前三个假设各自都有一条**听起来成立**的证据，全部证伪后才回头读 `register` 的实现。
  教训与 ADR-0022 同源：**别读代码猜行为，读实现定行为。**
- **仍未验证**：修复后的真实 HTTP 可用性需要重启宿主才能观测；
  本文只证明了注册调用符合契约，未证明端到端 200。
