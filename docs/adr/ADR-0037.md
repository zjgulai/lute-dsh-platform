# ADR-0037 · 产品包挂两层，靠 `role` 分离；局部技能的机关从「缺声明」换成「显式关断」

- 状态：accepted
- 日期：2026-09-12
- 决策者：用户（裁定「真做面板：包挂两层，host 行只开入口」）+ agent（取证后落形态）
- 决策记录：[Note](../notes/implemented/architecture/2026-09-12-product-package-two-layer-mount.md)
- **取代** [ADR-0036](ADR-0036.md) 决策 3：「产品包故意不声明 `dsh.bundle`，也不提供 `cordis.patch.yml`」

## 背景

[ADR-0036](ADR-0036.md) 决策 3 用「干脆不声明 `dsh.bundle`」来防一件事：产品包若被加进 profile 的 `dsh.profile.bundles`，它的 patch 会在**宿主层**再插一行，于是同一个插件挂两层，产品技能被注册进**全局层**，每个会话都能看到——**且没有任何报错**。

那把锁能用，但代价在 M2b 暴露出来了：**客户端 bundle 只有进了 profile 的 `bundles` 才会被加载**。也就是说，那把它锁住了入口面板。想有「点开必能用」的第 1 级（打开入口面板），包就**必须**进 bundles，因此必须声明 `dsh.bundle` 并附带 patch——正是被锁掉的那件事。

于是问题从「要不要挂两层」变成「**怎么挂两层而不泄漏**」。

## 决策

1. **同一个包挂两行，各有其活，用 `config.role` 分开。**

   | 行 id | 谁插的 | 配置 | 干什么 |
   | --- | --- | --- | --- |
   | `product-kol-hunter` | 岗位组合（`generate.mjs` 的 `PRODUCT_MOUNTS['agt-033']`） | 缺省（`role: "product"`） | 注册 L2 技能进 **agt-033 层**；注册两个 host 工具 |
   | `product-kol-hunter-entry` | `cordis.patch.yml`，经 profile 的 `dsh.profile.bundles` | **`role: "entry"`** | **什么都不注册**，只为客户端入口提供 bundles 挂载点 |

   两行 id 不同（与 `dsh-skill-subset` 在 profile 层与 50 个 preset 层各一行的先例同形），因此不构成重复注册。

2. **`role: "entry"` 时，插件在 `apply()` 的最前面直接 return**，一条技能、一个工具都不注册，只留一条说明原因的日志。这不是「少做点事」，是**拒绝做会泄漏的事**。

3. **机关必须是机检的，不是注释里的承诺。** 两处断言同一条属性：
   - `run.mjs --check`：用 `role:"entry"` **真跑一遍 `apply()`**，断言 `skills.register` 与 `tools.register` 的调用数**恰好为 0**；同时断言 patch 里那一行确实带 `role: entry`、且 profile 的 `bundles` 确实含本包。
   - `tests/plugin.spec.mjs`：同一条断言的单测版本（注册数组为空、effect 未登记、必有且仅有一条说明日志）。

4. **patch 里 `role: entry` 丢了，不会有任何报错，只会静默泄漏。** 因此它同时是 README 的头号警告与自检项。

## 备选方案

- **保持 ADR-0036 的缺声明锁**：放弃。它与「客户端入口要进 bundles」直接冲突；那把锁挡泄漏的同时把入口也挡死了。
- **包拆成两个包**（技能包 + 入口包）：放弃。同一个产品的技能与入口会分裂成两份交付物、两条版本线，而它们的唯一区别只是一行配置。
- **入口行也挂 preset 层**：放弃。客户端 bundle 的加载不由 preset 组合决定，入口行挂在 preset 上不会让客户端被加载。
- **靠 `dsh.client.inject` 或别的声明推断挂载层**：放弃。那是信息边，不决定 Loader 行，也不决定注册落层。

## 后果

### 正面

- **两层各有其家，且都可达**：技能与工具进 preset 层（局部），客户端入口经 bundles 加载（可达）。M2b 的前置障碍清除。
- **机关从代理变成属性**：ADR-0036 锁的是「包看起来不像 bundle」（间接）；现在锁的是「这个角色下注册数必须为 0」（直接）。后者不会因为将来别的声明变化而失效。
- **失败模式清晰**：丢 `role: entry` → 自检红 + 单测红；把岗位行删掉 → 自检红（挂载点检查）。

### 负面 / 未决

- **两行 id 的名字容易改错**：`product-kol-hunter` 与 `product-kol-hunter-entry` 只差一个后缀，而错的那一处恰好是静默的那一处。代偿是上面两条机检。
- **`role` 是自造约定**，平台不认识它——Cordis 会把 `config` 原样交给插件，语义完全由本包定义。这既是自由度也是风险：换个包不能照抄这个字段名。
- **`--check` 只在本机验过**：它读 `~/.dsh/profiles/desktop/package.json`，换 profile 名要改。
- **未运行**：两行在真实进程里的加载次序与最终注册落层，必须重启 Harness 才能实测。**本 ADR 不宣称已验证。**

**后续动作**：重启后验四件（products 路由 curl 探针、技能作用域对照、会话内真跑两个工具、卡片点开走第 2 级回退）；随后用 bundles 已就位的客户端挂载点做入口面板本身。
