# ADR-0099 · Wanzh 状态持久化 fail-closed、单一原子写入器与 OAuth flow 唯一所有者

- 状态：accepted
- 日期：2026-09-16
- 决策者：用户（lute，授权范围：先 `SEC-RT-006` → `SEC-RT-007`，限临时 HOME 内 Red/Green）+ agent
- 决策记录：[Note](../notes/implemented/capability/2026-09-16-wanzh-persistence-and-oauth-lifecycle.md)
- 相关：ADR-0009（一份事实只有一个家）、ADR-0014（门禁硬门槛）、总账 P-02（仪器假绿）、P-07（一条事实多个家）

## 背景

`dsh-wanzh-hulian` 的状态持久化与 OAuth 授权入口存在四个可复现缺陷（事实与读数见
上列 Note 的问题表）：损坏配置被当作**开启**、四个 JSON store 与九处技能文件
直写最终路径且永不收紧既有 0644、OAuth 授权流程的 `expiresAt` 没有任何定时器读它、
注册的十二条路由只回收九条。前两类属"失败方向错了"（配置不可读时能力反而打开），
后两类属"所有权不清"（状态散在一个模块级变量里，注册与回收各写一份清单）。

## 决策

1. 建立**插件内唯一的原子写入器** `lib/atomic-store.js`：同目录随机后缀临时文件（`wx`）、
   文件 `fsync`、`chmod` 后在 **rename 之前**校验权限位、`rename`、目录 `fsync`；
   失败时清理自己的临时文件并如实抛错。所有落盘（JSON 与技能 Markdown）只经它。
2. 读语义**分家**：文件不存在与内容损坏是两种不同的失败。损坏时**不改写原文件**（保留取证字节），
   能力按 fail-closed 关闭，并经 `/list` 返回结构化 health 供设置页显示修复指引。
3. 内置默认清单**不得**充当损坏时的替代品：损坏时保留卡片元数据但逐条强制 `enabled:false`。
4. 写入口拒绝在损坏文件上写入（`CorruptStateError`，路由层转 409 + 结构化 body）。
5. OAuth 流程收进 `lib/oauth-flow.js` 的单一所有者：重复 start 采用 supersede（关闭旧 flow 后新建）、
   到期定时器 `unref()`、六类终止路径共用一个幂等 `close(reason)`、`dispose()` 后拒绝新建；
   每次 `apply()` 独占一个 registry 实例。
6. 路由的注册与回收由**同一份清单**驱动，卸载时同时收口进行中的授权流程。
7. 读路径**永不抛出**：I/O 失败降级为可解释的健康读数（`*_unreadable`），不让一次读失败炸掉调用方。

## 备选方案

- 依赖宿主的 `@deepseek-ai/dsh-atomic-write`：设计同形，但把 fsync 明确排除在射程外，
  且会给插件增加一条随包出货的依赖。**否决**（复用设计，不复用依赖）。
- 先 rename 再校验权限：宽权限文件已在最终路径上，只能事后报警。**否决**。
- 损坏文件先改名归档再写默认配置：自动"修好"用户配置本身可疑，且归档步骤可能失败。**否决**。
- 重复 start 返回 409：卡片允许，但把"上一次卡住了"变成用户必须先理解的内部状态。**否决**。
- state 不匹配即关闭 flow：会让过期标签页的回调打断正在进行的授权。**否决**（改为保留 + 到期收尾）。

## 后果

- **行为变更**：损坏配置下能力由开启变为关闭；`connections.json` / `mcp-servers.json` 损坏**或形状不对**时
  条目由"回退默认清单"变为"逐条关闭"。「文件不存在」仍用默认值，两者语义已分开命名与断言。
  凭据类文件（PixPix token）是唯一例外：损坏时**归档原字节后重写**，因为"拒绝写入"在这里等于
  让失去同步的授权**永远无法重新授权**。
- **判据共用**：`isPlainObject` 由写入器导出、读路径复用——读写若各留一份谓词，同一个文件会
  "读说健康、写说损坏"（独立审证 2026-09-16 实测）。
- **并发边界**：读-改-写入口统一进同一条进程内串行链（重入即报错，避免不可见的挂死）。
  跨进程互斥（`withFileLock` 形态）未引入，属**已知边界**而非已解决项。
- **未验证**：客户端未消费新增的 `health` / `flow` 字段（需要重启 app 取得真实页面证据，
  本轮不写没跑到过的分支）；真实 OAuth 回调的端到端复现需要真实 tokenEndpoint；
  断电安全性未被进程级测试证明（目录 fsync 只做结构性断言并显式标注射程）。
- 包内 76 tests 全绿、`tsc` exit 0；根门禁 quick 70 项（69 pass / 1 skip / 0 fail）、
  full 77 项（76 pass / 1 skip / 0 fail），唯一 skip 为 `live-presets` typed skip。
- 新增门禁项 `wanzh-persistence-and-oauth` 收编 6 个 spec，并经恒真桩突变证明会红。
- 装载点已同步并逐字节复核；**运行中的 DSH 需重启才跑新字节**。
