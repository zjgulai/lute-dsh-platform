## 一、使用方法

- **触发**：大型/多步/有风险的功能开发，需要前置提问、API 边界、可玩的检查点、HTML 可视化、截图门禁、分阶段实施计划、递归重切分，或切片前要主动调研参考实现时
- **核心思路**：把大功能切成「阶梯式的小契约」——每个切片：人类看得懂、agent 测得了、整体完成前就有用
- **八条原则**：
  1. **切前先烤问**——一次一个问题（期望结果/非目标/评审面/神圣契约/缺失资产/首个可玩检查点），每个问题给推荐答案，你只需接受/拒绝/编辑；默认**不**做向后兼容与数据迁移（硬切换），除非你明确要
  2. **在 API 缝上切**——每个切片像小库：命名模块边界、类型化输入输出、确定性夹具、缝上测试
  3. **研究迷雾**——陌生领域/视觉目标/参考实现先做定向调研（官方文档/源码/论文优先）；有参考实现就先加复刻 spike
  4. **进度可视化**——视觉/交互类工作每个切片都可玩（路由/夹具页/CLI 探针/HTML 可视化），人可运行、截图、批判
  5. **优化反馈环**——下个有用问题能快速回答；素材类工作配「资产工作台」让人/艺术家实时预览替换
  6. **顺着仓库的自然形状**——monorepo 就按 apps/packages 规划，测试面给一等路由或命令
  7. **不因缺料卡壳**——缺素材/数据/凭据就规划占位符 + 替换契约，功能照常推进
  8. **并行起草再合成**——多切片功能不赌一次切分，多稿并行再综合
- **产物**：`specs/<feature>/` 下的规格文件，切片可独立验证、可人工评审
