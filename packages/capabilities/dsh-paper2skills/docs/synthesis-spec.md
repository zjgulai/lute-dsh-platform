# 合成规范 · S2a（子任务产出什么）

> 适配分两步：**S2a 子任务只写「判断类字段」**（本文件），**S2b 脚本组装**最终 `SKILL.md`（`scripts/assemble-skills.mjs`）。
> 这样拆的原因：卡页八段是既成事实，照抄即可（脚本干）；描述/触发/步骤/边界需要判断（模型干）。脚本保证 frontmatter 合法、字节不超限、章节序固定。

---

## 输入

`generated/batches/S2-NN.json`：

```jsonc
{
  "batch": "S2-07",
  "l2_domains": ["供应与履约"],
  "count": 48,
  "cards": [{
    "id": "Skill-Customer-Complaint-Supply-Root-Cause-KPI",
    "slug": "p2s-customer-complaint-supply-root-cause-kpi",
    "title": "客诉供应链根因KPI与闭环治理",
    "src_domain": "04-供应链",
    "l3": ["纠正预防措施", "客诉聚类", "质量分析"],
    "facets": { "l1_plane": "业务运营", "l2_domain": "供应与履约", "l3_business": "纠正预防措施", "l1_l2_l3": "业务运营/供应与履约/纠正预防措施" },
    "confidence": "high",
    "fills_gap_strong": ["纠正预防措施"],
    "fills_gap_adjacent": [],
    "sections": { "1. 解决的问题": "…", "2. 核心算法逻辑": "…", … },
    "relations": { "前置技能": ["Skill-…"], "延伸技能": [...], "可组合技能": [...] },
    "tags": ["…"]
  }]
}
```

## 输出

只写一个文件：`generated/adapt/S2-NN.json`

```jsonc
{
  "batch": "S2-07",
  "items": [{
    "id": "Skill-Customer-Complaint-Supply-Root-Cause-KPI",
    "description": "…",          // 必填，见下
    "user_summary": "…",         // 必填，≤80 字
    "user_try": "试试：…",        // 可选
    "whenToUse": "…",            // 必填
    "workflow": ["…", "…"],      // 选填，≤5 步
    "contract_in": "…",          // 必填
    "contract_out": "…",         // 必填
    "steps": ["…", "…", "…"],    // 必填，3–7 步
    "boundaries": ["…", "…"]     // 必填，≥2 条
  }]
}
```

`items` 必须与输入 `cards` **同序同集**，不得增删改 id。

## 逐字段判据

| 字段 | 规则 |
| --- | --- |
| `description` | 单行、无换行。结构固定为 `触发词：<3–6 个中文触发词，顿号分隔>。何时不用：<1–2 个相邻技能的边界>。安全边界：<该卡涉密/涉合规/涉执行器时的红线，没有就写「无」。>` **≤500 字符** |
| `user_summary` | 一句话业务简介，像技能中心的卡面文案。**≤80 字**，不写技术名词堆砌 |
| `user_try` | 「试试：<一句可直接对模型说的话>」。仅在卡页第 1/3 段有明确业务场景时写，否则省略该字段 |
| `whenToUse` | 与**相邻 L3** 的边界（例：本卡属「需求预测」，则写明「预测量级已定、需决定订多少时用『补货模拟』」） |
| `workflow` | ≤5 步，**只从卡页第 3 段（应用场景）与第 7 段（代码模板）提炼，不新造** |
| `contract_in` | 从第 4 段（输入数据要求）提炼：需要什么数据、什么格式、什么粒度 |
| `contract_out` | 从第 5 段（输出结果）提炼：产出什么、什么格式、给谁用。第 5 段太短时从第 3 段补 |
| `steps` | 3–7 步可操作动作，从第 3/7 段提炼。每步一句、动词开头 |
| `boundaries` | ≥2 条：① 何时不用（数据不满足/场景不符）② 能力边界。**若卡的 L3 属 `依赖协调` / `异常冻结与恢复` / `容量管理` / `失败恢复`，必须加一条**：<br>「本技能承载的是规则与契约产物（DAG 定序规则 / 熔断阈值与退避策略 / 置信门控与判据），不是执行器；真正的编排与冻结动作由模型外的确定性控制层执行。」 |

## 硬约束

1. **不新造事实**。业务数字（ROI、提升幅度、样本量）只能来自卡页第 1/6 段原文，不得润色放大。卡页没写的数字不许编。
2. **不改分类**。`facets` / `l3` 一律照抄输入，不重新分类。
3. **不合并卡**。一张卡一个条目。近重复族在装配阶段处理。
4. **`description` 里不出现换行与双引号**（脚本要做 JSON 引号化，双引号会破坏可读性）。
5. **只写 `generated/adapt/S2-NN.json` 一个文件**，不动输入文件、不动仓库任何文件。
6. 完成回复：批次号 / 输入卡数 / 输出条数 / `description` 超长的条数（应为 0）/ `boundaries` 少于 2 条的条数（应为 0）。
