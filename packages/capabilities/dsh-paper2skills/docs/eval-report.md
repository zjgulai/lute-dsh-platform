# 效果实测报告 · L6 路由与 L7 SkillOpt

> 日期：2026-09-12　·　范围：1338 张技能卡全量静态面 + 40 例真实路由抽样 + 20 张高价值卡轨迹实测
> 复现命令见 §5。原始数据在 `eval/out/`（机读），本文件是唯一的人读结论之家（ADR-0009）。

---

## 0. 一句话结论

**接线是通的，效果是负的。** 134/151 的 L3 供给在本岗可达、越岗暴露 0、分类字段零漂移——静态路由面干净。
但真跑起来：路由准确率 97.4%（用户照技能名说时）/ 89.7%（只给业务处境时），错选**全是同 L3 的孪生卡**；
而给模型一张技能卡后，交付物质量**反而下降**（holdout Δ −0.95，符号检验 p=0.084；换一轮 p=0.0038）。
针对这个下降做的 SkillOpt 补丁**被 held-out 验证门拒绝并已回滚**。

## 1. L6-A · 静态路由正确性（全量，零模型调用）

1338 张全部 `disable-model-invocation: true`，模型目录里根本没有它们。真正决定可达性的面只有两个：
preset 的 `skill-subset` 白名单、斜杠命令。所以静态面测的是这两个面的正确性。

| 指标 | 实测 | 判读 |
| --- | --- | --- |
| M0 可见性 | 已装 1338 · 模型关 1338 · 斜杠开 1338 · 被某岗露出 **349** | 全局目录未被推高（O1 达成） |
| M1 供给可达 | 151 个 L3 → 本岗可达 **134**（88.7%） | 差的 17 个就是已登记的结构性空白，非新问题 |
| M2 越岗暴露 | **0 / 374** 次暴露 | preset 只露出本岗拥有的 L3 上的卡，精确率满分 |
| M3 近重复共现 | **678 对**共现于 47 个 preset，涉 **365 张卡** | 单岗内平均要让模型在孪生卡间二选一 |
| M4 触发词冲突 | 中位 5 个/卡；preset 内 Jaccard ≥0.34 的冲突 **0 对** | 描述层没有明显撞词 |
| M5 负向指引 | 1450 条「何时不用…用「Y」」→ 可解析 **62.5%**（L3 名 84 · 卡标题 493 · 模糊 329 · 无解 544）；**本岗可达仅 105 条（7.2%）** | 见 §1.1 |
| M6 字段一致 | **1338 / 1338** | 装上盘的分类与库里的一致 |

### 1.1 M5 是真问题：负向指引写给了「不存在的全局目录」

每张卡的 `description` 都写着「何时不用：要 X 时用「Y」」。实测 1450 条这种指引里：

- 544 条（37.5%）点名的「Y」**在平台上找不到任何对应物**；
- 906 条能解析，但其中 **801 条指向的兄弟技能不在本岗的 skill-subset 里**（跨岗或未装配）。

也就是说：这些指引是按「平台有一个全局技能目录」的假设写的，而模型实际只看得到本岗那 10–25 条。
**指引里点名一个本岗调不到的技能，对模型是把门指到了墙上。** 这不影响路由能否成功（§2 证明模型
并不依赖这句话），但它是一处会误导人和模型的文档缺陷，已在 §6 列为待决项。

## 2. L6-B · 真实路由实测（40 例抽样 · 158 次有效调用）

### 2.1 设计（先定的判据，不是跑完挑的）

| 环节 | 做法 | 为什么这么定 |
| --- | --- | --- |
| 抽样框 | 被某 preset 露出 **且**该 L3 由本岗拥有 **且**正文可用 → 259 张 | 模型看不见的卡上测路由是假问题 |
| 抽样 | 按「近重复 / 独苗 × 8 责任域」分桶轮转，种子 20260912 → 40 张（33 有孪生 / 7 独苗） | 近重复是已知风险点，必须单独记账 |
| 出题 | 出题 agent **只读卡页逐字正文 ①②③ 段**（物理上不含合成字段），出两档任务 | 用合成字段出题就是自己考自己 |
| 难度 | `keyword`（用户照自己的说法讲）与 `situational`（只给业务处境、禁技术词） | 两档之差 = 触发词到底在起多大作用 |
| 候选集 | 该岗 preset 的 skill-subset **全量**（含非 p2s 既有技能），一卡一行照抄给模型 | 模型真实可见的技能面 |
| 正样本 | 任务来自卡 C 的正文，候选=C 所属岗 → gold = C | — |
| 负向臂 | 同一个任务，候选换到**同 L2 责任域**、与本卡**零 L3 交集**的另一岗 | 跨域负向太容易，测不出东西 |

### 2.2 结果

| 臂 | 严格口径 | 校正口径 |
| --- | --- | --- |
| 正样本 top-1 · keyword | **38 / 39 = 97.4%** | — |
| 正样本 top-1 · situational | **35 / 39 = 89.7%** | — |
| 负向拒答 · keyword | 37 / 40 = 92.5% | — |
| 负向拒答 · situational | 37 / 40 = 92.5% | — |
| 负向（合并） | 74 / 80 = 92.5% | **76 / 80 = 95.0%**（误拒的 6 次里 2 次被独立复核判为「可辩护」，说明是本次 gold 定错了，不是模型错） |
| **真实误召** | | **4 / 80 = 5.0%** |

近重复分层（这是全部差异的来源）：

| 分层 | n | pos-kw | pos-sit | neg-kw | neg-sit |
| --- | ---: | ---: | ---: | ---: | ---: |
| 岗内有孪生卡 | 33 | 31/32 = 96.9% | **28/32 = 87.5%** | 30/33 = 90.9% | 30/33 = 90.9% |
| 独苗 | 7 | 7/7 = 100% | 7/7 = 100% | 7/7 = 100% | 7/7 = 100% |

### 2.3 错选的解剖（比准确率本身更有用）

5 次正样本错选：**4 次选中了与本卡挂同一个 L3 的孪生卡**（`退货根因` ← → `客诉根因`；
`平台政策变更监控` ← → `法规变更监控`；`跨平台SKU实体对齐` ← → `商品知识图谱查询`），1 次答 none。

4 次真实误召：**全部**是跨 L3 的语义近邻（评论摘要 vs 评论分类、实验假设生成 vs 蓝海品类、
竞品响应建模 vs 动态定价、模型性能监控 vs AIGC 归因）——它们**不共享任何 L3**，
所以静态的 M3 近重复检测（按同 L3 共现）**抓不到这一类**。

> **两类缺陷互补，且只有前者能被静态检测覆盖。** 这是这次实测最实用的一条：
> 想压住路由错误，光靠「同 L3 去重」不够，还要按描述语义做跨 L3 的邻近检测。

## 3. L7 · SkillOpt 轨迹优化（20 张高价值卡）

### 3.1 选卡与设计

「高价值卡」判据事前定死、机械可判：`fills_gap_strong` 非空（缺口名就是它的 L3）**且**被某 preset 露出。
全库满足的 36 张 → 按 8 个缺口分层轮转抽 20 张。

| 臂 | 给什么 |
| --- | --- |
| `control` | 只有任务，不给卡 |
| `treat` | 读 `~/.dsh/skills/<card>/SKILL.md` 全文，"据此产出方案" |
| `treat_silent` | 同样给卡照读，但禁止提及资料本身（用来把「卡片内容」与「围着资料写元话语」分开） |
| `patch` | 见 §3.4 |

判分用**与卡无关的固定三维度**（交付物完整度 / 具体性 / 数据与口径明确，各 0–5），
盲配对（X/Y 顺序由 case_id 奇偶决定，与臂无关）。

### 3.2 结果：给卡反而更差

| 对比 | n | Δ（treat − control） | treat 胜 / control 胜 / 平 | 符号检验 p |
| --- | ---: | ---: | --- | ---: |
| run1 train | 20 | −0.30 | 8 / 11 / 1 | 0.324 |
| run1 holdout | 20 | **−0.85** | 3 / 15 / 2 | **0.0038** |
| v2 train · C-vs-T | 20 | −0.55 | 6 / 13 / 1 | 0.084 |
| v2 train · C-vs-S | 20 | −1.25 | 4 / 13 / 3 | **0.0245** |
| v2 holdout · C-vs-T | 20 | **−0.95** | 6 / 13 / 1 | 0.084 |
| v2 holdout · C-vs-S | 20 | **−1.95** | 1 / 17 / 2 | **0.0001** |

**六个对比方向全部一致：调用技能卡后交付物得分更低。**

两条必须一起看的对照：

- **位置偏差已排除。** control 作 X 时领先 1.17 分（13.10 vs 11.93），作 Y 时也领先 1.17 分
  （13.35 vs 12.18）——内容效应在两层里逐位相同；位置效应只有 ±0.25 且成对抵消。
- **判官噪声 ±0.6～0.7。** 同一批 control 文件在两轮里被判出 12.75 与 13.45。**小于 0.7 的 Δ 不可分辨。**

`treat_silent` 比 `treat` 更差，说明**伤害不在元话语**：把「别提请资料」加上去，产出更糟而不是更好。
逐份文件核过：三臂写进文件的正文里元话语命中均为 **0/40**，中位长度 514 / 638 / 534，中位量化判据数 9 / 8 / 8
——长度与判据密度都没有系统性差异。

### 3.3 机制：卡把答案从「经营方案」拉向「方法说明」

读被判负的成对样本，模式一致：

| | control 产出的样子 | treat 产出的样子 |
| --- | --- | --- |
| 阈值 | 「近 30 天、播放≥5万、≥3 个博主独立用、连续≥2 周」——从业务处境推出的作业规则 | 「72 小时为一个语义演变周期、信息熵 ≥ 0.65、新颖度 ≥ 5.0」——论文实验条件的参数 |
| 事实 | 「Recall@FPR=0.5%」——定义口径，不虚构事实 | 「欺诈召回由**基线 42%**提升至 ≥60%」——用户从未给过这个基线 |

卡里装的是**论文的方法与参数**，而任务问的是**这家公司该怎么干**。模型拿到卡后，
把方法参数原样搬进交付物当业务取值，把答案写成了「这个方法怎么运作」。
判官给 control 的高分理由反复出现同一句：**「可直接落地」**；给 treat 的低分理由反复是
**「阈值待标定、缺算式、偏框架」**。

### 3.4 SkillOpt 补丁与验证门：**拒绝**

按上述机制，对一个**纯合成字段**（`## 边界与不做`）加了全局条款——与既有 ADR 契约行同形：

> **参数移植纪律**：本卡正文出现的数值都是原论文实验条件下的取值，不是你手上业务的实测值。
> 引用时必须写明来路，并说明要用本业务的哪份数据、按什么口径重新标定；标定完成前只能当临时默认值并标注出来。

重装配 + 重安装 1338 张后，用同一任务、同一 control 基线、同一盲配对重跑：

| 对比 | n | Δ | 补丁胜 / control 胜 / 平 | p | 门 |
| --- | ---: | ---: | --- | ---: | --- |
| gate train | 20 | −1.15 | 4 / 14 / 2 | 0.015 | ✗ |
| gate holdout | 20 | −1.10 | 5 / 14 / 1 | 0.032 | ✗ |

**补丁没关差距，反而把它拉大了**（holdout 从 −0.95 到 −1.10，train 从 −0.55 到 −1.15）。
两条硬证据：

1. **补丁让 26/40 份产出挂上对冲措辞**（「待标定 / 需重新标定 / 临时默认值」），
   其他三臂是 **0/40**；长度与量化判据数没变。条款把「敢下判断的方案」变成了「处处留白的说明」。
2. 判官给补丁臂的否决理由直接引用了它自己写的话：「阈值待标定、无业务成本数字，落地性弱」。

**按门禁处置：回滚。** 已复原装配器并重装配重安装，复核证据：
`grep -rl 参数移植纪律 ~/.dsh/skills | wc -l` → `0`；20 张卡的 SKILL.md 与打补丁前 `cmp` **逐字节一致**；
`verify-install.mjs` → 应装 1338 / 已装 1338 / 问题 0。

## 4. 已知边界（不夸大这份报告能证明什么）

| 项 | 说明 |
| --- | --- |
| 判官是 LLM | 三维度固定量表 + 盲配对 + 位置偏差已检验，但**判官噪声实测 ±0.6～0.7**；小于这个数的 Δ 不可分辨。§3.2 里 run1 holdout 的 p=0.0038 与 v2 的 p=0.084 是同一实验的两次结果，这个离散度就是噪声的真实尺度。 |
| L7 的任务是「业务请求」 | 20 张卡的任务全部由业务处境写成。结论**只在这类任务上成立**；若用户要的是「把这篇论文的方法讲清楚」，卡可能是有用的。这次测的是「岗位分身替业务办事」。 |
| 出题与判分同源风险 | 出题只读逐字正文、判分用与卡无关的固定量表，两者都不看合成字段；但出题与判分都出自同一个模型族。 |
| L6 抽样框 259/1338 | 只有 349 张被某岗露出，其中 259 张满足「L3 归本岗 + 正文可用」。**其余 979 张本轮未测路由**。 |
| 17 条零供给 L3 | 未变。结构性空白，与本次实测无关。 |
| `利益冲突检查` | 仍如实标注「平台无供给」，未变。 |

## 6. 待决项（需要人拍板，不在本报告范围内）

1. **`何时不用` 里的跨岗指引要不要改？** 1450 条里 801 条点名了本岗调不到的技能（§1.1）。
   三个选项：① 改成只指本岗可达的兄弟；② 保留但补一句「该技能不在本岗」；③ 不改（当作文档而非路由输入）。
   改法涉及 1338 张卡的合成字段，是一次 S2 级重跑。
2. **孪生卡要不要合并？** 678 对同 L3 共现、365 张卡有孪生（§1）。压住它能把 situational 准确率
   从 87.5% 往 100% 推，但代价是丢卡（每 L3 只留一张）。这是材料侧决策，不是技能库侧。
3. **跨 L3 语义近邻检测要不要加进装配器？** §2.3 证明这是另一半误召来源，而现有静态检查抓不到。
   代价是一次全库两两语义比对（1338²，需嵌入模型）。
4. **技能卡的正确用法要不要写进 preset 的 persona？** §3.3 的机制指向的不是改卡，而是改**用卡的姿势**：
   先拿方法来，再翻成经营方案。这条可以在 preset 侧验证，成本远低于重跑 S2。
