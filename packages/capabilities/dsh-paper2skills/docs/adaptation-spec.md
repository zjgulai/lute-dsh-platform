# 适配规范 · 论文技能卡 → DSH SKILL.md

> 本文件是 S2 适配阶段（批次子任务）的**唯一判据**。改这里就是改判据，改完必须重跑受影响批次。
> 分类底座见 `data/taxonomy.json`（4 面 / 8 责任域 / 151 细分业务），落点见 `data/classification.json`。

---

## 1. 一张卡 → 一个技能目录

```
staging/<L2 责任域>/<slug>/SKILL.md        ← 正文；完整代码放同级 references/
```

| 项 | 规则 |
| --- | --- |
| `slug` | `p2s-` + 卡 id 去 `Skill-` 前缀小写化，非 ASCII 折叠为 `-`（例：`Skill-GraphRAG-Knowledge-Enhanced-Retrieval` → `p2s-graphrag-knowledge-enhanced-retrieval`） |
| 目录名 | 必须等于 frontmatter 的 `name` |
| 落位目录 | `staging/<L2 责任域>/`（如 `staging/供应与履约/`），便于人工按域抽检 |
| 附件 | 卡页第 7 段（代码模板）完整实现放 `references/<slug>.py`；SKILL.md 只留可读摘要 |

## 2. frontmatter（逐字段判据）

值一律 **JSON 引号化**（`"..."`）或布尔（`true`/`false`）—— 这是 81-Skills `validateFrontmatter` 的硬判据。

| 键 | 必填 | 来源 / 规则 |
| --- | --- | --- |
| `name` | ✅ | slug，匹配 `^[a-z0-9]+(-[a-z0-9]+)*$` |
| `title` | ✅ | 卡页 `.skill-main-title`，中文保留 |
| `description` | ✅ | **合成**：`触发词：…` + `何时不用：…` + 安全边界；≤500 字符 |
| `l1_id` / `l1_plane` | ✅ | 取自 `data/classification.json` 的 `facets`，**逐字抄，不得改** |
| `l2_id` / `l2_domain` | ✅ | 同上 |
| `l3_id` / `l3_business` | ✅ | 同上（`l3_business` = 首位 L3） |
| `l3_all` | ✅ | 全部 L3，`" / "` 分隔 |
| `l1_l2_l3` | ✅ | 同上，`面/域/细分业务` |
| `p2s_card_id` | ✅ | 原始卡 id（溯源用） |
| `p2s_src_domain` | ✅ | 技术族（源域，如 `04-供应链`）——正交属性，不是分类级 |
| `user_summary` | ✅ | 一句话业务简介（技能中心卡面），≤80 字 |
| `user_try` | 高价值卡 | 「试试：…」示例，仅在卡页有明确业务场景时写 |
| `workflow` | 可选 | ≤5 步，**只从卡页第 3/7 段提炼，不新造** |
| `whenToUse` | 可选 | 与相邻 L3 技能的边界 |
| `enabled` | ✅ | 固定 `"true"` |
| `disable-model-invocation` | ✅ | 固定 `"true"` —— 全局模型目录不得被推高（O1 默认） |
| `user-invocable` | ✅ | 固定 `"true"` —— 保留斜杠可达 |

## 3. 正文结构

保留卡页八段（**知识本体就是价值所在，不得摘要掉**），按序拼接：

```markdown
# <title>

## ① 解决的问题        ← 卡页 1.
## ② 核心算法逻辑      ← 卡页 2.
## ③ 业务应用场景      ← 卡页 3.
## ④ 输入数据要求      ← 卡页 4.
## ⑤ 输出结果          ← 卡页 5.
## ⑥ 业务价值 / ROI    ← 卡页 6.（含 ROI 数字、实施难度、质量评分）
## ⑦ 代码模板          ← 卡页 7.（摘要 + 指向 references/ 的完整实现）
## ⑧ 论文来源          ← 卡页 8.

## 输入 / 输出契约      ← 从 ④⑤ 提炼为可执行契约（谁给什么、产出什么格式）
## 执行步骤            ← 从 ③⑦ 提炼，3–7 步
## 边界与不做          ← 何时不用、能力缺口、ADR 边界声明
## 技能关联            ← 前置 / 延伸 / 可组合（取自卡页 Skill Relations）
```

**ADR 边界声明（强制）**：若该卡的 L3 属于 `依赖协调` / `异常冻结与恢复` / `容量管理` / `失败恢复`，正文必须在 `## 边界与不做` 里写明：

> 本技能承载的是**规则与契约产物**（DAG 定序规则、熔断阈值与退避策略、置信门控与升级判据），
> 不是执行器。真正的编排与冻结动作由模型外的确定性控制层执行。

## 4. 缺口认领（`fills_gap`）的写法

9 个平台缺口**本身就是 L3 名**，所以「这张卡补上某缺口」必须与卡的 L3 落点自洽：

| 档 | 判据 | 下游含义 |
| --- | --- | --- |
| **strong** | 缺口名就是本卡的某个 L3 | `skill-map.json` 里该业务技能 `kind: direct` |
| **adjacent** | 缺口名不是本卡 L3，但本卡至少一个 L3 与缺口**同属一个 L2 责任域** | `kind: partial` |
| **dropped** | 跨责任域且未挂该 L3 | 虚报，丢弃（留档 `fills_gap_dropped`，不静默抹掉） |

典型误区（已实际发生，务必避开）：

- ❌ 工厂**产能**/仓库**仓容**卡认领 `容量管理` —— 矩阵里的 `容量管理` 指 **AI 运行容量**（并发/配额/推理成本），不是工厂产能。
- ❌ 供应链**单点依赖**/双源切换卡认领 `依赖协调` —— 该缺口指 **AGT-002 跨角色/跨能力的依赖定序与编排**，不是物理供应网络。
- ❌ 平台账号关联风控卡认领 `利益冲突检查` —— 该缺口指 **关联交易/利益冲突审查**（AGT-005 守衡），不是账号封号规避。

## 5. 空 L3 的处理

确实无法归入 151 条任何一项的卡（如 AI 伦理/ESG 披露、纯方法论），`l3: []` + `note` 写明理由。
这类卡**照常适配安装**（技能本体仍有价值、可用斜杠调用），但**不进任何 preset 的 skill-subset**，
并在 `docs/classification-spec.md` 的「矩阵空白登记」里逐条列出。

## 6. 硬性纪律

1. **SKILL.md ≤ 12 KB**：超出说明代码没移进 `references/`。
2. **`description` ≤ 500 字符**：超出会被 `import-paper2skills.mjs` 拒绝。
3. **不新造事实**：业务数字（ROI、提升幅度）必须来自卡页第 1/6 段原文，不得润色放大。
4. **不合并卡**：近重复族在装配阶段处理（同族只让 1 张进 `skill-subset`），适配阶段一张卡一个技能。
5. **不动源**：只读 `paper_to_skills/playbook/`，绝不写回。
