# 技能卡片 · 结构化引导（Prompt 模板）方案分析 v1

> 痛点：卡片选中后只填入 `/技能 请使用「技能」帮我：` 的固定引导——用户不知道要提供什么、能得到什么，使用模糊。
> 状态：分析讨论稿，未改代码。

## 1. 现状事实（源码级核查）

| 入口 | 代码位置 | 现填充内容 | 可控性 |
| --- | --- | --- | --- |
| 技能卡片墙（出海+AI全栈+营销） | dsh-overseas-skills/lib/client.js `click()` | `"/" + title + " 请使用「" + title + "」帮我："` | **完全可控**（自有插件） |
| 斜杠选择器 | dsh-client-ui-skill（已打过中文标题补丁） | onPick → `/{candidate.name} ` | 可再 patch（有先例），候选对象带 `skill.description` |
| 知识库面板 | dsh-wanzh-hulian | 已结构化（「在 X 库搜：」） | ✓ 无需改 |

## 2. 技能内容的「输入信息」可用性（决定模板怎么来）

| 来源 | 样例 | 可自动提取？ |
| --- | --- | --- |
| 81 系 | `## 输入`（竞品列表/情报来源/分析维度…）、`## 使用方法`（Provide product + target market + launch date + budget） | **部分可**（有「输入」章节的约一半，格式仍不统一） |
| 营销系（Accio） | 核心功能列表 + 使用方法（半结构化） | 弱（多为功能枚举，不是输入清单） |
| AI全栈（mattpocock 译） | 教程式结构（无「使用方法/输入」章节，如 tdd） | 基本不可（需人工） |

**结论：全自动提取质量不可控、全人工（130+ 个）成本高 → 分层模板策略。**

## 3. 方案：三层模板来源

| 层 | 内容 | 覆盖 | 质量 |
| --- | --- | --- | --- |
| **L1 人工精选模板** | 高频技能逐个写「必填/可选」输入槽（结合该技能的 使用方法/输入 章节提炼） | 先做 ~30 个核心技能（选品/竞品/审计/上市/文案/季度复盘/属性分析/场景侦察…） | 高（复合该技能的引导） |
| **L2 自动提取兜底** | 从 SKILL.md 解析「## 输入」列表 /「## 使用方法」代码块行 → 生成输入清单 | 其余有可解析章节的 | 中 |
| **L3 通用模板** | 从 description 触发词 + 通用结构（目标/背景/约束/期望输出）生成 | 全部剩余 | 可用 |

## 4. 模板形态（拟）

```
/上市策略
请帮我制定产品上市策略：
【必填】
· 产品是什么：____
· 目标市场：____
· 发布时间窗口：____
· 预算上限：____
【可选】
· 当前增长瓶颈：____
· 目标用户画像：____
```

- 首行保持 `/技能` 斜杠（路由确定性不变）；
- 输入槽 ≤6 个、全文 ≤500 字符（不压垮输入框）；
- 无「输入」信息的技能 → L3 通用三件套（目标/背景/约束）。
