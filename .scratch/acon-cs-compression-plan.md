# ACON 客服长会话上下文压缩 · 交付方案

依据：`/Users/lute/.dsh/skills/p2s-context-compression/SKILL.md`（Skill-Context-Compression，ACON）
场景：跨境母婴客服，单会话 10–30+ 轮，订单/物流/规格接口单次返回 5000+ token。

## 一、口径（先定死，再动手）

- **token 计量**：cl100k_base 计数；预算以模型窗口的 **70%** 为硬顶。
- **关键事实（压缩永不丢的 6 类）**：订单号、SKU/规格、金额与币种、物流节点+时间戳、承诺时限（SLA/赔付）、用户已表达的情绪与诉求。
- **"准确率不降"的判定**：关键事实召回率 ≥ 99%；答错率较全量上下文基线 **+0.5pt 以内**。

## 二、阈值与配比

| 项 | 值 |
| --- | --- |
| 触发压缩 | 上下文 > 窗口 70% 或轮次 ≥ 10 |
| 原始保留 | 最近 **3 轮**全量 |
| 历史摘要 | 更早轮次压成 system 级摘要，**每 5 轮增量重写一次** |
| 单次接口返回 | > **1000 token** 才进结构化压缩，目标 ≤ **600 token** |
| 接口字段白名单 | 只留：单号、状态、时间戳、金额、SKU、规格差异、异常码；丢冗余数组与展示字段 |
| 兜底 | 摘要覆盖不到的细节，保留 **tool_call 句柄**，需要时原样回取 |

## 三、执行步骤

1. 汇总历史轮次 + 全部接口返回原文。
2. 按预算先保最近 3 轮与全部关键事实。
3. 超预算的接口返回按字段白名单抽行，压成结构化短摘要（保留原文句柄）。
4. 更早历史生成 system 级摘要，增量重写、保留最近 3 轮。
5. 用 **每场景 50–200 对**成功/失败轨迹校准准则：失败轨迹丢了哪个字段 → 补进白名单；成功轨迹里没人看的字段 → 移出白名单。
6. 灰度 **5% 会话跑 7 天**，三指标对基线比对，验收通过再全量。

## 四、验收指标（缺一不可）

压缩率（目标 60–70%）· 关键事实召回率 ≥ 99% · 答错率增幅 ≤ 0.5pt · 首响时延降幅 · 单会话 token 成本降幅。
**熔断**：灰度期答错率超基线 0.5pt 或关键事实召回 < 99%，立即回退全量上下文，并冻结该版准则。
