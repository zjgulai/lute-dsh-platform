## 2. 三条「一行级」缺陷 —— 缺陷在流水线里，不在 1338 个文件里

这三条都是**单个源码行**造成的，波及面却覆盖全库。这是本轮最重要的发现：
**修 3 行 + 重跑，比手改 1338 个文件更接近正解。**

### A. `extract-cards.mjs:35` —— 代码缩进被无条件压平

```js
.replace(/[ \t]+/g, ' ')      // 对整段文本生效，包括 <pre><code>
```

`cards.json` 里 1338 张卡的 ⑦ 代码段，**最大缩进 = 1 个空格，无一例外**（`=0` 的 0 张，`>1` 的 0 张）。
而源站 HTML 里同一段代码是 4 空格缩进、`<pre><code>` 包裹、完好无损。

后果：**2,580,415 B（占语料 23%）的 Python 被压成不可解析的文本**。
示例（`p2s-3d-bin-packing-optimization`）：

```python
@dataclass
class Item:
 """单个商品箱子"""      ← 原本 4 空格
 item_id: str
```

卡片上写着「Python 60 行 · **可运行复制**」（1148/1338 张有这个标签）。

### B. `extract-cards.mjs:34` —— 只解 `&#39;`，不解 `&#x27;`

```js
.replace(/&#39;/g, "'")       // 源站用的是 &#x27;
```

**689/1338 张（51%）**的代码里残留 HTML 实体：
`p[&#x27;l&#x27;]` 而不是 `p['l']`。

### C. `assemble-skills.mjs:92` —— 「短于 40 字」被当成占位

```js
function isPlaceholder(text) {
  const t = (text || '').trim()
  if (t.length < 40) return true        // ← 这一行
  return /请查看原始代码模板|请查看原始\s*Skill\s*卡片|未自动抽取|未抽取/.test(t)
}
```

命中的段落被替换成同一句假话：
`（卡页此段为占位内容，实际输入/输出规格见下方「输入 / 输出契约」。）`

按 `cards.json` 逐段落重算：

| 段落 | 真占位串 | 真内容 | **被 `<40 字` 误判清掉** |
| --- | ---: | ---: | ---: |
| ⑧ 论文来源 | 289 | 8 | **1,041** |
| ⑥ 业务价值 / ROI | 52 | 1,115 | **171** |
| ② 核心算法逻辑 | 0 | 1,170 | **168** |
| ① 解决的问题 | 0 | 1,278 | **60** |
| ③④⑤⑦ | 2,733 | 2,619 | 0 |
| **合计** | **3,074** | **6,190** | **1,440** |

抽样对照（`cards.json` → 已装 SKILL.md）：

| 卡 | cards.json 原文 | 已装卡 |
| --- | --- | --- |
| 3D 装箱优化 ② | `3D 装箱问题（Bin Packing Problem）：`（29 字） | 假占位 |
| 3D 装箱优化 ⑧ | `2406.12089` | 假占位 |

且这句假占位**指错了地方**：论文出处、ROI、算法逻辑三段都与「输入 / 输出契约」无关。

> 已装库里只剩 8 张 ⑧ 有真内容 —— 因为只有它们 ≥40 字（≥4 个 arXiv ID）。
> 这条自洽性反过来证明规则就是 `<40`。

**影响面**：`pnpm` 之外没有任何门禁测过它。`docs/test-report.md` 记的是
「正文跳过 **4520 处占位段落**」—— 数字对得上（3,074 真占位 + 1,440 误判 ≈ 4,514），
但从未有人拆开过这 4520 里有多少是真的。

## 3. 出处链条的另一半：`cards.json` 自己的 arXiv ID 也不可信

承 A/B/C 之上的独立问题。`cards.json` 里 **1,049 张卡**带 arXiv ID（1,152 个去重 ID），
但分层看是这样：

| 层 | 卡数 | 判据 |
| --- | ---: | --- |
| 明显假号 | **81** | 形如 `2305.12345`（×19 张）、`2106.12345`（×16 张）、`2106.04567`（×4 张） |
| 与他卡共用同一 ID | 95 | 一张卡一个「唯一来源」却出现 4–19 次 |
| 多 ID | 184 | 2–6 个 ID |
| 唯一 ID | 689 | 只被这一张卡引用 |

抽查 6 个「唯一 ID」对 arXiv 实查：

| ID | 卡 | 真论文 | 判 |
| --- | --- | --- | --- |
| 2502.12110 | A-MEM 记忆系统 | *A-MEM: Agentic Memory for LLM Agents* | ✅ |
| 2302.04761 | LLM 工具选择路由 | *Toolformer* | ✅ |
| 2407.01065 | 共形 ROI 预测 | *Improve ROI with Causal Learning and Conformal Prediction* | ✅ |
| 2510.05445 | AgentRouter 知识图谱路由 | *AgentRouter: A Knowledge-Graph-Guided LLM Router* | ✅ |
| 2406.12089 | 3D 装箱优化 | *Many-Body Quantum Geometric Dipole*（凝聚态物理） | ❌ |
| 2404.05961 | VOC 评论欺诈检测 | *LLM2Vec: LLMs Are Secretly Powerful Text Encoders* | ❌ |

6 抽 4 中 2 错（样本小，不作为比率用）。**结论：修 C 不等于「把 1,041 个 ID 全量还原」**——
那样会把 81 个假号和一批错配号一起洗进卡片，等于把 p2s 项目自己封堵过的
`G2-BASIS-CONTRADICTION`（漏洞 #10）在技能库里重演。

## 4. 「技能关联」段：28,102 条引用里 69% 是同一个名字写两遍

- 每张卡的关联段把同一目标写成两份：`Skill-Foo.html`、`Skill-Foo` → 冗余条目 **19,531 / 28,102 (69%)**
- **1338/1338 张卡在关联里列出了自己**
- 反向可解析率：目标用 `Skill-PascalCase`、目录用 `p2s-kebab-case`，靠 `p2s_card_id` 当 join 键才能对上 → **8,230/8,571 (96%) 可解析**，341 条指向不存在的卡
- 方向性：6,023 条「前置」边里 **6,023 条（100%）反向不存在** —— 图不是对称关系，是单向清单
- 该段字符数占全库 **65% 是模板**（n-gram 覆盖法），是除代码外第二大的模板来源
