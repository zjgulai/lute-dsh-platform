# 知识库入口重设计 · v3（设计反思 + 多来源抽象）

> 触发：用户反馈「好丑」——icon 不符合多来源定位、点卡后按钮不符合品牌调性。
> 状态：讨论稿，未改代码。

## 1. 深度反思（为什么丑）

| 反思点 | 问题 | 根因 |
| --- | --- | --- |
| 品牌独占 | 按钮/面板标题/占位图全是「得到大脑」logo | 按单来源设计——未来连 Notion/飞书/企业知识库时，logo 会互相打架，且入口语义收缩为「一个 App」而非「知识库」 |
| 信息噪音 | 卡片 meta 直接展示 `id: QJmRL4Gn` | 把调试信息当展示信息（技术观感） |
| 动作冗余 | 整卡可点 + 卡内还有「搜索/保存」两个小按钮 | 单一卡片两个相同时机，且小按钮样式粗劣（flex:1 挤压、宽高失衡） |
| 视觉密度 | 56px 封面大图铺满、网格卡片挤压、灰色调 | 未按品牌 token 设计，只做了「能用」 |
| 未来扩展 | 插入指令硬编码 `/得到大脑 …` | 多来源时模型无法区分来源 |

## 2. 新方案要点（多来源 + 品牌化）

### 2.1 通用抽象：入口=「知识库」（品牌中立）
- 左栏底部按钮：**纯文字「知识库」**（无 icon）；56px 窄轨时选项见决策问题。
- 面板标题「知识库」+ 副题「已连接 1 个来源 · 11 个库」；多来源时按**来源分组**（组头小字：得到大脑 / Notion / …）。
- 缩略图：优先知识库 cover 图；无 cover 时用**通用占位**（品牌薄荷底 + 简洁书本图形，非任何供应商 logo）。

### 2.2 动作模型：模式切换取代按钮堆（对齐品牌调性）
- 面板顶部**分段控件**：「搜索」/「存库」两态（品牌绿 active，白底 44px 圆角）。
- 卡片**单击即按当前模式**落指令——卡内不再有「搜索/保存」按钮，零冗余。
- 卡片形态（两选一，见决策）：

| | A. 列表式行卡（推荐） | B. 精简网格卡 |
| --- | --- | --- |
| 行高 | 52px 行卡：32px 圆角缩略图 + 名称 + 笔记数 + 右侧 chevron | 120px 高：36px 缩略图 + 名称 + 笔记数 |
| 视觉 | 干净、易扫读、多来源分组友好、未来按来源折叠自然 | 卡片感更强但 11+ 库时密度高 |
| 品牌 | 悬停浅薄荷底、选中绿描边，无灰色挤迫 | 同左 |

### 2.3 视觉规范（对齐 LUTE 品牌 + dsw token）
- 主绿 #58B848 / 深 #2E7D3C / 浅 #8FD48A / 薄荷底 #DCF1D6（与出海技能卡片墙一致）。
- 面板：360px 右停靠、白底、顶部 3px 品牌绿渐变条；标题 14px/600；正文 11-12px；关闭按钮 ghost（仅 ✕ 无底色）。
- 空态：未连接任何来源 → 显示「去 万物互联 连接知识库」+ 按钮（打开设置页）。
- 导航信息（id 等）移入 title tooltip / 插入文本，不再上卡面。
- 底部：默认库状态胶囊 + 「管理来源」链接（跳到万物互联知识库板块）。

### 2.4 指令文本通用化（多来源关键设计）
- **方案 X（推荐）**：命令按来源生成（得到大脑 → `/得到大脑 在「super_ip」（id: …）搜索：`；未来 Notion → `/notion …`）——零通用路由改动，面板按卡所属来源生成对应命令。
- **方案 Y**：统一 `/知识库` 命令（通用技能路由到各来源）——模型路由更统一，但要新建通用技能并承担（每来源）触发歧义，改动大。
- 面板是「选库机」：只负责**选哪个库 + 哪个来源**，命令文本由来源模板生成；来源模板注册在 catalog（CONNECTIONS 每条可带 commandTemplate）。

## 3. 决策问题

1. 卡片形态：A 列表式行卡（推荐）/ B 精简网格卡？
2. 动作模型：A 顶部「搜索/存库」分段切换 + 卡单击（推荐）/ B 取消分段，整卡单击=搜索，卡尾附「存库」小 icon（ghost）？
3. 窄轨入口：A 隐藏（仅宽轨显示「知识库」文字）/ B 显示通用图标（📚 风格，非品牌 logo）？
4. 指令通用化：X 按来源生成命令（推荐）/ Y 统一 /知识库 命令？

## 4. 决策记录与最终规格（v4，2026-09-06）

| 决策 | 选择 |
| --- | --- |
| 卡片形态 | **B 精简网格卡**：36px 圆角缩略图 + 名称 + 笔记数；无封面大图、无 id 文本；hover 薄荷底/绿描边；网格约 3 列（面板 360px） |
| 动作模型 | **A 分段切换**：面板顶部「搜索 / 存库」分段（品牌绿 active、白底胶囊）；卡片单击按当前模式落指令；卡内零按钮 |
| 窄轨入口 | **A 窄轨隐藏**：仅宽侧栏显示纯文字「知识库」（无 icon）；窄轨（56px）不渲染 |
| 指令文本 | **X 按来源生成**：catalog CONNECTIONS 每条增加 `commandTemplate: {search, save}`（含来源名+库名+库 id 插槽）；面板按卡所属来源生成命令（得到大脑 → `/得到大脑 在「X」（id: y）搜索：` / `…存库：`） |

## 5. 需求澄清：选择单元 = 知识库名称（2026-09-06）

用户明确：**可选的是知识库的名称，而不是某一篇笔记**。契约固化如下：

1. **卡片即知识库**：每个卡片 = 一个知识库（名称为主文案，64px 内单行截断）；卡上副文案为「笔记数」（元数据），不代表可选中笔记。
2. **面板内不出现任何笔记实体**：本面板是「选库机」——点卡只产出「在 X 库内做搜索/存库」的动作，笔记仅由模型在执行后以结果形式返回（对话流中），用户永不在此界面选笔记。
3. 「全部笔记」卡理解为「全部知识库（全局搜索）」更准确 → 改为「全部库 · 全局搜索」，避免误读为"一篇笔记"。
4. 插入文本以库名为主（库 id 仅作机器参数藏在命令内，模型可见但用户不感知）——视觉选择 = 名称。
5. 库名重复时（多来源同名校）：显示为「名称 · 来源」；id 仍只进命令文本。
