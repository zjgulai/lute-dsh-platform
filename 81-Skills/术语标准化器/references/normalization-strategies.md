# 标准化策略详解

## 策略概述

| 策略 | 合并规则 | 适用场景 |
|-----|---------|---------|
| **STRICT** | 仅合并 100% 相同概念 | 适用对象、关键概念 |
| **FLEXIBLE** | 合并同义词、变体 | 领域标签、一般术语 |

---

## STRICT 模式（严格）

### 合并规则

只有满足以下条件才合并：
1. 概念完全相同
2. 语义无歧义
3. 仅形式差异（大小写、空格）

### 示例

**输入**:
```
["财务报表", "Financial Statements", "financial statements", "财务分析"]
```

**输出**:
```json
{
  "mappings": {
    "财务报表": "财务报表",
    "Financial Statements": "财务报表",
    "financial statements": "财务报表",
    "财务分析": "财务分析"  // 未合并，不同概念
  },
  "groupings": [
    ["财务报表", "Financial Statements", "financial statements"]
  ]
}
```

### 适用字段

- `applicable_objects`: 适用对象
- `prerequisites`: 前置条件
- `constraints`: 约束条件

**原因**: 这些字段直接影响知识应用，必须精确

### LLM Prompt 模板

```
严格标准化规则：

1. 概念必须 100% 相同才合并
2. 细微语义差异视为不同概念
3. 仅允许以下变体：
   - 大小写差异（Ratio vs ratio）
   - 空格差异（Current Ratio vs CurrentRatio）
   - 全角半角差异

示例：
- ✅ 合并: "财务报表" = "Financial Statements"（同一概念不同语言）
- ❌ 不合并: "财务报表" ≠ "财务分析"（不同概念）
- ❌ 不合并: "流动比率" ≠ "速动比率"（不同指标）
```

---

## FLEXIBLE 模式（灵活）

### 合并规则

以下情况可以合并：
1. 同义词（意思相同的不同表达）
2. 语言变体（中英文对照）
3. 缩写与全称（ROI vs Return on Investment）
4. 单复数形式（ratio vs ratios）
5. 轻微拼写变体

### 示例

**输入**:
```
["财务分析", "Financial Analysis", "financial analysis", 
 "财报分析", "财务报表分析", "盈利分析"]
```

**输出**:
```json
{
  "mappings": {
    "财务分析": "财务分析",
    "Financial Analysis": "财务分析",
    "financial analysis": "财务分析",
    "财报分析": "财务分析",
    "财务报表分析": "财务分析",
    "盈利分析": "盈利分析"  // 未合并，范围不同
  },
  "groupings": [
    ["财务分析", "Financial Analysis", "financial analysis", 
     "财报分析", "财务报表分析"]
  ]
}
```

### 适用字段

- `domain_tags`: 领域标签
- 一般性分类标签

**原因**: 标签用于分组和检索，语义相似即可

### LLM Prompt 模板

```
灵活标准化规则：

1. 同义词可以合并
2. 中英文对照可以合并
3. 缩写与全称可以合并
4. 单复数形式可以合并
5. 行业俗称与正式名称可以合并

示例：
- ✅ 合并: "财务分析" = "financial analysis"（中英对照）
- ✅ 合并: "ROI" = "Return on Investment"（缩写）
- ✅ 合并: "财报" = "财务报表"（俗称）
- ❌ 不合并: "财务分析" ≠ "盈利分析"（范围不同）
```

## 混合策略配置

### 推荐配置

```python
STRATEGY_CONFIG = {
    "applicable_objects": "STRICT",   # 精确
    "prerequisites": "STRICT",        # 精确
    "constraints": "STRICT",          # 精确
    "domain_tags": "FLEXIBLE",        # 灵活
    "keywords": "FLEXIBLE"            # 灵活
}
```

### 原因

| 字段 | 策略 | 原因 |
|-----|------|------|
| applicable_objects | STRICT | 错误合并会导致知识误用 |
| prerequisites | STRICT | 遗漏前置条件会导致执行失败 |
| domain_tags | FLEXIBLE | 便于检索和分组 |

## 冲突处理

### 一对多映射

**问题**: 一个原始术语映射到多个标准术语

```json
{
  "mappings": {
    "分析": "财务分析",  // 错误！
    "分析": "数据分析"   // 错误！
  }
}
```

**解决**: 
1. 拒绝一对多映射
2. 要求提供上下文区分
3. 或使用更具体的术语

### 歧义术语

**问题**: 术语在不同语境下含义不同

**示例**: "比率"
- 财务语境 = 财务比率
- 数学语境 = 比值

**解决**:
1. 保留原样（STRICT 模式）
2. 添加前缀（"财务-比率", "数学-比率"）
3. 基于上下文消歧

## 质量评估

### 指标

1. **缩减率**: (原始术语数 - 标准术语数) / 原始术语数
   - 目标: 20-40%（过低=未充分合并，过高=可能过度合并）

2. **保留率**: 重要术语的保留比例
   - 目标: > 95%

3. **错误合并率**: 人工检查发现的错误合并比例
   - 目标: < 5%

### 检查清单

- [ ] 核心概念未被意外合并
- [ ] 同义词已被识别并合并
- [ ] 无一对多映射
- [ ] 无空值或空字符串映射
- [ ] 映射可逆（可追溯）
