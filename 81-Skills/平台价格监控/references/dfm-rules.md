# 价格监控合规与数据来源规范

## 数据来源原则

1. **优先官方 API**：Amazon 用 Product Advertising API，eBay 用 Finding API，AliExpress 用开发者 API。官方 API 合规、稳定、免限流风险。
2. **Scraper 默认禁用**：网页抓取有合规风险（违反 robots.txt、使用条款），仅供 API 不可用的备用方案，且需用户明确确认合规。
3. **Mock 模式**：无凭证或测试时使用，数据标注 `source=mock`，避免与真实数据混淆。

## 平台合规边界

| 平台 | 合规要求 | 风险 |
|------|---------|------|
| Amazon | 遵守 Associates 与 PA API 使用条款，不得抓取需登录页面 | 高频抓取触发风控/封禁 |
| eBay | Finding API 有调用配额，遵守 API 许可协议 | 超配额限流 |
| AliExpress | 遵守开发者 API 协议，不得获取非公开数据 | 违规封号 |

## 抓取频率与降级

- 频率控制：价格监控为**分钟级/小时级**，禁止秒级高频（会触发平台风控）。
- 降级顺序：缓存回退 → Mock 模式 → 跳过失败。
- 配额管理：接近 API 配额上限时自动降级，优先保证核心监控目标。

## 数据安全

- API 凭证通过环境变量传入（`AMAZON_ACCESS_KEY` 等），**禁止硬编码**。
- 敏感价格数据本地存储需做好保护，不落明文凭证。
- 禁止将竞品价格数据用于非法竞争（如恶意压价挤垮对手、批量刷差评）。
