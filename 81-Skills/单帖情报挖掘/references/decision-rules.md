# Decision Rules

## 1. 如何识别主帖子类型

优先根据主帖意图判断，而不是根据评论区情绪判断。

### complaint post
主帖以抱怨、失望、劝退、曝光、故障描述为主。

### consultation post
主帖以询问、求建议、购买前犹豫、想听经验为主。

### comparison post
主帖显式比较两个或多个产品、品牌、方案。

### recommendation post
主帖以主动推荐、安利、分享好物经验为主。

### troubleshooting post
主帖以“怎么修”“为什么坏了”“怎么解决”为主。

### post-purchase review
主帖以购买后使用感受为主，不一定强烈正负面。

如果一个帖子同时具备多重属性，应：

- 标记主类型
- 标记次类型
- 在输出中说明为什么这样判定

## 2. 什么算关键评论

优先保留以下评论：

- 原作者补充说明
- 提供新证据的评论
- 提供使用时长、故障模式、维修细节的评论
- 引发购买转向的评论
- 明确推荐竞品的评论
- 暴露使用边界和适配问题的评论
- 修正或反驳主帖结论的评论

不要平均看待所有评论。

## 3. 什么算高证据内容

高证据内容通常包括：

- 拆机/拆解描述
- 图片或视频说明
- 明确使用时长
- 具体故障模式
- 清晰使用场景
- 可复现过程
- 维修步骤
- 连续 replacement / refund / warranty 记录

纯情绪表达不等于高证据。

## 4. 什么算迁移信号

当评论中出现以下内容时，应识别为迁移信号：

- 原本想买 A，决定买 B
- 看完帖子放弃某品牌
- 主动推荐竞品
- 把竞品作为可靠替代
- 把某产品当作行业基准
- 先买 A，后转向 B

## 5. 什么算弱信号高价值内容

以下情况即使只出现 1 次，也应高优先级关注：

- 明确的具体故障
- 适配性问题
- 安全风险
- 长期耐久性疑点
- 会影响决策的“本来想买，现在不买了”
- 使用边界暴露
- 需要用户自行发明 workaround 的情况

低评论量不等于低价值。

## 6. 不同帖子类型的关注重点

### complaint post
优先找：

- 故障模式
- 证据强度
- 客服处理
- 保修逻辑
- 竞品迁移
- 是否形成群体共识

### consultation post
优先找：

- 购买动机
- 被吸引的卖点
- 用户犹豫点
- 单条具体负面反馈
- 初体验和长期体验的差异
- 适配性问题

### comparison post
优先找：

- 比较维度
- 用户权衡标准
- 最终决策逻辑
- 行业基准产品

### recommendation post
优先找：

- 推荐理由
- 适用人群
- 适用边界
- 是否存在幸存者偏差

### troubleshooting post
优先找：

- 用户尝试过哪些方案
- 社区提供了哪些修复路径
- 是否存在可维修性需求

### post-purchase review
优先找：

- 使用阶段
- 体验演化
- 初始满意是否经得住长期使用

## 7. 什么算反直觉洞察

满足以下任一条件可视为候选：

- 出现次数少，但业务后果重
- 正向表述背后藏着负向机制
- 负向内容反而是高价值研发素材
- 客服被夸奖，但品牌信任仍下降
- 用户自己发明解决方案，说明产品设计存在结构性缺口
- 咨询帖里的一条具体故障，比多条笼统好评更有预测价值
- 用户被卖点吸引，但真正出问题的是适配和耐久，而不是核心参数

## 8. 什么算最终业务动作

至少能映射为以下之一：

- 产品优化方向
- 售后策略调整
- 市场传播风险
- 竞品监控点
- VOC 标签监控规则
- 用户教育内容选题
- 适用人群边界提示
- FAQ / 帮助中心 / 社区回应素材
- 长期 VOC 监控或复查触发条件
