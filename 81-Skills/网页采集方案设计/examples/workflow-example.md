# 网页采集方案设计 — 工作流示例

## 场景：电商评论页采集方案设计

### 用户请求
> 帮我对这个电商评论页设计一套采集方案，要能长期监控口碑和差评预警

### 第一步：样本审计
- 用户提供评论页URL：https://example.com/product/B0XXXX/reviews
- 抽取3个真实评论样本，逐字段审计：

| 字段 | 是否存在 | 稳定可采 | 维护成本 | 建议 |
|------|---------|---------|---------|------|
| 评论ID | ✅ data-review-id | ✅ | 低 | 保留-必采 |
| 评分 | ✅ .star-rating | ✅ | 低 | 保留-必采 |
| 评论标题 | ✅ .review-title | ✅ | 低 | 保留-可选 |
| 评论正文 | ✅ .review-text | ✅ | 低 | 保留-必采 |
| 评论时间 | ✅ .review-date | ✅ | 中(需标准化) | 保留-必采 |
| 评论者昵称 | ✅ .reviewer-name | ✅ | 低 | 保留-可选 |
| 头像URL | ✅ .avatar | 否(CDN常变) | 高 | 剔除 |
| 回复内容 | ✅ .reply-text | 部分(仅20%有回复) | 低 | 保留-可选 |
| 回复时间 | ✅ .reply-date | 部分 | 中 | 保留-可选 |

### 第二步：字段优化
核心必采字段（8个）：评论ID、评分、评论正文、评论时间、商品ID、是否Verified Purchase、抓取时间
可选字段（4个）：评论标题、评论者昵称、回复内容、回复时间
剔除字段：头像URL、评论者等级徽章、评论置顶标识

### 第三步：输出交付物
- 文件一：采集字段设计（页面级+明细级分层）
- 文件二：字段说明与指标字典（含回复率、平均响应时长、差评率等衍生指标）
- 文件三：自动化采集PRD（翻页策略、去重策略、断点续采、质量审计规则）
