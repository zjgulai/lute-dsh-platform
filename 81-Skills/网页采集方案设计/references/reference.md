# Reference for Web Data Audit Designer

本文件用于沉淀网页数据方案设计的通用规则、字段裁剪标准、指标设计原则和质量审计建议。

它为 `SKILL.md` 提供补充规则，也为不同页面类型下的判断提供统一标准。

---

## 1. 字段裁剪原则

字段是否应进入首版设计，优先看以下四个维度：

### 1.1 业务价值

优先保留能直接支持以下分析的字段：

- 口碑与满意度分析
- 响应效率分析
- 内容主题分析
- 商品/服务问题定位
- 区域差异比较
- 价格与状态变化分析

### 1.2 获取稳定性

优先保留：

- 页面稳定展示字段
- DOM 结构稳定字段
- 不依赖复杂交互即可获取字段
- 不易受语言和地区切换影响字段

### 1.3 标准化难度

优先保留：

- 易清洗
- 易归一
- 易转结构化类型
- 易做去重与映射

### 1.4 长期维护成本

谨慎对待：

- 高频改版区字段
- 仅在部分样本偶现字段
- 高空值率字段
- 强依赖弹层或复杂二跳的字段

## 2. 字段优先级分类标准

### 必采

满足以下多数条件：

- 高业务价值
- 当前页面稳定可采
- 首版分析必须依赖
- 标准化成本低
- 长期维护收益高

### 可选

通常指：

- 有一定业务价值
- 但并非首版必需
- 或获取需要额外交互
- 或当前样本出现不稳定

### 不建议采集

通常指：

- 业务价值低
- 获取成本高
- 稳定性差
- 可由后处理生成
- 更适合放入日志或调试体系

---

## 3. 采集层与分析层边界

### 采集层字段

应满足：

- 页面原生存在
- 可直接采集
- 可复现
- 适合长期入库

示例：

- 标题
- 正文
- 评分
- 发布时间
- 回复时间
- 价格
- 状态
- 作者名

### 分析层字段

通常来自：

- NLP 模型
- 规则引擎
- 聚类或分类
- 业务映射

示例：

- sentiment_label
- topic_tags
- complaint_type
- risk_level
- product_mentioned
- severity_level

## 4. 时间字段处理建议

### 应优先检查的时间字段

- published_at
- reply_at
- experienced_at
- updated_at
- handled_at
- completed_at
- status_changed_at

### 建议保留 raw 的时间字段

- published_at_raw
- reply_at_raw
- experienced_at_raw
- status_changed_at_raw

### 标准化建议

- 优先转为统一 datetime / date
- 保留时区信息时尽量保留
- 对相对时间要记录采集时间作为参照
- 标准化失败时不要强行填值，应保留空值并记录 raw

## 5. 常见业务指标设计原则

### 5.1 基础指标

用于直接描述规模和结构：

- 总量
- 平均值
- 占比
- 分布
- 覆盖率
- 完整率

### 5.2 业务指标

用于支持具体业务动作：

- 好评率 / 差评率
- 回复率
- 平均响应时长
- 差评回复率
- 缺货率
- 折扣率
- 区域分布差异

### 5.3 衍生指标

用于更深入分析：

- 情感分布
- 主题占比
- 投诉类型占比
- 关键词提及率
- 风险变化趋势

## 6. 自动化采集设计建议

### 6.1 翻页策略

优先识别页面属于哪类：

- 分页 URL
- Next 按钮
- 无限滚动
- 筛选/排序切换触发加载

### 6.2 翻页成功判定

至少应满足以下之一：

- URL 变化
- 当前页码变化
- 第一条记录主键变化
- 列表记录集合变化

### 6.3 末页判定

至少应结合以下信号：

- Next 不存在
- Next 被禁用
- 连续翻页后内容不变
- 已到页面声明的最后页
- 连续滚动后记录数不再增加

### 6.4 去重建议

优先级：

1. 官方 ID
2. 详情 URL
3. 组合键

组合键常见方式：

- 作者 + 时间 + 标题 + 正文 hash
- 标题 + 时间 + 主体名称
- 名称 + 地址 + 价格 + 页面来源

## 7. 质量审计建议

### 7.1 核心字段完整率

建议重点监控：

- 主键非空率
- 主体内容非空率
- 时间字段非空率
- 作者/对象名称非空率

建议阈值：

- 关键字段完整率建议 >= 95%
- 核心主键字段完整率建议 >= 99%

### 7.2 页面覆盖率

适用于页面声明总数的场景：

$$
coverage\_rate = \frac{去重后抓取数}{页面声明总数}
$$

建议：

- 覆盖率 < 90%：高风险
- 90% \~ 95%：需人工复核
- >= 95%：通常可接受

### 7.3 翻页重复率

适用于分页/滚动列表：

- 相邻页重复率显著偏高时，需检查翻页失败
- 连续多页内容高度重复时，应触发异常

### 7.4 回复字段一致性

如果 `has_reply = true`，则通常至少应存在以下之一：

- reply_text
- reply_at_raw
- reply_at

否则说明解析规则可能不完整。

## 8. MVP 与扩展版建议

### MVP 版本

只保留：

- 高价值
- 稳定
- 易标准化
- 可直接支撑核心业务指标

通常用于首版上线。

### 扩展版本

可在以下条件满足后再增加：

- 首版已稳定运行
- 关键字段覆盖率达标
- 业务已验证新字段有价值
- 维护成本可接受

---

## 9. 推荐输出风格

在生成最终方案时，应尽量做到：

- 先给审计结论，再给方案
- 每个字段说明保留/剔除理由
- 每个指标说明业务价值
- 自动化方案尽量给出规则，而不是口号
- 用 MVP 思维控制规模
