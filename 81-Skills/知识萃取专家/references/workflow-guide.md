# 三阶段知识萃取工作流

本文档详细说明知识萃取的完整流程。在触发 skill 后，严格按照以下三阶段执行，每阶段完成后确认再进入下一阶段。

---

## 阶段一｜结构真相还原（分析引擎）

**目标**: 回答三个核心问题
1. 这本书在逻辑上是否成立？
2. 作者真正想解决的"核心问题"是什么？
3. 哪些内容是结论，哪些只是修辞或故事？

**输出要求**:

### 1. 一句话总论（≤100字）
用精准、无修辞的语言，锚定全书的核心命题。

### 2. 核心论点结构（3-5条）
使用「问题 → 主张 → 关键逻辑 → 结论」链条组织：
- 明确标注【因果关系】
- 明确标注【前提假设】
- 明确标注【适用边界】

### 3. 论证与证据地图
- 列出作者使用的证据类型（数据 / 案例 / 理论 / 类比等）
- 标注证据与主张的对应关系
- 对证据薄弱或逻辑跳跃处标注【待验证】

### 4. 方法与框架清单
- 提取书中可复用的方法、模型或操作步骤
- 明确每个方法的适用前提与使用条件
- 标注方法的可迁移性（通用 / 领域特定）

### 5. 反例与局限
- 系统拆解作者可能忽略的反例
- 指出容易被误用或过度泛化的部分
- 识别作者的潜在利益立场或认知盲区

**阶段一原则**:
- 追求"是否成立"，而非"是否好听"
- 不做行为建议，不谈个人改变
- 保持研究者的距离感和批判性

**阶段过渡判断**:
阶段一完成后，用一句话判断：「这本书，哪些部分【值得进入下一阶段】，哪些应被搁置？」

---

## 阶段二｜思维模型与场景迁移（框架引擎）

**目标**: 把"可信的内容"转化为【可迁移的思维工具】

**基于阶段一筛选后的内容，输出**:

### 1. 三个最强思维模型 / 框架
每个模型包含：
- 一句"人话"解释其本质（无术语版本）
- 它解决什么问题
- 它不解决什么问题（明确边界）
- 与原书论点的对应关系

### 2. 场景化应用推演
- 自动构造 1 个典型现实场景（或询问用户提供具体场景）
- 用上述模型逐步分析该场景
- 给出清晰的判断路径，而非结论跳跃
- 展示"如何思考"而非"思考什么"

### 3. 机会与陷阱
对每个模型列出：

**机会点（1-2个）**:
- 立即可用的应用场景
- 具体可执行的洞察

**陷阱（1-2个）**:
- 常见误用方式
- 致命错误判断
- 过度泛化的风险

**阶段二原则**:
- 模型 > 故事（抽象原则优于具体案例）
- 解释"为什么能用"，而非"看起来有用"
- 强调可迁移性，而非原书特定语境

---

## 阶段三｜行为转化与内化设计（行为引擎）

**目标**: 把模型转化为【可执行、可坚持、可复盘的行为系统】

**输出要求**:

### 1. 第一性原理提炼
- 从全书中抽象出 2-4 条底层认知规律
- 说明其心理/决策机制，而非表层技巧
- 解释"为什么这条原理在人性层面成立"

### 2. 行为转化表（Action Table）

对每条原理，输出以下表格：

| 字段 | 内容 |
|------|------|
| 原理名称 | 简洁命名 |
| 一句话本质 | 核心机制说明 |
| 每日/每周最小行动 | ≤5分钟，具体可操作 |
| 该行动能避免的典型错误 | 明确行为价值 |

### 3. 行为触发与复盘机制

**触发条件设计**:
- 1个清晰的启动信号（何时开始做）
- 与现有习惯的捆绑点（if-then 公式）

**复盘问题设计**:
- 1个低负担的每日/每周复盘问题
- 判断效果的具体指标（非主观感受）

**阶段三原则**:
- 不追求"激励感"或"顿悟感"
- 只追求"能否长期执行"
- 行动必须小到"不可能失败"

---

## 最终输出｜价值判定

三阶段全部完成后，用 3 句话回答：

1. **这本书最值得带走的是什么？**（核心价值提炼）
2. **如果只能保留一个模型/原则，应是哪一个？**（优先级判断）
3. **这本书更适合【哪一类人】在【什么阶段】阅读？**（精准受众定位）

---

## 输入信息检查清单

如以下信息缺失，在开始前先提出澄清问题：

- [ ] 书名和作者
- [ ] 阅读目的（学习 / 批判 / 应用 / 判断价值）
- [ ] 目标应用场景（个人成长 / 工作决策 / 教学分享等）
- [ ] 已有笔记或重点标注（如有）
