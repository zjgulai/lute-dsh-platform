# Skill Types - 技能类型框架

Skill 分为三种类型，类型决定测试方法与正文自由度。

## 类型概览

| 类型 | 定义 | 典型用途 | 正文风格 |
|------|------|----------|----------|
| **Technique** | 有明确步骤的方法 | 调试流程、图表制作 | 流程导向 |
| **Pattern** | 思维框架或决策模型 | 归因方法、拆解框架 | 判断导向 |
| **Reference** | 可检索知识库 | API 速查、字段规范 | 检索导向 |

---

## Technique（技术型）

### 定义
有明确输入输出、可重复执行的操作流程。

### 特征
- 步骤顺序明确
- 可验证的完成标准
- 输入输出格式固定

### 示例
- CSV 数据清洗流程
- Git 提交消息生成
- 错误日志分析步骤

### SKILL.md 结构

```markdown
---
name: csv-cleaner
description: |
  清洗和标准化 CSV 数据。
  当用户提及"清洗CSV"、"数据清洗"、"整理表格数据"时使用。
---

## 输入要求
- CSV 文件路径
- 目标格式说明

## 处理步骤
1. 检查编码和分隔符
2. 处理缺失值
3. 标准化日期格式
4. 验证输出

## 输出格式
- 清洗后的 CSV
- 变更日志
```

### 测试策略

**测试输入**: 新场景执行题

**通过标准**: 步骤完整且可复现

| 检查点 | 权重 |
|--------|------|
| 步骤顺序正确 | 30% |
| 边界情况处理 | 25% |
| 输出格式符合 | 25% |
| 错误处理完整 | 20% |

---

## Pattern（模式型）

### 定义
思维框架或决策模型，用于分析和判断。

### 特征
- 提供思考角度
- 有选择/判断标准
- 非唯一正确答案

### 示例
- 根因分析框架
- 技术选型决策树
- 代码审查检查清单

### SKILL.md 结构

```markdown
---
name: root-cause-analysis
description: |
  使用 5 Whys 和鱼骨图进行根因分析。
  当用户问"为什么出问题"、"根本原因是什么"时使用。
---

## 分析框架

### 5 Whys
1. 描述表面现象
2. 连续问 5 次"为什么"
3. 区分症状和原因

### 鱼骨图维度
- 人员
- 流程
- 技术
- 环境

## 决策标准

| 类型 | 特征 | 处理 |
|------|------|------|
| 直接原因 | 立即触发 | 记录但不停留 |
| 根因 | 系统性 | 重点解决 |
|  contributing | 加剧因素 | 考虑缓解 |
```

### 测试策略

**测试输入**: 选择题/归因题

**通过标准**: 能识别何时用、何时不用

| 检查点 | 权重 |
|--------|------|
| 正确使用框架 | 35% |
| 区分不同场景 | 30% |
| 提供合理判断 | 25% |
| 解释选择理由 | 10% |

---

## Reference（参考型）

### 定义
可检索的知识库，用于查询具体信息。

### 特征
- 信息密度高
- 快速定位
- 准确性要求高

### 示例
- API 文档速查
- 配置字段说明
- 错误码对照表

### SKILL.md 结构

```markdown
---
name: api-quick-ref
description: |
  快速查询 API 端点和参数。
  当用户问"API怎么用"、"端点是什么"、"参数说明"时使用。
---

## 核心端点

### POST /api/v1/items
创建新项

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| name | string | 是 | 项名称 |
| tags | array | 否 | 标签列表 |

### GET /api/v1/items/:id
获取单项详情

## 详细参考
- `references/endpoints.md` - 完整端点列表
- `references/errors.md` - 错误码说明
- `references/examples.md` - 请求示例
```

### 测试策略

**测试输入**: 检索+应用题

**通过标准**: 能找到正确信息并用对

| 检查点 | 权重 |
|--------|------|
| 快速定位信息 | 30% |
| 信息准确 | 35% |
| 正确应用 | 25% |
| 提供上下文 | 10% |

## 类型选择指南

### 问自己的问题

1. **是否有多步流程？**
   - 是 → 可能是 Technique

2. **是否需要判断/选择？**
   - 是 → 可能是 Pattern

3. **是否主要是信息查询？**
   - 是 → 可能是 Reference

4. **用户会得到相同输出吗？**
   - 相同输入 → 相同输出：Technique
   - 相同输入 → 可能不同输出：Pattern
   - 查询 → 信息：Reference

### 常见混淆

| 场景 | 易误判 | 正确类型 |
|------|--------|----------|
| "怎么调试XX错误" | Pattern | Technique（有明确步骤） |
| "选A还是B" | Technique | Pattern（需判断标准） |
| "XX配置详解" | Technique | Reference（信息查询） |

---

## 组合类型

复杂 Skill 可能包含多种类型元素：

```markdown
## 概述
[Pattern: 何时使用]

## 快速开始
[Technique: 标准流程]

## 参考
[Reference: 参数说明]

## 深度分析
[Pattern: 进阶判断]
```

主类型由核心用途决定。
