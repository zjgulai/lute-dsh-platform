# JTBD 框架核心概念

## 核心原则

1. **用户"雇佣"产品来完成某个任务** — 用户购买的不是产品功能，而是解决特定场景下的问题
2. **关注"为什么"而非"是什么"** — 理解驱动因素比列出功能清单更重要
3. **竞争不限于同类产品** — 替代方案可能来自完全不同的品类

## 分析维度

### 功能性任务 (Functional Jobs)
用户要完成的具体操作或任务目标。

### 情感性任务 (Emotional Jobs)
用户在使用过程中希望获得的情感体验。

### 社会性任务 (Social Jobs)
用户希望如何在他人面前被感知。

## 输出层级

| 层级 | 含义 | 证据标准 |
|------|------|----------|
| Fact | 已证实的评价/访谈/竞品证据 | 必须引用来源 |
| Inference | 基于多条事实的推理 | 说明推理链 |
| Hypothesis | 待验证的假设 | 标注[推测] |
| Validation | 下一步验证计划 | 给出具体指标 |
