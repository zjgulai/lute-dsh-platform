# 分桶决策规则（DFM Rules）

本文件是语义分桶器的渐进式披露第二层，只在需要做阈值选择、桶大小控制或特征字段决策时读取。

## 1. 阈值选择规则

| 数据特点 | 推荐阈值 | 说明 |
|---------|---------|------|
| 标签密集（每个 SKU 5+ 标签） | 0.5-0.7 | 高阈值避免过度合并 |
| 标签稀疏（1-3 标签） | 0.3-0.5 | 低阈值保证有意义的合并 |
| 标签差异极大 | 0.3 | 先用宽松阈值粗分，再大桶细分 |
| 需要严格区分 | 0.7-0.8 | 保守分组，减少误合并 |

**决策依据**：使用 Jaccard Overlap（|A∩B| / min(|A|,|B|)），较小集合为分母的非对称相似度，对小集合更敏感。

## 2. 桶大小控制

- **默认 max_bucket_size**：32
- **大桶判断**：桶内 SKU 数 > max_bucket_size 时触发递归细分
- **细分策略**：将阈值提高到 1.5 倍（如 0.5 → 0.75）重新分桶
- **单元素桶（singleton）**：孤立 SKU 单独标记，检查其标签是否完整或是否需降阈值

## 3. 特征字段优先级

```
1. context.applicable_objects     # 适用对象（最高区分度）
2. custom_attributes.domain_tags  # 领域标签（次高）
3. core_logic.logic_type          # 逻辑类型（type: 前缀）
```

**缺失回退**：某字段缺失时跳过该字段，不设默认值；全部缺失时返回空特征集并提示用户补充。

## 4. 传递关系处理

Union-Find 的关键价值在于传递性：A~B（重叠≥阈值）且 B~C，则 A、B、C 归入同一桶，即使 A 与 C 直接重叠度低于阈值。这避免了层次聚类 O(n² log n) 的高复杂度，将复杂度降到 O(n² α(n)) ≈ O(n²)。

## 5. 性能优化

- n ≤ 1000：直接全配对计算
- n > 1000：倒排索引预筛选，先按标签粗分候选对，减少配对计算
- n > 10000：提示预估耗时，建议分批处理
