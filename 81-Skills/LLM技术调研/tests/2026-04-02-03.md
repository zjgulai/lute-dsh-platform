## High-Confidence Updates

### Claude Code v2.1.89（发布：2026-04-01）

**来源：** [GitHub Releases](https://github.com/anthropics/claude-code/releases/tag/v2.1.89) / [Releasebot](https://releasebot.io/updates/anthropic/claude-code)

#### 1. Hooks 机制重大扩展

**`defer` 权限决策（PreToolUse hooks）**
- Headless 会话现在可以在工具调用处暂停，用 `-p --resume` 恢复后让 hook 重新评估
- 应用场景：CI/CD 流水线中需要人工审批某些危险操作时，可以先挂起再恢复

**`PermissionDenied` hook**
- Auto mode 拒绝命令后会触发此 hook
- 返回 `{retry: true}` 可以让模型重试该操作
- 应用场景：自动降级为更安全的替代命令

**重要说明（PreToolUse 的 defer 最佳实践）**：
```bash
# 安全审查 hook — 只拦截危险模式，其余不干预
if <dangerous_pattern>; then
    echo '{"permissionDecision": "deny", "reason": "unsafe pattern"}'
    exit 2
fi
# 默认：不输出 JSON，exit 0 = 隐式 defer，恢复原生权限系统
exit 0
```
注意：显式返回 `"allow"` 会**完全绕过**原生权限系统，这是已知的常见误用。

#### 2. Named Subagents in @ mention

- `@` 输入时的补全现在包含命名子代理
- 结合 TaskCreated hook 可以构建更清晰的多代理编排流

#### 3. `MCP_CONNECTION_NONBLOCKING=true`

- `-p` 模式跳过 MCP 连接等待
- MCP 服务器连接超时从"无限等待"缩短到 5 秒
- 对于有多个 MCP 服务器的用户，启动速度显著提升

## New Tactics You Can Use Today

### 战术 1：用隐式 defer 替代显式 allow（立即可用）

**背景**：很多开发者在 PreToolUse hook 中默认返回 `"allow"`，实际上这会绕过原生权限系统。

**操作**：
```bash
#!/bin/bash
# ~/.claude/hooks/pre-tool-check.sh
TOOL_NAME="$1"
TOOL_INPUT="$2"

# 只拦截危险模式
if echo "$TOOL_INPUT" | grep -q "rm -rf /"; then
    echo '{"permissionDecision": "deny", "reason": "destructive command blocked"}'
    exit 2
fi

# 隐式 defer — 不输出任何内容，恢复原生权限流程
exit 0
```

### 战术 2：用 `MCP_CONNECTION_NONBLOCKING=true` 加速启动（立即可用）

**操作**：
```bash
# 在 .env 或 shell profile 中添加
export MCP_CONNECTION_NONBLOCKING=true
```
对于配置了 3 个以上 MCP 服务器的用户，`-p` 模式启动速度可以明显提升，不再被最慢的服务器卡住。

### 战术 3：用 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 防止 autocompact 死锁（立即可用）

**背景**：v2.1.89 已修复 autocompact 死锁，但主动控制触发时机仍然有价值。

**操作**：
```bash
export CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=70  # 在 70% 时触发，留更多缓冲
```
结合 `/compact "preserve all file paths, test results, and current debugging state"` 手动触发，比自动触发保留更多关键上下文。

### 战术 4：审查 CLAUDE.md，精简技能注入（本周可做）

**背景**：v2.1.86 修复了嵌套 CLAUDE.md 被重复注入的 bug，但仍需主动管理上下文。

**操作**：
- 使用 `.claudeignore` 排除不相关目录（可节省 30–40% token）
- CLAUDE.md 只写 Claude 无法从代码中推断的信息
- 技能描述在 `/skills` 列表中限制在 250 字符以内（v2.1.86 已自动截断）

### 战术 5：用 `PermissionDenied` hook 实现优雅降级（立即可用）

```json
// ~/.claude/settings.json hooks 配置
{
  "hooks": {
    "PermissionDenied": [{
      "command": "~/.claude/hooks/permission-denied-handler.sh"
    }]
  }
}
```
```bash
#!/bin/bash
# permission-denied-handler.sh
# 当 auto mode 拒绝命令后触发，可以记录日志并建议替代方案
echo '{"retry": false}'  # 或 {"retry": true} 让模型重试
```

## Risks / Caveats

1. **`permissionDecision: "deny"` 在 Edit 工具上存在已知 bug**（[Issue #37210](https://github.com/anthropics/claude-code/issues/37210)）：即使 hook 返回 deny，Edit 工具仍然可能执行。这是安全关键场景下的风险，v2.1.89 未确认修复，使用前需验证。

2. **`PermissionDenied` hook 的 `{retry: true}` 慎用**：如果模型不断重试被拒绝的操作，可能导致 API 调用消耗超出预期。建议配合最大重试次数限制。

3. **Composer 2 定价变化**：Standard 模式 $0.50/M 输入 + $2.50/M 输出，Fast 模式 $1.50/M 输入 + $7.50/M 输出。重度用户需要重新评估成本预算。

4. **Self-Hosted Cloud Agents 的安全模型**：连接通过 HTTPS 出站到 Cursor 云，意味着 Cursor 的编排服务仍然参与任务分发。完全离线场景不适用。

5. **v2.1.89 的 `/buddy` 彩蛋**（4 月 1 日）：一个跟着看你写代码的小生物。不影响功能，但说明 Anthropic 在 Claude Code 上保持了轻松的工程文化。

## Suggested Experiments

### 实验 1：测试新的 defer 权限 hook

**目标**：验证 `exit 0 + 无输出 = 隐式 defer` 在实际工作中是否正确恢复原生权限系统

**步骤**：
1. 创建一个 PreToolUse hook，默认 `exit 0` 无输出
2. 触发一个需要权限确认的操作（如写入新文件）
3. 观察是否出现原生权限提示
4. 对比：将 hook 改为显式 `{"permissionDecision": "allow"}`，观察权限提示是否消失

### 实验 2：MCP 服务器数量对启动速度的影响

**目标**：量化 `MCP_CONNECTION_NONBLOCKING=true` 的实际加速效果

**步骤**：
1. 配置 3–5 个 MCP 服务器（可以包含一个故意慢响应的测试服务器）
2. 对比有/无 `MCP_CONNECTION_NONBLOCKING=true` 时的 `-p` 模式启动时间
3. 记录结果，确认 5 秒超时是否影响工具可用性

### 实验 3：长会话 CLAUDE.md 注入频率审计

**目标**：评估 v2.1.86 修复后，嵌套 CLAUDE.md 在长会话中的实际 token 消耗

**步骤**：
1. 在有嵌套 CLAUDE.md 的项目中开启一个长会话
2. 使用 `/stats` 监控 token 使用量
3. 与 v2.1.85 之前的历史数据对比（如有）
