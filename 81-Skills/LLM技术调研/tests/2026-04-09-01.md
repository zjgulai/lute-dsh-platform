## Executive Summary

- **Cursor 3.0（2026-04-02）** 将界面重心转向 **Agents Window**：本地 / worktree / 云端 / SSH 多环境并行跑 agent；编辑器内新增 **`/worktree`**、**`/best-of-n`**（多模型隔离 worktree 对比）、**`Await`** 工具与浏览器自动化收紧后的策略，直接影响日常编排方式。
- **Claude Code v2.1.94（2026-04-07）** 增加 **Amazon Bedrock + Mantle** 支持、对多类用户将 **默认 effort 从 medium 调为 high**（可用 `/effort` 控制），并修复 **429 长 Retry-After 导致界面「假死」**、插件 skill 命名与 hook 等一批稳定性问题。
- **Claude Code v2.1.91（2026-04-02）** 为 MCP 增加 **`_meta["anthropic/maxResultSizeChars"]` 最大约 500K** 的结果体积覆盖，并新增 **`disableSkillShellExecution`** 以在托管场景禁用 skill/命令中的内联 shell 执行。
- **Skills 文档侧** 强调：`description` 前载触发场景、**列表展示单条 description 仍可能截断至约 250 字符**、可通过 **`SLASH_COMMAND_TOOL_CHAR_BUDGET`** 或精简描述缓解；自定义命令与 skill 已统一为同一套 slash 模型。

## High-Confidence Updates

### Cursor 3.0：Agents Window、Design Mode 与编辑器内新命令
- **What changed**: 官方发布 Cursor 3，核心为 Agents Window；Design Mode 可在浏览器内标注 UI；编辑器支持多 Agent Tabs；新增 `/worktree`、`/best-of-n`；MCP Apps 支持 structured content；多 root 工作区的 **hooks 从所有根目录加载** 等行为修正。
- **Why it matters**: 多 agent 并行与隔离 worktree 成为一等公民，团队需同步约定「何时用 cloud / SSH / worktree」及评审流程。
- **How to use it**: 升级后通过 `Cmd+Shift+P -> Agents Window` 试用；用 `/best-of-n` 对同一任务跑多模型对比；关注企业侧插件导入默认策略变化。
- **Confidence**: High
- **Sources**: [Cursor Changelog 3.0](https://cursor.com/changelog/3-0)、[Agents Window 文档](https://cursor.com/docs/agent/agents-window)

### Claude Code v2.1.94：Bedrock/Mantle、默认 effort、插件 skill 与 hook 修复
- **What changed**: 设置 `CLAUDE_CODE_USE_MANTLE=1` 可使用 **Amazon Bedrock powered by Mantle**；API-key、Bedrock/Vertex/Foundry、Team、Enterprise 用户 **默认 effort 升为 high**；插件中以 `"skills": ["./"]` 声明时 **调用名以 SKILL frontmatter 的 `name` 为准**；`UserPromptSubmit` hook 可写 `hookSpecificOutput.sessionTitle`；多项终端/VSCode/429/登录诊断修复。
- **Why it matters**: 默认 effort 变化会直接影响 token/成本与回答深度；Bedrock 路径扩展了企业部署选项；插件 skill 命名稳定化减少「目录名与 slash 名不一致」的协作摩擦。
- **How to use it**: 用 `/effort` 显式确认或调回期望档位；Bedrock+Mantle 用户按 release 说明启用环境变量；检查插件内 skill 的 `name` 是否与文档/脚本一致。
- **Confidence**: High
- **Sources**: [claude-code v2.1.94 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.94)

### Claude Code v2.1.91：MCP 大结果与技能内 shell 管控
- **What changed**: MCP 工具结果可通过 `_meta["anthropic/maxResultSizeChars"]` **提升至约 500K 字符**；`disableSkillShellExecution` 可禁用用户/项目/插件来源 skill 与自定义 slash 中的内联 shell（bundled/managed 不受影响）；插件可带 `bin/` 可执行文件并由 Bash 以裸命令调用；`/claude-api` skill 对 agent 设计模式指引增强。
- **Why it matters**: 大 schema/日志类 MCP 输出可减少截断；企业可通过托管设置收紧「skill 预处理 shell」攻击面。
- **How to use it**: 在 MCP server 返回的大 payload 上标注 meta（按官方文档约定）；在 `settings.json` 配置 `disableSkillShellExecution` 以满足合规。
- **Confidence**: High
- **Sources**: [claude-code v2.1.91 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.91)

### Claude Code Skills：文档与触发/预算机制
- **What changed**: 官方文档明确 **custom commands 与 skills 合并为同一 slash 体系**；**嵌套 `packages/.../.claude/skills/`** 与 **`--add-dir` 目录下的 skills** 可被加载；`description` 过长时在列表中 **按约 250 字符截断**，另有动态总预算与 `SLASH_COMMAND_TOOL_CHAR_BUDGET`；`disableSkillShellExecution` 与 skill 内 ``!` `` 预处理的关系已写入文档。
- **Why it matters**: monorepo 与多目录授权下的 skill 发现路径更清晰；description 设计需「前载关键词」以对抗截断。
- **How to use it**: 为高频 skill 精简 description 首段；需要时设置 `SLASH_COMMAND_TOOL_CHAR_BUDGET`；在 monorepo 包内维护包级 `.claude/skills/`。
- **Confidence**: High
- **Sources**: [Extend Claude with skills](https://docs.anthropic.com/en/docs/claude-code/skills)

## New Tactics You Can Use Today

### Tactic 1
- **Action**: 在 Cursor 3 中打开 Agents Window，选一个非关键任务试用 **并行两个 agent**（本地 + worktree 或 cloud），对比完成质量与干预次数。
- **When to use**: 任务可自然拆分为独立子路径（如「调研 + 实现」或「多文件并行修改」）。
- **Expected benefit**: 更快获得可合并结果，并暴露团队流程里对隔离分支/评审的缺口。
- **Caveat**: `/best-of-n` 会消耗多模型成本；需约定如何择合与丢弃分支。

### Tactic 2
- **Action**: 升级 Claude Code 后运行 `/effort`，确认当前默认值是否符合预期；若使用 API-key 或 Bedrock 等企业通道，评估 **默认 high** 对成本与延迟的影响并固定团队基线。
- **When to use**: 刚升级至 v2.1.94 或发现回答变「更重」、费用上升时。
- **Expected benefit**: 避免无意识的成本漂移；把「默认深度」写成团队约定。
- **Caveat**: 不同账号类型行为不同，以官方 release 说明为准。

### Tactic 3
- **Action**: 若 MCP 返回大数据（库表结构、长日志），查阅 MCP 实现是否已支持 **`anthropic/maxResultSizeChars`** meta，并按需上调（上限以 release 为准，当前 release 称约 500K）。
- **When to use**: 频繁看到 MCP 结果被截断、导致 agent 误判 schema 或漏字段时。
- **Expected benefit**: 减少「半截 JSON」引发的幻觉修复循环。
- **Caveat**: 过大结果仍占上下文，需要配合筛选/分页策略。

### Tactic 4
- **Action**: 审计仓库与插件中的 `SKILL.md`：**`name` 是否与团队文档中的 slash 一致**；description 首句是否包含 **触发场景 + 关键词**（对抗 250 字符列表截断）。
- **When to use**: 插件以 `"skills": ["./"]` 分发、或 skill 触发率不稳定时。
- **Expected benefit**: 稳定调用名与自动触发率；降低「有 skill 但模型不知道何时加载」的摩擦。
- **Caveat**: 总描述预算仍受会话内 skill 数量影响，skill 过多时需分层与拆分。

## Risks / Caveats

- **版本与账号差异**：Claude Code 的默认 effort、权限与托管策略随渠道变化；结论以对应版本的 **GitHub Release** 与组织策略为准。
- **Cursor 功能面迁移**：3.0 changelog 明确多项能力从旧入口迁移；升级后需对照官方 changelog 更新内部 playbook。
- **MCP 大结果**：提高 `maxResultSizeChars` 会放大上下文占用，可能挤压其他工具结果；需配合「只取必要字段」的服务端设计。
- **二手解读**：非官方聚合站（如 release 聚合类站点）仅作线索，关键行为以 **cursor.com/changelog**、**GitHub releases**、**Anthropic 文档** 为准。
