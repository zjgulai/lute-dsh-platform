## High-Confidence Updates

### 1) Cursor 3.0 正式发布（Apr 2, 2026）

**来源：** [Cursor Changelog 3.0](https://www.cursor.com/changelog/3-0) | [Blog](https://cursor.com/blog/cursor-3)

核心新功能：

| 功能 | 说明 |
|---|---|
| **Agents Window** | 新界面，`Cmd+Shift+P → Agents Window` 启动，可同时查看所有 local/cloud Agent |
| **Design Mode** | 在浏览器中框选 UI 元素直接注入 Agent 上下文，精准反馈 |
| **Agent Tabs** | 多个 Agent 对话并排显示，grid 布局 |
| `/worktree` | 在隔离 git worktree 中执行任务，变更隔离 |
| `/best-of-n` | 同一任务并发跑多个模型 × 多个 worktree，比较输出 |
| **cloud↔local 切换** | Agent 会话可以从 local 切换到 cloud 继续跑，或从 cloud 切回本地调试 |

重要变更：
- cloud agents 已从 Editor 移除，统一进入 Agents Window
- worktree 支持也从 Editor 移至 Agents Window，UX 改善

### 2) Claude Code Skills 成为官方核心功能，文档大升级

**来源：** [Skills Docs](https://docs.anthropic.com/en/docs/claude-code/skills)

**最重要的新知识点：**

**① Skills 遵循 [agentskills.io](https://agentskills.io/) 开放标准**
> Claude Code 在标准基础上扩展了调用控制、Subagent 执行、动态上下文注入三大能力。

**② Commands 与 Skills 正式合并**
- `.claude/commands/deploy.md` 与 `.claude/skills/deploy/SKILL.md` 完全等效
- 已有 `.claude/commands/` 文件无需迁移，继续有效
- Skills 是推荐格式，因为支持多文件 + frontmatter 控制

**③ 新增关键 Frontmatter 字段一览：**

| 字段 | 作用 | 今天就能用 |
|---|---|---|
| `disable-model-invocation: true` | 禁止 Claude 自动触发，只允许用户 `/invoke` | 部署类 skill 必加 |
| `user-invocable: false` | 不出现在 `/` 菜单，只允许 Claude 自动调用 | 背景知识类 skill |
| `allowed-tools: Read Grep` | 预授权工具，无需每次审批 | 减少打断 |
| `context: fork` | 在隔离子 Agent 运行，不携带主会话历史 | 重型研究/大任务 |
| `agent: Explore` | 与 `context: fork` 配合，指定子 Agent 类型 | 可选 Explore/Plan/general-purpose |
| `paths:` | YAML list 格式的 glob，仅匹配指定文件时加载 | monorepo 场景必备 |
| `effort: max` | 指定此 skill 激活时使用最高推理强度（Opus 4.6 only） | 复杂 skill |
| `hooks:` | Skill 生命周期 hooks | 前置/后置自动化 |

**④ Bundled Skills（内置技能，即用）：**

| Skill | 用途 |
|---|---|
| `/batch <task>` | 分解 + 并发 Agent 执行大规模代码变更，自动开 PR |
| `/simplify [focus]` | 3 个并发 review Agent 找问题 + 自动修复 |
| `/loop [interval] <prompt>` | 定时循环执行，适合监控部署、巡检 PR |
| `/claude-api` | 加载当前语言的 Claude API 参考，自动识别 import |
| `/debug [desc]` | 开启 debug 日志 + 分析当前会话问题 |

**⑤ 动态上下文注入（`!``command```）：**

```yaml
---
name: pr-summary
context: fork
agent: Explore
---
## 当前 PR 状态
- Diff: !`gh pr diff`
- Comments: !`gh pr view --comments`
```

注入是预处理，Claude 只看到执行结果，不是命令本身。

## New Tactics You Can Use Today

### 战术 1：按调用者分类你的 Skills（立刻整理现有 skills）

建立三类：

```
A. 用户主动调用（部署、commit、发布）
   → disable-model-invocation: true

B. AI 自动加载（知识/规范/背景上下文）
   → 只写好 description，前 250 字含关键词

C. 混合（既可手动也可 AI 触发）
   → 默认，确保 description 与触发词精准匹配
```

### 战术 2：用 `context: fork` + `agent: Explore` 替代"让 Claude 直接做深度研究"

```yaml
---
name: deep-audit
description: 深度分析 skill 的闭环能力与外部依赖
context: fork
agent: Explore
---

分析以下维度：
1. 外部依赖（API/SaaS/账号）
2. 可降级路径
3. 关联技能

目标：$ARGUMENTS
```

**好处**：不污染主会话历史，结果干净摘要返回。

### 战术 3：`paths:` 实现 monorepo skill 分区

```yaml
---
name: frontend-conventions
description: 前端组件开发规范
paths:
  - packages/frontend/**
  - apps/web/**
---
```

只有在处理前端文件时才加载，避免跨项目污染。

### 战术 4：描述写法改造（250 字符上限）

❌ 旧写法：
```
description: 这是一个用于处理跨境电商 Skill 审计的工具，可以检查外部依赖……
```

✅ 新写法（前置触发词）：
```
description: 审计 skill 闭环能力与外部依赖。用户说"skill 审计"、"依赖检查"、"闭环分析"时触发。输出：依赖等级 + 闭环评分 + 整改建议。
```

### 战术 5：在 Cursor 中用 `/best-of-n` 做决策质量对比

适用场景：
- 架构方案选型
- 重构策略比较
- 同一需求多实现路径对比

每个方案在独立 worktree 跑，互不干扰，最后比结果。

## Signals Worth Watching

1. **Cursor 3.0 Agents Window** 目前是 opt-in（`Cmd+Shift+P → Agents Window`），预计后续会成为默认界面，值得提前熟悉工作流迁移成本。
2. **agentskills.io 开放标准** — Skills 跨 AI 工具互通的标准正在形成，Cursor Plugin Skills 与 Claude Code Skills 格式已经接近，关注 Kimi/Gemini 是否跟进。
3. **`/loop` + Automations 的关系** — Cursor Automations（Schedule 触发）+ Claude Code `/loop`（会话内循环），两个方向的"长期运行 Agent"正在收敛，可能会有统一抽象。

## Risks / Caveats

1. **`context: fork` skill 无法访问主会话历史** — 适合独立任务，不适合需要会话上下文的 skill。
2. **Cursor 3.0 cloud↔local 切换需要订阅支持** — 部分功能受 plan 限制。
3. **`/best-of-n` 费用较高** — 并发跑多个 worktree × 多个模型，成本翻倍，建议只用于真正需要对比的决策点。
4. **`disableSkillShellExecution` 会禁用 `!``command``` 注入** — 开启后动态上下文功能失效，安全与能力二选一。
