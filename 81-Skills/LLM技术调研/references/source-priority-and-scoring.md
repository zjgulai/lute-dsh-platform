# Source Priority And Scoring

这份规则用于给研究来源做分层、打分和取舍，避免把二手搬运、低信度爆料和高信度官方信息混在一起。

## 核心原则

- 一手来源优先于二手解读
- 原始发布时间优先于转述时间
- 能直接影响使用方式的信息优先于纯舆论讨论
- 多个独立高质量来源互相印证时，可信度上升
- 只有单一低信源支持的说法，默认进入 `待验证`

## 来源优先级

### Tier 1: 官方一手来源

优先使用这些来源作为主证据：

- 官方网站
- 官方文档
- 官方 changelog / release note
- 官方 GitHub 仓库、release、issue、discussion
- 官方博客
- 官方 X/Twitter 账号
- 明确可识别的核心维护者公开发言

**默认结论**：高置信候选

### Tier 2: 强社区信号

- 高质量 Reddit 讨论
- GitHub 非官方但高质量 issue / discussion
- 有具体截图、链接、复现实例的社区帖子
- 知名开发者的公开复盘

**默认结论**：中置信候选，需要尽量找一手来源佐证

### Tier 3: 二手解读与内容搬运

- 媒体转述
- 个人博客二次摘要
- 微信公众号解读
- 汇总帖、搬运帖、转译帖

**默认结论**：只能作为补充线索，不能单独支撑关键结论

#### 中文社区默认处理规则

以下来源默认按 Tier 3 处理，除非内容直接链接到并准确引用了官方一手材料：

- 微信公众号
- 掘金经验帖
- 知乎回答
- 中文社区搬运与转译文章

使用纪律：

- 可用来发现线索和关键词
- 可用来帮助理解中文语境下的实操经验
- 不可作为唯一主证据支撑重要结论
- 一旦和官方材料冲突，优先以官方材料为准
- 如果文章声称“官方已更新”，优先追到原始链接后再写入高置信结论

### Tier 4: 弱信号与传闻

- 无原始链接的截图
- 未说明出处的转述
- “听说”“据传”“有人说”类内容
- 无法确认发布时间和作者身份的内容

**默认结论**：标记为 `待验证` 或舍弃

## 评分维度

每条候选信息按 5 个维度做快速判断。

### 1. Source Authority / 来源权威性

- `5`：官方或核心维护者直接发布
- `4`：高质量社区一手观察，可复现
- `3`：可信二手解读
- `2`：普通社区转述
- `1`：匿名、无出处或不可溯源

### 2. Evidence Quality / 证据质量

- `5`：原始链接 + 原文摘录 + 时间明确
- `4`：有截图或日志，且能追溯
- `3`：有描述，但证据不完整
- `2`：只有主观看法
- `1`：几乎无证据

### 3. Freshness / 新鲜度

- `5`：在目标时间窗口内，且明显是新变化
- `4`：近期内容，但可能是延迟传播
- `3`：近期讨论旧功能
- `2`：较旧内容被重新炒热
- `1`：明显过时

### 4. Practical Impact / 实操影响

- `5`：今天就能改变工作流、效率或判断
- `4`：短期内值得尝试
- `3`：有参考价值，但不一定马上可用
- `2`：更多是认知层面的补充
- `1`：基本没有实际使用价值

### 5. Cross-Source Confirmation / 交叉验证

- `5`：两个以上独立高质量来源互证
- `4`：一个高质量来源 + 一个补充来源
- `3`：只有一个高质量来源
- `2`：只有一个中质量来源
- `1`：只有一个低质量来源

## 快速判定规则

- 优先写入 `High-Confidence Updates`：Tier 1 或综合判断明显可靠的内容
- 优先写入 `Signals Worth Watching`：方向有价值，但证据尚不完整的内容
- 不写入主结论：只有 Tier 3/4 且无法交叉验证的内容
- 中文社区/公众号内容默认进入补充线索池，除非已经完成一手来源回溯

## 证据卡最小模板

```yaml
topic: Cursor background agents
source_type: official_docs
publisher: Cursor
url: https://example.com
published_at: 2026-04-02
claim: 新增某种 agent workflow
excerpt: 原文关键句
confidence: high
practical_impact: 可以减少手动切换上下文
verification_status: verified
```

## 报告写作纪律

- 高置信信息写结论，再给来源
- 中置信信息写判断时，显式说明限制
- 待验证信息只写成观察线索，不写成事实
- 同一主题如果官方已说明，优先引用官方而非社区摘要
- 中文社区文章若只是二次总结，优先把它们降级写入 `Signals Worth Watching` 或 `Source Log`
