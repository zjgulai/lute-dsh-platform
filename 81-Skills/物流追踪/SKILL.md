# 物流追踪

跨多家承运商追踪货运状态、异常与预计到达时间。

> 使用边界：它只做执行态物流追踪和异常可视化，不做路线规划、成本测算或承运商决策；这些任务交给 `物流优化`。

## 何时使用

当用户提供运单号（含承运商名称）且请求为纯运单追踪时，触发本技能。缺单号或承运商时先追问澄清，不猜测。请求混合运单追踪与其他任务（成本测算/路线规划/补货决策/供应商评估/清关处理/承运商时效对比/供应链统筹）时，整体不触发本技能，路由到对应 Skill。

- 物流状态追踪：查询单个运单的当前状态、位置和轨迹
- 异常预警：检测滞留、延误、丢件等异常并给出建议
- 到货时间预测：基于承运商SLA和当前进度估算ETA
- 批量运单监控：同时追踪多个运单的整体在途情况
- 物流商表现对比：汇总各承运商的时效达成和异常率（有运单号时触发；无运单号的承运商时效对比属物流优化）

## 何时不用

- 物流路线/承运商方案优化（使用 `物流优化`）
- 复杂供应链管理（如库存预测、供应商评估、采购计划）
- 运输成本分析与优化
- 海关清关处理与关务合规咨询
- 物流方案设计（头程/尾程/仓配方案）
- 退货物流管理流程设计
- 承运商配送时效对比分析（无运单号的承运商选型对比，使用 `物流优化`）
- 库存补货计划与备货预测

## 使用方法

1. 用户提供物流单号和承运商名称
2. 若缺单号或承运商，追问澄清后再追踪
3. 解析单号格式，识别承运商和路线
4. 生成追踪报告：状态、轨迹、ETA、异常预警

## 输入

- 物流单号（必填）
- 承运商名称（必填，若能从单号格式推断则注明推断依据后继续）
- 发货/目的地（可选）

## 输出

- 物流状态更新：当前状态、位置、最新扫描节点
- 预计到达时间：基于承运商SLA和进度估算
- 异常提醒：滞留、延误、丢件等异常及建议
- 承运商表现：多单追踪时的汇总对比

## 错误处理

| 场景 | 处理方式 |
|------|----------|
| 未提供单号 | 追问：请提供运单号和承运商名称 |
| 未提供承运商 | 尝试从单号格式推断并发问确认；若无法推断则追问承运商 |
| 单号格式无效 | 告知格式异常，请用户确认单号是否正确 |
| 无追踪数据 | 说明无法获取实时数据，给出基于单号格式的推断和建议的查询渠道 |
| 多承运商同时查询 | 逐单追踪，按承运商分组汇总 |
| 混合请求（追踪+成本/路线/补货/供应商/清关/时效对比/统筹） | 整体不触发本技能，路由到对应 Skill（物流优化/库存预测/供应商评估/供应链主控） |

## 竞争壁垒

| 竞争对手 | 本技能做 | 对方做 | 分界 |
|----------|----------|--------|------|
| 物流优化 | 运单状态/ETA/异常 | 路线规划/成本/承运商选择 | 有单号查状态→本技能；要方案→物流优化 |
| 供应链主控 | 运单级追踪 | 库存/供应商/物流统筹 | 单一运单→本技能；多环节统筹→供应链主控 |
| 供应商评估 | 承运商表现 | 供应商交付/质量/价格 | 运单级对比→本技能；准入评估→供应商评估 |
